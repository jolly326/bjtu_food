# 后端接口测试指南

## 1. 接口对齐检查结论

本文档基于当前后端 Controller、小程序 `frontend/src/api`、浏览器管理端 `web/src/api` 和 `docs/bjtu_food_base.sql` 基础数据整理。

### 1.1 已满足小程序前端的接口

小程序当前主要调用以下接口，后端均已提供：

| 前端功能 | 小程序调用 | 后端状态 |
|---|---|---|
| 首页轮播图 | `GET /canteens/banners` | 已满足 |
| 食堂列表 | `GET /canteens` | 已满足 |
| 食堂图片映射 | `GET /canteens/images` | 已满足 |
| 档口详情 | `GET /canteens/stallDetail` | 已满足 |
| 热门菜品 | `GET /dishes/hot` | 已满足 |
| 菜品搜索/筛选 | `GET /dishes` | 已满足 |
| 菜品详情 | `GET /dishes/{id}` | 已满足 |
| 收藏列表/切换收藏 | `GET /favorites`、`POST /favorites/toggle` | 已满足，需登录 |

注意：小程序 `frontend/src/api/user.ts` 当前把登录参数命名为 `code`，但实际调用的是密码登录：

```json

  "password": "123456"
}
```

如果小程序后续要做真正的邮箱验证码登录，需要先调用 `POST /auth/email-code`，再调用 `POST /auth/login` 并传 `email + code`。

### 1.3 仍需注意的接口缺口

| 模块 | 当前状态 | 建议 |
|---|---|---|
| `GET /admin/stats/overview` | 目前返回占位字符串 | 如果 Web 仪表盘要展示真实统计，需要实现真实聚合数据 |
| `GET /admin/stats/trend` | 目前返回占位字符串 | 需要按日期统计浏览、评价等趋势 |
| `GET /admin/stats/rank` | 目前返回占位字符串 | 需要返回热门菜品排行 |
| Web 后台新增/删除用户 | 后端未提供专门接口 | 当前建议通过注册创建用户，通过禁用状态代替删除 |

## 2. 通用调用规则

### 2.1 基础地址

后端配置了统一前缀：

```text
http://localhost:8080/api
```

例如 Controller 中的 `/auth/login`，完整测试地址是：

```text
POST http://localhost:8080/api/auth/login
```

### 2.2 统一响应格式

所有接口统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

常见错误：

| code | 含义 |
---|---|
| 400 | 请求参数错误或业务校验失败 |
| 401 | 未登录或 token 无效 |
| 403 | 已登录但权限不足 |
| 500 | 服务器内部错误 |

### 2.3 登录态传递

登录成功后复制 `data.token`，后续需要登录的接口添加请求头：

```text
Authorization: Bearer <token>
```

Knife4j 的 Authorize 通常只需要填写 token 本体，不需要手动加 `Bearer`。

## 3. 认证与用户接口

### 3.1 获取邮箱验证码

用途：向校园邮箱发送验证码，用于注册或验证码登录。

```http
POST /auth/email-code
Content-Type: application/json
```

登录验证码测试参数：

```json
{
  "email": "20240001@bjtu.edu.cn",
  "purpose": "login"
}
```

注册验证码测试参数：

```json
{
  "email": "20240002@bjtu.edu.cn",
  "purpose": "register"
}
```

说明：验证码不会出现在响应体中，需要去邮箱查看。`purpose` 可传 `login` 或 `register`。

### 3.2 密码登录

用途：用户或管理员使用账号密码登录，返回 JWT token。

```http
POST /auth/login
Content-Type: application/json
```

普通用户：

```json
{
  "account": "20240001",
  "password": "123456"
}
```

管理员：

```json
{
  "account": "admin001",
  "password": "123456"
}
```

也可以用邮箱作为账号：

```json
{
  "account": "admin001@bjtu.edu.cn",
  "password": "123456"
}
```

### 3.3 邮箱验证码登录

用途：使用邮箱验证码登录已有用户。

```http
POST /auth/login
Content-Type: application/json
```

测试参数：

```json
{
  "email": "20240001@bjtu.edu.cn",
  "code": "邮箱收到的验证码"
}
```

前置条件：先调用 `POST /auth/email-code`，`purpose` 传 `login`。

### 3.4 注册

用途：创建普通用户，注册成功后直接返回 token。

```http
POST /auth/register
Content-Type: application/json
```

测试参数：

```json
{
  "username": "20240002",
  "email": "20240002@bjtu.edu.cn",
  "code": "邮箱收到的验证码",
  "password": "123456",
  "nickname": "交大新用户"
}
```

前置条件：先调用 `POST /auth/email-code`，`purpose` 传 `register`。

### 3.5 获取当前用户资料

用途：个人中心读取当前登录用户信息。

```http
GET /auth/profile
Authorization: Bearer <userToken>
```

### 3.6 修改当前用户资料

用途：修改昵称或头像。

```http
PUT /auth/profile
Authorization: Bearer <userToken>
Content-Type: application/json
```

测试参数：

```json
{
  "nickname": "交大学子",
  "avatar": "/images/seed/dishes/tomato-egg.jpg"
}
```

### 3.7 获取当前用户统计

用途：个人中心显示收藏数、评价数。

```http
GET /auth/stats
Authorization: Bearer <userToken>
```

### 3.8 修改密码

用途：修改当前登录用户密码。

```http
PUT /auth/password
Authorization: Bearer <userToken>
Content-Type: application/json
```

测试参数：

```json
{
  "oldPassword": "123456",
  "newPassword": "654321"
}
```

注意：该接口会真实修改密码。测试后如需恢复，可再用 `654321` 改回 `123456`。

## 7. 评价接口

### 7.1 菜品评价列表

用途：菜品详情页展示评价。

基础数据中菜品 `6` 有评价：

```http
GET /dishes/6/reviews?page=1&pageSize=20
```

### 7.2 提交评价

用途：当前用户对菜品评分和评论。

```http
POST /reviews
Authorization: Bearer <userToken>
Content-Type: application/json
```

建议测试参数：

```json
{
  "dishId": 1,
  "rating": 5,
  "content": "味道不错，分量也足。",
  "images": ["/images/seed/dishes/tomato-egg.jpg"]
}
```

注意：同一用户对同一菜品只能评价一次。基础数据中用户 `20240001` 已评价菜品 `6、11、12、28、35、40`，所以建议用 `dishId=1` 测试新增评价。

### 7.3 修改自己的评价

用途：修改当前用户自己的评价内容和评分。

```http
PUT /reviews/{id}
Authorization: Bearer <userToken>
Content-Type: application/json
```

测试参数：

```json
{
  "dishId": 6,
  "rating": 4,
  "content": "重新评价：整体不错。",
  "images": []
}
```

可用路径：

```http
PUT /reviews/1
```

说明：基础数据中评价 `1` 属于用户 `20240001`。

### 7.4 删除自己的评价

用途：删除当前用户自己的评价。

```http
DELETE /reviews/1
Authorization: Bearer <userToken>
```

注意：该操作会真实删除基础数据中的评价，建议只在回归测试或测试库中执行。

## 9. 图片上传接口

### 9.1 上传图片

用途：上传头像、菜品图、评价图。

```http
POST /upload/image
Authorization: Bearer <userToken 或 adminToken>
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
---|---|---|---|
| `file` | File | 是 | 支持 `jpg`、`jpeg`、`png`、`webp` |

成功响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "url": "http://localhost:8080/api/images/2026/06/xxx.jpg",
    "relativeUrl": "/images/2026/06/xxx.jpg"
  }
}
```

说明：

- 前端展示图片建议使用 `data.url`。
- 数据库存储图片建议使用 `data.relativeUrl` 或相对路径数组。
- Knife4j 测试时字段名必须是 `file`。

用途：后台分页查看用户。

```json
  "status": "disabled"
```

```json
  "status": "active"
```


```json
{
```
