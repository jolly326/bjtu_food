# 学生端接口 · 饮食记录

> **契约真源**：端点 / 入参 / 出参 / 错误码。通用约定见 [`api/README.md`](../README.md)。
> 列定义见 [`schema/dish_record.md`](../../schema/dish_record.md)。

一条**饮食记录** = 用户对某道菜的一次「去品尝 → 吃 → 评分」。本域全部操作落在**同一资源** `/my/records` 上，无动作式端点。

## `GET /my/records`

🔑 需登录 —— 「**我的食谱**」清单。

| 项 | 口径 |
|---|---|
| 入参 | 无 |
| 出参 | `[RecordVO]` —— 该用户**全部**记录，按 `wantedAt` **降序** |
| 分组 | 服务端**平铺**下发；端上按 `wantedAt` 的**月份 / 日期**自行分组（记录量级小，不做服务端筛选） |

**`RecordVO`**

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | number | 否 | 记录 ID |
| `dishId` | number | 否 | 菜品 ID |
| `name` | string | 否 | 菜品名称 |
| `imageUrl` | string | 否 | 菜品图绝对 URL |
| `wantedAt` | string | 否 | 点「去品尝」的时间 |
| `reaction` | number | **是** | `5` = 好吃 ｜ `3` = 一般 ｜ `1` = 踩；**`null` = 尚未评分** |

## `POST /my/records`

🔑 需登录 —— 「**去品尝**」：在记录集合中创建一条。

| 项 | 口径 |
|---|---|
| 入参 | `{ dishId }` |
| 行为 | INSERT 一条（`reaction = NULL`，`wantedAt` = 当前时间） |
| 幂等 | 该菜**已有未评分记录** ⇒ **不新建**，直接返回该既有记录 |
| 出参 | `RecordVO`（新建或复用的那条） |
| 错误码 | `400` `dishId` 缺失 ｜ `4001` 菜品不存在 / 已下架 |

## `PATCH /my/records/{id}`

🔑 需登录 —— **评分**（更新记录的 `reaction`）。

| 项 | 口径 |
|---|---|
| 入参 | `{ reaction }` —— **`5` / `3` / `1`**；其它值 ⇒ `400` |
| 行为 | 写 `reaction` + `reactedAt` |
| 🔴 一次性 | 只允许**未评分**记录评分；已评分 ⇒ `400`（要重评须再 `POST /my/records` 新建一条） |
| 归属 | 只能改**自己的**记录；非本人 ⇒ `4001`（不暴露他人记录是否存在） |
| 出参 | `RecordVO`（更新后） |
| 副作用 | 同事务内重算 `dish.avg_reaction` / `reaction_count` |
| 错误码 | `400` 取值非法 / 已评分 ｜ `4001` 记录不存在或非本人 ｜ `429` 命中限频 |

## `DELETE /my/records/{id}`

🔑 需登录 —— **取消品尝**：把该菜移出「我的饮食记录」。

| 项 | 口径 |
|---|---|
| 行为 | 物理删除该记录 |
| 🔴 边界 | **只允许删除未评分记录** —— 已给出结论（已评分）的记录不可撤销 ⇒ `400`「已评分，无法取消」 |
| 归属 | 只能删**自己的**记录；非本人 ⇒ `4001` |
| 出参 | `data: null` |
| 错误码 | `400` 已评分无法取消 ｜ `4001` 记录不存在或非本人 |
