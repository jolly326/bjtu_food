# client/dishes — 菜品资源

**归属**：`DishController` · `CorrectionController` · `ReviewController`（子资源）
**通用约定**（响应信封 / 分页壳 / 错误码 / 鉴权标记）见 [api/README.md](../README.md)

> 本文是 `/dishes*` 全部端点的**唯一契约来源**。各 feature 文档只描述业务规则，不重复字段表。

## GET /dishes

**鉴权**：🔓 公开 ｜ **用途**：菜品分页列表（首页网格、搜索结果共用）

### Query 参数
| 名称 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `page` | number | 否 | 1 | 页码；`<=0` 归一为 1 |
| `pageSize` | number | 否 | 10 | 每页条数；上限 **50**（超限截断），`<=0` 回退 10 |
| `keyword` | string | 否 | — | 关键词，对 **菜名 / 档口名 / 食堂名** 三处模糊匹配；空则不筛选。**≤30 字符，超限 → 400**「关键词不能超过 30 字」（端上搜索框 `maxlength=30` 同口径） |
| `view` | number | 否 | 首个启用视图 | **筛选视图 ID**，值域由 `GET /dishes/views` 下发；**白名单校验，非法值 → 400**（不静默降级） |
| `seed` | string | 否 | — | 会话随机种子。**`sortKind` 为 `random` 的视图消费它**（种子里 7 项均为该口径）；**命中 `keyword` 时不参与排序**（关键词搜索恒为稳定序）。**不传** ⇒ 排序退化为 `id` 升序（`CRC32(CONCAT(NULL,…))` 恒为 `NULL`，各行并列后由决胜键 `d.id` 决定）—— 搜索页正是此路径（不传 `seed`） |

> 参数集恰为这 5 项。筛选与排序由所选 `view` 唯一决定，**无排序入参**。
> `view` 与 `keyword` 可同时传（语义 AND），但端上约定二者不同时使用。

### 响应 `data` = `PageResult<DishListItemVO>`

分页壳仅 `records` 一项（见 [api/README](../README.md#分页结构-pageresultt)）。

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | number | 否 | 菜品 ID |
| `name` | string | 否 | 菜品名称 |
| `coverImage` | string | 否 | 封面图 URL（`images` 首图派生）；**无图时为空串** |
| `price` | number | 否 | 现价，**单位：分**（端上转「元」展示，已含折扣） |
| `originalPrice` | number \| null | **是** | 原价，单位分；`> price` 即有折扣。**无折扣为 null** |
| `avgRating` | number | 否 | 均分；**零评价下发 `5.0`**（冷启动展示值，见下「零评价展示口径」） |
| `canteenName` | string | 否 | 食堂名称（空串兜底） |
| `stallName` | string | 否 | 档口名称（空串兜底） |

共 **8 字段**，列表专用；详情专属字段不在此返回。

> **存储映射**（对应列 / 是否缓存列 / 能否修改）见 [schema/dish.md](../../schema/dish.md)。

### 零评价展示口径（`avgRating`）

| 场景 | `avgRating` | 端上呈现 |
|---|---|---|
| **有评价** | 真实均分（1~5，一位小数） | 「⭐ 4.5」 |
| **零评价** | **`5.0`**（展示兜底值） | 「⭐ 5.0」 |

- 🔴 **`avgRating` 出参恒非空**：零评价下发 `5.0` 而非 `null` —— 冷启动阶段大量菜品零评价，缺失值会让卡片评分位空缺、页面失真且不吸引用户停留。
- ⚠️ **不展示评价条数**：`rating_count` **不出公开出参**（保持列表 8 字段、详情 11 字段）—— 卡片只显示星 + 均分，**保持简洁**；可信度交由「评价区按星级筛选」承载（见 [GET /dishes/{id}/reviews](#get-dishesidreviews)），不在卡片堆信息。
- ⚠️ **展示值与排序值分离**：`avgRating` 的 `5.0` **只是出参兜底** —— **不参与排序**（种子里 7 个视图走会话伪随机序）；存储层口径见 [schema/dish.md](../../schema/dish.md)。该分离在**后期若重启评分加权排序时仍然成立**：若把兜底值送进排序公式，零评价菜会凭空获得满分权重而虚高置顶。

### 错误码
| code | 条件 |
|---|---|
| 400 | `view` 非法值 |

### 备注
- 公开接口恒只返回 `status='on'`（在售）菜品。
- 关键词为**前缀通配 `%kw%`**，无法使用索引（性能约束登记在对应功能文档）。

## GET /dishes/views

**鉴权**：🔓 公开 ｜ **用途**：首页筛选视图字典

### 请求参数
无。

### 响应 `data` = `DishViewVO[]`
| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | number | 否 | 视图 ID，端上点击后原样回传为 `view=<id>` |
| `label` | string | 否 | 标签文案（服务端资产，端上零硬编码） |

> 顺序 = **后台配置的 `order` 升序**（同序按 `id` 升序）。**匹配数为 0 的视图不下发**（避免点进空列表）；不传 `view` 时取**首个启用视图**。
> 出参恰 `id` / `label` 两项：筛选条件与排序口径都存服务端（[schema/dish_filter_view.md](../../schema/dish_filter_view.md)），端上不感知、也不回传。

## GET /dishes/for-you

**鉴权**：🔓 公开 ｜ **用途**：搜索页「猜你喜欢」

### Query 参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `seed` | string | 否 | 会话级随机种子。传入 ⇒ 按 `CRC32(seed-id)` 稳定伪随机序，**同一 seed 恒返回同一批**；不传 ⇒ 服务端**补一次性随机值**（仍是同一套 `CRC32` 稳定伪随机序，故「每次调用结果不同」这一旧口径不变；**已不再有 `ORDER BY RAND()` 兜底**——那是全表排序且无法用索引） |

### 响应 `data` = `GuessLikeVO[]`
| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 菜品名 |

> **仅出参 `name`**（随机语义下无其他消费点，零消费即删）。条数由服务端固定（6 条）。
> **无响应缓存** —— 会话内稳定已由 `seed` 表达在数据层。

## GET /dishes/{id}

**鉴权**：🔓 公开 ｜ **用途**：菜品详情
**被复用**：详情页浏览、浏览计数、反馈预填、编辑回读（4 处共用此契约）

### 路径参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | number | 是 | 菜品 ID |

### 响应 `data` = `DishDetailVO`（共 11 字段）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | number | 否 | 菜品 ID |
| `name` | string | 否 | 菜品名称 |
| `price` | number | 否 | 现价，单位分 |
| `originalPrice` | number \| null | **是** | 原价；无折扣为 null |
| `description` | string | 否 | 描述（空串兜底） |
| `images` | string[] | 否 | 图片绝对 URL 数组；**恒为数组**（无图为 `[]`，不为 null） |
| `stallName` | string | 否 | 档口名（空串兜底） |
| `canteenName` | string | 否 | 食堂名（空串兜底） |
| `floor` | string | 否 | 档口楼层（**受控字典值，汉字即值**，如 `二层`；空串兜底）；端上**直接展示、零映射**（见 [schema/stall.md](../../schema/stall.md)） |
| `avgRating` | number | 否 | 均分；**零评价下发 `5.0`**（同一展示口径，见 [GET /dishes](#get-dishes)「零评价展示口径」） |
| `attributes` | object[] | 否 | 描述属性，值为中文（服务端由取值 ID 翻译下发）；仅含该菜实际拥有的维度 |

**`attributes[]` 结构**

| 字段 | 类型 | 说明 |
|---|---|---|
| `dimensionId` | number | 维度 ID（`dish.attributes` JSON 的键） |
| `name` | string | 维度中文名 |
| `value` | string \| string[] | 中文值；`single` 为字符串、`multi` 为数组 |

> `value` **为中文文本**：后端由**取值 ID** 翻译后下发（取值字典见 [schema/dish_attribute_value](../../schema/dish_attribute_value.md)），端上直接渲染、无需映射。
> `dimensionId` 与 `dish.attributes` JSON 的键恒等（键为字符串形态的维度 ID）。
> 「我是否已评价」**不在本 VO 中**，判定时机 = 用户点击「写评价」时。

### 错误码
| code | 条件 | 端上处置 |
|---|---|---|
| 4001 | 菜品不存在 **或已下架** | 展示「菜品不存在」+ 返回首页（**下架对外等价于不存在**） |
| 400 | `id` 非数字（参数绑定失败） | 按「不存在」处理 |

### ⚠️ 副作用：非幂等 GET

每次成功响应（`code=200`）向 `dish_view_log` 写入一行浏览明细（`viewed_at` 精确到秒；`dish.view_count` 停写）。

- **不满足 HTTP「安全 / 幂等」语义**，调用方不得作为纯读接口缓存或静默重放。
- `4001` / 参数错误 / 网络失败**不计数**。
- IP 限频兜底：30 次/分 · 300 次/时。

> PV 口径的业务规则见 [A4 浏览计数](../../func/client/A-浏览与发现/A4-浏览计数.md)。

## GET /dishes/{id}/attributes

**鉴权**：🔓 公开 ｜ **用途**：反馈编辑态的属性候选（按需调用）

### 路径参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | number | 是 | 菜品 ID |

### 响应 `data` = 属性项数组
| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `dimensionId` | number | 否 | 维度 ID，与 `DishDetailVO.attributes[].dimensionId` 对齐 |
| `valueType` | string | 否 | `single` \| `multi` |
| `options` | string[] | 否 | 该维度**参考候选**（来自**取值字典** `dish_attribute_value`，按维度顺序）；**空数组 = 暂无参考值** |

> 只返回**该菜现有维度**；维度名与当前值已在详情接口中，本端点不重复下发。
> **候选不构成取值约束** —— 端上恒允许自由输入候选之外的值。
> 本端点失败**静默**（端上仍可自由填写），不阻断反馈主流程。

## GET /dishes/{id}/reviews

**鉴权**：🔓 公开 ｜ **用途**：某菜品的公开评价列表

### 路径与查询参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | number | 是 | 菜品 ID |
| `page` | number | 否 | 页码，默认 1 |
| `pageSize` | number | 否 | 默认 20；端上详情页固定传 10 |
| `rating` | number | 否 | **按星级筛选**：1~5 整数，仅返回该星级评价；不传 = 全部。**白名单校验，非法值 → `400`**（不静默降级） |

**排序**：`created_at DESC` —— **唯一排序**（时间倒序）。

> 🔴 **不改评价不改位**：覆盖提交**不刷新 `created_at`**（见下文「重复提交语义」）⇒ 首次评价的时间即其固定位置，**反复修改无法把自己刷到列表顶部**。
> 🔴 **筛选为服务端过滤**：分页在筛选**之后**计算（`WHERE rating = ?`参与 `LIMIT/OFFSET`）⇒ 端上切筛选须**重置 `page=1`**，否则可能出现空页。
> 端上筛选条（1~5 星 + 全部）为**静态枚举**（值域固定 1~5，无服务端字典需求）。

### 响应 `data` = `PageResult<ReviewVO>`（共 8 字段）

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | number | 否 | 评价 ID |
| `userId` | number | 否 | 评价者用户 ID（端上据此决定「删除 / 举报」入口显隐；**服务端另有鉴权兜底**） |
| `userNickname` | string | 否 | 昵称（空串兜底；注销账号显示「已注销用户」） |
| `userAvatar` | string | 否 | 头像 URL（**恒非空字符串**，无头像为空串） |
| `rating` | number | 否 | 评分 1~5 |
| `content` | string | 否 | 正文（空串兜底） |
| `images` | string[] | 否 | 配图绝对 URL，≤3 张；**恒为数组** |
| `createdAt` | string | 否 | 发表时间，格式 `yyyy-MM-dd HH:mm:ss` |

> **排序唯一 = 时间倒序**，无切换入口。
> 仅返回 `is_hidden = 0` 的评价，不下发 `isHidden`。
> 字符串字段恒非空（`COALESCE(...,'')` 兜底），端上无需判空。
> `dishId` / `dishName` 不在本 VO 中（仅本人视角需要）。

## POST /dishes/{id}/reviews

**鉴权**：🔐 认证（需学号邮箱认证，`bindEmail` 非空）｜ **用途**：提交评价（新建或覆盖）

### 路径参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | number | 是 | 菜品 ID；**body 不收 `dishId`**，归属由 token 锁定 |

### 请求体 `ReviewReq`
| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `rating` | number | **是** | 1~5，越界 → 400 |
| `content` | string | 否 | 最长 500 字（可只打星） |
| `images` | string[] | 否 | ≤3 张；须为经 `POST /upload/cloud-image` 转存后的 COS 绝对地址 |

> 归属取自 JWT，**禁止信任前端传入的用户标识**。

### 响应 `data`
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 评价 ID |

### 重复提交语义
**恒为覆盖更新同一行**（唯一键 `uk_review_user_dish`），未评价则新建。
覆盖时**保留原 `created_at`**（不刷新）、`is_hidden` 重置为 0（一人一菜只有一票）。
**不设提交限频** —— 防「反复重提把自己的评价刷回列表顶部」由「覆盖不刷新 `created_at`」承担：改评价不会把自己顶到列表首位，因此无需额外限频。

### 错误码
| code | 条件 |
|---|---|
| 4001 | 菜品不存在或已下架 |
| 400 | 参数越界 / 配图超限 / 内容安检 `risky` / 「已评价过」（并发竞态兜底） |
| 4031 | **邮箱未认证** —— 端上跳转身份认证页 |

### 副作用
| 目标 | 变化 | 时机 |
|---|---|---|
| `review` | INSERT / UPDATE | 事务内 |
| `dish.avg_rating` / `rating_count` | 重算 | **异步 AFTER_COMMIT**（失败仅告警，不回滚主链路） |

> 内容安检 `risky` → 400 **拦截、不落库**；`pass` / `review` 放行（无人工复核）。

## POST /dishes/{id}/correction

**鉴权**：🔑 需登录 ｜ **用途**：提交**菜品问题反馈**（两类：信息有误 / 已经下架）

> 请求体以 **`type`** 判别两类反馈（`field` 信息有误 / `gone` 已经下架）。
> 依据：菜品问题反馈是内容供给与维护闭环的一环。

### 路径参数
| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | number | 是 | 菜品 ID；**body 不收 `dishId`** |

### 请求体 `DishCorrectionReq`

**先选 `type`**，再按类型填充 —— 表单随类型切换：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | string | **是** | **`field`**=信息有误（默认语义）/ **`gone`**=已经下架；其他值 → `400` |

#### `type = field`（信息有误）—— **局部提交：只传改动项**

下表字段**均为选填**，未传 = 保持原值；「校验」列为该字段**一旦传入**必须满足的约束。

| 字段 | 类型 | 校验（传入时） | 说明 |
|---|---|---|---|
| `name` | string | 非空、≤64 字 | 菜品名称 |
| `price` | number | > 0 的整数 | 价格，**单位分** |
| `canteenName` | string | 非空 | 食堂名（自由文本） |
| `stallName` | string | 非空 | 档口名（自由文本） |
| `floor` | string | 非空、≤16 字 | 楼层；**须 ∈ 楼层字典**（真源见 [schema/stall.md](../../schema/stall.md)），字典外值 → `400`；**归属档口**，采纳时写回目标档口 |
| `attributes` | object | 键 = 维度 ID（字符串形态的 `dimensionId`） | 仅含改动的维度项；值为**中文文本**（多值为数组） |
| `images` | string[] | **≤3 张**、地址合法（**全量替换**：提交「改动后的完整图片数组」） | 图片绝对地址 |

> **`field` 型必须至少有一个改动项**，否则 → `400`（无可反馈的内容）。

> 请求体**无 `dishId`**；`type` 见上。

#### `type = gone`（已经下架）—— **一键提交即可成立**

| 字段 | 类型 | 必填 | 校验（传入时） | 说明 |
|---|---|---|---|---|
| `note` | string | **否** | ≤200 字 | **可选补充说明**：补「变成了别的菜 / 换窗口了 / 今天临时没供」等**无法用差异项表达**的信息 |
| `images` | string[] | **否** | **≤3 张**、地址合法 | **可选补充图片**：拍一张当前窗口，管理员无需二次跑现场 |

> 🔴 **`gone` 型「什么都可以不填」** —— 不传 `note`、不传 `images` 均**受理成功**。
>
> **设计意图**：用户的核心动作是「**点一下告诉系统它没了**」；补充项是为覆盖「变成了别的菜」这类**管理员需要额外信息才能判断**的场景。
> ⚠️ **补充项不得设为必填** —— 一旦必填，用户成本从「点一下」回升到「填表」，提交量将大幅下降（依据：内容供给与维护闭环的产能验证）。
>
> **`gone` 型不接受** `name` / `price` / `canteenName` / `stallName` / `floor` / `attributes` —— 传入 → `400`。理由：这些表达的是「**这道菜存在，只是信息写错了**」，与「**这道菜消失了**」语义冲突；若用户想补录信息，应改选 `field` 型（或管理员在 A3 直接编辑）。

> **楼层归属档口**：采纳时写回目标档口 `stall.floor`，**同档口其他菜品一并生效**。
> **不纠正原价** —— 原价随促销波动，属运营口径而非稳定事实。
> **`attributes` 键 = 维度 ID（字符串形态）、值 = 中文** —— 端上可自由输入（含字典之外的新值），**提交不入库**；服务端在**采纳**时按「维度 + 中文」查取值字典（命中即用、未命中新建）解析为**取值 ID** 后写入 `dish.attributes`（见 [schema/dish_attribute_value](../../schema/dish_attribute_value.md)）。
> **采纳写回是「按维度合并」而非整体覆盖** —— 反馈快照只含**改动的维度**，服务端 SHALL 保留 `dish.attributes` 的其余键，仅覆盖采纳项；某维度提交**空数组 = 清空该维度**（删除该键，不落空数组）。见 [B4](../../func/web/B-UGC治理/B4-菜品问题反馈管理.md)。

### 响应 `data`
`null`（成功即 `code=200`）

### 错误码
| code | 条件 |
|---|---|
| 4001 | 菜品不存在或已下架 |
| 400 | **`type` 缺失 / 非法** ｜ `field` 型**空改动项** ｜ **`gone` 型传了差异项字段** ｜ 字段越界（`note` >200 字、`gone` 型 `images` >3） ｜ 内容安检 `risky` ｜ IP 限频 |

> **IP 限频**：`2 条/分· 10 条/时`（两类**共用同一额度**）。
> **去重**：同一用户（`user_id`，匿名按 `0` 计）对**同一菜品**的 `gone` 型反馈**只计一次**（重复提交返回成功但不重复计数）；`field` 型不去重（可反复提交不同改动）。
> 提交**不代表立即生效** —— `field` 型由管理员采纳后才更新菜品数据并重算评分聚合；`gone` 型由管理员**人工决定**是否下架，**系统不自动下架**。
> 🔴 **处置口径**：`gone` 型的管理端处置**只能「下架」**（`status=off`，可逆），**不得提供「删除」**（删除为物理删除且级联删除评价，仅在 [A3 菜品管理](../../func/web/A-主数据维护/A3-菜品管理.md) 由管理员主动执行）。
> **回执**：有 `userId` 者按现有通例投递站内通知（**不做推送**）；「我的提交」列表可见处理结果（含 `rejected`）。
