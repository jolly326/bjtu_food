# 页面设计文档统一模板（TEMPLATE）

> 本模板为 `docs/pages/` 下所有页面设计文档的统一结构与表达规范。
> `首页.md` / `搜索页.md` 已符合本模板，其余各篇须按本模板重写，保证跨页一致、易读易改。

## 一、统一 Meta 块（每篇开头固定）

```
# <页面名>（<route>）

> 路径 `pages/xxx`，从 <入口> 进入的 <二级页 / TabBar 页>。
> 设计基调：<一句话，引用已拍板约束，如「搜索只针对菜品」「评价即动态」>。
> 复用小程序自研组件（见 `docs/project_spec.md` §4.2 组件清单）与设计 token（见 `client/src/uni.scss` / `client/src/theme/tokens.ts`）。
```

- 入口写清：TabBar 页 / 从某页某入口 `navigateTo` 进入 / 多个入口并列。
- 设计基调只写一句，且须与 `project_spec.md` 已拍板红线一致。

## 二、统一章节骨架

```
## 页面结构总览
<1–2 句说明页面由哪些区块 / 子页面构成；必要时附极简框线图（仅允许 | 与 —，禁止 emoji / ASCII 美术图）>

## 一、<区块1 标题>
<职责 + 内容 + 交互；尺寸 / 样式一律用 token（var(--…)），禁止硬编码 hex；用到的自研组件标明组件名>

## 二、<区块2 标题>
...

## N、状态与交互细节
<骨架屏 / 空状态 / 失败+重试 / 下拉刷新 / 触底加载（如适用）/ 认证弹层（如适用）/ 其他边界态>

## 细节设计（尺寸与样式规范）
<各区块具体尺寸 / token，统一放最后；与首页 / 搜索页一致>

## 交互路径
<入口 → 完成的典型路径，1–3 句>
```

## 三、统一表达规则（强制）

1. **颜色 / 尺寸一律用设计 token**：写 `var(--color-primary)` / `var(--text-secondary)` / `var(--radius-card)` / `var(--spacing-md)` / `var(--font-aux)` / `var(--weight-bold)` 等；**禁止硬编码 hex**（如 `#D4A045` / `#9B2A1D`）。原生 API 不接受 `var()` 的例外（如 `<swiper>` 指示点色）须集中在 `client/src/uni.scss` 登记，不在此范畴。
2. **禁止 emoji 与 ASCII 美术图**：正文不用 emoji 当图标；界面示意图仅在「页面结构总览」允许极简框线（`|` `-`），不画复杂界面图。
3. **章节编号统一**：区块用 `## 一、二、…`，细节设计固定 `## 细节设计（尺寸与样式规范）` 置于倒数第二节（交互路径之前 / 之后均可，但全站统一放最后第二节）。
4. **跨页共用逻辑不重复**：如「发布」走统一 `PublishReview` 组件，只在 `发布动态.md` 详写，他页用「见 `发布动态.md`」引用，不重复展开。
5. **图标统一语义**：功能 / 情感图标一律经 `IconSvg`（见 spec §4.2 映射），不用文本 / Unicode 当图标；中性占位用 `empty`，不用 `dish` 冒充。
6. **标注自研组件**：用到的小程序自研组件（`MomentCard` / `DishCard` / `WaterfallList` / `Rating` / `SectionTitle` / `EmptyState` / `AppButton` / `ImageFallback` / `ImageSwiper` / `PublishReview` 等）须写明组件名，确保实现复用。

## 四、与其他文档的契约

- 每篇文档的「路径 / 入口 / 跳转」须与 `docs/pages/readme.md` 索引、`docs/project_spec.md` §2.1 路由表三方一致。
- 跳转目标页存在独立文档的，用「见 `<目标页>.md`」引用，不重复其设计。
- 凡涉及「已拍板红线」（收藏移除 / 食堂档口降级属性 / 活动独立模块 / 搜索只针对菜品等），须与 `project_spec.md` 一致，冲突以 spec 为准（发现 spec 自相矛盾须提技术负责人裁定）。
