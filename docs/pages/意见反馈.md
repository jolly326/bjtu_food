# 意见反馈（pages/feedback/index）

> 本页为小程序二级页，从「我的」菜单 `navigateTo` 进入（可 `navigateBack`）。
> 首页「反馈菜品」入口经 `navigateTo ?object=dish` 预置「信息纠错」类型与对象；带 `name/id` 时预置菜品关联。
> **2026-08-17 重设计（拍板）：**
> 1. **定位 = 收集用户诉求**：给任何人的轻量意见快通道，30 秒说清一件事（建议 / 新菜品 / 纠错 / 问题）；**不设登录守卫，任何人可提交**（后端 `POST /feedback` 维持公开 PUB）。
> 2. **温度引导（克制）**：仅顶部一行短标题「想说点啥，直接说」；类型与字段合一为一张大卡（无分区标题），口语化类型 chip，弱化「填表单」的任务感，**不做大段引导文案**。
> 3. **动态表单 + 结构化字段**：类型前置单选必选（默认「提个想法」），字段随类型动态切换；每类型收集管理员处理所需的**关键结构化字段**（必填精简为 1 个，辅助字段选填），无多余提示文案。
> 4. **类型 4 类一级**：提个想法 `suggestion` / 推荐菜品 `add` / 信息不对 `error` / App 有问题 `bug`；「新增菜品」从纠错二级细分**提升为一级**（后端扩 `add` 枚举）。
> 5. **附图上传**：bug 截图 / 菜品图 / 纠错作证照片，经 `ImageUploader` 上传（绝对 URL），后端 `Feedback` 新增 `images`（JSON 数组字符串）落库，Web 管理端缩略图展示。
> 6. **纠错点 + 「已下架」作证流程**：纠错点单选（价格不对/名字写错/位置变了/已下架/其他）；选「已下架」不要求正文，仅可照片/文本作证。
> 7. **匿名心智**：底部一行「匿名提交 · 不记账号」+ 不收集联系方式（后端 `FeedbackReq.contact` 保留兼容历史数据）。
> 8. **「我的反馈」进度追踪已移除**（后续另做，`GET /feedback/my` 接口保留）；**举报保持独立**走内容页弹窗。

## 一、页面结构（顶部 → 底部）

```
Header（朱砂红底，返回键 @back="goBack"）
└─ scroll-view（全高；轻量单视图，无 Tab）
   ├─ .hero（一行短标题「想说点啥，直接说」，无副文案）
   ├─ CardSection（一张大卡，无分区标题：类型 + 动态字段合一）
   │   ├─ 类型 chip（4 类口语化，单选必选，默认「提个想法」）
   │   └─ 动态字段区（v-if 按类型切换，结构化字段、无冗余提示）
   │       ├─ 提个想法    → 建议内容（必填 textarea + counter）
   │       ├─ 推荐菜品    → 菜品名称（必填 input）/ 所在位置（选填 input）/ 一句话描述（选填 textarea-sm）/ 菜品图片（ImageUploader max=1）
   │       ├─ 信息不对    → preset-tip（预选菜品+「不是它」）/ 纠错点单选
   │       │             ├─ 非「已下架」→ 正确信息（选填 input）+ 纠错说明（必填 textarea + counter）
   │       │             └─ 「已下架」  → 作证照片（ImageUploader max=1）+ 作证文本（选填 textarea-sm）
   │       └─ App 有问题  → 问题描述（必填 textarea + counter）/ 操作步骤（选填 textarea-sm）/ 截图（ImageUploader max=1）
   ├─ .submit-inline（内嵌 AppButton「说出去」）
   └─ .anonymous-tip（「匿名提交 · 不记账号」）
```

> 无认证弹层 `AuthSheet`（任何人可反馈，无需登录）；无详情 BottomSheet、无「我的反馈」列表；无「联系方式」字段。

## 二、区块规范

### 1. 温度引导（hero）
- 仅一行短标题「想说点啥，直接说」（`--font-h3` 加粗）。**不做副文案/引导语**（避免无用文本）。

### 2. 类型（口语化 pill，单选必选）
- 4 类：提个想法 `suggestion` / 推荐菜品 `add` / 信息不对 `error` / App 有问题 `bug`。选中 `.type-chip.active`：`bg-primary-soft` + `border-color: var(--color-primary)`，字转主色。默认 `suggestion`。
- 类型即动态表单开关：切换后下方字段区 `v-if` 整体切换，各类型独立表单状态（`reactive` form 分段保存，切换不丢已填内容）。

### 3. 动态字段区（结构化字段，必填精简为 1 个，辅助选填，无冗余提示文案）
- **提个想法**：`textarea`（`--bg-input`、`min-height 220rpx`、`font-body`）+ 右上角计数器。占位「你的想法，比如：希望加几个素食窗口」。提交映射：`content` = 建议内容。
- **推荐菜品**（`type=add`）：
  - 菜品名称（必填 `input`，占位「菜名叫啥？（必填）」）
  - 所在位置（选填 `input`，占位「在哪吃到？（选填）」）
  - 一句话描述（选填 `textarea`，`content-input-sm`，占位「一句话描述口味/特色（选填）」）
  - 菜品图片（选填，`ImageUploader max=1`）
  - 提交映射：`content = 【新增菜品】菜名（+ \n所在位置：…）（+ \n描述：…）`，`relatedType=dish`，`images` 传图。
- **信息不对**（`type=error`）：
  - 预选菜品提示条（首页入口带入，`bg-primary-soft` + `dish` 图标 + 「说的是：菜名」+「不是它」移除）。
  - 纠错点（单选 chips：价格不对/名字写错/位置变了/已下架/其他）。
  - **非「已下架」**：正确信息（选填 `input`，占位「正确信息是？（选填）」）+ 纠错说明（必填 `textarea`，占位「具体哪儿不对？（必填）」）。提交映射：`content = 【纠错点】\n说明（+ \n正确信息：…）`。
  - **「已下架」**：不要求正文；作证照片（`ImageUploader max=1`）+ 作证文本（选填 `textarea`，占位「作证信息（选填）」）。提交映射：`content = 【已下架】（+ 作证文本）`，`images` 传作证照片。
- **App 有问题**（`type=bug`）：问题描述（必填 `textarea`，占位「发生啥了？（必填）」）+ 操作步骤（选填 `textarea`，`content-input-sm`，占位「操作步骤（选填）」）+ 截图（`ImageUploader max=1`）。提交映射：`content = 描述（+ \n操作步骤：…）`，`images` 传截图。

### 4. 提交按钮 + 匿名声明
- `.submit-inline` 内容内嵌（无固定底栏），水平 `margin 24rpx`；内嵌 `AppButton` 文案「说出去」（人味化，弱化「提交表单」感）。
- 底部 `.anonymous-tip`：「匿名提交 · 不记账号」（`--font-tiny` 四级灰），一行极简，降低「留名/被审视」顾虑。
- **无「联系方式」字段**（2026-08-17 拍板：不收集个人联系方式，降低填写负担）。

## 三、交互与状态

| 行为 | 实现 |
|---|---|
| 提交校验 | 按类型动态必填（建议内容 / 菜品名称 / 纠错说明、已下架除外 / 问题描述）；content ≤1000 字；无联系方式字段 |
| 新增菜品映射 | `type=add` + `content=【新增菜品】菜名[+所在位置][+描述]` + `relatedType=dish` + `images` |
| 已下架映射 | `type=error` + `content=【已下架】[+作证文本]` + `images`（作证照片），不要求正文 |
| 纠错映射 | `type=error` + `content=【纠错点】说明[+正确信息]`（纠错点如 价格不对/名字写错/位置变了/其他） |
| 提交成功 | Toast「收到！谢谢你」→ `resetForm()` 清空全部类型表单 → 停留本页（可连续提交） |
| 首页入口 | `?object=dish`（或带 name/id）→ 预选 `type=error` + 预置菜品名/关联 ID |
| 返回 | `goBack`：`getCurrentPages().length>1` 则 `navigateBack`，否则 `reLaunch` 首页 |
| 登录策略 | **无需登录**（拍板：任何人都可反馈）；后端 `POST /feedback` 保持公开 PUB |
| 匿名声明 | 底部「匿名提交 · 不会记录你的账号信息」 |
| 键盘避让 | textarea/input 均 `:cursor-spacing="20" :adjust-position="true"` |
| 图片上传 | `ImageUploader`（`uploadImage` → 绝对 URL 数组绑定 v-model；各场景 max=1） |

## 四、间距节奏（8pt 栅格）

- 卡片纵向间距：**16rpx（8pt）**。`tab-pane` 不用 flex gap，改由 `.tab-pane .card-section { margin: 0 24rpx 16rpx }` 单源控制。
- 首卡 → 顶部：8rpx（`.tab-pane .card-section:first-child { margin-top: 8rpx }`）。
- 水平对齐：卡片统一左右 `24rpx`。
- 字段内：`field` 纵向间距 `margin-bottom 16rpx`（末字段归零）；`field-label`（`--font-aux` 加粗二级灰）与输入间距 8rpx；chips 间距 `gap 16rpx`。

## 五、设计 Token（引用，单一事实源 App.vue / tokens.ts）

- 主色：`--color-primary`（朱砂红 `#9B2A1D` / 深色 `#C45A3C`）、`--color-primary-soft`。
- 圆角：`--radius-pill`(药丸) / `--radius-card`(卡片) / `--radius-tag`(标签/徽标) / `--radius-btn`(输入)。
- 底色：`--bg-page` / `--bg-soft` / `--bg-card` / `--bg-input`。
- 字号：`--font-tiny` / `--font-aux`(辅助/label) / `--font-body`(正文)；字重 `--weight-regular/semibold/bold`。
- 功能色：`--color-warning` / `--color-success` 及对应 `-soft`。
- 间距：`--spacing-2xs/xs/sm/md/lg/xl`。
- 动效：`--press-scale`(0.97)、`--press-transition`；视口 `100dvh` 渐进降级 `100vh`。

## 六、类型体系（前后端契约）

| 一级 | 枚举 | 提交映射 | 备注 |
|---|---|---|---|
| 提建议 | `suggestion` | `content` = 建议内容 | 想要的功能/体验改进 |
| 新增菜品 | `add` | `content` 结构化（名称/位置/特色）+ relatedType=dish + images | 2026-08-17 新增一级枚举，承载 UGC 补录 |
| 信息纠错 | `error` | `content = 【纠错点】说明（+正确信息）` 或 `【已下架】[+作证]` + images | 纠错点含价格/名字/位置/已下架/其他 |
| 遇到问题 | `bug` | `content` = 描述（+操作步骤）+ images | 系统问题/闪退/数据异常 |
| 其他 | `other` | — | 页面不再提供（2026-08-17 收敛）；后端枚举保留兼容历史数据 |
| 举报 | `report` | — | 页面不暴露，走内容页独立入口；relatedType=moment 必填 |

- 后端：`FeedbackConst` 类型枚举（suggestion/error/add/bug/other/report）；`type` 为 VARCHAR 透传无白名单校验，扩展安全。
- 后端 `Feedback.images`：VARCHAR(2048) JSON 数组字符串（绝对 URL）；`FeedbackReq.images` / `FeedbackMyVO.images` / `FeedbackAdminVO.images` 均为 `List<String>`，Service 序列化/反序列化（空/非法安全降级 null）。
- **`contact` 已不再由前端提交**（字段移除）；后端 `FeedbackReq.contact` / 表 `contact` 列保留以兼容历史数据，新提交为 null。
- Admin：`web/src/views/admin/FeedbackView.vue` `typeLabel`/`typeOptions` 已含 `add: '新增菜品'`、`bug: '系统问题'`；详情抽屉展示附图缩略图（点击新窗口放大）。
- 种子数据：`seed_data.sql` 含 `add` 类型演示记录（结构化 content 多行文本）。

## 七、审计红线（来自 project_spec §4，强制）

- 本页无固定底栏（提交按钮内嵌），不再适用 `action-bar-height` 避让；仅留 `env(safe-area-inset-bottom)` 安全白。
- 事件绑定用 `@tap` 而非 `@click`；类型/纠错点单选用 `role="radio"` + `aria-checked`，对象 chips 用 `role="button"` + `aria-label`。
- 按压缩统一 `var(--press-scale)`，禁止裸 `scale()`；真机按压用 `hover-class="pressed"`（微信 view 不支持 `:active`）。
- 图标统一 `IconSvg`，禁止 emoji 充当图标。
- 图片上传统一走 `ImageUploader`（`uploadImage`），禁止内联复制「+ 添加图片」逻辑。
- `prefers-reduced-motion` 降级：去按压缩放/过渡。

## 八、已知约束 / 待办
