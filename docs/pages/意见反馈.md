# 意见反馈（pages/feedback/index）

> 本页为小程序二级页，从「我的」菜单 `navigateTo` 进入（可 `navigateBack`）。
> 首页「反馈菜品」入口经 `navigateTo ?object=dish` 预置「内容纠错」类型与对象；带 `name/id` 时预置菜品关联。
> **2026-08-17 重设计（拍板）：**
> 1. **定位 = 轻量意见快通道**：给任何人的快速表达入口（**不设登录守卫，游客可直接提交**，后端维持 PUB），30 秒内说清一件事。
> 2. **单视图写反馈**：移除双 Tab 分段控制器与「我的反馈」记录列表（进度追踪后续另做，`GET /feedback/my` 接口保留）。
> 3. **类型收敛为 3 类**（提建议 / 信息纠错 / 遇到问题），移除「其他」，减少选择负担。
> 4. **纠错二级细分保留**（新增菜品 / 信息有误）：「UGC 并入」要求结构化表达"新增菜品"，首页「反馈菜品」入口语义依赖此细分。
> 5. **举报保持独立**：走内容页（动态/评论）弹窗 `ReportModal`，不并入本页。

## 一、页面结构（顶部 → 底部）

```
Header（朱砂红底，返回键 @back="goBack"）
└─ scroll-view（全高；轻量单视图，无 Tab）
   ├─ CardSection[反馈类型]        → 一级 type-chip（3 类）；选「信息纠错」展开二级（新增菜品/信息有误）
   ├─ CardSection[反馈对象(选填)]  → preset-tip（预选菜品+「移除」）+ type-chip
   ├─ CardSection[反馈内容]        → textarea(--bg-input, min-height 240rpx) + counter(≥900 转 warning)
   ├─ CardSection[联系方式(选填)]  → input(--bg-input) + 轻提示/错误文案
   └─ .submit-inline（内嵌提交按钮，全宽 AppButton）
```

> 无认证弹层 `AuthSheet`（任何人可反馈，无需登录）。
> 无详情 BottomSheet、无「我的反馈」列表（均已移除，进度追踪后续另做）。

## 二、区块规范

### 1. 反馈类型（一级 pill）
- 3 类：提建议 `suggestion` / 信息纠错 `error` / 遇到问题 `bug`。选中 `.type-chip.active`：`bg-primary-soft` + `border-color: var(--color-primary)`，字转主色。
- 默认 `suggestion`。
- **信息纠错二级细分**（选中 `error` 时展开）：新增菜品 `add` / 信息有误 `correct`。子 chips 更紧凑（`--font-tiny`、`bg-input` 底），与一级拉开层级。默认 `correct`。
  - 提交映射：`add` → `type=error` + `relatedType=dish`（对象强制菜品）+ content 自动加「【新增菜品】」前缀（admin 靠前缀区分，不改表）；`correct` → `type=error`，对象按选择。

### 2. 反馈对象（选填）
- 预选菜品提示条 `bg-primary-soft` + `dish` 图标 + 名称 + 「移除」（`hover-class="pressed"`）；下方对象 chips（菜品/档口/食堂/其他）。
- 首页「反馈菜品」入口（`object=dish`）→ 预选 `type=error` + 对象「菜品」；带 `name/id` 时预置关联。

### 3. 反馈内容
- `--bg-input` 多行框 + `--radius-card`，`padding-md`，`min-height:240rpx`，`font-body`；右上角计数器 `--font-aux`，`≥900/1000` 转 `--color-warning`。占位文案随类型联动（新增菜品/纠错/问题各有引导）。

### 4. 联系方式（选填）
- `--bg-input` 单行 `input` + `--radius-btn`，`cursor-spacing:20` 键盘避让；下方轻提示文案，格式错误时转 warning 并 Toast（不阻断提交）。

### 5. 提交按钮
- `.submit-inline` 内容内嵌（无固定底栏），水平 `margin 24rpx` 与卡片对齐，底部留白含安全区；内嵌 `AppButton` 默认 `width:100%` 全宽。

## 三、交互与状态

| 行为 | 实现 |
|---|---|
| 提交校验 | 内容非空、≤1000 字；contact 轻校验（可空，填了校验邮箱/微信格式，错误仅提示不阻断） |
| 新增菜品映射 | `feedbackAction==='add'` → `type=error` + `relatedType=dish` + content 前缀「【新增菜品】」 |
| 提交成功 | Toast「提交成功，感谢反馈」→ 清空表单（含二级细分重置 `correct`）→ 停留本页 |
| 首页入口 | `?object=dish`（或带 name/id）→ 预选 `type=error` + 对象「菜品」；二级默认 `correct` |
| 返回 | `goBack`：`getCurrentPages().length>1` 则 `navigateBack`，否则 `reLaunch` 首页（从「我的」进入回「我的」） |
| 登录策略 | **无需登录**（2026-08-17 拍板：任何人都可反馈）；后端 `POST /feedback` 保持 PUB |
| 键盘避让 | textarea/input 均 `:cursor-spacing="20" :adjust-position="true"` |

## 四、间距节奏（8pt 栅格）

- 卡片纵向间距：**16rpx（8pt）**。`tab-pane` 不用 flex gap（会与 `CardSection` 自带 margin 叠加成 56rpx 大缝），改由 `.tab-pane .card-section { margin: 0 24rpx 16rpx }` 单源控制。
- 首卡 → 顶部：8rpx（`.tab-pane` padding-top 由首卡 margin-top 8rpx 提供）。
- 水平对齐：卡片统一左右 `24rpx`，视觉中轴一致。
- 卡片内：`padding 24rpx`；chips 间距 `gap 16rpx`。

## 五、设计 Token（引用，单一事实源 App.vue / tokens.ts）

- 主色：`--color-primary`（朱砂红 `#9B2A1D` / 深色 `#C45A3C`）、`--color-primary-soft`。
- 圆角：`--radius-pill`(药丸) / `--radius-card`(卡片) / `--radius-tag`(标签/徽标) / `--radius-btn`(输入)。

- 字号：`--font-tiny`(二级细分) / `--font-aux`(辅助) / `--font-body`(正文)；字重 `--weight-regular/semibold/bold`。

- 动效：`--press-scale`(0.97)、`--press-transition`；视口 `100dvh` 渐进降级 `100vh`。

## 六、类型体系（前后端契约）

| 一级 | 枚举 | 二级 | 提交映射 | 备注 |
|---|---|---|---|---|
| 提建议 | `suggestion` | — | — | 想要的功能/体验改进 |
| 信息纠错 | `error` | 新增菜品 `add` / 信息有误 `correct` | `add` → content 前缀「【新增菜品】」+ relatedType=dish | 与首页「反馈菜品」入口对齐 |
| 遇到问题 | `bug` | — | — | 系统问题/闪退/数据异常 |
| 其他 | `other` | — | — | 页面不再提供（2026-08-17 收敛）；后端枚举保留兼容历史数据 |
| 举报 | `report` | — | — | 页面不暴露，走内容页独立入口；relatedType=moment 必填 |

- 后端：`FeedbackConst` 类型枚举（suggestion/error/bug/other/report）；`type` 为 VARCHAR 透传无白名单校验，扩展安全。
- Admin：`web/src/views/admin/FeedbackView.vue` `typeLabel` 与 `typeOptions` 已含 `bug: '系统问题'`。
- 种子数据：`seed_data.sql` 含 bug 类型演示记录。

## 七、审计红线（来自 project_spec §4，强制）

- 本页无固定底栏（提交按钮内嵌），不再适用 `action-bar-height` 避让；仅留 `env(safe-area-inset-bottom)` 安全白。
- 事件绑定用 `@tap` 而非 `@click`；可点元素用 `role` + `aria-label`（二级细分用 `role="radio"` + `aria-checked`）。
- 按压缩统一 `var(--press-scale)`，禁止裸 `scale()`；真机按压用 `hover-class="pressed"`（微信 view 不支持 `:active`）。
- 图标统一 `IconSvg`（线性 24px 网格，stroke 注入色），禁止 emoji 充当图标。
- `prefers-reduced-motion` 降级：去按压缩放/过渡。
