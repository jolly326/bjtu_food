# B1 · 纠错查看与选项字典

> 所属端：**管理端（运营）** ｜ 归属：**B 反馈与纠错**
> 返回：[总览](../README.md)

## 介绍

同一页承载两件事：**查看学生提交的菜品纠错并处置**，以及**维护错误类型字典**（纠错选项）。

系统只记录「学生反馈了什么」，**不做自动更正**，也**不给学生回执**。

> 接口见 [`api/web/issues.md`](../../../api/web/issues.md) · 列定义见 [schema/dish_issue.md](../../../schema/dish_issue.md) 与 [schema/dish_issue_option.md](../../../schema/dish_issue_option.md)。

## 业务规则

### 纠错待办

| 项 | 口径 |
|---|---|
| **一条 = 什么** | 一次提交 —— 🔴 **只含一个选项**（无文字、无配图） |
| 列表 | 🔴 **默认只查未处理**（`handledAt IS NULL`）；可按菜品筛；分页；按 `createdAt` 降序 |
| 展示 | 菜品（名 / 食堂 / 档口）+ **错误类型（中文，由选项字典翻译）** + 提交时间 + 处理时间 |
| **标记已处理** | `PATCH` 写 `handledAt`；传 `false` 可**撤销误标** |
| 🔴 **处置动作** | 运营**手动**去改菜品（[A3 菜品管理](../A-主数据维护/A3-菜品管理.md)）—— **系统不会自动更新任何字段** |
| 🔴 **无回执** | **不给学生发任何通知**；学生端也看不到处理结果 |
| 删除 | 提交行**永不删除** —— 保留「同一问题被反馈过几次」的严重度信号与审计 |

> 「默认只查未处理」是让列表规模 = **待办量**的关键：已处理的记录不再占用运营的注意力。

### 纠错选项（错误类型字典）

| 项 | 口径 |
|---|---|
| **字段** | **仅选项文案**（`name`）—— 不设图标 / 排序位 / 启停位 |
| 初始数据 | 3 条：**信息错误 / 图片不对 / 已停售关闭** |
| 列表 | **全量**（不分页 —— 量级固定小）；按 `id` 升序；展示**引用次数**（只读）与更新时间 |
| **新建** | 文案必填；即时生效 —— 🔴 **免发版、免端上改动** |
| **改名** | 🔴 **全站生效**（含**历史提交**的中文翻译） |
| **删除** | 🔴 **已被提交记录引用时拒绝**（被引用即禁删）；**引用次数为 `0` 才可删** |
| 无启停 | 🔴 **不设 `on` / `off`** —— 选项集合即有效集合 |

### 为什么「改名免费、删除受限」

- 学生提交里存的是 **`option_id`**，中文在**展示时**由字典翻译 ⇒ **改文案不触碰任何历史行**、零数据迁移；
- 反过来，一旦有历史提交引用了某选项，删掉它会让那些记录**失去中文**（外键直接拒绝）⇒ 只能删**从无引用**的选项。

> 这也是「删不掉旧选项」时的唯一出路：**改名复用**（把它改成新的语义），而不是删除。

## 数据（读写）

| 表 | 变化 | 说明 |
|---|---|---|
| `dish_issue` | SELECT · UPDATE（**仅 `handled_at`**） | 列定义见 [schema/dish_issue.md](../../../schema/dish_issue.md) |
