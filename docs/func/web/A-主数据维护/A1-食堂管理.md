# A1 · 食堂管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：食堂作为**可维护实体**（CRUD）。

## 介绍

维护**食堂（`canteen`）**——client 菜品位置行「食堂名」的数据源；档口的上层容器。

**定位**：食堂作为**可维护实体**——管理员可显式**新增 / 编辑 / 删除**；A3 菜品录入**从食堂下拉中选择**，避免"自由文本错别字 → 产生重复食堂"。

**职责边界**：只管食堂自身（名称），**不管**档口（A2）与菜品（A3）。

**删除约束**：食堂下仍有档口时**禁止删除**，避免孤儿档口。

**全部业务列可达**：`images` / `location` / `description` 与 `name` 一样，**在详情抽屉内可查看、可编辑**（client 侧零消费；字段与写入口径见 [api/web/stalls.md](../../../api/web/stalls.md)）；**不引入 `status`**。

**列表顺序**：**按 `id` 升序** —— 食堂是字典类主数据，**不设排序位、无排序入口**。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/stalls.md**](../../../api/web/stalls.md)（食堂与档口契约唯一真源）。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `canteen` | 增删改查（`name` 与 `images` / `location` / `description` 全部业务列） | 食堂本体 |
| `stall` | 删前计数（按 `canteen_id`） | 删除约束校验 |

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **提供 `POST` / `DELETE` 端点**（`CanteenAdminController`）。
- **名称唯一（应用层校验）**：新增与**改名**均查重（改名场景同样校验，避免以已有名绕过约束），重名 `400`；不加强 DB 唯一索引（历史数据可能已有重复，避免迁移阻塞）。
- **列表另带 `stallCount`**（联表统计，供删除前判断）。
- **`GET` 列表 / `PUT` 改名**：口径不变。
