# A3 · 菜品管理

**目标**：维护菜品本体与它的售卖位置。学生端结果卡与推荐结果都来自这里。

> 接口见 [`api/web/dishes.md`](../../../api/web/dishes.md) · 列定义见 [schema/dish.md](../../../schema/dish.md)、[schema/dish_location.md](../../../schema/dish_location.md)。

## 介绍

一道菜 = 本体（名称 / 描述 / 图 / 价格）+ N 个位置（食堂 / 档口 / 在售）。位置只是「在哪卖」，价格与图文共享本体；图或口味不同应新建另一道菜。不同档口的同名菜是两道不同的菜。

## 业务规则

### 菜品本体

| 字段 | 口径 |
|---|---|
| 名称 | 必填；**允许与其他菜品同名**（不同档口同名是两道菜） |
| 描述 | 可选，喂语义匹配；建议「名称 + 口味 + 场景 + 特点」；变更后重算当前模型向量 |
| 图片 | 单张；`null` = 清除 |
| 价格 | 元，落库为分；同一道菜所有位置共用；留空 = 价格待定 |

### 位置（`dish_location`）

| 项 | 口径 |
|---|---|
| 一菜多位置 | 一道菜可挂多个食堂 / 档口 |
| 唯一性 | 同一菜品同一 `(食堂, 档口)` 只允许一条 |
| 楼层 | 取档口 `floor`，不在位置重复录入；编辑界面可选择，用于收窄档口下拉，选择结果不落库 |
| 在售 | 每个位置独立控制；学生端只展开在售位置 |
| 🔴 归属一致性 | 选了档口时，档口所属食堂必须等于位置食堂，否则拒绝保存 |

### 保存与删除

- 位置**整表替换**：带 `id` 更新（保留该 `id`）、不带 `id` 新增、未出现删除；同一食堂 / 档口重复或传入不属于该菜品的 `id` ⇒ `400`。
- 删除为物理删除；位置 / 向量 / 反馈随外键 `ON DELETE CASCADE` 一并清除。
- 删除前由前端在弹窗内二次确认。

### 列表与筛选

- 可按食堂 / 档口 / 位置在售状态 / 名称模糊筛选，分页。
- 列表卡片展示菜品本体 + 位置摘要（食堂 · 楼层 · 档口 · 在售）。

## 数据（读写）

| 来源 | 用途 |
|---|---|
| `GET /admin/dishes` | 分页列表（食堂 / 档口 / 状态 / 名称筛选） |
| `POST /admin/dishes` · `PUT /admin/dishes/{id}` | 菜品本体 + 位置整表替换 |
| `DELETE /admin/dishes/{id}` | 物理删除（位置 / 向量 / 反馈级联） |
| `GET /admin/canteens` · `GET /admin/stalls` | 食堂 / 档口下拉源 |
