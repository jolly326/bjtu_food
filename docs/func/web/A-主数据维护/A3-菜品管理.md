# A3 · 菜品管理

> 所属端：**管理端（运营）** ｜ 归属：**A 主数据维护**
> 返回：[总览](../约定与红线.md)

## 介绍

维护菜品 —— 学生端「美食地图」页展示的一切都来自这里，也是点赞与纠错的**对象**。

> 接口见 [`api/web/dishes.md`](../../../api/web/dishes.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| **字段** | 所属食堂（**必填**）· 名称（必填）· 所属档口（**可选**，可不指定）· 楼层（**可选**）· 菜品图（可选）· 在售状态（`activate`：`true` 在售 / `false` 已下架） |
| **唯一性** | **同一食堂下** `name` 唯一 |
| **归属一致性** | 指定了档口时，该档口所属食堂必须等于菜品所属食堂，否则拒绝保存 |
| **档口可延后** | 档口未知时允许先不指定（食堂必填即可保存），后续在编辑态补选；学生端该字段展示占位「暂无」 |

| **状态** | 缺省在售（`activate=true`）；🔴 **下架对学生端等价于不存在** —— 不进地图，且**不可**被「点赞」/ 纠错 |
| 图片 | 单张大图；传 `null` = 清除 |
| 列表 | 可按档口 / 食堂 / 状态筛，并可只看「未指定档口」的菜品；档口 / 楼层为空时列表显示占位「暂无」；分页 |
| **只读列** | `likeCount`（点赞数）—— **派生缓存列**，由学生点赞自动重算，**本页不可直接改**；在本页列表内展示 |
| **批量操作** | 批量上架 / 下架 / 改档口：**逐条提交、单条只改目标字段**（其余字段随行带出）；改档口支持「**清空档口**」；🔴 **非原子** —— 失败项逐条列出，成功项已生效；🔴 **批量不含删除**（删除不可逆且有引用约束，只走单条二次确认） |
| **删除** | 🔴 管理员可**物理删除**菜品；存在**学生点赞**或**纠错**仍允许删除，引用项随外键 `ON DELETE CASCADE` **一并清除**（删除前前端弹窗内二次确认提醒「纠错/点赞将一并清除，不可恢复」） |

### 明确不录的字段（学生端不消费）

| 不录 | 原因 |
|---|---|
| 描述 / 简介 | 学生端**无详情页**，弹窗不展示描述 |
| 属性维度 / 取值 | 本期不设（无筛选需求） |
| 多图 | 磁贴只有一张大图 |
| 原价 / 折扣 | 无促销语义 |
| 分类 / 种类 | 本期不设（筛选维度只有食堂） |
| 售罄 / 今日供应 | 只有「在售 / 下架」两态 |

> **点赞数从哪来**：学生端「美食地图」的两态点赞（抖音式点赞 / 取消）驱动重算；**零点赞 = 0**，不得兜底成非零值（兜底会凭空抬高热度）。`likeCount` = `COUNT(dish_rating.liked = 1)`，不落风味评级。口径见 [`schema/dish.md`](../../../schema/dish.md)。

## 数据（读写）

| 表 | 变化 | 说明 |
|---|---|---|
| `dish` | INSERT / UPDATE / DELETE | 列定义见 [schema/dish.md](../../../schema/dish.md) |
| `dish_rating` · `dish_issue` | **随菜品级联清除** | 菜品被删除时，引用项随外键 `ON DELETE CASCADE` 一并蒸发（管理员删菜即清除，无需单独处理） |
