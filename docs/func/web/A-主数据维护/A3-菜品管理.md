# A3 · 菜品管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：菜品资料**唯一写入源**（含**复制**）；**允许删除**（评价级联，UI 二次确认）；属性**可空**；图片 **≤5 张**、有序、首图作封面。

## 介绍

维护**菜品（`dish`）主数据** —— client **首页 / 搜索 / 菜品详情**的唯一数据源。

**定位**：管理端是菜品资料的**唯一写入源**（学生端**无菜品写接口**）。提供 **列表 / 新增 / 编辑 / 复制 / 上下架 / 删除**。

**字段范围**：名称 / 所属档口 / 现价 / 原价 / 描述 / 图片 / 种类 / 描述属性 / 上架状态。
**派生只读（不可编辑）**：均分 `avgRating`、评价数 `ratingCount`、创建 / 更新时间。

**职责边界**：只管菜品**本体**。位置（食堂 · 楼层 · 档口名）由 [A2 档口管理](./A2-档口管理.md) **派生**（本页只选 `stallId`，不填名称）；菜品种类取值来自 [A6](./A6-首页筛选视图管理.md) 的种类字典（系统维度取值）；描述属性维度与取值来自 [A4](./A4-菜品属性维度管理.md)。

**删除约束**：**允许删除**。删除为**物理删除**，其评价**级联删除**（`review` 有 `ON DELETE CASCADE`）；反馈记录**保留**（`dish_correction` 不设外键，是"用户反馈过什么"的历史痕迹）。
> ⚠️ 删除**会影响历史**（评价与均分一起消失）⇒ UI 必须**二次确认**并明示「将一并删除该菜品的 **N 条评价**」（N 取列表已有的 `ratingCount`）。

**不纳入**：售罄 / 今日供应（产品定型一期不做）；独立审核（**录入即生效**，公开可见性只看 `status`）；历史累计浏览量 `dish.view_count`（🔴 2026-10-05 已**停写**，浏览量改由 `dish_view_log` 30 天窗口承载 ⇒ 列表下发 `recentViewCount`「近 30 天浏览」，见 [A3 契约](../../../api/web/dishes.md)）。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/dishes.md**](../../../api/web/dishes.md)（菜品主数据契约唯一真源）。归属下拉取自 [api/web/stalls.md](../../../api/web/stalls.md)，种类字典见 [api/web/categories.md](../../../api/web/categories.md)，描述属性维度与取值见 [api/web/dimensions.md](../../../api/web/dimensions.md)。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `dish` | 增删改查 + 全字段 | 菜品本体 |
| `stall` | **只读**（校验存在 + 回填档口名） | 归属档口；**本页不写**（档口由 A2 维护） |
| `canteen` | **只读**（回填食堂名） | 位置展示 |
| `dish_attribute_value`（系统维度「菜品种类」下） | **只读**（`mealTypeId` 归属校验 + 回填中文名） | 种类字典（A6） |
| `dish_attribute_dimension` / `dish_attribute_value`（描述维度） | **只读**（维度 ID 校验 + 取值 ID ↔ 中文翻译） | 描述属性（A4） |
| `review` | **删除菜品时级联删除** | `ON DELETE CASCADE`（应用层 `ReviewDishCascadeListener` 先删，外键兜底） |
| `dish_correction` | **不设外键**，删菜品后**保留** | 用户反馈留痕 |

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **列表筛选**：[`GET /admin/dishes`](../../../api/web/dishes.md) 提供 `stallId` / `canteenId`（经档口间接）/ `mealTypeId` / `status`（白名单 `on`/`off`，非法值 `400`）/ `keyword`（三路模糊，与 client 搜索同口径）；排序为 `updatedAt DESC`；出参含 `mealTypeId` / `mealTypeLabel`（种类中文名，A6 种类字典派生，端上零硬编码）。
- **列表 VO 与详情 VO 拆分**：列表 VO（瘦身）与详情 VO（全字段）分离，字段清单见 [api/web/dishes.md](../../../api/web/dishes.md)；列表只取所需列、**封面图由首图派生**。
  **前端须同步**（拆分与 `PUT` 整体替换是连锁的，缺一即出事）：`DishesView` 行改按列表 VO 消费；点「编辑」**先调 [`GET /admin/dishes/{id}`](../../../api/web/dishes.md) 取全字段再回填** —— 否则行内没有 `description` / `images` / `attributes`，而 `PUT` 是整体替换 ⇒ 保存会把它们清空（不可逆）。
- **单条详情端点**：[`GET /admin/dishes/{id}`](../../../api/web/dishes.md) 存在（编辑回填全字段）。
- **`PUT` 为「可编辑字段整体替换」**：以一条显式 UPDATE 写全可编辑字段；上下架拆为独立的状态端点（见 [api/web/dishes.md](../../../api/web/dishes.md)）。
  **null 语义逐字段定死**：`name`/`mealTypeId` 必填（空 → `400`）；`originalPrice` 的 `0`/`null` ⇒ **清空**；`description` 的 `null` ⇒ 空串；`images`/`attributes`/`stallId` 的 `null` ⇒ **不修改**（这三类是结构性内容，未带多为「未改动」而非「删除全部」，误判成清空会造成不可逆数据丢失 —— 要清空请传空数组 / 空对象）；`status` 本端点不写。
- **复制端点** [`POST /admin/dishes/{id}/copy`](../../../api/web/dishes.md)（当前无）。
- **归属只收 `stallId`**：`DishAdminReq` 只收 `stallId`，归属由 [A1](./A1-食堂管理.md) / [A2](./A2-档口管理.md) 的实体下拉提供，从源头消灭"自由文本错别字 → 重复档口 / 食堂"。
- **`mealTypeId` 为必填**；值域来源为**系统维度（菜品种类）** 下的取值（[A6](./A6-首页筛选视图管理.md)），须属于该系统维度（否则 → `400`）。
- **`attributes` 入参键 = 描述维度 ID、值为「取值 ID 或中文名」**（[A4](./A4-菜品属性维度管理.md) 取值字典：传 ID 精确命中；传中文名则同维度内未命中**自动登记**并替换为 ID；出参仍翻译为中文）；**不得携带系统维度（菜品种类）键** → `400`（种类只走 `mealTypeId`）。
- **图片 0~5 张、有序、首图作封面**：新增与编辑路径**共用同一个校验助手**：张数超上限 → `400`；序列化后长度超列宽 → `400`（防**静默截断**；列长度上限见 [schema/dish.md](../../../schema/dish.md)）；空的取舍按路径区分 —— 新增「请至少上传 1 张」、编辑「请至少保留 1 张」（编辑传空集合 = 要求清空 ⇒ 拒绝，要下架走状态端点（见 [api/web/dishes.md](../../../api/web/dishes.md)）；传 `null` = 不修改）。
- **删除**：物理删除 + 级联删除评价；UI 侧提供「将一并删除 N 条评价」二次确认。

## 备注（架构取舍）

- **`PUT` 整体替换而非部分更新**：本页是**表单式**编辑（提交全量字段），整体替换语义明确、不会出现"漏传一个字段导致旧值残留"；上下架是**行内操作**，单独给它一个端点比让前端"只传 status"更清晰。
- **列表 / 详情 VO 分离**：列表是"扫视"场景（要小、要快），详情是"编辑回填"场景（要全）；共用 VO 会让列表为 20 行 × 512 字描述 + 属性 Map 买单。
- **归属只认 `stallId`**：与 A1 / A2 的"实体化 + 下拉"一致。按名 upsert 会让同一档口因错别字分裂成多行，是重复数据的根源。
- **图片 0~5 张**：0 张合法（client 有统一图片占位 `ImagePlaceholder`）；上限 5 支撑详情页多图，且不超过 `dish.images VARCHAR(1024)` 的承载。
- **复制副本默认 `off`（下架）**：复制出来的是**半成品**，先下架、确认内容后再上架，避免半成品直接对用户可见。
- **菜品名不唯一**：同名菜品靠档口区分；强制唯一会阻碍"两个档口都卖番茄炒蛋"这类真实情况。
- **`ratingCount` 兼作删除影响的提示值**：它是**可见**评价数（`is_hidden = 0`）；删除会一并删掉隐藏评价，实际删除数**不少于**此值，故确认文案用「**至少** N 条评价」口径。
