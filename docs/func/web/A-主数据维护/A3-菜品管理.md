# A3 · 菜品管理

> 所属端：**管理端（运营）** ｜ 归属：**A 主数据维护**
> 返回：[总览](../约定与红线.md)

## 介绍

维护**菜品本体**与它的**多个售卖点**。学生端图标网格、内联展开卡与推荐结果都来自这里。

> 接口见 [`api/web/dishes.md`](../../../api/web/dishes.md) · 列定义见 [schema/dish.md](../../../schema/dish.md) 与 [schema/dish_offering.md](../../../schema/dish_offering.md)。

## 业务规则

### 菜品本体

| 项 | 口径 |
|---|---|
| **字段** | 名称（必填）· 描述（可选，喂语义匹配）· 菜品图（可选）· 在售状态（`activate`） |
| **唯一性** | `name` **全库唯一** —— 同一道菜多食堂售卖只建一行 `dish` |
| **描述** | 建议「名称 + 口味 + 场景 + 特点」一句话；变更后服务端自动重算 `embedding` |
| **图片** | 单张大图；传 `null` = 清除 |
| 状态 | 缺省在售；🔴 下架对学生端等价于不存在 |

### 售卖点（`dish_offering`）

| 项 | 口径 |
|---|---|
| **一条 = 什么** | 这道菜在某个**食堂 + 档口**的售卖记录，带独立价格与在售状态 |
| **一菜多行** | 一道菜可在多个食堂 / 多个档口售卖 ⇒ 多条售卖点 |
| **食堂** | 必填，下拉选（来源 [食堂管理](./A1-食堂管理.md)） |
| **档口** | **可空** —— 学校自营 / 大食堂统一出餐时留空 |
| **楼层** | 取所选档口的 `floor`，不在售卖点重复录入 |
| **价格** | 单位**分**，可空（未录入） |
| **在售** | 每个售卖点独立控制 |
| 🔴 **归属一致性** | 选了档口时，该档口所属食堂必须等于售卖点的食堂，否则拒绝保存 |

### 列表与编辑

| 项 | 口径 |
|---|---|
| 列表 | 可按食堂 / 档口 / 状态筛；**每个菜品展示售卖点摘要**（食堂 · 档口 · 价格，逐行） |
| 编辑 | 菜品本体 + 售卖点表格：**可增删行**，每行下拉选食堂 / 档口、填价格与在售 |
| 保存语义 | 售卖点**整表替换**：未出现在列表中的旧售卖点删除，带 `id` 更新、不带 `id` 新增 |
| 删除 | 🔴 物理删除；售卖点与菜品反馈随外键 `ON DELETE CASCADE` 一并清除（删除前二次确认） |

### 明确不录的字段

| 不录 | 原因 |
|---|---|
| 多图 | 图标只需一张图 |
| 原价 / 折扣 | 无促销语义 |
| 分类 / 种类 | 口味交给描述 + 语义匹配 |
| 标签（辣 / 清淡…） | 不维护人工标签 |
| 时段（早 / 午 / 晚） | 所有菜品全天售卖 |
| 售罄 / 今日供应 | 只有「在售 / 下架」两态 |

## 数据（读写）

| 表 | 变化 | 说明 |
|---|---|---|
| `dish` | INSERT / UPDATE / DELETE | 列定义见 [schema/dish.md](../../../schema/dish.md) |
| `dish_offering` | INSERT / UPDATE / DELETE | 随菜品整表替换；删菜时级联清除 |
| `feedback`（菜品级） | **随菜品级联清除** | 删菜时一并蒸发 |
