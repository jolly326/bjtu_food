# A2 · 档口管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：与 A1 同一口径 —— 档口作为**可维护实体**（CRUD）。

## 介绍

维护**档口（`stall`）**——菜品的直接归属，**必须挂靠一个食堂**；持有**楼层**与**窗口号**。

**定位**：与 A1 同——档口作为**可维护实体**（CRUD）；A3 菜品录入**从档口下拉中选择**（按所选食堂过滤），避免"自由文本错别字 → 重复档口"。

**职责边界**：只管档口自身（所属食堂 / 名称 / 楼层 / 窗口号），**不管**食堂（A1）与菜品（A3）。

**删除约束**：档口下仍有菜品时**禁止删除**（`400`），避免孤儿菜品。

> ⚠️ **楼层归属档口**：`floor` 是档口的**场所属性**，**改动会影响该档口下的所有菜品**（菜品详情的位置行取档口楼层）。
> **楼层是受控字典、值即汉字**（值域见 [schema/stall.md](../../../schema/stall.md)）：本页以**下拉**录入，**存储值就是显示的汉字**（如 `二层`），与小程序端菜品问题反馈页的楼层单选同用一份字典 —— **全链零映射**。
> **变更规则（字典先动、数据后跟）**：**新增**楼层 = 两端下拉各加一项（免迁移）；**删除 / 改名**楼层 = **先把该楼层的档口改到其它楼层**（本页逐个改，档口量级十数条），再改字典 —— 因此**不需要兜底 / 例外**（不会出现字典外的值）。

**不纳入的字段（已定：保留不删）**：`images` / `location` / `description` / `sort_order`（client 零消费）—— **保留不删**、**不建管理入口**，也不在本次清理范围（口径见 [`docs/README.md`](../README.md) 的「已知取舍」）；**不引入 `status`**。

## 接口

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `stall` | 增删改查 | 档口本体 |
| `canteen` | 读名称校验归属存在、回填食堂名 | 所属食堂 |
| `dish` | 删前按档口计数 | 删除约束校验 |

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **提供 `POST` / `DELETE` 端点**（`CanteenAdminController`）。
- **新增 `canteenId` 筛选**。
- **新增 `canteenName` / `dishCount` 出参**。
- **名称唯一（应用层校验）**：同食堂下查重，重名 `400`；改名场景同样校验（避免以已有名绕过约束；`canteenId` 未传时取当前归属再判），不加强 DB 唯一索引。
- **不纳入字段**：`images` / `location` / `description` / `sort_order` 不纳入。
- **`floor` 为受控字典（值即汉字）**：`FloorDict` 为唯一真源，写入时校验 + 归一化。
- **`GET` 列表 / `PUT` 修改**：口径不变。
