# A6 · 首页筛选视图管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：后台维护首页筛选 tab 的**文案 / 顺序 / 显隐**与**筛选条件 / 排序口径**（全量后台可配、免发版），并维护**菜品种类字典**（系统维度取值）。

## 介绍

维护 client **首页筛选栏** —— [`GET /dishes/views`](../../../api/client/dishes.md) 下发的那排 tab。

**定位**：首页筛选栏是**低频运营项**，但它是**纯数据**：一个 tab = 一行 [`dish_filter_view`](../../../schema/dish_filter_view.md)（文案 + 顺序 + 显隐 + 条件 + 排序口径）。**新增 / 编辑 / 删除 tab 都在后台完成，免发版、零代码**。

**两层模型**：

| 层 | 落点 | 职责 |
|---|---|---|
| **视图** | 表 [`dish_filter_view`](../../../schema/dish_filter_view.md) | 一个 tab 的全部口径（文案 / 顺序 / 启停 / 筛选条件 / 排序口径）**全部落库** |
| **种类值** | 表 [`dish_attribute_value`](../../../schema/dish_attribute_value.md) 中**系统维度（菜品种类）** 行 | 菜品「种类」字段（`dish.meal_type_id`，存取值 ID）的**取值域**；视图条件**引用**它、**不派生**它 |

**职责边界**：只管首页筛选栏与种类字典；**不管**菜品本体（A3）、属性维度与取值（A4）、首页 Banner（A5）。

**约束**：**不允许停用 / 删除「最后一个启用的视图」**（否则端上筛选栏为空、无落地页）。

## tab 的筛选条件与排序口径

> 条件与排序口径存在视图行的 `conditions` / `sort_kind` 列，由管理端「新建 / 编辑视图」写入；**不可**写 SQL / 表达式 / 函数。

**条件字段白名单**（`conditions` 的有限语言，AND 组合）：

| 条件字段 | 类型 | 操作符 | 值来源 |
|---|---|---|---|
| `mealTypeId`（菜品种类） | 枚举 | `=` / `in` | **种类取值 ID**（[种类字典](#值管理菜品种类)，见「值管理」） |
| `discount`（有折扣） | 布尔 | `isTrue` | 派生 `original_price > price`，无值 |
| `price`（现价） | 数值 | `between` / `>=` / `<=` | 手填，单位分 |
| `stallId` / `canteenId` | 枚举 | `=` / `in` | [A2 档口](./A2-档口管理.md) / [A1 食堂](./A1-食堂管理.md) |
| `avgRating`（均分） | 数值 | `>=` | 手填（0~5） |
| `createdAt`（上新） | 日期 | `近 N 天` | 手填 |

**排序白名单**（`sortKind`，单选）：`priceAsc` / `priceDesc` ｜ `discountDesc` 折扣力度 ｜ `ratingDesc` 均分 ｜ `newest` 上新 ｜ `random` 会话种子随机。

> **组合关系只有 AND**；空条件（`[]`）= 全部菜品。
> **种子初始 7 个视图**（「为你推荐」+ 6 个种类视图）：条件与排序**同表存储**，后台可改可删；条件语义与文档口径见 [api/web/views.md](../../../api/web/views.md)。

## 值管理（菜品种类）

菜品种类是**系统维度**（`dish_attribute_dimension.system = 1`）下的一组取值，在管理端「分类」抽屉（[A3 菜品录入](./A3-菜品管理.md)的分类下拉旁）**登记与重命名**：

- **产生**：分类抽屉登记（只填中文名，ID 由后端生成）；
- **重命名**：改 `label` 全站生效（**数据锚在取值 ID** —— `dish.meal_type_id` 存的就是它，故改名免费）；
- **保护**：系统维度**不可删、不可改取值类型**；其取值**被菜品引用时不可删**。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/views.md**](../../../api/web/views.md)（筛选视图契约，含**条件语言与排序白名单**）与 [**api/web/categories.md**](../../../api/web/categories.md)（种类取值契约）。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `dish_filter_view` | 增删改查 `label` / `conditions` / `sort_kind` / `enabled` / `sort_order` | 视图本体（tab 的全部口径） |
| `dish_attribute_value` | 系统维度下取值的增删改查（登记 / 改名 / 排序） | 菜品种类字典 |
| `dish` | **只读**：统计 `matchedCount`（`status='on'` 口径）与种类引用计数 | 匹配数与引用计数 |

## 客户端可见性规则

[`GET /dishes/views`](../../../api/client/dishes.md) 下发 = **`enabled = 1`** 的视图，且：

- **匹配数为 0 的视图不下发**（避免用户点进空列表）；
- 顺序 = `order` 升序；
- [`GET /dishes?view=<id>`](../../../api/client/dishes.md)：**非法 ID → `400`**；**不传 `view`（如搜索页）→ 取首个启用视图（按 `order`）**。

> **端上首屏默认选中第一个 tab**；服务端**无"默认视图"概念**（无 `is_default` 标记）。
> **不允许停用 / 删除"最后一个启用的视图"**（避免下发规则自相矛盾）。
> **端上只认 `id` + `label`**：筛选条件与排序口径全在服务端，端上零文案、零条件感知。

## 备注（架构取舍）

- **条件语言是白名单，不可配 SQL**：字段 / 操作符 / 值三层白名单 + 参数化绑定，封死开放 SQL；白名单唯一真源 = 条件引擎 `DishViewConditions`。
- **视图全在库**：tab 的文案 / 顺序 / 显隐 / 条件 / 排序都是数据，后台自助增删改 —— 运营不再需要发版；端上契约（`id` + `label`）恒定。
- **种类字典化、数据锚在 ID**：`dish.meal_type_id` 存种类取值 ID，改名免费；种类同时是一个属性维度，故可复用 A4 的取值管理能力（登记 / 改名 / 排序 / 引用计数）。
- **排序端点用 `/sort`**：`items` 全量提交，服务端整体替换 `order`（与全站拖拽排序口径一致）。
