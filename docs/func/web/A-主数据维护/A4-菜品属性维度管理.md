## 介绍

维护菜品属性的**维度**（`dish_attribute_dimension`）与**取值字典**（`dish_attribute_value`）。

**模型**：
- **维度**：维度 ID + 中文名 + 单/多选 + 顺序 + **是否系统维度** —— 定义「有哪几行、每行叫什么、单选还是多选」；**菜品 `attributes` JSON 的键 = 描述维度 ID**。
- **系统维度**（`system = true`，当前 = 「菜品种类」）：取值即**菜品种类字典**，被 `dish.meal_type_id` 引用；本页可见其行与取值，但**取值类型不可改、维度不可删**，且其取值**不写入 `attributes`**（录入入口在 [A3 菜品管理](./A3-菜品管理.md) 的种类下拉与 A6 的种类抽屉）。
- **取值**：每个维度下的一组可选值（中文 `label` + 顺序）；**菜品存的是取值的 ID**，出参时服务端翻译成中文 ⇒ **客户端契约不变**。
- **名称全部可改、且免费**：维度名、取值名都只是展示，数据锚在**维度 ID / 取值 ID** ⇒ 改名**不影响任何菜品数据**。
- **单 / 多选可切换**：后端在同一事务内自动迁移该维度下菜品的数据形状（单值 `id` ↔ 多值 `[id]`）。
- **灵活取值**：
  - 管理端录入菜品时**可直接输入新值 → 自动登记**进取值字典；
  - **菜品问题反馈**提交的新值**不立即入库** —— 仅当该反馈被管理员**采纳**时，按中文查字典（命中即用；**未命中自动新建一行**）后再写回菜品（见 B4）。
- **删除约束**：维度 / 取值**被菜品引用时禁止删除**（`400`），防止静默丢数据；**系统维度恒不可删**。

## 备注（架构取舍）

- `dish.attributes` **保持 JSON 列**（存取值 ID），**不引入关联表**：改动最小，且「按取值计数」（`dishCount` / 删除约束）是低频管理操作，扫描可接受。
- **排序一律「拖拽 + 批量端点」**（与 [A6](./A6-首页筛选视图管理.md) 同口径）：顺序是**人工意志**而非业务字段，一次原子提交比逐条填 `order` 更不易出错。`order` 仍留在 VO 里回显，只是**不从保存请求传入**。
- 若将来需要「**按属性筛选菜品**」，应迁移为关联表（如 `dish_attribute_ref(dish_id, value_id)`）——登记为演进预留。
- **客户端侧文档**：`docs/func/client/A-浏览与发现/A3-菜品详情.md`、`docs/func/client/B-UGC表达与治理/B6-菜品问题反馈.md`、`docs/ui/client/菜品详情.md` 与 `docs/api/client/dishes.md` 均为「服务端按**取值 ID** 翻译后下发中文」口径；**客户端展示契约不变**。
