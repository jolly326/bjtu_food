# 运营端约定与红线

> 所属端：**管理端（运营，Web）**
> 本文件是运营端的最高口径：功能文档入口与全部红线（为什么 / 边界在哪）。
> **效力**：任何新功能 / 改动若与本文冲突，**必须先修订本文（重新拍板）再动代码**。
> 接口契约见 [`api/`](../../api/CONVENTIONS.md)，库表见 [`schema/`](../../schema/)，页面视觉见 [`ui/web/`](../../ui/web/)。

## 阅读约定

> 每份功能文档的基准节序为 **介绍 → 业务规则 → 数据（读写）**；接口与字段一律不复述，只留链接。
> 文档与代码的一致性由 `npm run verify`（`check:tokens` / `type-check` / `vitest` / `eslint` / `build`）保障；运营端自身不设 `check:doc` / `check:contract` 脚本，`docs/` 与 `web/src` 的零旧方案残留、相对链接由 `client` 侧 `check:doc --strict` 统一覆盖，故文档内**不另设**「与代码的差异」段。

## 项目约定与红线

### 定位

- **内部工具**：给校园运营（学生团队 / 后勤）录入与维护菜品数据、查看学生反馈。
- **不做**：用户管理（无封禁）、内容审核、数据导出、多角色权限。
- **单管理员**：无角色分级，不做按角色隐藏入口。

### 数据录入是唯一数据源

- 学生端**全部**菜品 / 档口 / 食堂数据**只能**由本站录入 —— 没有第二条写入途径。
- 因此 🔴 **录入质量 = 学生端数据质量**：名称、图片、位置必须准确。

### 唯一性（应用层保证）

| 范围 | 约束 |
|---|---|
| 食堂 | `name` **全局唯一** |
| 档口 | **同一食堂下** `name` 唯一 |
| 菜品 | 菜品本体 + N 个位置；同一菜品同一位置唯一，不同菜品可同名 |

### 删除边界

| 对象 | 规则 |
|---|---|
| 食堂 | 🔴 **有下属档口时拒绝删除** |
| 档口 | 🔴 **有下属菜品时拒绝删除** |
| 菜品 | 可删；🔴 **连带清理**其菜品反馈（外键 `ON DELETE CASCADE`）—— 删前须确认 |

### 反馈数据只读

- 反馈正文与处理状态**运营端不修改、不删除正文**，唯一可变字段是 `handledAt`（标记已处理）。
- 反馈处置的唯一动作是**标记已处理**（`handledAt`），且 🔴 **不给学生任何回执**。

### 合规与不做的事

- 运营端**不展示任何用户标识**（学生全匿名）。
- **不做**操作日志 / 审计表（反馈处置只用一个 `handledAt` 时间戳留痕）。
- 图片（菜品图）**不送内容机审** —— 素材由运营自行上传。

### 明确**无入口**的表（防后人误加）

| 表 | 为何无入口 |
|---|---|
| `user` | 🔴 **全匿名设计的必然** —— 学生数据不在运营端展示（运营既不需要看，也不该看） |
| `admin` | 🔴 **单管理员** —— 账号行由**数据库直接维护**；**无注册、无自助改密**（见 [C1](./C-账号与访问/C1-管理员登录.md)） |

> 这两张表**刻意没有**查看或管理入口。若将来要加（如「用户数统计」「管理员改密」），**须先重新拍板**。
> 除这两张外，其余 **6 张表均有入口**：`canteen`→A1 · `stall`→A2 · `dish`→A3 · `feedback`→B1。

### 界面框架与配色

- **顶部固定导航栏**承载品牌名、四个功能入口（食堂 / 档口 / 菜品 / 反馈处理）、操作员与退出登录；全部导航集中在顶栏，页面不另设底部悬浮菜单。窄屏时导航收为图标，四个入口仍一屏可达。
- **列表卡片**统一由 `ListCard` 提供，结构只有「卡片本体 → 内容区」两层：标题与状态同行，元信息合并为一行，正文与操作平铺其后。页面容器只做纵向排布，不套第二层卡片。
- **卡片字段**只呈现运营处置所需信息：名称 / 状态 / 计数 / 价格 / 归属 / 正文 / 操作；编号、更新时间、提交与处理时间等日期类信息不进入卡面。
- **配色**为灰黑沉稳基调：近黑页面底、深灰卡面、浅灰文字、单一低饱和靛蓝作强调色；层级靠明度差与细描边建立，不做双层卡片与 3D 堆叠阴影。全部色值、圆角、间距由 `web/src/styles/theme.css` 单点承载，`docs/ui/web/` 页面稿只写本页结构与交互。
- **设计令牌**（`theme.css` 唯一真源）：颜色走 `--el-color-*` / `--el-bg-*` / `--el-text-*` / `--el-border-*` / `--el-fill-*` 与 `--web-bg-*`；圆角 `--web-radius-*`；间距 `--web-gap*` / `--web-page-pad` / `--web-topbar-h`；字号 `--web-font-sans` 与 `--web-font-{xs,sm,base,lg}`；控件 `--web-control-h` / `--web-control-h-touch`；动效 `--web-duration-{fast,base}` / `--web-ease-out`（`motion.css` 共用同一组）；遮罩 `--web-mask`。页面与组件样式一律引用令牌，禁裸色值与裸尺寸。
- **响应式断点**（`theme.css` 单点收口）：`≤1199px` 收紧栅格与页面间距；`≤767px` 全部输入类控件与按钮统一 `--web-control-h-touch`（44px）/ `--web-font-lg`（16px）；`≤640px` 筛选区与页脚纵排整宽、弹窗贴底、位置表单单列；`@media (hover:none)` 只保留 `:active` 反馈。`index.html` 带 `viewport-fit=cover`，底部间距叠加 `env(safe-area-inset-bottom)`。
- **状态与文案**：状态标签统一 `.tag` / `.tag--on` / `.tag--off` / `.tag--sm`（紧凑场景复用同一套状态色）；按钮文案统一为「保存 / 取消 / 删除 / 标记处理 / 添加位置」；在售态统一「在售 / 已下架」，启停态统一「正常 / 已停用」；成功提示统一由 `ElMessage.success` 承载。
- **列表页架构**：分页状态机由 `usePagedList` 单点提供（`rows / total / page / loading / error / hasNext / totalPages / load / go / reload`），页面不各自计算总页数；页头经 `Teleport defer to="#layout-pageheader"` 挂到吸顶区；加载 / 空 / 错误三态互斥，错误态保留当前数据并提供重试。
- **代码归属**：公共组件 ≥2 页使用才进 `web/src/components/`；列表卡片、状态标签、分页器、弹窗、图片字段为跨页公共件；页面私有表单逻辑留在各 View；零消费的组件、composable 与样式类不登记。
- **请求与会话**：`api/request.ts` 只负责基址 / 超时 / 信封解析 / 凭证失效发现；401 落地的会话清理与跳转由 `main.ts` 注册的处理器收口（请求层不 import router / store），避免 storage 与 store 两份真源；图片上传按资源归 `api/images.ts`。
- **写路径**：保存流程（上传 + 提交）同在一个 `try` 内，失败必弹提示、复位 `saving` 并把草稿态回滚到编辑前（图片回到原 URL，不把本地 `blob:` 提交给服务端）；分页状态机以请求序号丢弃迟到响应，连点翻页 / 筛选抖动不覆盖新状态。
- **编辑弹窗**：桌面居中卡片、窄屏贴底底部贴纸；高度取 `dvh`，卡片为 flex 列三行 —— 标题行 / 表单主体 `.dialog__body`（唯一滚动区，滚动不传给背景）/ 操作区行。标题与操作区是常规流内的固定行，**操作区不覆盖也不遮挡表单内容**（含上传图片等按钮），主体高度不足时只滚动主体。弹窗挂载到 `App.vue` 的 `#overlay-root` 全局覆盖层（层级 300，高于顶栏 200 与吸顶页头 10）；弹窗内不设页面级 `!important` 覆盖。弹窗内触控目标 ≥44px、相邻控件间距 ≥8px、输入字号 16px；三个编辑弹窗统一为宽版卡片（`min(880px, 100%)`）并共用 `theme.css` 的 `.edit-grid` 两列字段栅格（≤`767px` 收为单列）：食堂「名称 / 状态」+ 跨列图片，档口「所属食堂 / 名称」「楼层 / 窗口号」「状态 / 图片」，菜品「名称 / 价格」「描述 / 图片」+ 跨列售卖位置；菜品位置行宽屏单行五列、窄屏折行；共用图片预览 16:9、最大宽 `320px`。**确认删除视图**（弹窗内整卡切换，`ConfirmDeleteCard`）为短内容、不使用滚动区：标题 / 说明 / 操作区同为常规流子节点，操作区填满卡片底缘并与说明文字保持 `--web-gap-loose` 间距。
- **滚动条**全站收敛为 6px 低对比细条（透明轨道），主内容区、弹窗与下拉一致；原生宽滚动条不呈现。
