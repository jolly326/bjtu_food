## 每篇统一结构

1. **元信息头** —— `所属端 ｜ 鉴权 ｜ 归属 ｜ 状态`（状态须与上表标记一致）。
2. **介绍** —— 定位 / 职责边界 / **删除约束** / **不纳入的字段**。
3. **接口** —— **一行链接**指向 [`docs/api/web/`](../../api/web/) 下对应的资源文档（端点 / 入参 / 出参 / 错误码不在本目录维护）。
4. **数据** —— 读写哪些表、各表做什么（列口径链接 `docs/schema/`）。
5. **与当前代码的差异** —— **必填节**；逐条登记设计 vs 现有实现，清零写「无」。
6. **备注** —— 架构取舍 / 业务规则说明。

## 编写约定

> **契约口径**（鉴权 / 响应信封 / 错误码 / 分页 / 金额 / 时间格式 / 拖拽排序提交）以 [api/README.md 的「通用约定」](../../api/README.md) 为唯一真源，**本目录不复述**。

| 项 | 口径 |
|---|---|
| 删除约束 | 被下级实体引用时**禁止删除**（`400`），由应用层计数校验 |
| **处置回执** | 处置类动作（隐藏评价 / 处理反馈 / 处置举报 / 反馈采纳）**向提交人投递站内回执**（**投递判据 = `userId` 有效**：静默登录的游客**有 userId，同样投递**；**匿名提交（`user_id = 0`）不投递**），正文含**处置结论**且**支持可选的原因 / 附注**；投递失败**不阻塞**处置。先例：`dish_correction.reply` / `reject_reason`、`user_feedback.reply` / `reject_reason`。**例外**：C2 的**禁用 / 删除账号不发回执**（账号无法登录 ⇒ 看不到通知）；**解绑邮箱同不发**（端上 `4031` 实时引导重新认证，见 [C2](./C-账号与访问/C2-用户管理.md)） |
| 埋点 / 统计 | **本期不做** —— 两端 UI 稿均不标注埋点；确有需要时另立规范（事件名 + 触发时机 + 属性），不在页面稿里零散写 |
| 不复述真源 | 接口 / 字段以 [`api/`](../../api/README.md)、字段类型 / 长度 / 约束以 [`schema/`](../../schema/README.md) 为准，用链接不复制正文 |
