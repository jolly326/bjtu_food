# B1 · 评价管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**B UGC 治理**
> **口径要点**：**保留物理删除**（UI 二次确认）；**隐藏发回执**且支持**可选附注**；**重新评价即恢复可见**（重新提交 = 全新内容、重新过机审）。

## 介绍

治理学生在 client 发表的**评价**（`review`）—— **隐藏 / 恢复显示 / 删除**；影响 client 评价列表与**菜品均分**。

**定位**：`is_hidden` 是**唯一可见性判据** —— 隐藏后**公开列表与「我的评价」都不可见**（**含作者本人**）；评分聚合只统计 `is_hidden = 0`。

**职责边界**：只管**评价本身**。举报的**处置流水**在 [B3 举报管理](./B3-举报管理.md) —— 从举报进入本页处置时，依据看 B3 记录，评价表不冗余存一份。

**动作恰好三个**：隐藏 / 恢复显示 / 删除。**无内容安全态处置端点** —— 机审 `pass` / `review` 直接放行、`risky` 直接拒绝，**不存在待复核队列**。

**删除**：**物理删除**（`review` 无软删列），并触发菜品评分重算；**不可逆** ⇒ UI **二次确认**。

**回执**（对齐项目通用口径，见 [web/README](../README.md) 的「处置回执」）：

- **隐藏 / 删除都向作者投递站内回执**（登录级）—— 否则作者只会看到评价"凭空消失"；
- 隐藏**支持可选附注**（`note`，≤200 字）：有则随回执展示，无则用固定文案；
- 回执投递失败**不阻塞**处置。

**回执文案**：评价隐藏→「评价已被隐藏」、评价删除→「评价已被删除」（两路文案分流，端上只渲染「标题 + 正文 + 时间」，**不按类型分支**）：

| 结论 | 标题 | 正文 |
|---|---|---|
| 隐藏（无附注） | `评价已被隐藏` | `你的评价已被管理员隐藏。` |
| 隐藏（有附注） | `评价已被隐藏` | `你的评价已被管理员隐藏。说明：<note>` |
| 删除 | `评价已被删除` | `你的评价已被管理员删除。` |

> 隐藏 / 删除后该评价**对作者本人亦不可见**（见「客户端可见性」节），故回执是作者**唯一**的解释渠道 —— 文案必须成对落地，不得只投递空正文。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/reviews.md**](../../../api/web/reviews.md)（评价治理契约唯一真源）。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `review` | 读写（可见性 / 隐藏附注）；删除整行 | 评价本体 |
| `dish` | **只读**（回填菜名）；评分聚合经事件**重算** | 关联菜品 + 均分缓存 |
| `user` | **只读**（昵称 / 头像） | 评价者 |
| `notification` | **写**（隐藏 / 删除回执） | 站内回执 |

> 列口径见 [schema/review.md](../../../schema/review.md)。

## 客户端可见性（不变）

- 公开列表 [`GET /dishes/{id}/reviews`](../../../api/client/dishes.md) 与「我的评价」[`GET /my/reviews`](../../../api/client/my.md) **只返回 `is_hidden = 0`**（含作者本人）；
- 举报目标校验 `existsVisibleById`：**已隐藏 = 对外不存在 = 不可被举报**；
- 评分聚合只统计 `is_hidden = 0`，写入 `dish.avg_rating` / `dish.rating_count`（**提交后同步重算**）。

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **筛选参数**：`hidden`(`boolean`)；`dishId` 筛选（按目标菜品定位）；排序为 `createdAt DESC`。
- **端点**：[`PUT /admin/reviews/{id}/hidden`](../../../api/web/reviews.md)（状态资源），请求体 `{hidden, note?}`。
- **隐藏回执 + 可选附注**：隐藏附注列（幂等迁移段；列口径见 [schema/review.md](../../../schema/review.md)）；隐藏时可选填写并随回执下发，恢复显示时清空。
- **删除回执**：管理员删除评价亦向作者投递站内回执（与隐藏同一投递口径）。
- **出参统一 boolean**：`ReviewAdminVO.hidden`(boolean)（库列 `review.is_hidden` 仍 0/1，只改出参、不改列）。

## 备注（架构取舍）

- **"重新评价即恢复可见"保持现状**（覆盖提交时 `is_hidden` 重置为 0）：重新提交是**全新内容**、**重新过机审**，且平台是**校内用户池**，绕过处置的风险可接受；不动 `uk_review_user_dish` 的唯一键覆盖语义。
- **保留物理删除**：违规内容有时**必须清除**（隐藏只能"不可见"）；不可逆 ⇒ 二次确认。
- **附注落库而非只发通知**：处置可追溯（谁因何被处置）；与 [`dish_correction.reply`](../../../schema/dish_correction.md) / [`user_feedback.reply` + `reject_reason`](../../../schema/user_feedback.md) 的**既有做法一致**。
- **回执口径**：登录级（游客提交的 UGC 也能收到，判据 = 有可归属 `userId`）；投递失败**不阻塞**处置（独立 try）。
- **不加 `updatedAt`**：见 [api/web/reviews.md](../../../api/web/reviews.md) 说明。
