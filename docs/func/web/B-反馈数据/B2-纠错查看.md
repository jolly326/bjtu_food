# B2 · 纠错查看

> 所属端：**管理端（运营）** ｜ 归属：**B 反馈数据**
> 返回：[总览](../README.md)

## 介绍

查看学生提交的**菜品纠错**，并据此**手动**更正菜品信息 —— 系统只记录「学生反馈了什么」，**不做自动更正**，也**不给学生回执**。

> 接口见 [`api/web/issues.md`](../../../api/web/issues.md) · 选项字典的维护见 [B3 纠错选项管理](./B3-纠错选项管理.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| **一条 = 什么** | 一次提交 —— 🔴 **只含一个选项**（无文字、无配图） |
| 列表 | 🔴 **默认只查未处理**（`handledAt IS NULL`）；可按菜品筛；分页；按 `createdAt` 降序 |
| 展示 | 菜品（名 / 食堂 / 档口）+ **错误类型（中文，由选项字典翻译）** + 提交时间 + 处理时间 |
| **标记已处理** | `PATCH` 写 `handledAt`；传 `false` 可**撤销误标** |
| 🔴 **处置动作** | 运营**手动**去改菜品（[A3 菜品管理](../A-主数据维护/A3-菜品管理.md)）—— **系统不会自动更新任何字段** |
| 🔴 **无回执** | **不给学生发任何通知**；学生端也看不到处理结果 |
| 删除 | 提交行**永不删除** —— 保留「同一问题被反馈过几次」的严重度信号与审计 |

> 「默认只查未处理」是让列表规模 = **待办量**的关键：已处理的记录不再占用运营的注意力。

## 选项从哪来

- 每条提交的**错误类型中文**来自选项字典（`dish_issue.option_id` → `dish_issue_option.name`）；
- 因此**改选项文案会连带改变历史提交的展示文本** —— 这是既定设计（见 [B3](./B3-纠错选项管理.md)）；
- 本页**只读**选项，**不提供**选项的增删改入口。
