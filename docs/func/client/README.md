## 项目约定与红线

> **效力**：任何新功能 / 改动若与本节冲突，**必须先修订本节（重新拍板）再动代码**。

### 产品形态（防跑偏）

- **一句话**：校园菜品展示与轻量评分平台 —— 帮学生解决「今天吃什么」。
- **三个 tab**（TabBar 显示名）：**发现**（看档口海报）· **美食**（扑克式单卡，可「去品尝」）· **记忆**（按月回看 + 就地评分 + 菜品纠错）。
- **无搜索**；**无「我的」页面**；**无菜品详情页**（信息全在卡片 / 海报上）。
- **全匿名**：不做注册 / 登录 / 认证 / 注销；身份由微信 openid 静默识别，**不在任何界面展示**。
- **无文字与图片 UGC**：学生侧只有「去品尝」「三态评分」「菜品纠错选项」三类动作 ⇒ **不送内容安全检测**。
- **无分享、无社区、无收藏**。

### 身份与鉴权

- 冷启动 `wx.login` 静默换取 openid → 服务端建 / 取用户行 → **下发凭证**（端上**缓存 7 天**）；**端上只带凭证、不传 openid**。
- 🔴 **所有端点统一要求凭证**（唯一例外是换凭证的 `POST /auth/wechat-login` 本身）—— **没有「公开端点」这一态**。
- **无权限分级**：身份只用于「归属本人数据」与频控。

### 评分口径

- **个人感受三态**：喜欢 = `5` ｜ 一般 = `3` ｜ 不喜欢 = `1`（一次点击切换，不增档位）。
- **群体风味评级五档**（卡片左上字母 + 右上「风味评级 / 档位词」）：好评度 = `(喜欢×100 + 一般×50 + 不喜欢×0) ÷ 总评价数` = `(avg_reaction − 1) × 25` —— **S** ≥ 85（臻荐）｜ **A** 70 ~ <85（极荐）｜ **B** 60 ~ <70（推荐）｜ **C** 50 ~ <60（尚可）｜ **D** < 50（平实）。
- 🔴 **评级门槛**：评分条数 ≥ 3 才出等级；不足 3 条 ⇒「待评」（不出字母）。
- 🔴 **文案中性**：五档只用平缓的中性口碑词，**不得出现劝退 / 负面表述**；评级是同学口味口碑汇总，不是菜品质量或卫生评价。
- 🔴 零评分：**存储为 NULL**、展示「待评」，**不得兜底成 5.0** —— 兜底值会凭空获得高分并污染推荐权重。

### 合规与不做的事

- 🔴 **MP 后台必须配置《用户隐私保护指引》** —— 声明收集微信 openid（用于标识用户以保存饮食记录与评分）。**未配置无法通过代码版本审核**（属填表，不是开发）。
- **不做**站内的隐私政策 / 用户协议页面，也不自绘授权弹窗 —— 协议文本由微信托管，如需展示用 `wx.openPrivacyContract()`。
- **不收集**手机号 / 邮箱 / 位置 / 相册 / 昵称头像；学生端**不调用任何需授权的隐私接口**（不出现授权弹窗）。
- **无账号体系**：不做注册、登录、认证、注销、密码。

### 数据库

库结构唯一真源 = [`schema/`](../../schema/README.md)；变更**先改表文档**，再直连远程库执行，两者必须一致。

### UI 实现红线

- 事件统一 `@tap`（禁 `@click`）；按压反馈用 `background: var(--color-bg-soft)` / `opacity` 微降，禁 `transform: scale`。
- 颜色全走语义 token，禁裸 hex。
- 图片为空或加载失败一律走 `ImagePlaceholder`；图标统一 `AppIcon`，禁 emoji / 文本当图标。
