# 学生端文档总览（功能 + UI）

> 本目录是**学生端（微信小程序）**文档的入口，分两类：
> - **功能文档**（`[A-D]-*/` 四个板块）：只写**业务规则**（为什么 / 边界在哪），按板块分目录 / `<字母><序号>-<主题>.md` 命名；
> - **UI 文档**（[`ui/`](../../ui/client/)）：只写**视觉与交互**，索引见 [ui/README.md](../../ui/client/README.md)。
>
> 接口契约与字段见 [`api/`](../../api/README.md)，库表设计见 [`schema/`](../../schema/README.md)。
> 功能文档与 UI 文档**各按自身标准分层**，分类标准 / 命名 / 粒度均不强制 1:1 对应。

## 阅读约定

> 每份文档的**基准节序**为 **介绍 → 数据（读写）→ 与当前代码的差异**（个别篇按需增设「跨域事件 / 设计决议 / 展示口径」等节）；**接口与字段一律不复述** —— 「介绍」段内以**一行链接**指向 [`api/`](../../api/README.md)。
> - **不写落地状态**（「待实现 / 已落地」等一律不写）；与代码不一致的条目集中在文末「与当前代码的差异」段，清零时写「无（文档与代码一致）」。
> - **不写跨功能表述**（如「本页面还涉及 X 功能」「页面路径 / 组件名」）—— 页面归属见 [`docs/ui/client/`](../../ui/client/)。
> - **不复述接口与字段**：契约在 `api/`，本文只链接引用；同一契约出现两份措辞必然漂移。
> - 功能文档与 UI 文档**各按自身标准分层**，分类标准 / 命名 / 粒度均不强制 1:1 对应。

### 端定位与数据链路

| 端 | 定位 | 约束 |
|---|---|---|
| `client/`（小程序） | **用户端**：业务数据**唯一产生源**（浏览 / 评价 / 反馈 / 菜品问题反馈） | **无菜品写接口**（菜品资料由管理端维护，小程序端只读，防回退） |
| `server/`（Spring Boot） | **数据服务**：唯一存储与业务规则 | 提供统一契约（`/` 用户接口） |

数据流向：小程序产生 → MySQL → 小程序即时反映。

### 后端分层与契约

- 包结构 `com.bjtufood.<域>`，严格四层 **controller / service(+impl) / mapper / entity / dto**；**禁跨层调用**；ORM = MyBatis-Plus。跨域依赖规则见 [`docs/README.md`](../../README.md) 红线（由 `ArchTests` 强制）。
- 统一响应 / 分页壳 / 错误码 / 金额 / 时间的通用约定见 [`api/README.md`](../../api/README.md)，**本目录不复述**。
- 用户身份只从 `SecurityUtil.getCurrentUserId()` 取，**禁信任前端传 userId**。
- 写操作加 `@Transactional`；机审等慢操作**移出事务**；跨域写用同步事件与发布方同进同退。

### 认证与鉴权

- **无账号密码体系**：打开即 `POST /auth/wechat-login` 静默建号 → **游客态**（默认已登录，无登录页）。
- 需邮箱认证的 UGC 操作**仅**四项：写评价 / 重新评价 / 删除本人评价 / 查看「我的评价」；**举报 / 反馈 / 菜品问题反馈为 🔑 需登录**（静默登录后即具备，无需邮箱认证；未携带凭证一律 `401`）。未认证返回 **`4031`**（与 `403` 分流）。
- **用户写入口一律需登录**：UGC 写请求必须可绑定账号 —— 否则匿名脚本可无 token 灌库，且既无法归因 / 也无法按账号维度限频。
- 认证判据 = `bindEmail` 非空，**不进 JWT**（后端实时查库）。
- **系统通知为 🔑 登录级**：游客与已认证用户同权，游客提交的反馈 / 举报 / 菜品问题反馈同样收到回执。
- 角色**仅 `STUDENT` / `ADMIN`**。

### UGC 治理与账号处置

- **双层治理**：单条机审只能挡「明显违规」，挡不住「反复试探边界」⇒ 内容层拦截之外，还须在**账号维度**累积处置：累计违规 **3 / 6 / 9 次**分别触发警告 / 限言 24 小时 / 限言 7 天，**≥12 次封禁**。
- **计数来源只有两处**：机审 `risky` 命中（内容被拦 / **未入库**）+ **举报成立**（管理端处置结论为「通过」，记给被举报内容的作者）。
- **限言判据 = `user.muted_until` 是否在未来**（不设独立状态列）⇒ **到期自动恢复，无需人工动作**；限言期**写端点一律 `403`「账号已被限制发言，请稍后再试」，读不受限**。
- **封禁 = 账号禁用**：写 `status='disabled'` 并吊销该 userId 全部 token（复用既有禁用语义，不新增状态值）。
- **每次处置必须留痕 + 告警**：留痕在 [`user_violation`](../../schema/user_violation.md)（只追加），告警走管理端同一通道 —— 防「静默封号」不可复盘。
- **全局吊销的四个触发点必须齐备**：注销账号 / 账号被禁用（含封禁）/ 邮箱换绑（本人认证与管理员解绑）/ 管理员人工踢下线。

### UI 实现红线（改 `client/` 必查）

跨页通用形态与组件规格见 [`client/ui/公共组件与形态基线.md`](../../ui/client/公共组件与形态基线.md)，**本目录不复述**。学生端特有约束：

- 事件统一 **`@tap`**（禁 `@click`）。
- 按压反馈统一 `background: var(--color-bg-soft)` / `opacity` 微降，**禁 `transform: scale`**。
- 颜色全走语义 token，**禁裸 hex**。
- **图片占位统一 `ImagePlaceholder`**：任何图片为空或加载失败一律走公共组件（通用 `image-broken`，头像用 `user`），**禁自绘占位 / 禁裸 `<image>` / 禁裂图**。图标统一 `AppIcon`，禁 emoji / 文本当图标。
- 瀑布流区块（`HomeContent.vue` 内）直渲染 `DishCard`，**禁向子组件具名 slot 分发**（mp-weixin 下同名 slot 塌缩成空白）。
- 底部 Sheet 统一下拉关闭手势（≈120px）+ `prefers-reduced-motion` 降级。

### 产品定型（一页纸，防跑偏）

- **一句话**：交大人的「吃什么不踩雷」—— 校园菜品信息展示与检索平台，用户反馈经安检与审核回流为高质量信息。
- **品牌名 = 「知行食记」**：小程序标题 / 启动页、分享文案、隐私政策与用户协议、管理后台页头与登录页、认证邮件发件人与正文、**安全告警前缀** 一律用**同一品牌**。**判据**：任一用户可见文案里出现其它产品名即为缺陷。
- **五支柱**：① 信息展示优先（「售罄 / 今日供应」一期不做）；② 轻社区边界（UGC 仅「评价」一种形态，不做动态 / 关注 / 私聊 / 收藏）；③ UGC 通道唯一（菜品共建走反馈 / 菜品问题反馈 → 管理员录入）；④ 合规底线（**全部用户图片与 UGC 文本过微信内容安检**——UGC 配图与头像同走一条上传链路，仅 `risky` 拦截）；⑤ 轻运营（无运营位）。
- **平台边界**：游客可浏览 / 搜索一切；**写评价 / 重新评价 / 删除本人评价 / 查看「我的评价」须认证**（四项），**举报 / 意见反馈 / 菜品问题反馈须登录**（静默登录后即具备，无需邮箱认证）；通知仅站内通知中心***不做任何推送**；浏览量仅管理端参考***不参与排序**，评分聚合写入 `dish` 缓存列；北极星 = 周活 / 留存。
- **演进预留（做之前须重新拍板）**：Excel 批量导入 → OCR 菜单识别 / 微信订阅消息推送 / 「售罄 / 今日供应」即时状态 / 推荐算法演进。
- **不属于上述主线的需求一律不投入**（「开发招募自荐」等暂缓项见下方待办清单）。
