# A1 · 搜索找菜

**目标**：学生输入一句话，系统匹配出符合的菜品；首页始终呈现当前条件下的菜品结果集，条件可解释、可逐项取消。

> 页面形态 / 视觉 / 交互口径只在 [ui/client/菜品首页.md](../../../ui/client/菜品首页.md) 维护，本文件只写业务规则。

## 介绍

首页是单页、单一结果态：冷启动展示无条件结果集（全量在售位置），提交一句话后展示条件结果集，清空条件回到无条件结果集。布局与组件恒定，数据与结果条文案随条件变化。

结果条展示当前条件回显、结果数与生效约束胶囊。约束有两类：**食堂**、**预算**。

## 业务规则

### 初始态

- 冷启动 `GET /dishes` 拿全量在售菜品，端上把每个 `locations` 项展开为一张结果卡，按菜名做一次稳定序后渲染；该结果同时缓存为「全量集」，供清空条件时回填。
- 每张卡取 `imageUrl` / `name` / `description` 与该条 `locations` 的 `offeringId` / `canteenName` / `floor` / `stallName` / `price`；图片缺失时用占位块。
- 全量为 0 道时展示「还没有菜品上架」，不提供清空按钮。

### 搜索流程

```
结果条 / dock 输入一句话 → 回车 / 点搜索
  → POST /dishes/recommend { query }
  → 返回 { dishes }
  → 结果集整体替换（交叉淡入），描述全文展开态收起
```

### 命中判定

| 环节 | 口径 |
|---|---|
| 硬约束 | 只认三类：**完整菜名**（query 含某道菜的完整名称）、**食堂名**（query 含食堂名）、**价格上限**（`N 元` / `N 块`，按「不超过」理解） |
| 售卖点收窄 | 食堂名 / 价格命中时，只保留符合条件的售卖点（`locations` 同步收窄，端上据此只渲染命中的卡） |
| 排序 | 剩余菜品按「query 向量 ↔ 菜品描述向量」余弦相似度降序；同分保持服务端原始顺序 |
| 条数 | 未开精排最多 30 条、开精排最多 10 条；**不设相似度下限**，过滤后有多少返回多少 |
| 向量来源 | 只用与当前模型一致的预计算向量：本地模型下缺失/不符则实时补算；外部向量服务下**跳过**该行（由回填脚本补齐），避免一次搜索打 N 次外部请求 |
| 精排（可选） | `SYSTEM1_ENABLED=true` 时对向量 top-30 做一次 rerank 取前 10；🔴 精排超时/失败 **退回向量排序**，不影响可用性 |
| 条件结果排序 | 端上直接采用服务端返回顺序，**不二次排序** |

### 约束来源与撤销

| 来源 | 行为 |
|---|---|
| query 解析 | 端上按 A1 三类硬约束中的**食堂名 / 价格上限**两类从已提交 query 拆出约束，渲染为结果条胶囊；完整菜名属于查询主体，不做胶囊 |
| 取值行 | 点结果条 `食堂` / `预算` 就地展开一行横向滚动取值；已选排前带 `×`，其余纯文字，单选、点已选项即取消；取值只列当前全量集 `locations` 中实际出现的食堂名，预算为固定档位 |
| 卡面点选 | 结果卡上的食堂名可点，等价于把该食堂名追加进 query |
| 撤销 / 追加 | 构造新 query → 重新提交 `POST /dishes/recommend`；清空条件回填全量集 |
| 约束维度 | 只有食堂 + 预算两类，胶囊最多 2 个；不设排序控件、不设常驻筛选面板、不设下拉选择器 |

> 约束解析规则在端上与服务端各持一份，结论写入 `client` 侧约束解析模块；服务端口径见 [接口契约](../../../api/client/dishes.md)。后续若契约补 `constraints`，端上解析收敛到服务端返回值。

### 结果集替换与失败降级

- 结果集整体替换：旧列表淡出 / 新列表淡入（交叉淡入），端上按 `offeringId` 复用卡片节点。
- 输入框文本与已提交 query 不一致时，结果条置灰显示「结果待更新 · 按回车搜索」，当前结果集保持。
- 请求失败 / 模型超时 ⇒ Toast「搜索失败，请稍后再试」，结果集保持当前内容，可直接再次触发；🔴 不把失败态渲染成「无结果」。

### 命中为空（分级）

| 场景 | 表现 |
|---|---|
| 有硬约束且 0 命中 | 「`食堂名` 暂时没有符合的菜」+ 去掉该条件 + 换个说法 |
| 无硬约束且 0 命中 | 「没找到符合的菜，换个说法试试」+ 看全部菜品 |

### 结果卡承载

- 卡片身份单位 = `offeringId`：一道菜在 N 个位置在售则渲染 N 张卡，每张卡给出该位置确定的 `食堂 · 楼层 · 档口 · 售价`。
- 描述常驻卡面，超过 3 行时点「全文」在卡内展开完整 `description`；同时只允许一张展开，切换 / 收起 / 发起搜索 / 清空条件均收起。
- 无楼层 / 无档口显示「暂无」，`price = null` 显示「价格待定」。
- 卡面提供「反馈这道菜」入口，见 [B1](../B-轻量反馈/B1-文本反馈.md)；同一道菜的多张卡共用 `dishId`。

## 数据（读写）

| 来源 | 用途 |
|---|---|
| `GET /dishes` | 无条件结果集（全量在售），并缓存为全量集 |
| `POST /dishes/recommend` | 条件结果集 |
| `DishVO.locations` | 展开为结果卡（每项一卡）；`offeringId` 作卡片稳定键，食堂名作约束取值行数据源 |
