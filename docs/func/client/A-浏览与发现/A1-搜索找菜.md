# A1 · 搜索找菜

**目标**：学生输入一句话，系统匹配出符合的菜品；首页始终呈现当前条件下的菜品结果集，条件可解释、可逐项取消。

> 页面形态 / 视觉 / 交互口径只在 [ui/client/菜品首页.md](../../../ui/client/菜品首页.md) 维护，本文件只写业务规则。

## 介绍

首页是单页、单一结果态：冷启动展示无条件结果集（全量在售菜品），提交一句话后展示条件结果集，清空条件回到无条件结果集。布局与组件恒定，只有数据随条件变化。

约束由服务端从 query 解析：**食堂名**、**价格上限**两类；端上不展示、不编辑约束。

## 业务规则

### 初始态

- 冷启动 `GET /dishes` 拿全量在售菜品，每道菜渲染一张结果卡，按菜名做一次稳定序后渲染；该结果同时缓存为「全量集」，供清空条件时回填。
- 每张卡取菜品本体的 `imageUrl` / `name` / `description` / `price`，以及 `locations` 中各位置的 `canteenName` / `floor` / `stallName`；图片缺失时用占位块。
- 全量为 0 道时展示「还没有菜品上架」，不提供清空按钮。

### 搜索流程

```
HUD 输入一句话 → 回车 / 点搜索
  → POST /dishes/recommend { query }
  → 返回 { dishes }
  → 结果集整体替换（新列表淡入），描述全文展开态与反馈表单展开态一并收起
```

### 命中判定

| 环节 | 口径 |
|---|---|
| 硬约束 | 只认三类：**完整菜名**（query 含某道菜的完整名称）、**食堂名**（query 含食堂名）、**价格上限**（`N 元` / `N 块`，按「不超过」理解） |
| 命中收窄 | 食堂名 / 价格命中时，只保留符合条件的行 |
| 排序 | 剩余菜品按「query 向量 ↔ 菜品描述向量」余弦相似度降序；同分保持服务端原始顺序 |
| 条数 | 未开精排最多 30 条、开精排最多 10 条；**不设相似度下限**，过滤后有多少返回多少 |
| 向量来源 | 只用与当前模型一致的预计算向量：本地模型下缺失/不符则实时补算；外部向量服务下**跳过**该行（由回填脚本补齐），避免一次搜索打 N 次外部请求 |
| 精排（可选） | `SYSTEM1_ENABLED=true` 时对向量 top-30 做一次 rerank 取前 10；🔴 精排超时/失败 **退回向量排序**，不影响可用性 |
| 条件结果排序 | 端上直接采用服务端返回顺序，**不二次排序** |

### 约束来源与撤销

| 来源 | 行为 |
|---|---|
| query 解析 | 服务端按三类硬约束（完整菜名 / 食堂名 / 价格上限）从已提交 query 解析；端上不展示、不编辑约束 |
| 撤销 / 追加 | 构造新 query → 重新提交 `POST /dishes/recommend`；清空条件回填全量集 |
| 约束维度 | 只有食堂 + 预算两类，chip 最多 2 个；不设排序控件、不设常驻筛选面板、不设下拉选择器 |

> 约束解析规则在端上与服务端各持一份，结论写入 `client` 侧约束解析模块；服务端口径见 [接口契约](../../../api/client/dishes.md)。后续若契约补 `constraints`，端上解析收敛到服务端返回值。

### 结果集替换与失败降级

- 结果集整体替换：新列表淡入，端上按 `dish.id` 复用卡片节点。
- 请求失败 / 模型超时 ⇒ Toast「搜索失败，请重试」，结果集保持当前内容，可直接再次触发；🔴 不把失败态渲染成「无结果」。

### 命中为空（分级）

| 场景 | 表现 |
|---|---|
| 有硬约束且 0 命中 | 「`食堂名` 没有结果」+ 去掉条件 + 换个说法 |
| 无硬约束且 0 命中 | 「没找到，换个说法」+ 看全部菜品 |

### 结果卡承载

- 卡片身份单位 = `dish.id`：一道菜一张卡，其全部在售位置在卡面并列展示；图 / 描述 / 价格取自菜品本体。
- 描述常驻卡面，超过 2 行时点「展开」在卡内呈现完整 `description`；同时只允许一张展开，切换 / 收起 / 发起搜索 / 清空条件均收起。
- 位置按 `食堂 楼层 档口` 顺序空格连接，省去中间分隔符；无位置显示「暂无位置」，`price = null` 显示「价格待定」。
- 卡面段 4 左侧「反馈」、右侧「展开 / 收起」；反馈入口见 [B1](../B-轻量反馈/B1-文本反馈.md)。

## 数据（读写）

| 来源 | 用途 |
|---|---|
| `GET /dishes` | 无条件结果集（全量在售），并缓存为全量集 |
| `POST /dishes/recommend` | 条件结果集 |
| `DishVO.locations` | 同一卡内并列展示的各在售位置；`dish.id` 作卡片稳定键 |
