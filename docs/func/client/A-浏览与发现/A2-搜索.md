## 介绍

按关键词找菜。页面**只有三件事**：**搜索**（关键词检索菜品）、**搜索记录**（**纯本地**，不上服务端）、**猜你喜欢**（**后端随机推送菜品**——无推荐算法、无热度排序、无个性化；随机性按**会话**收敛：端上传会话级 `seed`，同一次会话内多次进入拿到**同一批**词条，**重进小程序**才整体重洗）。输入关键词即调 `GET /dishes?keyword=…` 展示结果，该词**写入本地搜索记录**（去重、最新在前、上限 4 条；支持清空，无记录时整块不渲染）。

> **搜索记录写入口径**：**用户主动发起的搜索都写入**——① 显式提交（回车 / 点「搜索」按钮）、② **点「猜你喜欢」词条**；**仅点「搜索记录」自身词条重搜不写入**（已在记录内）。上限 4 条，去重、最新在前。
> **状态口径**：清空搜索框 = 清词 **并** 退回发现态（不残留旧结果）；左上角返回 = **恒退出本页**（详见 [`docs/ui/client/`](../../../ui/client/) §4.1）。

> 接口 / 字段见 [api/dishes.md](../../../api/client/dishes.md)。

## 搜索口径

| 项 | 口径 |
|---|---|
| **入参** | 搜索页只用 `keyword`，**不传** `view` 与 `seed`；结果排序由服务端唯一决定，端上不传排序参数、无排序入口 |
| **匹配范围** | 菜名 / 档口名 / 食堂名**三处**模糊匹配 —— 关键词搜食堂名仍然可用 |
| **端上页长** | 固定 20（`RESULT_PAGE_SIZE`）；服务端归一化上限 100 |
| **字段复用** | `DishListItemVO` 8 字段**全量消费**，结果卡渲染位置行；**不为搜索另拆 VO**（多一个 VO 即多一份契约维护成本） |
| **不显示距离** | 搜索结果卡与详情页均无定位、无距离计算 |

### 搜索记录（**纯本地**，不上服务端）

| 项 | 口径 |
|---|---|
| 写入范围 | **用户主动发起的搜索都写入**：① 显式提交（回车 / 点「搜索」）；② **点「猜你喜欢」词条** |
| 例外 | **仅点「搜索记录」自身词条重搜不写入**（已在记录内） |
| 上限与顺序 | **≤4 条**，去重，**最新在前** |
| 清空 | 无记录时整块不渲染；清空走二次确认（破坏性操作） |

### 猜你喜欢口径

| 项 | 口径 |
|---|---|
| **语义** | 服务端**随机抽取**在售菜品名 —— **不按热度排序、不做个性化、不与用户历史相关**（「随机」即需求本身） |
| **条数** | 服务端固定 6 条；端上**不写死条数与文案**，按返回渲染，空数组则整块不渲染 |
| **刷新边界** | **重进小程序才整体重洗**。端上**无任何「主动换一批」入口**（全仓无 `onPullDownRefresh`）—— 用户无法解释内容为何变化，只能读成「界面不稳定」 |
| **`seed` 机制** | 端上冷启动生成一次、会话内恒定；服务端按 `CRC32(seed-id)` 稳定伪随机序 ⇒ 同一次会话内多次进入拿到**同一批** |
| **`seed` 与推荐流同源不同值** | 端上用同一会话基准派生两个种子（首页流 / 猜你喜欢各一个）—— 若共用同一 `seed`，两处取的是同一全序的前 N 个 ⇒ 首屏与发现态出现**同一批菜**（观感像 bug） |
| **不缓存响应** | 「会话内稳定」已由 `seed` 表达在数据层；再加 TTL 缓存的键必须含 `seed` 才有意义，收益与复杂度不成正比 |
| **契约留扩展位** | 将来升级为个性化 / 推荐算法时**端上契约不变**（仍 `name` 列表），只换服务端取数逻辑 |

## 待优化

> 本节登记**已拍板暂不做**的增强项（非缺陷）；触发条件成立时再评估，不在评审清单内重复挂账。

| 事项 | 现状 | 优化方向 | 触发条件 |
|---|---|---|---|
| **关键词匹配为粗糙模糊** | 菜名 / 档口名 / 食堂名 `%keyword%` 三路模糊；无拼音首字母、无分词；全表扫描已在 `DishMapper.xml` 登记（当前菜品量级下无感） | 拼音首字母列（建菜时后端生成 + 存量回填）+ 搜索空结果引导 | 内容量显著增长，或出现「搜不到已知菜品」的实际反馈 |
