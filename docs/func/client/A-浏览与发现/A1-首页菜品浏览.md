# A1 · 首页菜品浏览

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔓 公开**（免登录）
> 归属：**A 浏览与发现**
> 返回：[功能总览](../README.md)

## 介绍

看今天有什么可吃：**双列菜品卡片网格**（图 / 名 / 价 / 评分 / 位置），支持按**筛选视图**（横向标签栏，如「为你推荐」与各菜品种类）筛选（**筛选与排序由服务端按所选视图唯一决定：种子里 7 个视图均按会话种子伪随机序，端上无排序入口**）；无食堂 / 价格筛选入口。进入首页自动加载第 1 页，上滑触底自动加载下一页。

> 接口 / 字段见 [api/dishes.md](../../../api/client/dishes.md) · [api/banner.md](../../../api/client/banner.md)。

## 首页口径

| 项 | 口径 |
|---|---|
| **在售过滤** | 公开接口恒只返回 `status='on'`（在售）菜品 |
| **视图决定排序** | 筛选与排序由所选视图**唯一决定** —— **种子里 7 个视图均按会话种子伪随机序**（`random`）；端上**无排序入口** |
| **`view` 与 `keyword`** | 语义为 **AND**；**端上约定二者不同时使用**（首页传 `view`，搜索页传 `keyword`），组合能力保留给服务端 |
| **`view` 校验** | 传**视图 ID**；**白名单校验，非法值 → 400**，不静默降级 |
| **筛选栏渲染** | **100% 由字典端点直出** —— 端上不前置拼接、**不写任何兜底项**；标签文案（含「为你推荐」）是**服务端资产** |
| **字典失败** | 筛选栏**整体不渲染**（不留空栏），列表仍按「不传 `view`」→ 首个启用视图加载 |
| **空类隐藏** | **匹配数为 0 的视图不下发**（避免点进空列表）；**不传 `view` 时取首个启用视图**（它是空 `view` 的落点） |
| **页长与封顶** | `pageSize = 10`（`HOME_PAGE_SIZE`），最多 10 页 = **100 条封顶**；触底提前量 300px |
| **并行加载** | Banner 与菜品列表**并行**发出，Banner 失败**不阻塞首屏**；单张图失败只该张降级为占位 |
| **无距离** | 不展示距离（无定位权限申请、无距离计算） |

## 设计决议（现行口径）

> 本节按「一个决策一个小节」组织（`### A` ~ `### E`），可被目录 / 锚点直接跳转；**各小节只写最终设计形态**，实现进度一律见文末「与当前代码的差异」。

### A. 排序口径

`GET /dishes` 的筛选与排序**由所选视图决定**（视图的 `sortKind`，存 [dish_filter_view.sort_kind](../../../schema/dish_filter_view.md)），端上不传排序参数（无 `sortBy` / `sortOrder`）：

| 视图的 `sortKind` | 条件 | 排序 |
|---|---|---|
| `random`（**种子里 7 个视图**，含推荐类与 6 个种类视图） | 无 `keyword` 且带 `seed` | `ORDER BY CRC32(CONCAT(seed, '-', id)), id`——**稳定伪随机序**：同一 seed ⇒ 同一全序（`id` 决胜键防哈希碰撞）⇒ 翻页不重不漏；换 seed ⇒ 整体重洗 |

| `discountDesc` / `priceAsc` / `priceDesc` / `ratingDesc` / `newest`（**可选口径**，可在后台为视图配置） | 对应视图配置 | 各自主序 + `d.id` 决胜键（决胜键不用浏览量 —— 浏览量无上限，参与排序即可被低成本刷量霸榜） |

- **`seed` 生命周期 = 会话级**：端上**冷启动（重进小程序）生成一次**，会话内恒定——切视图 / 首屏 / 失败重试**都不重掷**，翻页沿用同一值 ⇒ 同一次会话内顺序完全稳定（内容不会自己变），重进小程序才整体重洗。**非**每次 reset 重掷（内容在会话内自变，而端上无「主动换一批」入口 ⇒ 用户只读成「界面不稳定」）；**非** `ORDER BY RAND()`（真随机会导致跨页重复 / 漏项）；**非**按天全局种子（全站同序、当天无新鲜度）。
- **范围**：`seed` 对**全部 `random` 视图**生效（种子里 7 个视图均为此口径）——端上**可无脑随请求下发**，无需判断视图语义。
- 合「排序口径由服务端唯一决定、端上无排序入口」原则：`seed` 是**数据顺序种子**而非排序参数，端上不提供任何排序 UI。

### B. 列表 / 详情出参拆分

`GET /dishes` 与 `GET /dishes/{id}` 各自只装自己的消费集：

| VO | 使用端点 | 字段集 |
|---|---|---|
| `DishListItemVO` | `GET /dishes`（首页网格 + 搜索结果） | 卡片消费集（单图 + 菜名 / 价格 / 评分 / 归属），字段见 [api/dishes.md](../../../api/client/dishes.md) |
| `DishDetailVO` | `GET /dishes/{id}`（详情页） | 详情消费集（含描述、图集、楼层、动态属性等），字段见 [api/dishes.md](../../../api/client/dishes.md) |

- **实现要求**：列表接口一律返回列表 VO（单封面图、无图集数组），详情接口返回详情 VO；两场景**各按自己的取数口径**，**禁止列表查询图省事取全列**；
- **端上形态**：列表与详情**各自建模**（类型分离，定义见端上代码）；卡片直读封面图字段。

### D. 筛选视图与菜品种类字段决议

> **背景**：横向筛选栏上的一个按钮，是「**用户想看什么**」的**导航视角**（本文档称 **view / 筛选视图**），与「**菜品是什么**」的入库字段（`dish.meal_type_id`，本文档称 **菜品种类**）**不是一回事**。种类只是「按种类取数」的一类视图；「折扣」等视图按别的口径取数，同一个 `view` 参数位即可承载。
> **视图 ≠ 数据字段**：视图由 **ID** 标识（端上回传），其取数参数（种类视图时 = 种类取值 ID）才是底层字段值。
> **与 `attributes` 的关系**：`attributes` 的**描述维度**可**多值、横切**（一道菜可同时是辣、清真、热食），种类是**单值、互斥、全量覆盖**——两者不是一类字段。

**D1 存储形态：单值列 + 系统维度取值字典**

- `dish` 表为 **`meal_type_id`** 单值列（`BIGINT`），存**种类取值 ID**；值域来自**系统维度（菜品种类）** 下的取值（管理端维护，见 [schema/dish_attribute_dimension.md](../../../schema/dish_attribute_dimension.md)）；
- **不建外键**——`meal_type_id` 只是 dish 的一个字段；
- 新增 / 修改种类 → 在**管理后台自助维护**，**免发版**；
- **筛选视图**：文案 / 顺序 / 启停 / **筛选条件 / 排序口径**全部存表 `dish_filter_view`（**纯数据，后台可增删改**）；**所有 tab 平等**（没有 `kind` 分类——是否用到种类，由该视图自己的条件决定）；
- 视图与种类取值**解耦**（多对多）：视图引用它，不派生它。设计真源见 [A6 首页筛选视图管理](../../web/A-主数据维护/A6-首页筛选视图管理.md)。

**D2 视图清单（种子初始：1 默认 + 6 个种类视图）**

| tab 文案 `label` | 初始筛选条件 | 排序 |
|---|---|---|
| 为你推荐 | 无条件（**首个视图**） | `random` 会话种子伪随机 |
| 套餐盖饭 | `mealTypeId = <套餐盖饭取值 ID>` | `random` 会话种子伪随机 |
| 家常小炒 | `mealTypeId = <家常小炒取值 ID>` | `random` |
| 面食粉类 | `mealTypeId = <面食粉类取值 ID>` | `random` |
| 香锅干锅 | `mealTypeId = <香锅干锅取值 ID>` | `random` |
| 风味小吃 | `mealTypeId = <风味小吃取值 ID>` | `random` |
| 汤饮甜品 | `mealTypeId = <汤饮甜品取值 ID>` | `random` |

> 上表是**种子初始值**（落在 `dish_filter_view` 表里，后台可改文案 / 调顺序 / 显隐 / 改条件 / 删视图），不是硬编码清单。
> **「为你推荐」不是种类视图**：它筛选条件为空 + 会话种子伪随机序，是端上不带 `view` 时的**首个视图**；它与其他视图**同等对待**（端上只认 `id` + `label`）。
> **菜品种类的值域** = 系统维度（菜品种类）下的取值集合——后台录入的白名单即取此集合；与视图**解耦**（视图引用它，不派生它）。

**D3 判定口径（后台录入与数据修正的唯一判据）**

> **按「菜名与做法形态」判，不看主料、不看口味。**

| 形态特征 | 归入 |
|---|---|
| 「饭 + 菜成套」（盖饭 / 套餐） | 套餐盖饭 |
| 「炒 / 烧 / 煮 / 宫保 / 鱼香」等家常热菜 | 家常小炒 |
| 「粉 / 面 / 馍 / 拉面」（一碗主食） | 面食粉类 |
| 「干锅 / 香锅 / 麻辣烫 / 冒菜」 | 香锅干锅 |
| 「烧烤 / 点心 / 包子 / 烧卖 / 肠粉 / 炸物」 | 风味小吃 |
| 「粥 / 汤 / 奶茶 / 甜品」 | 汤饮甜品 |

**已定的 5 处边界**：骨汤麻辣烫 → 香锅干锅；冒脑花 → 香锅干锅；香辣虾 → 家常小炒；糖醋里脊 → 家常小炒；烧烤整组（烤五花肉 / 烤茄子 / 羊肉串 / 烤馕 / 烤冷面）→ 风味小吃。

**D4 归属清单（种子 31 道：全量覆盖、无空类）**

| 种类 | 菜品 |
|---|---|
| 套餐盖饭（3） | 黄焖鸡米饭、招牌烤肉饭、咖喱鸡排饭 |
| 家常小炒（9） | 宫保鸡丁、水煮牛肉、回锅肉、番茄炒蛋、土豆烧牛肉、香辣虾、糖醋里脊、鱼香茄子、宫保虾球 |
| 面食粉类（4） | 牛肉拉面、兰州牛肉面、羊肉泡馍、炒粉 |
| 香锅干锅（3） | 干锅花菜、骨汤麻辣烫、冒脑花 |
| 风味小吃（9） | 鲜肉小笼、广式肠粉、烤五花肉、烤茄子、烤冷面、羊肉串、烤馕、鲜虾烧卖、叉烧包 |
| 汤饮甜品（3） | 皮蛋瘦肉粥、珍珠奶茶、杨枝甘露 |

**D5 落地要求**

1. **库**：`dish.meal_type_id` 与种类字典的列定义以 `docs/schema/` 为唯一真源，结构变更**直连远程库执行**；菜品种类赋值见种子数据（D4 表）；
2. **筛选**：`GET /dishes?view=<视图 ID>`，**白名单校验、非法值 400**；种类视图精确等值匹配（单值列 + `idx_dish_meal_type` 索引）；
3. **字典**：只读端点 `GET /dishes/views`，按 `dish_filter_view.order` 升序下发 `[{ id, label }]`；**匹配数为 0 的视图不下发**（避免点进空列表）；不传 `view` 时服务端取**首个启用视图**；
4. **出参**：**公开菜品出参（`DishListItemVO` / `DishDetailVO`）不含种类**（卡片不展示 → 零消费即删）；后台 `DishAdminReq` / `DishAdminVO` 含（录入下拉 + 编辑回填 + 列表筛选）；
5. **端上**：筛选栏 100% 由字典端点直出渲染（端上不前置拼接、**不写任何兜底项**），单选，切换即重置分页；**字典未到位 / 失败 ⇒ 筛选栏整体不渲染**（不留空栏），列表仍按「不传 `view`」→ 首个启用视图加载 —— 标签文案（含「为你推荐」）是**服务端资产**，端上零文案；
6. **种子数据**：珍珠奶茶、杨枝甘露 不标 `rice`（米）属性，避免详情页显示「米」；
7. **合规登记**：种类语义为**单值分类字段**（非多值，与 `attributes` 里可多值的描述维度区分）。
8. **视图维护口径**（见 [A6](../../web/A-主数据维护/A6-首页筛选视图管理.md)）——
   - **改文案 / 调顺序 / 启停 / 改条件 / 新增 / 删除**：后台直接操作，**免发版**（视图是纯数据）；
   - **端上契约恒定**：端上只认 `id` + `label` 并把 `id` 回传为 `view`，故以上任何变更端上零改动。

### E. 首页 Banner 轮播接口化决议

> **UI 细节（16:10 定档、标题带、吸顶范围）以 [`docs/ui/client/`](../../../ui/client/) §1 / §3.3 / §11 为唯一真源。**

| # | 决议 | 说明 / 影响 |
|---|---|---|
| E1 | **Banner 由后端接口下发（`GET /banners`），端上轮播渲染** | 端上**不写死 URL、不排序、不写死张数**；Banner 为**静态运营位**（无推荐算法），本节只做运营位轮播，**不引入个性化推荐** |
| E2 | **首屏结构：Banner 为正常流首块，吸顶容器只含搜索区 + 标签栏** | Banner 整块（含状态栏背后与左上角标题）**随页面滚出即消失**——**不折叠、不定格、不作为吸顶容器背景**；吸顶态顶端**不重复渲染**「知行食记」标题。硬性约束：搜索区 + 标签栏同组吸顶（UI 文档 §13 第 3 条）、「Banner 滚出后不残留图片背景」、「吸顶态不重复渲染标题」 |
| E3 | **宽高比锁定 16:10** | Banner 总高 = 屏宽 × 10/16（375 宽 ≈234px）+ 最小高度兜底（≥ 状态栏 + 标题带 + 运营内容最小可视高 ≈120px）；**素材一律 16:10 出图**（混比例会导致轮播切换时块高抖动、吸顶阈值漂移）；加载中 / 失败使用**同高占位图**。完整论证见 UI 文档 §3.3 |
| E4 | **库：`banner` 表** | 存轮播位素材（图片地址、排序值、启用开关）；`status` 取 `on` / `off`（与 `dish.status` 同风格，仅启用项参与轮播）。落库口径：**以 [`docs/schema/banner.md`](../../../schema/banner.md) 为唯一真源（列定义见该表文档），结构变更直连远程库执行** |
| E5 | **Banner 录入在管理端** | Banner 素材**由管理后台维护**（`/admin/banners`，见 [A5](../../web/A-主数据维护/A5-首页Banner管理.md)）；**小程序端无任何 Banner 写接口**，种子脚本仅作初始素材来源 |
| E6 | **契约红线对齐** | 出参仅 `id`（轮播 key）+ `imageUrl`；`sort_order` / `status` 服务端内部用、不出参；**无跳转字段**（端上零点击交互）；空集合返回 `[]`（非 404 / null）；Banner 请求与菜品列表**并行**、Banner 失败不阻塞首屏；统一响应 `{ code, message, data }` / camelCase / 错误码沿用全站统一口径（`200` / `400` / `401` / `403` / `4001` / `4031` / `500`） |
| E7 | **`GET /dishes` 及 `GET /dishes/views` 契约不受 Banner 模块影响** | Banner 模块只新增一个只读端点与一张表 |
