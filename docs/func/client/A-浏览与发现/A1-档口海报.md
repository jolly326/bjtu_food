# A1 · 档口海报

> 所属端：**学生端（微信小程序）** ｜ 鉴权：🔑 需登录
> 归属：**A 浏览与发现**
> 返回：[功能总览](../README.md)

## 介绍

第一个 tab（**橱窗**）：以**竖版海报**呈现各档口，一屏一张，左右滑动（可回看上一张）。

海报**承载全部信息** —— 档口名称 / 所属食堂 / 位置均在图上，页面**不叠加任何文本**；因此运营出图时必须把这三项画进海报。

> 接口 / 字段见 [`api/client/posters.md`](../../../api/client/posters.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| 取数 | 有海报的档口（一个档口一张海报；**未上传的档口不出现**） |
| 顺序 | **随机** —— 与菜品推荐同款思路（每次请求重掷；一屏一张、用户不遍历全量，故不要求跨页稳定） |
| 滑动 | 左右滑动，连续顺滑；**可回看上一张** |
| 点击 | 无跳转、无点击行为 |
| 顶部问候 | 随时间变化的问候语（早 / 午 / 晚三态），**不含姓名** |
| 海报比例 | **3:4**（竖版；素材一律按此出图） |
| 空集合 | 无任何海报时，页面不渲染海报区 ⏳ |

## 数据（读取）

| 表 | 读什么 | 说明 |
|---|---|---|
| `stall` | 海报图地址（**`poster` 列**，相对路径） | 一档口一张；未上传（`NULL`）的档口不出现在海报页 |
| `canteen` | — | 食堂名由海报图承载，不单独下发 |

## 演进预留

海报顺序**当前为随机**。若商业化需要「商家宣传位」的固定 / 优先顺序，届时为 `stall` 加排序列（如 `poster_sort`），并把排序改为「**按序优先 + 随机兜底**」：

- **端上契约不变** —— `GET /posters` 出参仍是 `[{ id, imageUrl }]`，只是**顺序来源**不同；
- **现在不加列** —— 该列当前零消费方，加了只会成为死字段；届时一次 `ALTER` 即可。

> **做之前须重新拍板**（本节即该能力的登记处）。
