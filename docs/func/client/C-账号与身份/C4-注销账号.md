# C4 · 注销账号

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔑 需登录**（游客态与已认证态均可注销，不要求邮箱认证）
> 归属：**C 账号与身份**
> 返回：[功能总览](../README.md)

## 介绍

用户主动注销当前账号（合规硬需求）。语义为**匿名化，而非物理删除**：身份信息全部清空、账号标记 `deleted`、token 立即失效；**历史评价与反馈保留**（昵称自然变为「已注销用户」，评分聚合不破坏）。流程：点「注销账号」→ 二次确认 → 调 `DELETE /auth/account`（**跳过 401 静默登录重试**：静默登录会建出新游客号，重试会误删新账号）→ 成功后清本地 token 与用户信息（页面回落游客态）；已注销账号重复调用 → 400「账号已注销」（终态保护）。**不可恢复**：注销即解绑 `openid`，同一微信重新登录会创建**全新账号**，旧账号的历史评价 / 反馈保留但**不会归属新账号**；无冷静期、无撤回入口。

> 接口 / 字段见 [api/auth.md](../../../api/client/auth.md)。

**无请求体、无参数**；注销对象 = JWT 中的当前用户，端上**不传 userId**。

## 匿名化清单（**注销 ≠ 删除全部数据**）

不物理删除 `user` 行，而是**匿名化**：

| 变化 | 变为 | 原因 |
|---|---|---|
| 昵称 | `'已注销用户'` | 历史评价 / 反馈经 JOIN 取昵称，自然匿名化 |
| 用户名 | `'deleted_{id}'` | 释放唯一键占用；否则后续建号撞唯一键 |
| 头像 / 邮箱 / 微信标识 / 认证绑定 | 空值 | 清空个人信息；**解绑微信与认证关系**（允许原邮箱再次认证、同一微信重新建号）；空值不占唯一索引 |
| 账号状态 | `'deleted'` | 与登录拦截、UGC 写拦截形成**持久化兜底** |

逐列口径见 [schema/user.md](../../../schema/user.md)。

**其他表的连带变化**

| 表 | 变化 | 原因 |
|---|---|---|
| `email_verification_code` | DELETE（按 `email` 与 `bind_email` 两批） | 避免残留验证码在他端被消费 |
| `notification` | DELETE（按 `user_id`） | 账号维度过程性数据，注销后无读取方，保留即孤儿 |
| `review` / `user_feedback` | **保留** | 内容价值 —— 去身份化展示，**评分聚合不破坏** |
| Token 黑名单 | 拉黑当前 token + 该 userId | 当前请求立即 401；其余设备历史 token 在单实例未重启期间一并失效（内存态，7 天窗口） |

> 通知随注销删除、内容保留 —— 同一注销动作下**两种口径刻意不同**：前者是过程性数据，后者是内容资产。

## ⚠️ 端上必须跳过 401 静默重登

**请求层对本端点禁用 401 自动重试。**

理由：静默登录会为同一微信**建出新账号**，自动重试将误删新建的账号。

## 不可恢复

注销即解绑 `openid`，同一微信重新登录创建**全新账号** —— 历史评价 / 反馈保留但**不归属新账号**。无冷静期、无撤回入口。

## 数据（落库）

见上「副作用」两张表。**注销 ≠ 删除全部数据**：不物理删除 user 行、不删评价 / 反馈（保证口碑数据与评分聚合不被破坏）；系统通知随注销删除。
