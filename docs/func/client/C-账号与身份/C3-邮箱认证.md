# C3 · 邮箱认证

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔓 发码公开 / 核验需登录**
> 归属：**C 账号与身份**
> 返回：[功能总览](../README.md)

## 介绍

用**学号邮箱**（`{学号}@bjtu.edu.cn`）做身份认证，认证通过后解锁 UGC 写操作（写评价、重新评价、删除本人评价）。仅限校内邮箱域名，**无密码、无注册**。流程：跳转**身份认证页**（学号 + 邮箱验证码表单，页面形态见 [docs/ui/client/](../../../ui/client/)）→ 填**学号**（端上自动推导校园邮箱）→ 发码 → 输入验证码核验 → 成功后返回账号信息（`bindEmail` 已写入）；JWT 不含 `bind_email`、后端实时查库判定，**无需重发 token**，返回原页、由原页 onShow 续接待办动作，UGC 入口解锁。**成功提示同时承担资料层引导**（登录与资料两层分离：登录走静默建号，昵称头像属认证后完善能力）→ 提示「认证成功，可到「我的主页」完善昵称头像」；**不跳转、不打断续接**（落点 = 「我的主页」身份卡的「编辑个人信息」入口，该入口仅认证态渲染）。

> 接口 / 字段见 [api/auth.md](../../../api/client/auth.md)。

## 认证流程口径

| 项 | 口径 |
|---|---|
| **邮箱推导** | 端上传**学号**，服务端推导 `{学号}@bjtu.edu.cn` —— 无需、也不接受直接传邮箱 |
| **认证判据** | `bindEmail` 非空即已认证；**不进 JWT**，后端实时查库判定 |
| **换绑后吊销既有 token** | 认证写入后**吊销该 userId 全部既有 token**（换绑改变了账号能力边界，且可能伴随旧账号的数据归属迁移）；端上收到 `401` 后由请求层**自动静默登录换发新 token 并重试一次**，用户无感、续接待办动作不受影响 |
| **返回结构** | 直接返回 `UserInfoVO`（**无 `userInfo` 外层包装**），字段集与 `POST /auth/wechat-login` 严格一致 |
| **成功提示** | 同时承担资料层引导（提示到「我的主页」完善昵称头像）——**不跳转、不打断续接**，由原页 `onShow` 续接待办动作 |
| **续接机制** | 从需认证入口跳入时记录动作，认证成功返回原页后续接；未完成认证离开则清除待办 |

## 账号合并规则

核验通过时，按邮箱命中情况处理：

| 场景 | 处理 | 原因 |
|---|---|---|
| 无历史邮箱绑定 | 直接绑定当前微信账号 | 常见路径 |
| 该邮箱已被**另一个微信**绑定 | **替换绑定**：旧微信 `bind_email=NULL`（回到游客态）；业务数据归属迁移到当前微信 | 避免一人多号数据分裂 |
| 存在历史「邮箱注册账号」 | 归属迁移后把旧账号标记 `deleted` 并释放邮箱唯一键 | 只保留当前微信账号 |

> 归属迁移通过领域事件完成，各域监听器自行清理本域数据，详见各域 feature 的「跨域事件」段。

## 数据（落库）

| 表 / 列 | 变化 | 中文解释 |
|---|---|---|
| `email_verification_code` | INSERT / UPDATE | 写入验证码**哈希**（不存明文）、有效期 **10 分钟**、消费后置时间（**防重复使用**）；列定义见 [schema/email_verification_code.md](../../../schema/email_verification_code.md) |
| `user.bind_email` | → 学号邮箱 | **认证状态唯一真源**（非空即已认证；**不进 JWT**，后端实时查库判定），同时用于「替换绑定」判定 |
