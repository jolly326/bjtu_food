# B2 · 评分反馈

> 所属端：**学生端（微信小程序）** ｜ 鉴权：🔑 需登录
> 归属：**B 轻量反馈**
> 返回：[功能总览](../README.md)

## 介绍

在「记忆」的卡片上**就地评分**：**喜欢 / 一般 / 不喜欢**（三态）。个人感受固定三档；系统把全体投票汇总为**群体风味评级**（S / A / B / C / D 五档），用于美味卡片与记忆卡片的「左上字母 + 右上风味评级」。评分同时是推荐排序的唯一输入（见 [A2](../A-浏览与发现/A2-美味.md) 的加权随机）。

> 接口 / 字段见 [`api/client/records.md`](../../../api/client/records.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| 三态取值 | **喜欢 = `5` ｜ 一般 = `3` ｜ 不喜欢 = `1`**；个人档位**固定 3 级、不增档位** |
| 群体好评度 | `(喜欢×100 + 一般×50 + 不喜欢×0) ÷ 总评价数`，等价于 `(avg_reaction − 1) × 25` |
| 五档评级 | **S** ≥ 85「臻荐」｜ **A** 70 ~ <85「极荐」｜ **B** 60 ~ <70「推荐」｜ **C** 50 ~ <60「尚可」｜ **D** < 50「平实」 |
| 🔴 评级门槛 | **投票人数 ≥ 3 才出等级**；不足 3 人 ⇒「待评」（不出字母） |
| 🔴 文案中性 | 五档只用平缓中性口碑词，**不得出现劝退 / 负面表述**；评级是同学口味口碑汇总，**不是菜品质量或卫生评价** |
| 🔴 零评分 | **存储为 NULL**、展示「待评」；**不得兜底成 5.0** —— 兜底值会让新菜凭空获得高分并污染推荐权重 |
| 粒度 | 🔴 **一人一菜一票** —— 评分真源 = [dish_rating](../../../schema/dish_rating.md)（`UNIQUE(user_id, dish_id)`，一人一菜一行）；改分 = 覆盖本行；**清除评价 = 删行（整体撤票）**；多次品尝共用同一票 |
| 🔴 循环评分 | 同一条记录**可就地改分**：点表情图标按 **未评价 → 喜欢 → 一般 → 不喜欢 → 未评价** 循环；第 4 步写 `reaction = null`（**清除评价**），并同事务重算群体评级 |
| 入口 | **仅「记忆」内的卡片**；已记录可改分 —— 不允许对未点过「去品尝」的菜直接评分 |
| 归属 | 由当前静默识别的用户决定，**禁止信任端上标识** |
| 频控 | 写入口限频（见 [`secur/S-03`](../../../secur/S-03-限频与接口防护.md)） |

> 样例：喜欢 1｜一般 3｜不喜欢 3 ⇒ 好评度 =（100 + 150）÷ 7 ≈ **35.7** ⇒ **D「平实」**。
