# B4 · 我的食谱

> 所属端：**学生端（微信小程序）** ｜ 鉴权：🔑 需登录
> 归属：**B 轻量反馈**
> 返回：[功能总览](../README.md)

## 介绍

第三个 tab（**记忆**）：本人**饮食记录**的清单 —— 按**月份时间线**回看，月内**按日期分组**，每条记录可就地评分、纠错，未评分的还可取消。

它是「去品尝」（[B1](./B1-品尝标记.md)）产生数据的**唯一消费处**：记录只在这里出现，别处看不到。

> 接口 / 字段见 [`api/client/records.md`](../../../api/client/records.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| **入列** | **仅「去品尝」产生的饮食记录** —— 没点过「去品尝」的菜不出现（无论是否浏览过） |
| **日期 / 月份归属** | 按 `wantedAt`（点「去品尝」的时间）分组；同一次品尝的重复评分不改变分组 |
| **月份时间线** | 只列出**有记录的月份**（降序）；某月无记录则不出现在时间线上 |
| **未评分态** | `reaction` 为空的记录呈未评分态，可就地评分（[B2](./B2-评分反馈.md)） |
| **已评态** | 已评分的记录**不可改**；要重新评分须**再次去品尝**（新增一条记录） |
| **取消** | 只有**未评分**记录可取消（从清单移除，物理删行）；已评分不可取消 |
| **纠错** | 卡片可提交菜品纠错（[B3](./B3-菜品纠错.md)） |
| **只读性** | 记录由本人产生，**服务端不代改**；运营端只读（见 [`api/web/records.md`](../../../api/web/records.md)） |
| **归属** | 恒为**当前静默识别的用户**（见 [C1](../C-用户身份/C1-openid%20静默识别.md)）—— 看不到他人的记录 |

## 数据（读取）

| 表 | 读什么 | 说明 |
|---|---|---|
| `dish_record` | 本人全量记录（按 `wantedAt` 降序） | 列定义见 [schema/dish_record.md](../../../schema/dish_record.md) |
| `dish` | 菜名 / 图片 / 风味评级 | 记录里展示的菜品信息**随菜品实时变化**，不留快照；评级由 `avg_reaction` + `reaction_count` 派生（口径见 [B2](./B2-评分反馈.md)） |
| `stall` · `canteen` | 位置（如卡片需要展示） | — |

> **一次请求取全量** —— 记录量级小（用户自己吃过的菜），服务端不做月份筛选，由端上按 `wantedAt` 自行分组（见 [`api/client/records.md`](../../../api/client/records.md)）。
