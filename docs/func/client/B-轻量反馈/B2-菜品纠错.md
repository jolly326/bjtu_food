# B2 · 菜品纠错

> 所属端：**学生端（微信小程序）** ｜ 鉴权：🔑 需登录
> 归属：**B 轻量反馈**
> 返回：[功能总览](../README.md)

## 介绍

在「美食地图」底部弹窗内发现菜品信息有误时提交 —— **只需选一个选项**，无文字、无配图。运营查看后**手动更新菜品信息**；🔴 **不追踪、不通知处理结果**（提交成功仅有本地提示）。

> 接口 / 字段见 [`api/client/issues.md`](../../../api/client/issues.md)。

## 业务规则

| 项 | 口径 |
|---|---|
| 入口 | **「美食地图」底部弹窗**（点磁贴唤起弹窗 → 点击/右滑进入反馈页） |
| 输入 | **只选一个选项**；无文字、无配图 ⇒ **不涉内容安全送检** |
| 选项 | 字典驱动（3 条：信息错误 / 图片不对 / 已停售关闭），端上零硬编码 |
| 归属 | 由当前静默识别的用户决定（见 [C1](../C-用户身份/C1-openid静默识别.md)），**禁止信任端上标识** |
| 提交结果 | 提交即完成 —— **不追踪处理结果、无站内通知**（端上仅提示「已收到反馈」） |
| 去重 | 同一人 + 同一菜 + 同一选项的**未处理**记录至多一条（重复提交幂等复用） |
| 频控 | 写入口限频（见 [`secur/S-03`](../../../secur/S-03-限频与接口防护.md)） |
| 运营侧 | 运营端逐条查看并**手动**修改菜品信息，改完标记已处理 |

## 数据（读写）

| 表 | 变化 | 说明 |
|---|---|---|
| `dish_issue` | INSERT | 一条提交事实；列定义见 [schema/dish_issue.md](../../../schema/dish_issue.md) |
| `dish_issue_option` | SELECT | 选项字典（按 `id` 升序；本字典无启停位） |
