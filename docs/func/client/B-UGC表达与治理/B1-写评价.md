# B1 · 写评价

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔐 认证**（需学号邮箱认证）
> 归属：**B UGC 表达与治理**
> 返回：[功能总览](../README.md)

## 介绍

给一道菜打星 + 写文字 + 最多 3 张配图。**先发后审**：文本与图片通过微信内容安全检测即**立即公开**，无人工复核；后续如被举报，由管理员事后处置。

**提交是单一动作**：恒 `POST /dishes/{id}/reviews`。每人对同一菜品仅一条评价（唯一键 `uk_review_user_dish`）——未评价时新建；已评价时由服务端**覆盖同一行**（评分 / 文字 / 配图整体重写）。端上不区分首评 / 重评：**无「写前判定」、无「重新评价」双态**，详情页不预填旧值，点「写评价」恒打开空表单（页面形态见 `docs/ui/client/`）。提交流程：选星级（1~5 必填）→ 文字（可跳过）→ 配图（≤3 张，逐张压缩上传取 COS URL 后随评价提交）；检测不通过则提示错误、不发布。

> 接口 / 字段见 [api/dishes.md](../../../api/client/dishes.md) · [api/upload.md](../../../api/client/upload.md)。

**归属由 token 锁定当前登录用户**（**禁止信任前端**），路径 `{id}` 决定菜品，不可换菜。

## 提交口径

| 项 | 口径 |
|---|---|
| **先发后审** | 文本与图片通过内容安检即**立即公开**，无人工复核；后续如被举报由管理员事后处置 |
| **单一动作** | 恒 `POST`，端上**不区分首评 / 重评**：无「写前判定」、无覆盖提示，详情页不预填旧值 |
| **文字可选** | 可只打星不写文字（`content` 非必填） |
| **端上后续动作** | 提交成功**无须回读**，重拉评价列表即可 |

### 重复提交的覆盖语义

| 项 | 口径 |
|---|---|
| 落库 | **覆盖更新同一行**（非删行重建），唯一键不变、旧内容不留残留 |
| `created_at` | **保留原值**（不刷新）—— 🔴 首次评价时间即该评价的固定位置，**反复修改无法把自己刷到列表顶部** |
| `is_hidden` | **重置为 0**（重新评价即恢复可见） |
| 次数 | **不限次** —— `created_at` 保留原值，改评价不会置顶，故**提交不限次、不设限频** |

> 覆盖路径与首次提交**逻辑完全相同**：安检口径、配图规格、4031 分流、评分聚合事件均一致。

### 内容安全（提交闸门，不落库）

| 环节 | 判定 |
|---|---|
| 文本 `msgSecCheck` v2（`scene=2`） | `pass` / `review` → **放行**；`risky`（含未知 / 缺失态）→ **400 拦截、不落库** |
| 图片 `imgSecCheck` | 违规（`87014`）→ 400；**单张失败只跳过该张**，不中断其余图片 |

> 内容安全检测即终局，**无人工复核**：命中拦截即 400，不存在「先入库、后人工复审」的中间态。
> 四条 UGC 写链路（写评价 / 意见反馈 / 菜品问题反馈 / 图片上传）**全部**经后端送检，端上不做本地预检，
> 也无任何一条链路绕过 —— 送检口径统一收敛在服务端（见 [api/](../../../api/client/) 各端点契约）。

## 数据（落库）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `review` | **INSERT**（未评价）/ **UPDATE**（已评价覆盖同一行） | 归属**当前登录用户**（**禁止信任前端**）与所评菜品；覆盖时重写评分 / 文字 / 配图，`created_at` **保留原值**、隐藏态重置为可见；列定义见 [schema/review.md](../../../schema/review.md) |
| 菜品评分聚合缓存列 | **提交后同步** UPDATE | 通过 `ReviewSubmittedEvent` → `RatingUpdateListener`（AFTER_COMMIT）在提交响应返回前重算评分聚合；**口径：仅计未隐藏的评价**；列定义见 [schema/dish.md](../../../schema/dish.md) |

## 跨域事件

本功能涉及的领域事件及其在本域的订阅行为。

| 事件 | 发布方 | 本域订阅行为 |
|---|---|---|
| `ReviewSubmittedEvent` | review（评价提交 / 更新 / 删除 / 隐藏） | **重算**菜品评分聚合（`avg_rating` / `rating_count`） |

> 监听器为 `@TransactionalEventListener(AFTER_COMMIT)` —— 事务提交后**同步重算**（提交响应返回前完成），保证提交者本人立即读到新值。
> **失败仅告警、不回滚主链路**：聚合异常不阻断用户提交评价。
> 因聚合列是缓存列，另由每日定时对账任务兜底（见 [schema/dish.md](../../../schema/dish.md#派生与缓存列)）。
