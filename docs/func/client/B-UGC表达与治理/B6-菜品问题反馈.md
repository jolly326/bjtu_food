# B6 · 菜品问题反馈

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔑 需登录**（免邮箱认证）
> 归属：**B UGC 表达与治理**
> 返回：[功能总览](../README.md)

> 流程：**唯一入口**（详情页「菜品有问题?」）→ 跳转**独立页面** → **先选问题类型** → 表单随类型切换 → 提交。
> 依据：菜品问题反馈是内容供给与维护闭环的一环（用户对库内菜品有疑问时的主要上报入口）。

## 介绍

用户浏览菜品时发现问题，从**菜品详情页信息卡名称行「菜品有问题?」**进入本功能（导航参数携带 `dishId`，进页即**预绑定该菜品、表单内不允许切换**），**先选择问题类型**再提交：

| 类型 | 语义 | 表单 |
|---|---|---|
| **信息有误**（`field`） | 这道菜**存在**，只是资料写错了（菜名 / 价格 / 食堂 / 楼层 / 档口 / 口味 / 配图） | 字段全部预填，**只改错的地方** |
| **已经下架**（`gone`） | 这道菜**消失了** | 一键提交即可成立；说明与图片为**可选补充** |

- **入口唯一**：菜品详情页信息卡名称行「**菜品有问题?**」（携带当前菜品 ID）；「意见反馈」页**不提供**该入口，也不提供任何跨菜品的问题表单；
  - 标签取「**菜品有问题?**」—— 同时涵盖「信息有误」与「已经下架」两类；
- **只改差异项**（`field` 型）：字段全部预填，**只提交改动过的项**，未改动的不上传；
- **`gone` 型零成本**：**不填任何内容也能提交**；「补充说明」（≤200 字）与「图片」（≤3 张）为**折叠的选填项**，默认不展开；
- **预填未完成禁止提交**（`field` 型）；**无改动时禁用提交**；字段错误 = 错误边框 + 行内文案 + 首错定位；
- 图片上限：`field` 型 **≤3 张**（预填详情图片数组，可增删 / 替换；**与菜品图集上限一致**，避免"改动即截短"）；`gone` 型 **≤3 张**（选填）；
- **不暗示提交即生效**：`field` 型由管理员采纳后更新资料；`gone` 型由管理员**人工决定**是否下架（**系统不自动下架**）；
- 处理结果经站内通知回执（**登录级，含游客**）。

## 交互流程（对齐美团「报错」模型）

```
菜品详情页 · 信息卡名称行「菜品有问题?」
        ↓（携带 dishId）
┌─────────────────────────────────┐
│  菜品问题反馈                     │
│  ① 先选类型（单选）              │
│    ○ 信息有误                    │
│    ● 已经下架                    │
│  ② 表单随类型切换                │
│        [ 提交 ]                  │
└─────────────────────────────────┘
        ↓
POST /dishes/{id}/correction  { type, ... }
```

### `gone` 型（已经下架）的界面

```
┌─────────────────────────────────┐
│  这道菜已经没了吗？               │
│       [ 确认提交 ]               │  ← 不填任何内容，直接可点
│  ▸ 补充说明（选填）               │  ← 折叠，≤200 字
│  ▸ 添加图片（选填，≤3 张）        │  ← 折叠
└─────────────────────────────────┘
```

> 提交按钮**恒可用** —— 补充区不是必填项。这是本功能的**核心成本约束**：
> 用户是「**事实校对员**」而非「内容生产者」，一旦要求填表，提交量将大幅下降。

> 接口 / 字段见 [api/dishes.md](../../../api/client/dishes.md)。

> `gone` 型**不需要预填详情**（无需调详情接口）—— 这也是它成本低的原因之一。

## 反馈口径

| 项 | 口径 |
|---|---|
| **入口唯一** | 菜品详情页信息卡名称行「**菜品有问题?**」（携带 `dishId`）；**意见反馈页不提供**该入口，也不提供跨菜品表单 |
| **菜品锁定** | 进页即**预绑定**该菜品，表单内**不允许切换** |
| **类型先行** | 进页**先选类型**（单选），表单随类型切换 |
| **局部提交**（`field`） | 字段全部预填，**只提交改动过的项**；未改动的不上传 |
| **提交门禁**（`field`） | 预填未完成**禁止提交**；**无改动时禁用提交** |
| **一键提交**（`gone`） | **提交恒可用**；补充说明 / 图片均为**选填** |
| **不暗示即生效** | `field` 由管理员采纳后更新资料；`gone` 由管理员人工决定是否下架 |
| **鉴权级别** | **需登录**（🔑）—— 写请求必须绑定账号，不要求邮箱认证 |
| **回执投递** | 登录级 —— 游客与登录用户同样收到处理回执 |

### 关键边界

| 项 | 口径 |
|---|---|
| **🔴 `gone` 与「删除」无关** | 管理端处置 `gone` 反馈**只能「下架」**（`status=off`，**可重新上架**，评价保留）；**删除是物理删除且级联删除评价**，仅在 [A3 菜品管理](../../web/A-主数据维护/A3-菜品管理.md) 由管理员主动执行 |
| **`gone` 型不提交差异项** | 端上**不展示**名称 / 价格 / 食堂 / 档口 / 楼层 / 口味字段（服务端亦 `400` 拒绝）—— 那些表达的是「菜存在但写错了」，与「菜消失了」语义冲突 |
| **重复反馈** | 同一用户对同一菜品的 `gone` 型**只计一次**（重复提交成功但不重复计数）；`field` 型不去重 |
| **楼层归属档口**（`field`） | `floor` 采纳时写回**目标档口**的 `stall.floor` —— **同档口其他菜品一并生效**。目标档口解析：`stallName` 改动则用新档口，未改动则用该菜当前所属档口 |
| **楼层取值（受控字典）**（`field`） | `floor` 为**受控字典**：`负一层` / `一层` / `二层` / `三层` / `四层`（真源见 [schema/stall.md](../../../schema/stall.md)）。端上以**固定字典底部单选**呈现，**显示与提交都是同一个汉字**（**零映射**）；**端上不得自由输入楼层**。字典变更规则见 schema/stall.md |
| **不纠正原价** | 原价随促销波动、属运营口径，短期打折不构成稳定事实；**只菜品问题反馈现价** |
| **属性候选仅供参考**（`field`） | 候选来自**取值字典**；**端上恒允许输入候选之外的新值** —— 新值**不立即入库**，仅在反馈**被采纳**时登记进字典。候选接口失败**静默**，仍可自由填写 |
| **不做推送** | 回执**仅站内通知中心**，**不接微信推送**（现行平台边界） |

## 数据（落库）

| 表 | 操作 | 说明 |
|---|---|---|
| `dish_correction` | INSERT | **两类共用**：`field` 型存**改动项快照**（仅存改动的项，未改动留空）+ 动态属性；`gone` 型各差异项**恒空**，仅存备注（≤200 字，选填）+ 配图（≤3 张，选填）。共同：类型 + 菜品 + 归属用户（**匿名为 `0`**）+ 初始状态待处理；列定义见 [schema/dish_correction.md](../../../schema/dish_correction.md) |
| `dish` | 读 / 写 | `gone` 处置时把菜品**下架**（可逆）；**绝不联动删除**；列定义见 [schema/dish.md](../../../schema/dish.md) |
| `stall` | 读 / 写 | `field` 采纳时解析归属档口（两段式）；楼层改动则写回该档口楼层；列定义见 [schema/stall.md](../../../schema/stall.md) |
| `dish_attribute_dimension` | 读 | 动态属性维度定义（渲染表单的维度名 / 单多选）；列定义见 [schema/dish_attribute_dimension.md](../../../schema/dish_attribute_dimension.md) |
| `dish_attribute_value` | 读 / 写 | 取值字典：**编辑候选来源**；`field` **被采纳时**按中文登记新值（命中即用、未命中新建）；列定义见 [schema/dish_attribute_value.md](../../../schema/dish_attribute_value.md) |

> **属性模型（动态属性 + 取值字典）**：
> · 维度定义（`dish_attribute_dimension`）：维度 ID / 中文名 / 单选或全选 / 展示顺序（列定义见 [schema/dish_attribute_dimension.md](../../../schema/dish_attribute_dimension.md)）；
> · 取值字典（`dish_attribute_value`）：某维度下的可选值；**菜品存取值 ID**，出参时服务端翻译为中文（列定义见 [schema/dish_attribute_value.md](../../../schema/dish_attribute_value.md)）；
> · 用户**可自由输入字典之外的新值**，但**提交反馈不写库** —— 仅在该反馈**被采纳**时按中文登记（命中即用，未命中新建）；
> · 菜品属性值存 `dish.attributes`（JSON）：键 = **维度 ID**（JSON 内为字符串形态），值 = **取值 ID**（`single` 为数字 / `multi` 为数字数组）；仅含该菜实际拥有的维度；
> · **R13**：`attributes` 的键 MUST 等于维度 ID（后端据此拼装 `GET /dishes/{id}` 的属性展示、并解析编辑项）。
> · **扩展路径**：新增维度 = 插 `dish_attribute_dimension` 一行，**免 ALTER、免发版**；新增取值 = 录入 / 采纳时输入新值即可（**自动登记**）。
