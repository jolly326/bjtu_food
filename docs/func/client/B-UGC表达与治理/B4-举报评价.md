# B4 · 举报评价

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔑 需登录**（静默登录后即可提交，无需邮箱认证）
> 归属：**B UGC 表达与治理**
> 返回：[功能总览](../README.md)

## 介绍

举报违规评价，交给管理员处置（受理可联动隐藏被举报评价）。举报是**独立资源**（不与意见反馈混存），流程：评价卡三点菜单「举报评价」→ **底部弹出原因单选弹层**（选项实时取自后端字典，端上零硬编码）→ 点选原因 → 提交；成功后提示处理预期，管理员处置后举报人收到站内回执（**登录级，含游客**）。**不填写任何文本、不传配图**——举报结论以**结构化原因单选**为准，管理员据此直接处置；需要补充说明的场景走 [B5 意见反馈](./B5-意见反馈.md)。

> 接口 / 字段见 [api/reviews.md](../../../api/client/reviews.md)。

## 业务口径

| 项 | 口径 |
|---|---|
| **不要求文本 / 配图** | 举报结论以**结构化原因**（字典 `optionId` 单选）为准；请求体**只有原因一项**，被举报对象由路径 `{id}` 表达 |
| **原因字典** | 选项**实时取自后端字典**（`GET /report-options`，仅启用项、按 `id` 升序），端上**零硬编码**、不排序（展示顺序即服务端下发次序）；提交上送 `optionId` |
| **目标必须公开可见** | 已隐藏 / 已删除的评价对外等价于不存在 ⇒ 提交举报返回 `4001` |
| **重复举报去重** | 同一登录用户对同一评价**不重复举报**（服务端查重后 `400`） |
| **鉴权级别** | **需登录**（🔑）—— 写请求必须绑定账号，不要求邮箱认证 |
| **回执投递** | 提交入口**恒需登录**（`user_id` 恒为真实用户）⇒ **一律投递**（静默登录的游客同样收到处理回执） |
| **不做推送** | 回执**仅站内通知中心**（见 [D1 系统通知](../D-系统与合规/D1-系统通知.md)） |

## 数据（读写）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `report` | INSERT | 一条举报记录：举报人（**恒为真实登录用户**）、被举报评价 ID、举报原因字典项；**只存提交事实**，无状态列；列定义见 [schema/report.md](../../../schema/report.md) |
| `moderation_task` | INSERT（提交**同一事务**预建） | 预建 `pending` 处置任务行（多态键 `type='report'`）——「未处置」是显式行；列定义见 [schema/moderation_task.md](../../../schema/moderation_task.md) |
| `notification` | INSERT（管理员**处置时**） | 处置回执（`reply_title` / `reply_content` 快照，与处置**同一事务**写入，**恒投递**）；列定义见 [schema/notification.md](../../../schema/notification.md) |

> **被举报评价被删除**时，举报行**保留**（`report.review_id` 置空）、处置任务行同样保留——举报人的诉求与处置结论不因评价删除而消失。
