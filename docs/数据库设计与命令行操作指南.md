# 数据库设计与字段说明文档

> 项目：校园食堂信息系统 - 食在交大  
> 数据库：MySQL 8.0  
> 数据库名：`bjtu_food`  
> 基础脚本：`docs/bjtu_food_base.sql`

本文档用于说明当前数据库中每张表的业务作用、字段含义和常用操作。当前系统只有两类用户身份：普通用户 `user` 和管理员 `admin`。注册时必须通过校园邮箱验证码绑定邮箱，并设置登录密码；登录时支持密码登录和邮箱验证码登录。

---

## 1. 总体关系

系统围绕“食堂 - 档口 - 菜品 - 用户互动”设计。

```text
canteen 1 -- N stall 1 -- N dish
user    1 -- N favorite N -- 1 dish
user    1 -- N review   N -- 1 dish
user    1 -- N item_list 1 -- N list_item N -- 1 dish
banner  N -- 1 canteen
email_verification_code 用于记录邮箱验证码
```

通用约定：

- 所有 `id` 都是自增主键。
- `created_at` 表示创建时间。
- `updated_at` 表示最近更新时间。
- `images` 字段保存 JSON 字符串，例如 `["/images/seed/dishes/tomato-egg.jpg"]`。
- 菜品价格统一用“分”存储，例如 `1200` 表示 12 元，避免小数精度问题。

## 2. 表字段说明

## 2.1 `user` 用户表

用途：保存普通用户和管理员账号。用户注册时需要绑定校园邮箱并设置密码，后续可以通过密码或邮箱验证码登录。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 用户唯一编号。其他表通过 `user_id` 关联它。 |
| `username` | VARCHAR(50) | 是 | 无 | 用户名，通常可保存学号或工号，例如 `20240001`。 |
| `email` | VARCHAR(100) | 是 | 无 | 校园邮箱，注册和登录的核心凭证，必须唯一。 |
| `password` | VARCHAR(255) | 是 | 无 | BCrypt 加密后的密码哈希，用于密码登录。数据库中不保存明文密码。 |
| `nickname` | VARCHAR(50) | 是 | 空字符串 | 用户昵称，用于个人中心、评价列表展示。 |
| `avatar` | VARCHAR(255) | 否 | NULL | 用户头像地址。 |
| `role` | VARCHAR(20) | 是 | `user` | 用户身份。`user` 表示普通用户，`admin` 表示管理员。 |
| `status` | VARCHAR(20) | 是 | `active` | 账号状态。`active` 可正常使用，`disabled` 表示被禁用。 |
| `created_at` | DATETIME | 是 | 当前时间 | 用户创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 用户资料最近更新时间。 |
| `last_login_at` | DATETIME | 否 | NULL | 最近一次登录时间，登录成功后更新。 |

重要约束：

```sql
UNIQUE KEY uk_user_username (username);
UNIQUE KEY uk_user_email (email);
```

角色说明：

| role | 说明 |
|---|---|
| `user` | 普通用户，可以浏览菜品、收藏、评价、创建清单。 |
| `admin` | 管理员，可以进入浏览器管理端，维护食堂、档口、菜品、用户和评价。 |

常用查询：

```sql
SELECT id, username, email, nickname, role, status, last_login_at
FROM `user`;
```

## 2.2 `email_verification_code` 邮箱验证码表

用途：保存邮箱验证码记录，用于注册校验和验证码登录校验。验证码不建议明文长期保存，后端当前会保存 BCrypt 哈希。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 验证码记录编号。 |
| `email` | VARCHAR(100) | 是 | 无 | 接收验证码的校园邮箱。 |
| `code_hash` | VARCHAR(255) | 是 | 无 | 验证码哈希值。后端使用 BCrypt 保存验证码，不保存明文验证码。 |
| `purpose` | VARCHAR(30) | 是 | `login` | 验证码用途。常用值：`login`、`register`。 |
| `expires_at` | DATETIME | 是 | 无 | 过期时间，超过该时间验证码无效。 |
| `used_at` | DATETIME | 否 | NULL | 使用时间。为空表示尚未使用，非空表示验证码已被消费。 |
| `created_at` | DATETIME | 是 | 当前时间 | 验证码创建时间。 |

业务规则：

- 注册时使用 `purpose = 'register'`。
- 登录时使用 `purpose = 'login'`。
- 同一个验证码成功使用后会写入 `used_at`，避免重复使用。
- 后端只接受 `@bjtu.edu.cn` 校园邮箱。

常用查询：

```sql
SELECT id, email, purpose, expires_at, used_at, created_at
FROM email_verification_code
ORDER BY created_at DESC;
```

## 2.3 `canteen` 食堂表

用途：保存食堂级别的信息，一个食堂下面可以有多个档口。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 食堂唯一编号。 |
| `name` | VARCHAR(100) | 是 | 无 | 食堂名称，例如“明湖餐厅”。 |
| `location` | VARCHAR(255) | 否 | NULL | 食堂位置描述。 |
| `description` | TEXT | 否 | NULL | 食堂简介、备注或数据来源说明。 |
| `sort_order` | INT | 是 | 0 | 展示排序值，数字越小越靠前。 |
| `status` | VARCHAR(20) | 是 | `open` | 食堂状态。`open` 表示开放，`closed` 表示关闭。 |
| `created_at` | DATETIME | 是 | 当前时间 | 创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 更新时间。 |
| `images` | TEXT | 否 | NULL | 食堂图片列表，JSON 字符串。 |

常用查询：

```sql
SELECT id, name, location, status
FROM canteen
ORDER BY sort_order;
```

## 2.4 `stall` 档口表

用途：保存食堂下的档口、窗口、楼层或区域信息。一个档口属于一个食堂，一个档口下面可以有多个菜品。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 档口唯一编号。 |
| `canteen_id` | BIGINT | 是 | 无 | 所属食堂 ID，关联 `canteen.id`。 |
| `name` | VARCHAR(100) | 是 | 无 | 档口名称。 |
| `location` | VARCHAR(255) | 否 | NULL | 档口位置，例如“一层”“二层”。 |
| `description` | TEXT | 否 | NULL | 档口简介。 |
| `avg_rating` | DECIMAL(2,1) | 是 | 0.0 | 档口平均评分，通常可由菜品评分汇总得到。 |
| `sort_order` | INT | 是 | 0 | 同一食堂下的展示排序。 |
| `status` | VARCHAR(20) | 是 | `open` | 档口状态。`open` 开放，`closed` 关闭。 |
| `created_at` | DATETIME | 是 | 当前时间 | 创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 更新时间。 |
| `images` | TEXT | 否 | NULL | 档口图片列表，JSON 字符串。 |

外键：

```sql
FOREIGN KEY (canteen_id) REFERENCES canteen(id);
```

## 2.5 `dish` 菜品表

用途：保存菜品信息，是系统展示、搜索、评价、收藏的核心表。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 菜品唯一编号。 |
| `stall_id` | BIGINT | 是 | 无 | 所属档口 ID，关联 `stall.id`。 |
| `name` | VARCHAR(100) | 是 | 无 | 菜品名称。 |
| `price` | INT | 是 | 0 | 菜品价格，单位为分。 |
| `tags` | VARCHAR(255) | 是 | 空字符串 | 菜品标签，多个标签用英文逗号分隔。 |
| `description` | TEXT | 否 | NULL | 菜品描述、推荐理由或数据来源说明。 |
| `avg_rating` | DECIMAL(2,1) | 是 | 0.0 | 平均评分，由评价数据计算。 |
| `rating_count` | INT | 是 | 0 | 评价数量。 |
| `favorite_count` | INT | 是 | 0 | 收藏数量。 |
| `view_count` | INT | 是 | 0 | 浏览数量。 |
| `status` | VARCHAR(20) | 是 | `on` | 菜品状态。`on` 上架，`off` 下架。 |
| `created_at` | DATETIME | 是 | 当前时间 | 创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 更新时间。 |
| `images` | TEXT | 否 | NULL | 菜品图片列表，JSON 字符串。 |

常用标签：

| 标签 | 说明 |
|---|---|
| `recommended` | 推荐菜品 |
| `signature` | 招牌菜 |
| `daily` | 日常套餐 |
| `halal` | 清真 |
| `spicy` | 辣味 |
| `western` | 西式 |
| `vegetarian` | 素菜 |

常用查询：

```sql
SELECT d.id, d.name, d.price, d.avg_rating, d.favorite_count,
       s.name AS stall_name, c.name AS canteen_name
FROM dish d
JOIN stall s ON d.stall_id = s.id
JOIN canteen c ON s.canteen_id = c.id
WHERE d.status = 'on'
ORDER BY d.favorite_count DESC;
```

## 2.6 `favorite` 收藏表

用途：记录用户收藏了哪些菜品。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 收藏记录编号。 |
| `user_id` | BIGINT | 是 | 无 | 用户 ID，关联 `user.id`。 |
| `dish_id` | BIGINT | 是 | 无 | 菜品 ID，关联 `dish.id`。 |
| `created_at` | DATETIME | 是 | 当前时间 | 收藏时间。 |

唯一约束：

```sql
UNIQUE KEY uk_favorite_user_dish (user_id, dish_id);
```

作用：同一个用户对同一道菜只能收藏一次，后端“收藏/取消收藏”接口可以基于它实现幂等逻辑。

## 2.7 `review` 评价表

用途：记录用户对菜品的评分、文字评价和现场图片。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 评价编号。 |
| `user_id` | BIGINT | 是 | 无 | 评价用户 ID，关联 `user.id`。 |
| `dish_id` | BIGINT | 是 | 无 | 被评价菜品 ID，关联 `dish.id`。 |
| `rating` | TINYINT | 是 | 无 | 星级评分，建议范围为 1-5。 |
| `content` | TEXT | 否 | NULL | 评价文字内容。 |
| `images` | TEXT | 否 | NULL | 评价图片列表，JSON 字符串。 |
| `is_hidden` | TINYINT | 是 | 0 | 管理员是否隐藏该评价。`0` 显示，`1` 隐藏。 |
| `created_at` | DATETIME | 是 | 当前时间 | 评价创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 评价更新时间。 |

唯一约束：

```sql
UNIQUE KEY uk_review_user_dish (user_id, dish_id);
```

作用：同一个用户对同一道菜只能保留一条评价。用户修改评价时应更新原记录，而不是重复插入。

## 2.8 `item_list` 美食清单表

用途：保存用户创建的美食清单。一个清单可以包含多道菜。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 清单编号。 |
| `user_id` | BIGINT | 是 | 无 | 创建清单的用户 ID，关联 `user.id`。 |
| `name` | VARCHAR(100) | 是 | 无 | 清单名称，例如“期末复习夜宵清单”。 |
| `description` | TEXT | 否 | NULL | 清单描述，可用于备注推荐理由。 |
| `share_token` | VARCHAR(64) | 是 | 无 | 分享令牌，用于无需登录查看分享清单。 |
| `created_at` | DATETIME | 是 | 当前时间 | 创建时间。 |
| `updated_at` | DATETIME | 是 | 当前时间 | 更新时间。 |

唯一约束：

```sql
UNIQUE KEY uk_item_list_share_token (share_token);
```

作用：保证每个分享链接唯一。

## 2.9 `list_item` 清单菜品关联表

用途：保存某个美食清单里包含哪些菜品。

| 字段 | 类型 | 必填 | 默认值 | 作用 |
|---|---|---:|---|---|
| `id` | BIGINT | 是 | 自增 | 清单项编号。 |
| `list_id` | BIGINT | 是 | 无 | 清单 ID，关联 `item_list.id`。 |
| `dish_id` | BIGINT | 是 | 无 | 菜品 ID，关联 `dish.id`。 |
| `created_at` | DATETIME | 是 | 当前时间 | 加入清单的时间。 |

唯一约束：

```sql
UNIQUE KEY uk_list_item_list_dish (list_id, dish_id);
```

作用：同一个清单中同一道菜只能出现一次。

外键中的 `ON DELETE CASCADE`：

```sql
FOREIGN KEY (list_id) REFERENCES item_list(id) ON DELETE CASCADE;
```

含义：删除清单时，清单里的菜品关联记录会自动删除。

## 3.5 验证码测试与排障

正常测试应调用 `/auth/email-code`，由后端通过 SMTP 向校园邮箱发送验证码。只有在排查数据库或接口逻辑时，才建议手动插入验证码记录。

注意：正式流程不保存明文验证码。下面示例中的哈希对应测试验证码 `123456`。

```sql
INSERT INTO email_verification_code
    (email, code_hash, purpose, expires_at)
VALUES
    ('20240001@bjtu.edu.cn', '$2a$10$PKDZfcJPBEtOqeSSsnEgruL9EEGiBZUzfhhv.8T82Y8iRw5Om03Ue', 'login', DATE_ADD(NOW(), INTERVAL 10 MINUTE));
```

然后接口登录时提交：

```json
{
  "email": "20240001@bjtu.edu.cn",
  "code": "123456"
}
```

正式环境应通过邮件发送验证码，并保存验证码哈希。

## 4. 数据维护建议

1. 修改数据前先 `SELECT` 查清目标记录。
2. 删除菜品前先确认是否存在收藏、评价、清单关联。
3. 不要随意执行 `DROP TABLE` 或 `TRUNCATE TABLE`。
4. 线上数据库重建前必须先备份。
5. 用户角色只使用 `user` 和 `admin`，不要再写入 `student`、`canteen_admin`、`sys_admin`。
6. 当前登录支持两种方式：`account + password` 密码登录，或 `email + code` 验证码登录。
