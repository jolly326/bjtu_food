# A. 学生端（微信小程序）

## A-01 微信静默登录 / 游客态 🔓

- **干什么**：打开小程序即用，无需注册。微信静默换取身份；未认证 = 游客（可看可搜，不可写评价/点赞）。
- **UI**：全局（无登录页）。未认证点「写评价/有用」弹出 `AuthSheet` 引导去认证。
- **操作**：打开即自动登录，无感知。
- **接口**：`POST /auth/wechat-login`（openid 换 JWT）
- **数据**：`user`（username=`wx_+openid尾16位`、nickname、avatar、verified）；JWT 仅含 userId（无角色字段）。

## A-02 首页菜品浏览 🔓

- **干什么**：看今天有什么可吃：菜品卡片流（图/名/价/评分/位置/标签）。
- **UI**：TabBar「首页」→ `pages/home/index`。筛选条：**食堂 / 价格 / 辣度**；首次进入一次性定位提示（用于距离排序）。
- **操作**：滚动浏览 → 点筛选选食堂/价格区间/辣度 → 点卡片进详情。
- **接口**：`GET /dishes`（keyword / status='on' / canteen / price / spice / tags 筛选 + 排序）
- **数据**：读 `dish`（name/price/images/avg_rating/rating_count/tags/spice_level/status）+ `stall`/`canteen`（归属与位置）。

## A-03 搜索 🔓

- **干什么**：按关键词找菜。
- **UI**：首页搜索入口 → `pages/find/index`（搜索框 + 结果列表 `FindResults`）。
- **操作**：输入关键词（命中**菜名或别名**）→ 结果列表点卡片进详情。
- **接口**：`GET /dishes?keyword=…`
- **数据**：读 `dish.name` / `dish.alias`（管理员配置的搜索别名）。

## A-04 菜品详情 🔓

- **干什么**：看一道菜的完整信息与评价。
- **UI**：`pages/detail/dish/index`：图片轮播 + 信息卡（名/价/原价划线/描述/辣度/食堂·档口·位置）+ 评价区。
- **操作**：看图看评 → 评价区「写评价」→ 评价卡三点菜单「举报」。
- **接口**：`GET /dishes/{id}`；`GET /reviews?dishId=…`
- **数据**：读 `dish` 全字段；读 `review`（仅 `is_hidden=0`）+ `review_useful`（有用数）。

## A-05 浏览计数 🔓（自动）

- **干什么**：统计菜品热度（同一用户当日只计一次）。
- **UI**：无（进详情页自动触发）。
- **操作**：无需操作。
- **接口**：`POST /dishes/{id}/view`
- **数据**：写 `dish.view_count`；写 `view_log`（当日去重判据 `updated_at`）。

## A-06 写评价 🔐

- **干什么**：给菜品打星 + 文字 + 最多 3 张配图。**先发后审**：文本+图片通过微信内容安全检测即公开。
- **UI**：菜品详情评价区「写评价」→ `ReviewComposer` 底部弹层（星级 + 文字 + 配图，`ImagePicker` 自动压缩）。
- **操作**：选星 → 输文字（可跳过）→ 加图（可选）→ 提交。检测不通过 = 报错提示；通过 = 立即出现在评价区。
- **接口**：`POST /reviews`（认证；risky → 400）
- **数据**：写 `review`（rating/content/images）；异步维护 `dish.avg_rating/rating_count`。

## A-07 评价「有用」🔐

- **干什么**：给别人的评价点「有用」，帮后来者排序。
- **UI**：评价卡「有用」按钮（带计数）。
- **操作**：点一下切换（再点取消）。未认证 → 弹 AuthSheet。
- **接口**：`POST /reviews/{id}/useful`
- **数据**：写 `review_useful`（一人一评一票，唯一索引）；异步维护 `review.useful_count`。

## A-08 删除本人评价 🔐

- **干什么**：删掉自己写的评价（评分随之重算）。
- **UI**：「我的评价」列表行内「删除」，或菜品详情本人评价卡。
- **操作**：点删除 → 二次确认 → 消失。
- **接口**：`DELETE /reviews/{id}`（仅本人）
- **数据**：删 `review` 行；异步重算 `dish.avg_rating/rating_count`；删 `review_useful` 关联。

## A-09 举报评价 🔓

- **干什么**：举报违规评价，交给管理员处置。
- **UI**：菜品详情评价卡三点菜单「举报」→ `ReportModal` 弹窗（填理由）。
- **操作**：填理由 → 提交 → 提示「48 小时内处理」。
- **接口**：`POST /feedback`（`type=report`，`relatedType=review`，免认证）
- **数据**：写 `user_feedback`（type/sub/content/related_type/related_id）。

## A-10 我的评价 🔐

- **干什么**：看自己发过的全部评价（含被隐藏的，会标「已被隐藏」）。
- **UI**：「我的」宫格「我的评价」→ `pages/my-reviews/index`。
- **操作**：浏览 / 删除。
- **接口**：`GET /my/reviews`（本人视角不过滤 is_hidden）
- **数据**：读 `review`（本人全部）。

## A-11 意见反馈 🔓（建议 / 投稿 / 纠错）

- **干什么**：对菜品的一切诉求。三类：**提个想法**（suggestion，二级：想法/问题）、**推荐菜品**（add，投稿）、**信息不对**（error，纠错/下架，关联菜品）。
- **UI**：「我的」宫格「意见反馈」→ `pages/feedback/index`（类型 chip + 动态表单 + 配图 ≤3）。
- **操作**：选类型 → 填结构化字段（投稿：菜名/价格/位置；纠错：关联菜品+说明）→ 可加图 → 提交。**提交后由管理员处理，确认后才会展示**（文案已明示）。
- **接口**：`POST /feedback`（免认证；risky → 400）
- **数据**：写 `user_feedback`（type/sub/content/images/related_type=dish/related_id）。

## A-12 系统通知（处理回执）🔓

- **干什么**：收管理员的处理回执（已认证用户）。
- **UI**：「我的」宫格「系统通知」→ `pages/notifications/index`（未读红点 / 全部已读）。
- **操作**：点开看回执正文 → 标记已读。
- **接口**：`GET /my/notifications` · `GET /my/notifications/unread-count` · `PUT /my/notifications/read-all` · `PUT /my/notifications/{id}/read`
- **数据**：读/写 `notification`（type 仅 `feedback_handle`；管理员处理反馈时投递，游客不投递）。

## A-13 个人资料 🔓

- **干什么**：改昵称、头像。
- **UI**：「我的」→ 用户卡 → `pages/profile/index`。
- **操作**：改昵称 / 换头像（走上传链路）→ 保存。
- **接口**：`GET /auth/profile` · `PUT /auth/profile`
- **数据**：写 `user.nickname/avatar`。

## A-14 邮箱认证 🔓

- **干什么**：学号邮箱认证（解锁写评价/点赞）。仅限校内邮箱域名。
- **UI**：AuthSheet 弹层（无独立页）：输入校内邮箱 → 收验证码 → 输码。
- **操作**：填邮箱 → 收码 → 输码提交 → `verified=1`。
- **接口**：`POST /auth/email-code`（发码）· `POST /auth/verify-email`（核验）
- **数据**：写 `email_verification_code`（code_hash/expires_at/used_at）；写 `user.verified/bind_email/verified_at`。

## A-15 注销账号 🔓

- **干什么**：删除本人数据（匿名化）。
- **UI**：个人资料页底部「注销账号」→ 二次确认。
- **操作**：确认注销 → 评价匿名化/通知清理/账号删除。
- **接口**：`DELETE /auth/account`
- **数据**：`user.status=deleted` + 级联清理（review 归名、notification 清理）。

## A-16 隐私政策与用户协议 🔓

- **干什么**：合规入口：说明收集哪些信息、用途、存储与删除权利。
- **UI**：「我的」底部信息区唯一可点元素 → `pages/privacy/index`（隐私政策 / 用户协议两个 tab）。
- **操作**：查看即可（纯展示）。
- **接口**：无（端内静态文案）。
- **数据**：无。

# B. 管理端（Web 后台，口令制无登录）

## B-01 菜品管理（核心）🔑

- **干什么**：菜品的增删改查与上下架——**菜品信息唯一录入源**。
- **UI**：导航「菜品」→ `/dashboard/content`：页头 H1「菜品」+ [新增菜品] → 筛选条（食堂/价格/辣度/标签/状态 + 搜索）+ 表格（名称/位置/价格/评分/状态）。
- **操作**：新增（DishFormDialog：名/价/折扣/描述/图/辣度/标签/食堂·档口——**食堂档口名不存在自动创建**）→ 行点击进详情 → 编辑（同一弹窗）/ 上下架（switch）/ 删除。
- **接口**：`GET|POST|PUT|DELETE /admin/dishes`
- **数据**：写 `dish` 全字段 + `stall`/`canteen` upsert；读同。

## B-02 菜品详情查看 🔑

- **干什么**：看一道菜的完整信息与全部评价（含隐藏的）。
- **UI**：列表行点击 → `/dashboard/content/dishes/{id}`：页头（返回+菜名+副标题 食堂·档口·评分）→ 信息卡 + 评价列表（`ReviewDetailDialog` 查看详情）。
- **操作**：查看 / 编辑 / 删除（页头）；点评价看详情。
- **接口**：`GET /dishes/{id}` · `GET /reviews?dishId=…`（含隐藏）
- **数据**：读 `dish` + `review`（本人后台视角全部）。

## B-03 评价管理（事后处置）🔑

- **干什么**：处理违规评价：隐藏 / 显示 / 删除。**无审核概念**——机检通过即公开，这里只做事后处置。
- **UI**：导航「评价」→ `/dashboard/reviews`：筛选（显示状态 + 搜索）+ 表格（用户/评分/内容/菜品/时间/显隐开关）+ 统计（共 N · 已隐藏 K）。
- **操作**：显隐 switch → 二次确认；选中 → 批量隐藏/显示/删除；行「查看」开详情抽屉。
- **接口**：`GET /admin/reviews` · `PUT /admin/reviews/{id}/hide` · `DELETE /admin/reviews/{id}`
- **数据**：写 `review.is_hidden` / 删行。
- **深链**：支持 `?rid=<评价id>` 自动定位高亮（由反馈处理页跳入）。

## B-04 反馈处理（唯一运营闭环）🔑

- **干什么**：处理学生全部诉求（建议/投稿/纠错/举报）：采纳（据此录入/修改/下架菜品）或不采纳（必填原因），并回执。
- **UI**：导航「反馈」→ `/dashboard/feedback`：筛选（状态默认待处理 / 类型 / 搜索）+ 表格（类型/关联对象/内容/提交人/时间/状态）+ 处理抽屉。
- **操作**：点「处理」→ 抽屉看内容与关联对象 → 采纳（回复必填）或不采纳（回复+原因必填）→ 标记处理 → 已认证提交人收通知。
  - 投稿类：据此在「菜品」页录入菜品后标记处理。
  - 纠错类：点「菜品名 →」跳到菜品列表定位修改。
  - 举报类：点「评价 #id →」直达评价管理定位隐藏/删除。
- **接口**：`GET /admin/feedbacks` · `PUT /admin/feedbacks/{id}`
- **数据**：写 `user_feedback`（status/reply/reject_reason/handled_at）；写 `notification`（回执）。

## B-05 学生账号管理 🔑

- **干什么**：禁用/启用学生（禁用后无法登录），查看其浏览/评价行为。
- **UI**：导航「学生账号」→ `/dashboard/system`：筛选（状态+搜索）+ 表格（头像/昵称/认证/状态/注册时间）+ 行为弹窗。
- **操作**：禁用/启用 switch → 确认；点「行为」看该学生浏览与评价记录。
- **接口**：`GET /admin/users` · `PUT /admin/users/{id}/status`
- **数据**：写 `user.status`；读 `view_log`/`review`（行为展示）。

## B-06 图片上传（表单内）🔑

- **干什么**：菜品图 / 学生头像的上传能力（两条独立链路）。
- **UI**：内嵌于 DishFormDialog（菜品多图）与个人资料（头像）；无独立页面。
- **操作**：表单内选图 → 自动压缩 → 上传 → 回填 URL。
- **接口**：`POST /upload/image`（multipart 直传）· `POST /upload/images`（云存储 fileId 转发 COS）
- **数据**：无独立表（返回 COS URL 写入 `dish.images` / `user.avatar`）。
