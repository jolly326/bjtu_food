## 一、项目管理相关

### 1.1 项目管理平台与工具

项目协同采用飞书进行统一管理，覆盖任务分配、进度记录、会议纪要、文档协作和阶段材料归档。立项书、设计文档、测试记录和阶段成果均集中维护，便于版本追踪和阶段检查。围绕模块任务建立飞书看板，明确负责人、截止时间和完成状态，满足课程设计过程管理的要求。

### 1.2 版本控制系统

代码管理采用 Git 与 GitHub。仓库统一保存前端代码、后端代码、接口文档、设计文档和阶段成果，提交记录用于反映开发过程、问题修复和功能演进。开发阶段按主分支与功能分支协同推进：主分支保存稳定版本，功能开发在独立分支完成，自测通过后合并，以降低多人并行开发带来的冲突风险。

### 1.3 开发模型

项目采用增量开发模型，按"系统骨架先行、核心功能优先、增强能力后补"的顺序推进：

| 阶段 | 内容 | 产出 |
|------|------|------|
| 第一阶段 | 项目初始化 + MySQL 建表 + 种子数据 + 用户认证模块 | 可登录注册的后端服务 |
| 第二阶段 | 食堂档口模块 + 菜品模块（列表/搜索/详情） | 可浏览菜品的小程序 |
| 第三阶段 | 评价模块 + 收藏模块（含事件驱动更新） | 完整互动链路 |
| 第四阶段 | 清单模块（含分享功能）+ 管理后台 | 完整业务流程闭环 |
| 第五阶段 | 前后端联调 + 测试 + 文档完善 | 可演示的完整系统 |

### 1.4 任务分解与跟踪方式

任务管理同时从模块维度和人员维度展开。项目执行过程中采用以下跟踪方式：

## 二、软件相关

### 2.1 软件名称与项目简介

**项目名称：食在交大**

本项目是一个面向北京交通大学学生的校园食堂菜品展示与互动系统，旨在解决学生"中午/晚上吃什么"的选择困难问题。系统通过微信小程序端向学生展示各食堂档口的菜品信息，支持浏览、搜索、评价、收藏和美食清单分享等功能；同时提供浏览器管理端，供食堂管理员维护菜品信息和查看营业数据，供系统管理员管理用户和审核评价。

### 2.2 功能需求

#### 2.2.1 用户角色

系统包含四类操作人员：

| 角色 | 权限范围 |
|------|---------|
| 学生用户 | 浏览菜品、搜索筛选、查看详情、发表评价、收藏菜品、创建/分享美食清单 |
| 食堂管理员 | 管理所属档口的菜品（增删改查、上下架）、查看数据统计看板 |
| 系统管理员 | 管理食堂/档口框架、管理用户账号、审核评价内容 |
| 游客（未登录） | 浏览菜品和评价列表，触发互动操作时跳转登录 |

#### 2.2.2 功能模块

**模块一：用户认证**

- 登录/注册：支持学号/工号注册和登录，使用 bcrypt 加密存储密码
- JWT 认证：登录成功后颁发 Token，有效期7天，后续请求携带 Token 进行身份验证
- 用户管理（系统管理员）：用户列表查询、启用/禁用账号、修改角色

**模块二：食堂档口管理**

- 食堂/档口层级结构管理：食堂下含多个档口，档口下含多个菜品
- 公开查询：学生无需登录即可查看食堂列表和档口列表
- 管理端操作（系统管理员）：新增/编辑/删除食堂和档口（删除时校验关联数据）

**模块三：菜品浏览与搜索**

- 菜品列表：分页展示，支持关键词搜索、食堂/档口筛选、标签筛选、价格区间筛选、多字段排序
- 默认排序：按综合热度（收藏量×3 + 浏览量×1 + 评价数×5）降序
- 热门推荐：独立接口返回收藏量 TOP10 菜品
- 菜品详情：展示大图、价格、标签（必吃推荐/招牌菜）、评分分布、评价列表
- 浏览量统计：防刷机制，同一用户同一菜品 5 分钟内只计 1 次

**模块四：菜品管理（食堂管理员）**

- 菜品 CRUD：新增、编辑、删除（软删除）、上下架切换
- 标签设置：可标记"必吃推荐"和"招牌菜"等标签
- 数据统计看板：总览数据（浏览量/收藏量/评分）、趋势折线图、热门菜品排行

**模块五：就餐评价**

- 提交评价：1-5星评分 + 文字感受 + 现场图片（最多3张）
- 编辑/删除：用户可修改或删除自己的评价（软删除）
- 评价列表：按时间倒序展示，包含评价者昵称和头像
- 敏感词过滤：入库前使用 DFA 算法检测违规内容
- 评价审核（系统管理员）：查看、隐藏、删除违规评价

**模块六：菜品收藏**

- 切换收藏：点击收藏/取消收藏（幂等操作），每人每菜唯一
- 收藏列表：分页展示已收藏菜品
- 批量收藏：供清单一键收藏功能使用，自动去重

**模块七：美食清单**

- 创建清单：从收藏中勾选菜品，命名并生成清单
- 分享功能：创建时自动生成分享 Token，可通过链接分享给微信好友
- 清单查看：好友通过分享链接无需登录即可查看清单内容
- 一键收藏：将清单内所有菜品加入自己的收藏（已收藏自动跳过）

**模块八：文件上传**

- 图片上传：支持 jpg/png/jpeg 格式，单文件 ≤5MB
- 本地存储：上传至服务器 uploads 目录，按日期分目录存放

#### 2.3.2 B/S 架构说明

系统采用**前后端分离的 B/S 架构**：

- **后端**：Spring Boot 应用部署在服务器上，提供 RESTful API 接口
- **前端**：微信小程序和浏览器管理后台均为前端渲染层，通过 HTTP 请求调用后端 API
- **数据交互**：前端与后端之间通过 JSON 格式进行数据交换，完全遵循 HTTP 协议
- **本质**：无论是微信小程序还是浏览器，都是 Client 端通过 HTTP 访问 Server 端资源，符合 B/S 架构的定义

#### 2.3.3 数据库选型

采用 MySQL 8.0 关系数据库，原因如下：

- 课程指定使用 Oracle 或 MySQL
- MySQL 8.0 支持完整的 SQL 标准、事务（InnoDB）、外键约束、索引优化
- 成熟的 JDBC 驱动与 Spring Boot / MyBatis-Plus 良好兼容
- 本地部署方便，适合课程演示场景

#### 2.4.2 后端分层架构

后端采用模块化分层设计，每个业务模块独立包，模块间低耦合：

| 层 | 组件 | 职责 |
|----|------|------|
| Controller 层 | 各模块的 Controller | 接收 HTTP 请求、参数校验、调用 Service、返回统一格式响应 |
| Service 层 | 各模块的 Service 接口 | 业务逻辑编排、事务管理 |
| Mapper 层 | MyBatis-Plus Mapper | 数据库 CRUD 操作 |
| Entity 层 | 实体类 | 数据库表映射 |

**模块间通信原则**：
- 所有模块仅依赖 common 公共模块（配置、异常、工具类）
- review（评价）和 favorite（收藏）模块通过 **Spring 事件机制** 通知 dish 模块更新评分和收藏数，不直接调用
- list（清单）模块通过 **Service 接口注入** 调用 favorite 的批量收藏方法

#### 2.4.3 数据库设计

系统包含 **8 张核心数据表**，E-R 关系如下：

```
user 1 ──── N review N ──── 1 dish N ──── 1 stall N ──── 1 canteen
  │                           │
  │                           │
  1                           1
  │                           │
  N                           N
favorite N ──── 1 dish    list_item N ──── 1 dish
  │
  │
  1
  │
  N
item_list N ──── 1 user
```

**各表核心字段：**

| 表名 | 核心字段 | 说明 |
|------|---------|------|
| user | id, username, password, nickname, role, stall_id, status | 用户表，角色：student/canteen_admin/sys_admin |
| canteen | id, name, description, sort_order | 食堂表 |
| stall | id, canteen_id, name, description | 档口表，外键关联食堂 |
| dish | id, stall_id, name, price(分), tags, status, view_count, collect_count, avg_rating, rating_count | 菜品表，价格以"分"存储防止浮点精度问题 |
| review | id, user_id, dish_id, rating, content, images, is_hidden | 评价表，支持软删除和隐藏 |
| favorite | id, user_id, dish_id (UNIQUE) | 收藏关系表，每人每菜唯一 |
| item_list | id, user_id, name, share_token | 美食清单表 |
| list_item | id, list_id, dish_id | 清单项表，外键级联删除 |

#### 2.4.4 事件驱动设计

```
评价提交 → ReviewService → 发布 ReviewSubmittedEvent
                                          ↓
                          RatingUpdateListener（dish模块监听）
                          → AVG(rating) 重算 → 更新 dish.avg_rating

收藏/取消 → FavoriteService → 发布 FavoriteChangedEvent
                                          ↓
                          CollectCountListener（dish模块监听）
                          → COUNT(favorites) → 更新 dish.collect_count
```
