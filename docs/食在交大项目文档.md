## 第一部分：项目概述

### 1.1 项目背景

校园食堂信息系统"食在交大"旨在解决学校食堂后勤与学生、游客之间的信息差问题：

- **食堂后勤**：活动/新品只能发公众号，触达率低，无数据反馈
- **在校学生**：每天纠结"吃什么、去哪里吃"，信息分散
- **外来游客**：进校想体验食堂，但完全不知道有什么好吃的

**核心价值**：一个连接食堂后勤、在校学生、外来访客的校园美食信息展示平台，解决"发出去没人看"和"想吃找不到"的双向信息差。

### 3.2 后端模块划分

| 模块 | 包路径 | 核心职责 | 依赖关系 |
|------|--------|---------|---------|
| **common** 公共模块 | `com.bjtufood.common` | 全局配置(CORS/Knife4j/Jackson)、统一响应(Result/PageResult)、异常处理(GlobalExceptionHandler)、工具类(JwtUtil/SensitiveFilter) | 零依赖 |
| **auth** 认证模块 | `com.bjtufood.auth` | 登录/注册/JWT/用户资料/密码管理/邮箱验证码 | 依赖 common |
| **canteen** 食堂档口 | `com.bjtufood.canteen` | 食堂/档口/轮播图CRUD与查询 | 依赖 common |
| **dish** 菜品模块 | `com.bjtufood.dish` | 菜品查询/搜索/详情/浏览量/评分同步/统计接口 | 依赖 common、favorite、review |
| **review** 评价模块 | `com.bjtufood.review` | 评价提交/编辑/删除/审核，发布事件→dish重算评分 | 依赖 common |
| **favorite** 收藏模块 | `com.bjtufood.favorite` | 收藏/取消/批量收藏，发布事件→dish更新收藏数 | 依赖 common |
| **list** 清单模块 | `com.bjtufood.list` | 清单创建/详情/删除/分享/一键收藏 | 依赖 common、favorite |
| **upload** 文件上传 | `com.bjtufood.upload` | 图片上传（本地存储） | 依赖 common |

### 3.3 模块间通信原则

- **所有模块仅依赖 common**，互不直接依赖
- **事件驱动解耦**：review 和 favorite 模块通过 Spring ApplicationEvent 通知 dish 模块更新评分/收藏数
- **Service 接口注入**：list 模块通过 Spring 注入调用 favorite 的批量收藏方法

### 3.4 事件驱动流程

```
评价提交 → ReviewService → 发布 ReviewSubmittedEvent
                                          ↓
                          RatingUpdateListener（dish模块监听）
                          → AVG(rating) 重算 → 更新 dish.avg_rating

收藏/取消 → FavoriteService → 发布 FavoriteChangedEvent
                                          ↓
                          CollectCountListener（dish模块监听）
                          → COUNT(favorites) → 更新 dish.collect_count
```

**注意事项**：
- 事件处理使用 `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`，确保事务提交后再触发
- demo 阶段使用同步事件，无需引入消息队列

### 3.5 安全架构

- **认证方式**：JWT（jjwt 0.12.3），Token 有效期7天
- **密码加密**：BCrypt
- **Spring Security 配置**：公开接口白名单（登录/注册/食堂/菜品/分享查看等），`/admin/**` 路径要求 ADMIN 角色
- **JWT 过滤器**：`JwtAuthFilter` 继承 `OncePerRequestFilter`，解析 Token 并设置 SecurityContext

### 3.6 统一响应与异常处理

- **Result\<T\>**：`{ code, message, data }` 统一响应体
- **PageResult**：分页响应封装
- **GlobalExceptionHandler**：统一处理 BusinessException、UnauthorizedException、参数校验失败、兜底异常

- 所有 id 为自增 BIGINT 主键
- `created_at` 和 `updated_at` 所有表都有

### 5.4 首页（pages/home/index）

**页面布局（从上到下）：**

1. **自定义导航栏**：砖红色背景，标题"食在交大"

3. **轮播图(Banner)**：自动轮播，带渐变遮罩

| 点击搜索框 | 跳转发现页 |
| 下拉刷新 | 支持 |

**数据来源**：`useDishStore` → `fetchHomeBanners()` / `fetchCanteens()` / `fetchCanteenImages()` / `fetchRecommend()`

### 5.5 发现/搜索页（pages/find/index）

**页面布局：**

4. 底部Tab栏

**搜索逻辑：**

> **设计说明**：发现页采用极简设计，暂不做榜单、推荐、筛选。搜索功能仅支持菜品名称模糊匹配。

### 5.11 个人中心页（pages/profile/index）

采用**单页面多状态**设计：

**未登录状态**包含三种模式：
1. **登录模式**：密码登录（账号+密码）或验证码登录（校园邮箱+验证码）
2. **注册模式**：用户名 + 校园邮箱 + 昵称 + 密码 + 验证码
3. **找回密码**：邮箱 + 新密码 + 验证码

| 模式 | 入口 | 字段 |
|:----:|:----:|------|
| 登录 | 默认 | 账号/邮箱 + 密码，或邮箱+验证码 |
| 注册 | 登录页切换 | 用户名 + 校园邮箱 + 昵称 + 密码 + 验证码 |
| 找回密码 | 登录页切换 | 邮箱 + 新密码 + 验证码 |

验证码仅限 `@bjtu.edu.cn` 邮箱，发送有60秒倒计时。

**已登录状态：**
- 用户头像（可点击更换：相册/相机选择并上传）
- 昵称（可点击弹出 Modal 修改）
- 用户 ID 展示
- 统计：收藏数、评价数
- 菜单项：我的评价（显示"功能开发中"）、关于食在交大（显示版本号）
- 退出登录（带确认弹窗）

## 第七部分：API 接口定义

### 7.1 通用规范

- **基础路径**：`http://localhost:8080/api`
- **统一响应格式**：`{ "code": 200, "message": "操作成功", "data": ... }`
- **认证方式**：`Authorization: Bearer <token>`
- **HTTP 状态码**：200=成功, 400=参数错误, 401=未登录, 403=无权限, 500=服务端错误
- **分页响应**：`{ "code": 200, "data": { "list": [...], "total": 100 } }`
