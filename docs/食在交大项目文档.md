## 一、项目介绍

"食在交大"是一个面向北京交通大学学生的**校园美食分享评价与社交内容平台**，解决"每天不知道吃什么"的难题。

平台由档口老板发布内容、管理员审核、学生浏览评价与分享，形成"**发现 → 决策 → 分享**"闭环。

> 定位为内容信息公示与美食点评社区，不涉及点单、支付、配送等外卖功能。

### 技术栈

| 层级 | 技术选型 |
|------|----------|
| 小程序端 | uni-app (Vue 3 + TypeScript + Vite + Pinia) |
| 管理后台端 | Vue 3 + TypeScript + Element Plus + ECharts |
| 后端 | Spring Boot 3.2 + Java 21 + Maven |
| 数据库 | MySQL 8.0 + MyBatis-Plus |
| 认证 | Spring Security + JWT（7天有效期） |

## 二、系统架构

### 2.1 三层架构

| 层 | 说明 |
|----|------|
| **前端展示层** | 微信小程序端（游客/学生/档口老板）、Web管理端（管理员） |
| **后端服务层** | 9 个模块：common、auth、canteen、dish、review、content、favorite、list、upload |
| **数据存储层** | MySQL 8.0 — 12 张表 |

### 2.2 后端模块

| 模块 | 核心职责 |
|------|---------|
| **auth** | 登录/注册/JWT/邮箱验证码，支持 user/stall_owner/admin 三种角色 |
| **canteen** | 食堂/档口/轮播图 CRUD，档口绑定档口老板（owner_id） |
| **dish** | 菜品查询/搜索/详情/评分同步/审核状态/活动管理/标签管理 |
| **review** | 评价提交/编辑/删除/"喜欢"投票/评价审核，事件驱动更新评分 |
| **content** | 档口发布内容审核（通过/驳回） |
| **favorite** | 收藏/取消/批量收藏（前端MVP暂不使用） |
| **list** | 美食清单创建/查看/删除/分享 |
| **upload** | 图片上传（本地存储，按日期分目录） |

### 2.3 模块间通信

- **仅依赖 common**：所有业务模块只依赖 common 公共模块
- **事件驱动解耦**：review 和 favorite 通过 Spring ApplicationEvent 通知 dish 模块更新评分/收藏数
- **数据隔离**：档口老板的接口只返回 `stall.owner_id = 自己` 的数据
