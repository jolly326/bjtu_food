# secur · 安全设计真源

> **性质**：**安全设计真源**。回答「谁能进、能做什么、挡住了什么、边界在哪」。
> **与其他文档的分工**：本目录只写**安全机制与威胁边界**；业务口径见 [`func/`](../func/client/README.md)、接口契约见 [`api/`](../api/README.md)、库表见 [`schema/`](../schema/README.md)、页面形态见 [`ui/`](../ui/client/README.md)。
> **设立原因**：安全机制**天然横跨端与层**（鉴权 + 限频 + 密钥 + 网络边界）。若分散写入各业务文档，会出现「同一机制在多处各写一份」而漂移。

## 1 · 分包结构

按**端**分包（与 [`func/`](../func/client/README.md) 同一套端划分），每包内按**主题**拆篇、**文件名不带端前缀**：

| 包 | 范围（威胁模型分区） | 入口 |
|---|---|---|
| [`client/`](./client/README.md) | 小程序端（学生端）：身份链路、越权与参数校验、滥用与内容防护 —— **Zone B** | [client/README.md](./client/README.md) |
| [`web/`](./web/README.md) | 管理端（管理后台）：登录与凭证、防爆破与限流、审计与告警 —— **Zone A** | [web/README.md](./web/README.md) |
| [`server/`](./server/README.md) | **跨端共用**的机制（限频器 / CORS / 密钥管理 / 异常兜底）与**部署 / 网络边界** | [server/README.md](./server/README.md) |

**归属判定**：只对 `/admin/**` 有意义 ⇒ `web/`；只对学生接口有意义 ⇒ `client/`；两端共用或属部署边界 ⇒ `server/`。
**阈值分配**：机制原理写在 `server/`，**具体阈值落在对应端**（同一事实只写一处）。

### 1.1 · 双安全区对比

| 维度 | Zone A · 管理端（`web/`） | Zone B · 小程序端（`client/`） |
|---|---|---|
| 路径前缀 | `/admin/**` | `/auth`、`/dishes`、`/reviews`、`/feedback`、`/reports`… |
| 鉴权 | 管理端 JWT（独立密钥）+ 账密登录 | 学生 JWT（独立密钥）+ 微信静默登录 |
| 身份源 | `admin_account`（BCrypt 口令） | `user`（服务端 `code2Session`） |
| 流量特征 | 低频、单人、**高权限且破坏不可逆** | 高频、多用户、最小权限 |
| 防御重心 | 凭证攻击（爆破）+ 接口滥用 + **留痕与告警** | 越权 / 篡改 / 爬取 / UGC 滥用 / 灌库 |
| 设计姿态 | 允许自由操作数据，但**一切写操作可追溯、可告警** | **默认拒绝**：能不给的能力不给，给了也必须服务端强校验 |

## 2 · 威胁模型（总览）

按「谁能打、打什么、后果、谁挡」四段划分，每条指向具体防线文档。

| # | 攻击面 | 后果 | 主防线 | 归属 |
|---|---|---|---|---|
| T1 | **管理端凭证泄露** | 🔴 **物理删菜品 + 级联删评价，不可逆** | 账密登录（前端不持有口令）+ 可吊销 JWT | [web/登录与凭证](./web/登录与凭证.md) |
| T2 | **暴力猜管理员密码** | 同上 | IP + **账号双维度**限频、渐进锁定、退避、**改密即吊销** | [web/防爆破与限流](./web/防爆破与限流.md) |
| T3 | **狂打 `/admin/**`** | 线程打满 ⇒ **小程序用户也进不来** | IP 限频（位于鉴权之前）+ token 维度写限频 | [web/防爆破与限流](./web/防爆破与限流.md) |
| T4 | **狂打业务公开接口** | 连接池 / 线程耗尽 | 双维度限频 | [client/滥用与内容防护](./client/滥用与内容防护.md) |
| T5 | **验证码枚举 / 发码轰炸** | 绑定他人邮箱 | IP 限频 + 邮箱冷却 + 尝试次数封禁 | [client/滥用与内容防护](./client/滥用与内容防护.md) |
| T6 | **学生 token 冒充管理员** | 越权进管理端 | 两套 JWT **独立密钥** + 独立账号表 | [web/登录与凭证](./web/登录与凭证.md) |
| T7 | **管理端 JWT 被窃** | 有效期内冒用 | 逐请求状态回查可即时吊销 + 审计告警可发现 | [web/登录与凭证](./web/登录与凭证.md) |
| T8 | **IDOR（篡改 id 操作他人资源）** | 删他人评价 / 改他人反馈 | **对象级归属校验**（以 JWT 内 userId 为准） | [client/接口安全与越权防护](./client/接口安全与越权防护.md) |
| T9 | **参数篡改 / 字段注入** | 越权字段生效 | DTO 约束 + **拒绝未声明字段** | [client/接口安全与越权防护](./client/接口安全与越权防护.md) |
| T10 | **恶意爬取**（高频拉列表 / 顺序枚举 ID） | UGC 资产外泄 | 读限频 + ID 枚举检测 + 蜜罐探针 + 分页上限 | [client/滥用与内容防护](./client/滥用与内容防护.md) |
| T11 | **UGC 灌库**（刷评价 / 反馈 / 举报） | 审核配额耗尽、数据污染 | 双维度写限频 + **违规累积处置** | [client/滥用与内容防护](./client/滥用与内容防护.md) |
| T12 | **违规内容漏放** | 校园场景合规事故 | 机审 **fail-closed**（上游不可达即拒收；缺凭据 / 无 openid 不放行） | [client/滥用与内容防护](./client/滥用与内容防护.md) |
| T13 | **高权限操作无留痕** | 出事无法追溯 / 举证 | **不可变审计日志** + 实时告警 | [web/审计与告警](./web/审计与告警.md) |
| T14 | **数据库直连公网** | 🔴 **全量数据泄露 / 删库** | 应用账号**仅 DML** + 口令轮换 + 私网连接 | [server/部署与网络边界](./server/部署与网络边界.md) |
| T15 | **上传型攻击**（图片马 / 炸弹 / 穿越） | 任意文件 / 资源耗尽 | 白名单 + 魔法字节 + 尺寸上限 + 重命名 + 云端安检 | [server/通用防护机制](./server/通用防护机制.md) |
| T16 | **限流 / 吊销绕过（多实例）** | 限额被放大 N 倍 | 触发条件：**≥2 实例前下沉 Redis** | [server/通用防护机制](./server/通用防护机制.md) |
| T17 | **内部信息探测**（异常 message / 调试面） | 结构探测线索 | 受控文案 + 调试面生产关闭 | [server/通用防护机制](./server/通用防护机制.md) |

## 4 · 残余风险（已知但未消除，明确记录而非假装不存在）

风险明细按端登记在各包 README 的「残余风险」节：

| 包 | 残余风险 |
|---|---|
| [client/](./client/README.md) | token 明文落本地存储（平台限制）· 内存计数 · 疑似内容放行 · 匿名提交无账号可绑 |
| [web/](./web/README.md) | JWT 有效期内可冒用 · **无 IP 白名单（平台不支持）** · secret 泄露 · 内存计数 · 多角色未建立 |
| [server/](./server/README.md) | **数据库端口公网可达** · 内存限频（≥2 实例须下沉 Redis） |

**跨端共同的两条**：

| # | 风险 | 触发重评的条件 |
|---|---|---|
| 1 | **限频 / 黑名单 / 封禁计数为进程内实现**，多实例时各自计数 | **云托管扩到 ≥2 实例** ⇒ 必须下沉 Redis，否则限额被放大 N 倍 |
| 2 | **无网络层 IP 白名单 / 安全组** | 换到有安全组的平台；或管理端不再单人 |

## 5 · 约定

1. **密钥永不入库**：所有 secret / 口令 / 密钥一律走**环境变量**，不写入文档、不提交仓库。
2. **文档只写当前口径**：变更轮次从 git 历史查（沿用 [`docs/README.md`](../README.md) 总约定）；设计已定而代码未同步的条目，登记在**各篇文末「与当前代码的差异」**节（清零写「无」）。
3. **新增防线必须登记进本 README 的威胁模型表** —— 否则「挡住了什么」无从回答。
4. **平台约束优先于理论最优**：托管平台的限制会否决某些加固手段，此类**否决理由必须记录**（见 [server/部署与网络边界](./server/部署与网络边界.md)），避免将来反复尝试同一条死路。
5. **涉及决策的取舍**（尚未拍板的安全口径）集中登记在 [`docs/测试/安全待决策项.md`](../测试/安全待决策项.md)，**不散落**在各篇正文里。
