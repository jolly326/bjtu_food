# 操作审计与告警

> **范围**：管理端**操作留痕**、**实时告警**、**破坏性操作防护**。
> **真源**：本文档。鉴权见 [登录与凭证](./登录与凭证.md)；限流见 [防爆破与限流](./防爆破与限流.md)。

管理端是**唯一具备不可逆破坏力**的入口。鉴权只解决「**谁能进**」；本文解决「**进来后干了什么、出事了谁知道**」—— 二者不可互相替代。

## 1 · 操作审计日志

### 1.1 · 表设计口径

只追加表 **`admin_audit_log`**：

| 列 | 说明 |
|---|---|
| `admin_id` | 操作人（`admin_account.id`） |
| `http_method` | 仅写操作落库：`POST` / `PUT` / `DELETE` / `PATCH` |
| `path` | 应用内路径（已剥离 context-path），如 `/admin/dishes/12` |
| `target_id` | 目标资源 ID（自路径提取的纯数字段；无则 NULL） |
| `result` | `success` / `fail:<HTTP 状态码>` |
| `ip` / `ua` | 来源 IP 与 User-Agent（按列宽截断） |
| `before_value` / `after_value` | 变更前 / 后对象快照（JSON，脱敏） |
| `created_at` | 由 DB 时钟写入 |

**列定义真源**：[`schema/admin_audit_log.md`](../../schema/admin_audit_log.md)。
**不含请求体**：请求体可能含口令类字段（如改密），一律不入审计表 —— 审计记录「谁、何时、对哪个资源、用什么方法、结果如何」。
**不可变**：只追加，不提供修改 / 删除入口；保留期 **1 年**，超期归档（归档动作本身亦留痕）。

**快照的覆盖面**（"变更前后值"支持误删后重建）：

| 覆盖 | 快照 |
|---|---|
| 全部 `DELETE` 端点（菜品 / 评价 / 账号处置 / 主数据 / Banner / 视图 / 维度与取值 / 举报原因） | 仅 `before_value`（删除后无对象） |
| 状态跃迁类（评价隐藏 / 恢复、账号启停、解绑认证邮箱） | `before_value` + `after_value` |

快照由 Service 在改动前后调用 `AuditSnapshot` 登记（**请求级**，取走即清除，不跨请求残留）；序列化失败时快照缺失但**留痕仍在**（审计是旁路，绝不把业务请求打成 500）。

### 1.2 · 覆盖范围（硬约束）

**全部管理端写操作**强制落审计，**无例外**：

- 主数据增删改（食堂 / 档口 / 菜品 / 属性维度与取值 / 筛选视图 / Banner / 举报原因）；
- UGC 处置（隐藏 / 恢复 / 删除评价、反馈回复与退回、举报处置、菜品问题反馈采纳 / 拒绝 / 下架）；
- 账号操作（用户启用 / 禁用 / 解绑邮箱 / 删除账号）；
- 管理员自身操作（登录成功、登录失败达阈值、改密）。

**接入方式**：注解式（`@AuditLog` 声明式标注在写端点 / 服务方法上），由切面统一落库。

**防漏挂护栏**：以测试断言「**所有写端点必须带审计注解**」—— 新增写端点忘了标注即测试失败（与「新增 `{id}` 写端点必须补归属校验」同性质的防回退约束）。

**降级口径**：审计写入失败**不阻塞业务**（业务成功但审计失败 ⇒ 记录高危日志 + 告警），避免「审计表故障拖垮管理端」。

## 2 · 实时告警

「账号被拿下」这件事**必须有人立刻知道** —— 否则攻击者可以慢慢删、慢慢改，直到下次登录才发现。

| 项 | 口径 |
|---|---|
| 通道 | **飞书 / 企业微信机器人 Webhook**（成本 ≈0、即时推送，适配单人运维），**开启签名校验**（`timestamp` + `HMAC-SHA256(timestamp + "\n" + secret)` + Base64） |
| 注入 | 经环境变量注入 Webhook 地址与签名密钥；**真值不入库、不入仓、不入文档** |
| 未配置行为 | 服务**正常启动**，但启动时 **WARN 明确提示「告警通道未启用」**（告警是增强能力，不阻断启动；但生产必须配置） |
| 内容约束 | 告警正文**不得包含**口令 / token / 密钥 / 完整个人隐私字段 |
| **推送 + 落库** | 每条告警**既推送、也落库**（`security_alert`）—— 群消息解决「立刻知道」，库里的记录解决「事后回看」 |
| 阻塞口径 | 落库与推送都在**告警线程池**内完成，业务请求不被 DB 往返与 webhook 超时拖慢（来源 IP 在调用线程取好再传入：告警线程没有 Web 上下文） |
| 降级口径 | 落库失败只记 ERROR，**不再推送**（推送会再写一行，形成递归）；告警是旁路，绝不让业务失败 |

### 2.1 · 告警规则

| # | 规则 | 类型键 / 级别 | 优先级 |
|---|---|---|---|
| 1 | **登录失败达锁定阈值**（有人在爆破） | `LOGIN_LOCKOUT` / 严重 | **必选** |
| 2 | **登录成功即告警**（含来源 IP；单人管理端的每一次登录都应是本人发起，多出一次即失守信号） | `LOGIN_SUCCESS` / 提示 | **必选** |
| 3 | 管理端**口令修改**（账号安全配置变更） | `PASSWORD_CHANGED` / 警告 | **必选** |
| 4 | **学生账号违规累积处置**（自动限言 / 封禁，含来源与依据线索） | `VIOLATION_PENALTY` / 警告 | **必选** |
| 5 | **爬取特征命中**（顺序枚举 ID / 批量命中不存在的资源） | `CRAWL_DETECTED` / 警告 | 增强 |
| 6 | **审计写入失败**（留痕出现缺口） | `AUDIT_WRITE_FAILURE` / 严重 | **必选** |
| 7 | 单 token 请求速率异常（>200/分，疑似 token 被滥用） | — | 增强 |
| 8 | 单次批量删除 / 停用 **> N 条** | — | 增强 |

> 📌 规则 1 与 2 是**最关键的两条信号**：「有人在爆破」与「爆破成功了」。二者任何一个静默，管理端就等于**无监护**。

### 2.1.1 · 回看面板（告警记录）

| 项 | 口径 |
|---|---|
| 数据源 | 只追加表 [`security_alert`](../../schema/security_alert.md)：类型 / 级别 / 标题 / 明细 / 来源 IP / 发生时间 |
| 类型与级别 | 类型决定级别（同一类事件级别恒定，调用方不自选）；**类型与级别中文标签在写入时落库为快照** —— 枚举重命名不会让历史记录失去可读性 |
| 面板 | 管理端「账号 → 安全告警」（[C3](../../func/web/C-账号与访问/C3-安全告警.md) · [ui/web/列表页模板 §C3](../../ui/web/列表页模板.md)），按类型 / 级别筛选、按发生时间倒序（同秒按 id 倒序，保证行序稳定） |
| 权限 | **只读**：记录只追加，面板无新建 / 编辑 / 删除入口（能改告警的人就能抹掉自己的痕迹）；`viewer` 角色同样可查看 |
| 保留期 | 与审计日志同口径（超期归档为运维动作） |

### 2.2 · 必须同时具备的响应动作

告警只是「告知」；**响应**是「止损」：

| 场景 | 响应动作 |
|---|---|
| 确认 token 被滥用 | **踢下线**（`POST /admin/users/{id}/kick`，只失效 token 不动账号列）或**一键停用账号**（`AdminAuthFilter` 逐请求回查 ⇒ 立即全网生效） |
| 确认密码泄露 | 改密（自增凭证版本 ⇒ 既有 token 立即失效）+ 人工核查 |
| 确认误删 | 依审计日志的 `before_value` **快照**（被删记录的原样）+ 时间线定位并重建 |

## 3 · 破坏性操作防护

「物理删菜品 + 级联删评价」不可逆，故采用**三层叠加**（不引入二次凭证，避免正常使用摩擦）：

| 层 | 措施 | 作用 |
|---|---|---|
| 1 | **前端二次确认** | 防误点（**不构成防护** —— 客户端行为可绕过） |
| 2 | **后端写限频（20/分）+ 归属 / 引用校验 + 删除入口仅 `super` 可见** | 防脚本批量删；被下级引用即 `400` 拒绝 |
| 3 | **审计（含 `before/after` 快照）+ 批量阈值告警** | 防「悄悄删完」；快照支持**追溯恢复**（列定义见 [`schema/admin_audit_log.md`](../../schema/admin_audit_log.md)） |

**明确不引入**：一次性确认令牌（`X-Confirm-Token` 类）—— 收益主要在「防误操作」，而第 1、3 层已覆盖；代价是显著增加正常使用摩擦。

## 4 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 高权限操作无留痕 | 路径 + 写方法的落库判定 | —（留痕而非拦截） | 审计落库（含前后值 + IP + UA） |
| 批量删除 / 批量停用 | 单次操作条数阈值 + 写限频 | `429`（写限频） | **实时告警** + 审计 |
| 敏感配置 / 账号状态变更 | 审计钩子 | — | 实时告警 |
| 从「撞对的」账号继续操作 | 新 IP 登录告警 | — | 踢下线 / 一键停用账号 + 审计复核 |
| 删除被绕过（非 `super` 直调删除接口） | `AdminAuthFilter` 角色门控 | `403` | 越权 WARN + 审计 |
