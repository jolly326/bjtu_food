# secur/web — 管理端安全设计

> **范围**：管理后台（`web/` 消费、`/admin/**` 暴露）的**凭证与登录、防暴力破解、限流、操作审计与告警** —— 即威胁模型中的 **Zone A**。
> **性质**：管理端**安全设计真源**。功能设计见 [`func/web/`](../../func/web/README.md)，页面形态见 [`ui/web/`](../../ui/web/README.md)，接口契约见 [`api/`](../../api/README.md)，库表见 [`schema/`](../../schema/README.md)。
> **总览与跨端矩阵**见 [`secur/README.md`](../README.md)；后端通用机制见 [`secur/server/`](../server/README.md)；小程序端见 [`secur/client/`](../client/README.md)。

## 1 · 设计前提与姿态

| 项 | 口径 |
|---|---|
| 使用形态 | **单人、低频、高权限**；管理员**本人自由操作全部业务数据**（不做功能删减） |
| 破坏力 | 🔴 **物理删菜品 + 级联删评价，不可逆** —— 这是全站唯一不可逆能力 |
| 部署 | web **只跑本地**；后端因微信云托管限制**必须开公网** ⇒ 攻击者**不需要碰你的前端产物**，可直接打公网 `/admin/**` |
| 防御重心 | ① **进得来吗**（凭证攻击：暴力破解 admin 密码）② **进来后干了什么**（留痕与告警）③ **狂打拖垮全站**（接口限流） |

> 📌 **web 只在本地这件事，对公网攻击毫无帮助** —— 它只是给你用的界面，不是一道防线。

## 3 · 端侧安全基线（反向证据）

| 维度 | 结论 |
|---|---|
| 前端产物 | **不含任何口令 / 密钥** —— 口令仅在登录表单提交瞬间存在于内存 |
| 凭证存储 | token 存 `sessionStorage`（关标签页即失效），**不用 `localStorage`** |
| XSS | 全站 Vue `{{ }}` 自动转义；无 `v-html` / `eval` / 危险 `innerHTML`；**「零 XSS」是 token 存储安全的第一防线** |
| 无独立凭证 | 前端**不持有**任何长期凭据；不给入口层注入凭证的机会 |
| 路由守卫 | 进入受保护路由前校验登录态（以服务端 `/admin/auth/me` 为准，非仅看本地 token） |

## 4 · 残余风险（明确记录而非假装不存在）

| # | 风险 | 现状 / 缓解 | 重评条件 |
|---|---|---|---|
| W-R1 | **管理端 JWT 泄露即可冒用**（有效期内） | token **可吊销**（停用账号逐请求生效）；web 本地 + `sessionStorage` 使泄露面很小 | 管理端迁到公网托管 |
| W-R2 | **无网络层 IP 白名单** | 🔴 **平台不支持**：微信云托管无安全组概念；且校园网出口 IP 共享，白名单会退化为「全校可访问」（见 [`secur/server/部署与网络边界.md`](../server/部署与网络边界.md)） | 换到有安全组的平台 |
| W-R3 | **`admin.jwt.secret` 泄露 ⇒ 可伪造管理端 token** | 走环境变量、不入库不入仓；弱密钥启动阻断 | — |
| W-R4 | **限频计数为进程内实现**，多实例下各自计数 | 单容器云托管，重启清零可接受；**扩到 ≥2 实例前必须下沉 Redis** | 云托管扩到 ≥2 实例 |
| W-R5 | **角色划分依赖人工赋值**（`admin_account.role` 直连库维护，无管理入口） | 账号行由数据库维护、仅 2~3 行，直连维护成本可忽略；引入管理入口会新增「谁能改角色」的自指权限问题 | 管理端账号数增长到需要自助管理时 |
