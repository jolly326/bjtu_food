# 防暴力破解与限流

> **范围**：管理端登录的**双维度限频与账号锁定**、**密码策略**、**token 维度限频**。
> **真源**：本文档。登录机制本身见 [登录与凭证](./登录与凭证.md)；告警通道见 [审计与告警](./审计与告警.md)；限频器实现见 [`secur/server/通用防护机制.md`](../server/通用防护机制.md)。

---

## 1 · 为什么必须双维度

**纯 IP 维度可被换 IP 绕过**（校园网多出口 / 代理池），而 **admin 用户名固定且可猜**（评论、文档、协作记录都可能泄露），密码一旦被字典命中即失守 —— 而管理端破坏**不可逆**。

⇒ 登录防护 = **IP 维度**（防单源狂打）× **账号维度**（换 IP 也累加）。

| 层次 | 拦住什么 |
|---|---|
| IP 限频 | 单来源高速试探 |
| **账号锁定** | 换 IP 的分布式试探（计数按 `username` 累加，跨 IP 仍生效） |
| 指数退避 | 「少量尝试」也变得不经济 |

## 2 · 登录限制（三层）

### 2.1 · IP 维度限频

| 端点 | 阈值 | 位置 |
|---|---|---|
| `POST /admin/auth/login` | **5/分 · 20/时** per IP | 进入口令校验**之前** |

### 2.2 · 账号维度渐进锁定

| 连续失败次数 | 锁定 | 说明 |
|---|---|---|
| 5 | **5 分钟** | 起锁 |
| 10 | **1 小时** | 升级 |
| 20 | **24 小时** | 上限 |

- **成功登录即清零**该 `username` 的失败计数（避免误伤本人）。
- 锁定期间该账号**一律拒绝**（即使密码正确、即使来自新 IP）。
- 计数与锁定状态**与 IP 维度并行**，任一超限即拒。

### 2.3 · 指数退避

自第 **3** 次连续失败起，登录响应**人为延迟递增，封顶 3 秒** —— 让「少量尝试」也付出时间成本。

### 2.4 · 硬约束

| # | 约束 |
|---|---|
| 1 | 锁定与退避的通知文案**不得**区分「账号不存在 / 已锁定 / 密码错误」的差异语义（防枚举）；对本人可提示「尝试过于频繁，请稍后再试」 |
| 2 | 失败日志**分级**：同源前 2 次 WARN、第 3 次起 DEBUG（首条必留可观测，狂打不刷爆日志） |
| 3 | 计数与锁定为**进程内内存**（与全域限频同款）；多实例须一并下沉 Redis |

## 3 · 管理员密码策略

**落地位置**：`POST /admin/auth/password`（改密端点是强度校验的**唯一入口** —— 账号由直连库登记，不存在「初始化设弱口令」的旁路）。

| 项 | 口径 |
|---|---|
| 最小长度 | **≥12 位** |
| 复杂度 | **含三类字符**（大写 / 小写 / 数字 / 符号中至少三类） |
| 校验位置 | **服务端强制**（前端提示只是体验；绕过前端直接调接口同样被拦） |
| 轮转 | **不强制轮转** —— 单人场景下强制轮转的收益不抵运维摩擦（忘改导致自己进不去） |
| 超期提示 | 距上次改密（从未改密则按建号时间）**>180 天** ⇒ `GET /admin/auth/me` 回 `passwordAging=true`，端上提示改密（**不强制踢出**） |
| 历史复用 | 不设历史密码表（不强制轮转 ⇒ 无复用判据） |
| 改密后 | **吊销既有 token** —— 改密即自增 `credential_version`，过滤器逐请求比对 ⇒ 旧 token 全部失效；响应回一枚**新 token** 供本端续用，其余端需重新登录 |

> 口令泄露后的止损手段是**改密**（自增凭证版本 ⇒ 既有 token 全部失效）与**人工核查**，而不是提高口令复杂度。

## 4 · 接口限流（/admin/** 全域）

| 维度 | 阈值 | 目的 |
|---|---|---|
| **IP** | `/admin/**` **60/分 · 600/时** | 防狂打导致 Tomcat 线程打满 ⇒ **小程序用户也进不来** |
| **token（写操作）** | **20/分** per `adminId` | 防 token 泄露后被脚本批量调用（批量删除 / 停用） |
| **token（异常速率）** | **>200/分** | 触发**告警**，提示「token 可能泄露被滥用」 |
| 读操作 | 沿用 IP 闸 | 管理端「读多写极少」，写单独收紧既不误伤本人，又能掐断脚本滥用 |

**关键设计**：

| 项 | 口径 | 理由 |
|---|---|---|
| 位置 | **口令校验「之前」** | 未鉴权流量恰是攻击主体；置于其后则失败请求仍逐条进过滤器、逐条打日志 |
| 阈值 | **刻意放宽**（业务接口为 30/分） | 管理端单人使用，正常操作远低于此；每分钟闸挡脚本狂打，每小时闸防慢速持续渗透 |
| scope | `admin-api`（与业务限频命名空间隔离） | 额度互不串扰 |
| 拒绝方式 | `BusinessException` → `GlobalExceptionHandler` → **`429`** | 与业务限频完全相同的响应路径，不另造格式 |

## 5 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 单源高速猜密码 | IP 失败计数 | `429` | 告警（阈值）+ 审计 |
| 换 IP 分布式猜密码 | **账号维度**失败计数（跨 IP 累加） | 账号渐进锁定 + 指数退避 | 告警 + 锁定记录 |
| 密码泄露后冒用 | 新 IP / 异常时段登录检测 | 改密即吊销既有 token | **登录成功亦告警**（防「撞对了无人知」） |
| token 泄露被脚本滥用 | 写操作频次 + 请求速率 | token 维度写限频（20/分） | 超 200/分 ⇒ 告警 + 一键停用账号 |
| 狂打 `/admin/**` 拖垮全站 | IP 计数 | `429` | 告警 |
