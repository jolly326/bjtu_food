# 登录与凭证

> **范围**：管理端身份来源、凭证形态与存储、登录错误口径、鉴权边界。
> **真源**：本文档。防爆破 / 限流 / 口令策略见 [防爆破与限流](./防爆破与限流.md)；操作留痕见 [审计与告警](./审计与告警.md)。

---

## 1 · 凭证设计约束

管理端的破坏性能力（**物理删菜品 + 级联删评价**，不可逆）要求凭证具备「**泄露不等于失守**」的性质。三条硬约束：

| # | 约束 | 落地 |
|---|---|---|
| 1 | **前端不得持有口令** | 口令只在登录表单提交瞬间存在于内存，不入产物、不落持久化 |
| 2 | **凭证须可验证、不可伪造** | 管理端 JWT **带签名**（独立 `admin.jwt.secret`），攻击者伪造不出 |
| 3 | **凭证须可吊销** | 短期 JWT + 账号 `status` **逐请求**即时作废（不缓存） |

> 📌 三条共同指向同一结论：**鉴权必须是「服务端验证身份 + 签发可吊销凭证」，而不是「双方共享一个秘密」**。

## 2 · 机制

### 2.1 · 身份从哪来

```
管理员在登录页输账号密码
  → POST /admin/auth/login
  → 服务端查 admin_account，比对 BCrypt 哈希
  → 通过 ⇒ 用 admin.jwt.secret 签发管理端 JWT（含 accountId）
  → 前端存 sessionStorage，后续请求带 Authorization: Bearer <jwt>
```

| 项 | 做法 | 理由 |
|---|---|---|
| 密码存储 | **BCrypt**（cost 10） | 不可逆 + 自带盐 + 计算成本可调 |
| 账号来源 | **独立 `admin_account` 表**，与学生 `user` 身份体系**完全隔离** | 学生体系的任何问题不外溢到管理端 |
| JWT secret | `admin.jwt.secret`，**独立于 `spring.jwt.secret`** | 🔴 共用则学生可自签管理端 token 冒充 |
| JWT 有效期 | 24 小时 | 使用场景为「一人偶尔用」；配「逐请求状态回查」后，过期并非唯一止损手段 |
| 密码校验依赖 | 仅 `spring-security-crypto` 的 `BCryptPasswordEncoder` | 不引 `spring-boot-starter-security`（避免自动配置与过滤器链副作用） |

### 2.2 · 密钥取值约定

| 项 | 约定 |
|---|---|
| 配置键 | `admin.jwt.secret`（类型化绑定，前缀 `admin`） |
| 环境变量 | **`ADMIN_JWT_SECRET`** —— 真值只经环境变量注入，**不入库、不入仓、不进文档** |
| 取值要求 | **≥32 字节随机串**；过短 / 过弱 / 缺失 ⇒ **启动即失败**（fail-fast） |
| 稳定性 | **必须固定**：每次启动重新生成会使已登录 token 全部失效，用户被反复踢出 |
| 独立性 | 🔴 **必须不同于 `spring.jwt.secret`** |

### 2.3 · 防枚举与防时序侧信道

| 项 | 口径 | 理由 |
|---|---|---|
| 登录失败提示 | **统一**「账号或密码错误」 | 🔴 区分「账号不存在 / 密码错误」= **用户名枚举** |
| 响应耗时 | **统一**：账号不存在时**仍执行一次 BCrypt 比对** | 否则「快速返回」即暴露账号不存在 |
| 秘密比对 | 一律 `MessageDigest.isEqual`（**等时比较**） | 🔴 `String.equals` / `==` 在首字节不同处提前返回，可据响应时间差逐步缩小口令空间 |
| 未授权响应 | 一律 `401`，不带「账号是否存在」类信息 | — |

### 2.4 · token 存储：`sessionStorage`

**选 `sessionStorage` 而非 `localStorage`**：关标签页即失效 —— web 仅本机运行、token 24h 过期，无需跨会话保持；少一份持久化泄露面即少一份风险。

> **取舍代价**：浏览器崩溃 / 手动关标签页需重新登录。对「一人本地管理」可接受。
> **安全前提**：其安全性建立在**全站零 XSS** 之上（见 [`secur/web/README.md`](./README.md) §3）。

### 2.5 · 角色与权限边界

**三档角色**（`admin_account.role`），由 `AdminAuthFilter` 按「**HTTP 方法 + 角色**」在**服务端强制**判定：

| 角色 | 可做什么 | 典型用途 |
|---|---|---|
| `super` | 全部（含**删除**类不可逆操作） | 博主 / 负责人 |
| `operator` | 读 + **业务写**（新增 / 修改 / 处置 / 启停），**不含删除** | 日常运营 |
| `viewer` | **仅读**（`GET` / `HEAD` / `OPTIONS`） | 只读查看 / 观摩 |

| 约束 | 口径 |
|---|---|
| 门控位置 | **服务端强制**（过滤器按方法 + 角色判定）；前端按角色隐显入口只是**体验**，绕过前端直接调接口同样被拦 |
| 拒绝方式 | **`403`**（**非 `401`**）—— 身份有效、仅权限不足；用 `401` 会把用户无谓地踢出登录 |
| 未知角色 | **一律按 `viewer`（只读）处理**（fail-closed：数据异常时宁可少给权限） |
| 越权留痕 | 每次越权尝试记 WARN（含路径与来源 IP），越权本身即安全信号 |
| 授权标记 | 认证上下文同时授予 `ROLE_ADMIN` 与 `ROLE_ADMIN_<角色>`，供后续接口级门控使用 |
| **自助端点例外** | `/admin/auth/password` 作用于「本人账号」，**不受角色门控**：只读角色同样需要能改自己的口令。仍要求有效 token |

**前端隐显口径**（判据收敛在 `web/src/utils/permissions.ts`，与服务端同源）：
`viewer` 不显示写入口（新增 / 编辑 / 处置 / 启停），`operator` / `viewer` 均不显示**删除**入口 —— **仅 `super` 可见删除**。角色缺失 / 未知一律按 `viewer` 处理（fail-closed，与服务端 `normalizeRole` 同口径）。

## 3 · 端点与错误码

| 端点 | 鉴权 | 作用 |
|---|---|---|
| `POST /admin/auth/login` | 🔓 **必须在白名单内** | 账号密码换 token |
| `GET /admin/auth/me` | ✅ 需 token | 回当前管理员账号信息（前端确认登录态 + 回填角色与安全提示） |
| `POST /admin/auth/password` | ✅ 需 token（**自助，不受角色门控**） | 改密（并吊销既有 token，回新 token） |

| code | 条件 | 端上行为 |
|---|---|---|
| `401` | 未带 token / token 失效 / 账号已停用 / **凭证版本已失效（改密）** / 登录失败 | **清 token → 跳登录页** |
| `403` | 已认证但角色不足（只读角色写操作 / 非 `super` 删除） | 提示无权限（**不触发重新登录**） |

> 🔴 **`POST /admin/auth/login` 若漏加白名单 ⇒ 必 401，功能完全不可用**（登录请求自身被拦截）。这是本条设计最易踩的坑。

## 4 · 设计边界

| 项 | 边界 |
|---|---|
| **角色与权限边界** | 三档角色（`super` / `operator` / `viewer`），由 `AdminAuthFilter` 按「HTTP 方法 + 角色」**服务端强制**判定 —— 见 §2.5 |
| **IP 白名单** | ❌ **不可行** —— 微信云托管无安全组能力，且校园网出口 IP 共享 ⇒ 白名单退化为「全校可访问」。详见 [`secur/server/部署与网络边界.md`](../server/部署与网络边界.md) |
| **入口层注入凭证**（nginx 反代藏 token） | ❌ **已否决** —— 入口层只能「保管 / 藏」凭证，**绝不能「判断」**（判断要查库、验签，必须在应用层）；自动注入凭证 + 扩大暴露面 = **负优化** |
| **操作留痕** | ✅ 已建立（见 [审计与告警](./审计与告警.md)）—— 鉴权只解决「谁能进」，留痕解决「进来后干了什么」，两者不可互相替代 |

**两项不可省略的既有防护**（重做即倒退）：

| 机制 | 说明 |
|---|---|
| **fail-closed** | 未配置 secret / 缺 token / URI 解析异常 ⇒ **全部拒绝**，而非放行 |
| **等时比较** | `MessageDigest.isEqual`，堵死「靠响应时间差缩口令空间」这条路 |

## 5 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 猜解 admin 密码 | 双维度失败计数（见 [防爆破与限流](./防爆破与限流.md)） | 账号渐进锁定 + 指数退避 | 告警 + 审计 |
| 用户名枚举 | 统一文案 + 统一耗时 | `401` | 高频失败 ⇒ 告警 |
| 伪造 / 改签管理端 token | 签名校验失败 | `401`（fail-closed） | 审计 + 源 IP 标记 |
| 已停用账号继续使用 token | **逐请求**回查 `admin_account.status` | `401`（不缓存，停用即刻生效） | 审计 |
| 学生 token 冒充管理员 | 两套 JWT 密钥独立 | `401` | 审计 |

## 6 · 与当前代码的差异

> 登记设计已定、代码尚未同步的条目；清零即写「无」。

**登录与角色门控：无（文档与代码一致）** —— 账密登录、BCrypt、独立密钥 + 启动强度校验、逐请求状态回查即时吊销、**凭证版本比对（改密即失效）**、统一错误文案与统一耗时（账号不存在时仍跑一次 BCrypt）、`sessionStorage` 存储、白名单与 `401` 处置、三档角色门控与 `403` 越权处置、**前端按角色隐显入口**均已落地。
