# 滥用与内容防护

> **范围**：小程序端的**限频（防滥用 / 防灌库）**、**爬取防护**、**内容机审**、**违规累积处置**。
> **真源**：本文档。越权与参数校验见 [接口安全与越权防护](./接口安全与越权防护.md)；限频器实现与跨端口径见 [`secur/server/通用防护机制.md`](../server/通用防护机制.md)。

---

## 1 · 限频：双维度（IP × 用户）

### 1.1 · 为什么必须双维度

**纯 IP 维度在换 IP 面前失效** —— 校园网多出口 / 代理池 / 移动网络切换即可绕过。IP 维度防的是「同一来源狂打」，**用户维度防的是「同一账号换 IP 刷量」**，二者并行、**任一超限即拒**。

### 1.2 · 口径

| 端点族 | IP 维度 | **用户维度（per-userId）** | 目的 |
|---|---|---|---|
| `POST /dishes/{id}/reviews`（写评价） | **2/分 · 10/时** | **3/分 · 20/时** | 防刷评价；用户维度略宽以免误伤真实高频用户 |
| `POST /feedback`（意见反馈） | 2/分 · 10/时 | 2/分 · 10/时 | 防灌库 |
| `POST /reviews/{id}/report`（举报） | 2/分 · 10/时 | 2/分 · 10/时 | 防刷举报 |
| `POST /dishes/{id}/correction`（菜品问题反馈） | 2/分 · 10/时 | 2/分 · 10/时 | 防刷纠错 |
| `GET /dishes` · `GET /dishes/{id}/reviews`（列表读） | **60/分 · 600/时** | **60/分 · 600/时** | 防脚本爬取 |
| `GET /dishes/{id}`（详情） | 30/分 · 300/时 | — | 兼作浏览计数防刷 |
| `POST /auth/email-code`（发码） | 3/分 · 10/时 | —（无登录态） | 防换邮箱绕过冷却 |
| `POST /auth/verify-email`（核验） | 5/分 · 20/时 | — | 防 6 位码枚举 |
| `POST /auth/wechat-login`（静默登录） | 30/分 · 300/时 | — | 防外呼配额耗尽 / 批量建号 |

**通用规则**：被拒请求**不消耗额度**（否则正常用户会被自己的重试打进冷却）；超限统一 `429`（走 `GlobalExceptionHandler`，与业务限频同一响应路径）；每处限频日志**分级**（同源前 2 次 WARN、第 3 次起 DEBUG），防攻击流量刷爆日志。

> 🔴 **限频不能替代鉴权**：它防「速率」，不防「身份」。身份必须由鉴权判定。

## 2 · 爬取防护

| 措施 | 口径 |
|---|---|
| 分页上限 | 学生端 `pageSize` 上限 **50**，超限服务端截断（防一次拉全量） |
| 读限频 | 列表端点双维度限频（见 §1.2） |
| **ID 枚举检测** | 同一来源对 `{id}` 的**顺序递增**访问（相邻差值 ≤ 3）在 1 分钟窗口内 **> 20 次** ⇒ 判定为枚举 |
| **蜜罐探针** | 同一来源命中**不存在的 ID** 在 1 分钟窗口内 **> 10 次** ⇒ 判定为扫描（正常路径（点卡片进详情）几乎不会请求不存在的 id） |

**判据取值依据**：正常用户按 `{id}` 直取资源是「跳着看」（首页 → 收藏 → 搜索），既不会在 1 分钟内走 20 个相邻 id，也不会连续撞 10 个不存在的资源；两条阈值都留在「真实用户不可能触及、脚本必触发」的区间。

**识别与处置**：命中即**临时限流**（该来源 5 分钟内读 `4001` 之外一律 `429`）+ 推送安全告警；**到期自动解除**（不封账号 —— 误判代价必须可自愈）。接入点为 `GET /dishes/{id}`（喂蜜罐探针 + 顺序遍历两条判据）与 `GET /dishes/{id}/reviews`（只喂顺序遍历判据 —— 无评价 ≠ 无该菜，存在性在此不可判定）。
| 游客可见集合**最小化** | 公开 GET 仅 `/dishes/**`、`/banners/**`、`/images/**`（业务公开资源）与 `/report-reasons`；**用户列表等敏感集合仅管理端可见** |
| 归属校验 | 爬取者拿不到他人资源（见 [接口安全与越权防护](./接口安全与越权防护.md) §2） |

> 📌 **游客可读「公开信息」是产品口径**（首页 / 搜索 / 详情免登录），不因防爬而收紧为「必须登录」；抓手放在**速率与枚举异常检测**上，而非取消公开能力。是否取消公开读见 [`docs/测试/安全待决策项.md`](../../测试/安全待决策项.md)。

## 3 · 内容安全（UGC 机审）

### 3.1 · 判定口径

| 结果 | 处置 |
|---|---|
| `risky`（明确违规） | **拦截 `400`**，不入库 |
| `pass` / `review`（疑似） | **放行入库**（无人工复核队列）—— UGC 治理闭环口径 |
| 上游不可达 / 超时 | **fail-closed：`500` 拒绝入库**（宁可拒收，不放违规内容过关） |
| **凭据未配置 / openid 缺失** | **fail-closed**：生产环境缺凭据 ⇒ 启动失败；无 openid ⇒ 拒绝入库。**不存在「跳过检测放行」分支** |

### 3.2 · 覆盖范围

- **文本**：评价正文、反馈正文、菜品问题反馈说明、用户昵称等一切用户可控文本。
- **图片**：UGC 配图与**头像**走**同一条**安检链路（`POST /upload/cloud-image` → 内容安检 → 转存对象存储），**不存在「头像可绕过」的旁路**。
- 上传自身的形态校验（扩展名白名单 / 魔法字节 / 尺寸 / 像素上限 / 文件名）见 [`secur/server/通用防护机制.md`](../server/通用防护机制.md)。

### 3.3 · 事后手段

举报（IP + 用户双维度限频、同一评价去重）+ 违规累积处置（见 §4）。

## 4 · 违规累积处置（账号维度）

**单条机审只能挡「明显违规」，挡不住「反复试探边界」**。故在内容层拦截之外，补**账号维度**的累积梯度：

| 阶段 | 累计违规次数 | 处置 |
|---|---|---|
| 0 | 1 ~ 2 | 仅累计（不改账号任何形态） |
| 1 | 3 ~ 5 | 账号标记 + 警告 |
| 2 | 6 ~ 8 | **限言 24 小时** —— 限言期**全部写端点 `403`**，读不受限 |
| 3 | 9 ~ 11 | **限言 7 天** |
| 4 | ≥ 12 | **封禁**（等同账号禁用：拦登录 + 吊销该 userId 全部 token） |

**阈值取值依据**：前三档（3 / 6 / 9）刻意留出「误触 / 试探」的余量 —— 正常用户不会在内容被拦三次后仍反复提交；到 12 次已不是误操作，须立即止损。

**计数来源**：机审 `risky` 命中（内容被拦、**未入库**，按 openid 定位账号）+ 举报成立（管理端处置结论为「通过」，记给**被举报内容的作者**）。同一内容重复举报已被提交侧去重，不重复计数。

**限言的实现口径**：判据是 `user.muted_until` **是否在未来**（不是独立状态列）⇒ **到期自动恢复，无需任何人工动作**；封禁才写 `status='disabled'`。列定义见 [`schema/user.md`](../../schema/user.md)。

**硬约束**：每次处置动作**必须留痕并推送告警** —— 留痕在 [`user_violation`](../../schema/user_violation.md)（只追加：来源 / 线索 / 本次动作），告警走与 [管理端告警](../web/审计与告警.md) **同一通道**。系统自动处置不是某个管理员点的动作，不留痕会让「某账号为什么被限言 / 被封」无从复盘。解封：限言由到期自动恢复；封禁由管理员人工启用（`PUT /admin/users/{id}/status`）。

## 5 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| UGC 灌库（脚本刷评价 / 反馈 / 举报） | 双维度限频 + 机审命中 | `429` / `400` 拒绝 | 违规累积 ⇒ 限言 / 封禁 + 告警 |
| 恶意爬取（高频拉列表 / 顺序枚举 ID） | 读限频 + ID 枚举检测 + 蜜罐探针 | `429` + `pageSize` 截断 | 告警 + 临时限流（5 分钟，到期自愈） |
| 违规内容入库 | `risky` 判定 / 上游可达性 | `400` / `500`（fail-closed） | 告警 + 降级提示 |
| 图片马 / 图像炸弹 / 路径穿越 | 扩展名 + 魔法字节 + 尺寸 + 像素上限 + UUID 名 | `400` 拒绝 | 审计（高频则告警） |
| 发码轰炸 / 验证码枚举 | 邮箱冷却 + IP 限频 + 尝试次数封禁 | `429` / `400` | 告警 |
| 上游审核服务降级被利用 | 出网调用失败捕获 | `500` fail-closed | 告警（提示上游异常） |

## 6 · 与当前代码的差异

> 登记设计已定、代码尚未同步的条目；清零即写「无」。

**无（文档与代码一致）** —— 双维度限频、爬取防护（读限频 + ID 枚举检测 + 蜜罐探针）、UGC 机审 fail-closed、举报去重与违规累积梯度处置（含留痕与告警）均已落地。

> 附注：机审命中的违规计数**尽力而为**（写库失败只记 ERROR，不影响本次拦截结论）—— 计数丢失远比「把一次明确拦截变成不明故障」轻。
