# S-03 · 限频与接口防护

> 返回：[安全总览](./README.md)

## 一、限频矩阵

| 端点 | 维度 | 阈值 | 目的 |
|---|---|---|---|
| `POST /my/records`（去品尝） | 账号 | 30 / 时 | 防刷标记 |
| `PATCH /my/records/{id}`（评分） | 账号 | 60 / 时 | 防刷评分 |
| `DELETE /my/records/{id}`（取消） | 账号 | 30 / 时 | 防刷取消 |
| `POST /dishes/{id}/issues`（纠错） | 账号 | **10 / 时** | 防刷屏运营端 |
| 读端点（`/dishes` · `/posters` · `/canteens` · `/dish-issue-options`） | 账号 | 300 / 时（**四个端点合计共享**同一配额，键 = 账号） | 防爬取（**同样要求凭证**，见 [S-02](./S-02-鉴权与归属校验.md)） |
| 全局 IP 兜底 | IP | 60 / 分 | 防脚本（**HTTP 层中间件**，`/healthz` 不计数） |
| `POST /auth/wechat-login` | IP | 20 / 时 | 防 code 刷换 |
| `POST /admin/sessions` | IP | 10 / 分 | 登录兜底（**运营端防护本期不展开**，仅此兜底） |

> **账号维度**的键 = 服务端从凭证解析出的用户（见 [S-01](./S-01-身份与凭证.md)）；**端上不参与**。

## 二、命中口径

| 项 | 口径 |
|---|---|
| 响应 | **`429`** + `message` 含**可等待秒数** |
| 端上 | Toast 展示 + **退避倒计时**：请求层抛出带 `retryAfter`（等待秒数）的错误，页面据此**禁用该入口**直到倒计时结束自动恢复；**429 不自动重试**（只有 `401` 才静默重登重试） |
| 顺序 | **鉴权与入参解析之后、领域业务校验之前**限频 —— 命中即 `429`，不进入业务逻辑 |
| 与鉴权的关系 | 账号维度限频在**鉴权之后**（无凭证 ⇒ `401`，不消耗账号配额）；全局 IP 兜底在 HTTP 层按来源 IP 独立计数，与鉴权无关 |

## 三、存储：进程内（单进程前提）

| 项 | 口径 |
|---|---|
| 存储 | **进程内存**（固定窗口计数）—— 无外部依赖，故**不存在"降级策略"问题** |
| 🔴 **前提** | 后端以 **单实例 + 单 worker（uvicorn 单进程）** 运行 —— 多进程会**各自持有计数**，实际阈值 × 进程数 |
| 🔴 **触发条件** | 出现**任一**即必须下沉共享存储（Redis）：① 单进程 **CPU 长期 > 70%**；② **P95 响应时间持续上升**且非 DB / 外部调用瓶颈；③ 主动要开**多实例做高可用** |
| 开发期例外 | **每次发布**的滚动更新会有**数秒~数分钟的新旧实例并存**（③ 场景的临时形态）—— 期间计数短暂分裂，**可忽略**（限频是防护层，不是业务正确性） |

### 容量判据（为何本规模下单进程足够）

| 项 | 估算 |
|---|---|
| 用户规模 | 5,000 人 |
| 日活（按 30%） | ≈ 1,500 人/天 |
| 人均请求 | ≈ 20 次/天（3~5 次打开 × 每次数次请求） |
| 日请求量 | ≈ 3 万 |
| 峰值时段 | 饭点两段，合计约 3 小时 |
| **峰值 QPS（按 10× 突发）** | **≈ 30 ~ 50** |

> 单进程 async（uvicorn）处理 **I/O 型**请求可达**数百 QPS** ⇒ **5,000 人规模下余量充足**，无需 Redis。
> 判据是**并发 QPS 与 CPU**，**不是注册用户数** —— 上表可按实际日活 / 人均请求重算。

### 兜底设计（即使将来多进程也仍有效）

限频阈值按「**最坏情况仍能防刷**」设定（如纠错 10/时）—— 即便将来因多进程导致阈值 ×N，防护仍成立；届时**再决定**是否换 Redis（换的只是存储实现，接口与业务不动）。

## 四、上传防护（**仅运营端**）

| 项 | 口径 |
|---|---|
| 端点 | `POST /admin/images` |
| 校验 | 类型 `jpg` / `png` / `webp`；单张 ≤ **5MB**；**服务端校验**（不信任 `Content-Type` 声明） |
| 用途 | 档口海报 · 菜品大图 |
| 内容安全 | **不送微信机审** —— 素材由运营自行上传（学生端无上传端点） |

## 五、不做的事（防回退）

| 项 | 原因 |
|---|---|
| 滑动窗口 / 令牌桶 / 分布式限流 | MVP 量级小，固定窗口计数足够 |
| Redis 等外部限流存储 | 见 §三 触发条件（单进程下无收益，且会引入"连不上怎么办"的降级问题） |
| 验证码 / 人机校验 | 无注册登录流程 |
| IP 黑名单 / 封禁 | 校园网出口 IP 共享，封禁会误伤整校 |
| 内容机审 | 学生侧零自由输入（只有选项与评分数字） |
