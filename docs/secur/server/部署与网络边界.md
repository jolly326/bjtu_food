# 部署与网络边界

> **范围**：后端的**暴露面**、部署形态、平台约束导致的**不可行加固手段**、以及**数据库可达性与凭据**口径。
> **真源**：本文档。鉴权机制见 [`secur/web/登录与凭证.md`](../web/登录与凭证.md)；通用防护见 [通用防护机制](./通用防护机制.md)。
> **核心价值**：记录「**为什么不能这么做**」—— 避免将来反复尝试同一条已被平台否决的死路。

---

## 1 · 部署形态

| 项 | 结论 |
|---|---|
| **后端** | 微信云托管 |
| **公网访问** | **开启** —— 供本地管理端直连 |
| **内网访问** | 开启 —— 供小程序 `wx.cloud.callContainer` 走内网 |
| **管理端（web）** | **只跑在本地**（开发服务器），不上云 |
| **小程序** | 走 `wx.cloud.callContainer` **内网**，不受公网开关影响 |
| **容器时区** | **`Asia/Shanghai`** —— 保证 DB 时钟写入的持久化时间戳与应用时钟一致 |

> ⚠️ **「web 本地」≠「后端内网」**：后端的「内网」是微信云托管自身的内网，本地浏览器**不在其中** —— 这就是必须开公网的原因。

## 2 · 🔴 平台约束：微信云托管没有「安全组」

**这是本文档最重要的一条**，它否决了一类看起来很自然的加固手段。

| 你想要的 | 能否做到 | 原因 |
|---|---|---|
| 配置 **IP 白名单 / 安全组** | ❌ **不能** | 控制台**无安全组概念**，无入站 IP 白名单配置入口 |
| **端口级**暴露 / 映射（如开放 SSH） | ❌ **不能** | 无端口暴露能力；入站流量只能走 **HTTP/HTTPS** 且必须经云托管分配的域名 |
| **内网穿透隧道**（frp / ngrok / SSH 隧道） | ❌ **不能** | 隧道要求在服务端跑客户端并**主动向外建连**，托管云环境无 shell 权限、无法控制出网策略 |

**云托管提供的网络管控只有两个开关**：

| 开关 | 作用 |
|---|---|
| **公网访问开关** | 控制服务是否拥有公网 HTTPS 域名（**唯一的外部流量总闸**） |
| **内网访问开关** | 控制是否分配内网域名（同一环境内其他服务可直连） |

## 3 · 不可行手段的否决记录（勿重复尝试）

### 3.1 · 「只允许我的 IP 访问 `/admin/**`」

❌ **不可行**，两个独立原因，任一即否决：

| 原因 | 说明 |
|---|---|
| 平台不支持 | 微信云托管无 IP 白名单配置入口（见 §2） |
| **校园网出口 IP 共享** | 你与校内同学可能**共用同一个出口 IP** ⇒ 白名单等于允许**全校**访问，退化为无防护 |

> 📌 若将来换到有安全组的平台，且有固定 IP，可重新评估。

### 3.2 · 「后端不开公网 + 隧道」

❌ **不可行**，见 §2 第三行。

### 3.3 · 「用反向代理藏管理端凭证」

❌ **负优化，已否决**。让反向代理对每个请求自动注入管理端凭证 = 把凭证交给入口层白送：

| 维度 | 结论 |
|---|---|
| 攻击者需要什么 | 🔴 **什么都不需要**（入口层白送） |
| 攻击请求能否到 DB | 🔴 每请求都到（打连接池） |
| 拖垮谁 | 🔴 **小程序用户** |

> **两条硬结论**：① 入口层只能「保管 / 藏」凭证，**绝不能「判断」** —— 判断必须在应用层（要查库、验签）。② **入口层自动注入凭证 + 扩大暴露面 = 负优化** ⇒ 要上云必须「入口层不注入凭证 + 应用层账密登录」**整套一起做**。

## 4 · 真实暴露面

因为管理端在本地而后端在公网，**攻击者不需要碰你的前端产物**：

```
攻击者
  → 直接打公网 https://<云托管域名>/api/v1/admin/**
  → 需通过账密登录拿到管理端 JWT
  → 未授权请求被管理端鉴权过滤器拦在鉴权层
```

| 攻击面 | 防护 | 残余风险 |
|---|---|---|
| `/admin/**` | 账密登录 + 双维度限频 + 账号锁定 + 审计告警 | 无 IP 白名单（平台限制，见 §3.1） |
| 学生接口（公开） | 双维度限频 + 归属校验 + 参数校验 + 机审 | 无 IP 白名单 |
| **数据库端口** | 🔴 **直接公网可达** | 见 §5 |

## 5 · 🔴 数据库可达性与凭据

| 项 | 现状 |
|---|---|
| 数据库形态 | 托管数据库（云厂商），**端口在公网可直接连接** |
| 可达性 | 🔴 端口对公网开放 |
| 凭据 | 🔴 历史口令曾以明文出现在协作记录 / 启动脚本中 —— **须视为已泄露** |
| **应用账号权限** | 🔴 应用当前以**超级账号（root）** 连接：含 `DROP` / `ALTER` / `GRANT` / `CREATE USER` 等高危权限 —— 应用一旦被攻破（如出现注入或 RCE），可直接删库 / 改结构 / 改权限 |

**这是全站唯一可以「一次性拿到全量数据」的路径**，且与管理端 / 小程序端的任何加固**无关**：拿到连接串即可直连拖库、改库、删库。

### 5.1 · 已定口径

| # | 口径 |
|---|---|
| 1 | **应用账号仅 DML** —— 无 `DROP` / `ALTER` / `GRANT` / `CREATE`，DDL 由人工提权执行（见 [通用防护机制](./通用防护机制.md) §3.3） |
| 2 | **口令轮换** —— 曾明文暴露的口令一律作废重设，新值只经环境变量注入 |
| 3 | **优先私网连接** —— 若托管数据库提供私网 / 内网连接能力，改走内网，不再公网直连 |
| 4 | 连接串与凭据**只从环境变量读取**，禁止写入任何文档 / 代码 / commit message / 规则文件 |

> 上述第 2、3 项的**执行**（改口令、改权限、切换连接方式）会立即影响运行中的服务与其环境变量文件 —— 属需明确授权的运维动作，见 [`docs/测试/安全待决策项.md`](../../测试/安全待决策项.md)。

### 5.2 · 变更后必做

任何库结构 / 权限变更后，同步更新 [`schema/`](../../schema/README.md) 使**文档与远程库实况一致**（流程见 [`schema/README.md`](../../schema/README.md)）。

## 6 · 迁移成本（若将来迁往自有服务器）

| 组件 | 成本 | 说明 |
|---|---|---|
| 管理端（web） | 🟢 **≈0** | 全目录零硬编码地址，一律走环境变量注入的 API 基址 |
| 后端（server） | 🟢 ≈0 | 纯 Spring Boot，仅改环境变量 |
| 反向代理 | 🟢 改一行 | — |
| **小程序调用方式** | 🔴 **高** | 需从「云托管内网调用」切到「自有域名直连」+ 服务器域名配置 + **ICP 备案 + HTTPS** |

> ⇒ **迁移成本与「管理端放本地还是上云」无关**，不应用「迁移成本」作为选型依据；真正的长周期项是**域名备案**。

## 7 · 维护约定

🔴 **当平台约束变化时（如云托管新增 IP 白名单能力），须回来更新 §2、§3**，并同步评估 [`secur/web/README.md`](../web/README.md) 的残余风险 W-R2。

这类「不可行手段」记录的价值在于：**它把「我想这么加固」变成「已确认此路不通」**，避免每个后来者重新论证一遍。

## 8 · 与当前代码的差异

> 登记设计已定、代码尚未同步的条目（本包多为**部署 / 运维口径**，非代码条目）；清零即写「无」。

| # | 差异 | 类型 |
|---|---|---|
| 1 | **数据库口令未轮换**（曾明文暴露的旧口令仍在用） | 运维动作（待授权） |
| 2 | **受限账号已建立（`SELECT` / `INSERT` / `UPDATE` / `DELETE`，无任何 DDL），但线上仍在用 root** | 运维动作：**须先在云托管把连接凭据换为受限账号并发布，确认正常后再撤销 root 连接** —— 顺序颠倒会即刻中断线上 |
| 3 | **未切换私网连接**（当前公网直连） | 部署（待评估平台能力后执行） |
