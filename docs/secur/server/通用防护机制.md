# 通用防护机制

> **范围**：跨端复用的防护手段 —— 限频器、CORS、密钥与凭据管理、时序侧信道、异常与信息暴露、数据与接口基线。
> **真源**：本文档。具体阈值按端分配（管理端见 [`secur/web/防爆破与限流.md`](../web/防爆破与限流.md)，学生端见 [`secur/client/滥用与内容防护.md`](../client/滥用与内容防护.md)）；暴露面与数据库边界见 [部署与网络边界](./部署与网络边界.md)。

## 1 · 限频器

### 1.1 · 实现口径

进程内内存实现：`ConcurrentHashMap<scope:key, 时间戳队列>` + **按 key 加锁** + 定时清理过期条目。

```java
new Rule(limit, windowMs)   // 例：new Rule(3, 60_000L) = 每分钟 3 次
```

**维度**：同一机制可挂不同 key —— `scope:ip`（来源维度）与 `scope:userId` / `scope:adminId`（身份维度）。**双维度并行、任一超限即拒**（见各端阈值表）。

### 1.2 · 关键设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 锁粒度 | **按 key（单个客户端）** | 全局锁在并发压测下拒绝分支比放行分支**慢约 40%** |
| 被拒请求 | **不消耗额度** | 否则正常客户端会被自己的重试打进冷却 |
| 容量兜底 | 条目上限 **10000** | 异常流量下 key 不无限增长 |
| 窗口上限 | 单条规则窗口 ≤ 1 小时 | 清理线程据此判定过期 |
| 拒绝响应 | `BusinessException` → `GlobalExceptionHandler` → **`429`** | 全站同一响应路径，不另造格式 |
| 日志分级 | 同源前 2 次 WARN、第 3 次起 DEBUG | 首条必留（真实攻击可见），狂打刷不爆日志 |

### 1.3 · 存储与扩缩容触发条件

| 项 | 口径 |
|---|---|
| 当前存储 | **进程内内存**（限频、token 黑名单、验证码封禁计数同此） |
| 已知后果 | ① 重启清零 ② **多实例各记各的 ⇒ 限额被放大 N 倍、吊销只在单实例生效** |
| 当前裁决 | 单容器云托管下**接受现状**（重启清零可接受） |
| 🔴 **触发条件** | **云托管扩到 ≥2 实例前，必须下沉 Redis**（`INCR` / Lua 滑动窗口），否则该条件不满足即不得扩容 |

> ⚠️ **限频不能替代鉴权**：它防「速率」，不防「身份」。持有有效凭证的请求对限频而言都是「合法」的 —— 身份必须由鉴权判定。

## 2 · CORS

| 项 | 口径 |
|---|---|
| 配置 | `CORS_ALLOWED_ORIGINS` 环境变量，**默认空** |
| 空值行为 | 🔴 **拒绝一切带 `Origin` 的浏览器请求**（fail-closed） |
| 生产取值 | 本地管理端地址（web 跑本地 + backend 公网 ⇒ 该项是管理端能连上的**前提**；置空会使管理端全站 CORS 403） |
| 凭证 | `allowCredentials = false` |
| 非暴露风险 | 放行 `localhost` **不是对外开放** —— 浏览器 `Origin` 由页面自身决定，外部站点无法伪装成 `localhost`；小程序走微信内部链路，**不带浏览器 `Origin`，不受此约束** |
| 预检放行 | 🔴 **`OPTIONS` 预检不携带凭证**，须在**三处**放行：① 安全配置全局放行 `OPTIONS /**`；② 学生端 JWT 过滤器对 `OPTIONS` 直接放行；③ 管理端过滤器 `shouldNotFilter` 对 `OPTIONS` 返回 true。**任缺一处，预检返回 401 且不含 CORS 头，浏览器判定「跨域被拦」**（CORS 过滤器排在安全链之后，无法补救） |
| 出网请求 | 全部微信出网请求统一携带 `User-Agent` —— 微信网关 WAF 对「multipart + 空 UA」的 POST 直接回 **412**；基址可经环境变量覆盖，容器内可改走微信内网通道 |
| 集中管理 | 全站**无散落的 `@CrossOrigin`**，CORS 统一由配置类收口 |

## 3 · 密钥与凭据管理

### 3.1 · 硬规则

| 规则 | 说明 |
|---|---|
| **永不入库** | 口令 / secret / 密钥一律走**环境变量**，不写文档、不提交仓库、不进 commit message |
| **示例文件只放占位符** | `.env.example` 不带真值 |
| **双 JWT 密钥独立** | 学生 `JWT_SECRET` ≠ 管理端 `ADMIN_JWT_SECRET`，共用则学生可自签管理端 token |
| **弱密钥启动阻断** | 缺失 / 过短 / 命中开发默认值 ⇒ **启动失败**（fail-fast） |
| **凭据不进日志** | 出网调用日志对 `secret` 等参数脱敏 |

### 3.2 · 环境变量清单

| 变量 | 用途 | 备注 |
|---|---|---|
| `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD` | 数据库连接 | 真值仅运行时注入；见 [部署与网络边界](./部署与网络边界.md) §5 |
| `JWT_SECRET` | 学生 JWT 签名 | 生产无默认值 |
| `ADMIN_JWT_SECRET` | 管理端 JWT 签名 | **固定值**（每次重启变则已登录 token 全部失效） |
| `CORS_ALLOWED_ORIGINS` | 管理端本地地址 | 为空则拒绝一切带 `Origin` 的浏览器请求 |
| `ALERT_WEBHOOK_URL` | 告警推送地址 | 未配置则告警通道不启用（启动 WARN 提示），见 [`secur/web/审计与告警.md`](../web/审计与告警.md) |
| `ALERT_WEBHOOK_SECRET` | 机器人签名校验密钥 | 开启签名校验后每条推送带 `timestamp` + `sign`；未配置则不签名 |

### 3.3 · 数据库账号最小权限

| 项 | 口径 |
|---|---|
| 应用账号权限 | **仅 DML**（`SELECT` / `INSERT` / `UPDATE` / `DELETE`）—— **无 `DROP` / `ALTER` / `GRANT` / `CREATE`** |
| DDL 执行 | 由人工提权执行（库结构变更流程见 [`schema/README.md`](../../schema/README.md)），应用账号不得持有 |
| 目的 | 即使应用被攻破（如出现注入或 RCE），也**打不出删库 / 改结构**这一档破坏 |

## 4 · 时序侧信道防护

所有「比对秘密」的场景（密钥、token、验证码）一律 **`MessageDigest.isEqual`（等时比较）**。

> 🔴 **不可用 `String.equals()` 或 `==` 替代**：它们会**在首个字节不同处提前返回**，攻击者可据响应时间差逐步缩小口令空间。同理，登录路径须保持「账号不存在时仍执行一次 BCrypt 比对」以抹平耗时差。

## 5 · 异常与信息暴露

| 场景 | 口径 |
|---|---|
| 未捕获异常（兜底 500） | 统一文案（如「服务器繁忙，请稍后再试」）；**堆栈只入日志，不回客户端** |
| 反序列化失败 | 不透出 cause |
| **内部非法参数（`IllegalArgumentException` 等）** | 统一返回**受控文案**，原始 `message` 仅入日志 —— 内部枚举值 / 字段名 / 约束信息不得外显（给攻击者的结构探测线索） |
| 业务可读提示 | 只由**受控业务异常**（`BusinessException`）承担，文案为可展示给用户的最终形态 |
| 框架痕迹 | 生产关闭调试页与详细错误信息；不暴露框架版本类响应头 |
| 业务码唯一判据 | 端上只读响应体 `code`，**不解析 `message` 文本** |

## 6 · 数据与接口基线（反向证据）

| 维度 | 结论 |
|---|---|
| **SQL 注入** | **无** —— 全量 ORM 包装器 + `#{}` 占位；XML 无 `${}`；无 JDBC 字符串拼接 |
| **敏感数据回显** | `openid` / 口令 / token **不出现在任何 VO**；仅以布尔（如「是否已绑定」）暴露 |
| **文件上传** | 扩展名白名单 + 魔法字节嗅探 + 大小上限 + 图像尺寸与像素上限 + 编号重命名（不沿用原名，防路径穿越）+ 云端内容安检 |
| **静态资源映射** | 上传根目录直映射；写入侧已做路径归一化，读取侧依赖框架 `PathResource` 默认防穿越 —— **当前安全** |
| **调试面** | 接口文档默认关闭（仅开发环境开启）；生产仅开放健康检查 / 基础信息端点，且**不回显细节** |
| **前端 XSS** | 两端全站模板自动转义，无 `v-html` / `eval` / 危险 `innerHTML` |
| **前端密钥** | 前端产物内**零密钥** |

## 7 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| SQL 注入 | 参数化查询（结构性消除） | — | — |
| 限流绕过（多实例各记各的） | — | **≥2 实例前下沉 Redis**（触发条件） | — |
| 内部信息探测（异常 message / 调试面） | 异常类型 + 生产开关 | 受控文案 / 默认关闭 | 高频探测 ⇒ 告警 |
| 上传型攻击（图片马 / 炸弹 / 穿越） | 白名单 + 魔法字节 + 尺寸 + 像素 + 重命名 | `400` | 审计（高频则告警） |
| 秘密比对时序侧信道 | — 等时比较（结构性消除） | — | — |
| 数据库账号越权（删库 / 改结构） | — | 应用账号**仅 DML** | — |
