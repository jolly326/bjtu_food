# S-02 · 鉴权与归属校验

> 安全设计真源：本目录 S-01 · S-02 · S-03 · S-04。

## 端上不传身份（红线）

- 全部接口的身份一律来自**服务端从凭证解析**（见 [S-01](./S-01-身份与凭证.md)）。
- **请求体 / query 一律不接受** `userId` / `openid` 一类用户标识字段 —— 收到即视为**参数非法**。
- 学生端**没有「按用户读取」的端点**：反馈只写不读，归属字段由服务端从凭证解析后写入。

## 归属校验口径

| 场景 | 处置 |
|---|---|
| 写操作的归属（学生端 `POST /feedback`） | `user_id` 取自凭证，**请求体不接受用户标识** |
| 运营端操作**不存在 / 已删除**的记录 | **`4001`「资源不存在」**，与「无权限」同一响应 |
| 🔴 意图 | **不暴露记录是否存在**（避免 ID 枚举探测） |
| 越权尝试的留痕 | **不落库**（无审计表）—— 与「管理端不做操作日志」同一口径 |

## 出参最小化

| 规则 | 说明 |
|---|---|
| 学生端出参**不含** `userId` / `openid` | 端上不需要——身份只用于服务端归属 |
| 学生端出参**含** `dishId` | 端上反馈以它作为目标标识，不构成跨用户暴露 |
| 运营端出参**不含**用户标识 | 全匿名（反馈数据均无用户标识） |
| 学生端内容端点不返回任何用户数据 | 推荐 / 字典均为纯内容（**同样要求凭证**，无「公开端点」态） |

## 鉴权矩阵

🔴 **学生端所有业务端点统一要求凭证** —— 推荐 / 字典等**内容端点同样需学生凭证**，没有「公开端点」这一态。

| 端点组 | 要求 | 未满足 |
|---|---|---|
| `POST /auth/wechat-login` | 🔓 公开（**唯一例外**：换凭证本身不能要求凭证） | — |
| 学生端其余全部端点（`GET /dishes` · `POST /dishes/recommend` · `POST /feedback`） | 🔑 需携带学生端凭证 | `401` |
| `/admin/**`（除 `POST /admin/sessions`） | 🔑 运营端 bearer（**独立 secret**） | `401` |
