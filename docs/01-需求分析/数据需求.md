# 需求分析 — 数据需求

> 版本：v2.0 | 更新日期：2026-07
>
> 设计原则：满足 3NF（第三范式），消除传递依赖和部分依赖。

---

## 一、新增表

### 1. dish_promotion 菜品活动表

**用途**：记录菜品的限时活动/特价信息，与 dish 1:1 关联（有活动时才有记录）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK | 主键 |
| dish_id | BIGINT | NOT NULL, UNIQUE, FK→dish | 菜品ID，唯一保证一道菜最多一个活动 |
| promotion_price | INT | NOT NULL | 活动价格（分） |
| end_time | DATETIME | NOT NULL | 活动截止时间 |
| created_at | DATETIME | NOT NULL | 创建时间 |

> 满足 3NF：活动价格和截止时间只依赖于活动本身，不依赖 dish 的其他字段。

### 2. dish_tag 菜品标签表

**用途**：菜品标签，解决原 `tags` 字段逗号分隔违反 1NF 的问题

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK | 主键 |
| dish_id | BIGINT | NOT NULL, FK→dish | 菜品ID |
| tag | VARCHAR(30) | NOT NULL | 标签名，如 `recommended`, `spicy`, `halal` |

> 满足 1NF：每个标签独立成行，可扩展、可搜索。

### 3. review_useful 评价喜欢表

**用途**：记录学生对评价的"喜欢"投票

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK | 主键 |
| user_id | BIGINT | NOT NULL, FK→user | 投票用户 |
| review_id | BIGINT | NOT NULL, FK→review | 被投票评价 |
| created_at | DATETIME | NOT NULL | 投票时间 |

> UNIQUE(user_id, review_id)：同一用户对同一评价只能投一票。

### 4. user_feedback 用户反馈表

**用途**：用户通过"联系开发者"页面提交的建议和Bug反馈

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK | 主键 |
| user_id | BIGINT | NOT NULL, FK→user | 提交用户 |
| content | TEXT | NOT NULL | 反馈内容 |
| contact | VARCHAR(100) | DEFAULT NULL | 联系方式（选填） |
| status | VARCHAR(20) | NOT NULL, DEFAULT 'pending' | `pending` / `read` / `resolved` |
| created_at | DATETIME | NOT NULL | 创建时间 |

## 二、扩展字段（已有表）

### stall 表

| 新增字段 | 类型 | 约束 | 说明 |
|---------|------|------|------|
| owner_id | BIGINT | FK→user | 档口老板用户ID，用于数据隔离 |

### dish 表

| 新增/修改字段 | 类型 | 约束 | 说明 |
|-------------|------|------|------|
| status | VARCHAR(20) | NOT NULL, DEFAULT 'off' | `off`(下架) / `pending`(待审核) / `approved`(已上架) / `rejected`(已驳回) |
| is_new | TINYINT(1) | NOT NULL, DEFAULT 0 | 是否标记为新品 |
| created_by | BIGINT | FK→user | 提交者用户ID（档口老板） |

> 注：原 `tags`, `is_promotion`, `promotion_price`, `promotion_end_time` 字段移至 dish_tag 和 dish_promotion 表。

### user 表

| 新增字段 | 类型 | 约束 | 说明 |
|---------|------|------|------|
| status | VARCHAR(20) | NOT NULL, DEFAULT 'active' | `active`(正常) / `frozen`(冻结) / `banned`(封号) |

> 原 status 只有 `active/disabled`，扩展为支持冻结和封号。

## 三、数据关系（3NF）

```
user（学生/档口老板/管理员）
  ├── 1:N review（评价）
  ├── 1:N review_useful（"喜欢"投票，作为投票者）
  ├── 1:N user_feedback（反馈）
  └── 1:1 stall（档口，仅档口老板）

canteen
  └── 1:N stall

stall
  ├── N:1 canteen（所属食堂）
  └── 1:N dish

dish
  ├── N:1 stall（所属档口）
  ├── 1:N review（收到的评价）
  ├── 1:N dish_tag（标签）
  └── 0:1 dish_promotion（活动，可选）

review
  ├── N:1 user（评价者）
  ├── N:1 dish（被评菜品）
  └── 1:N review_useful（收到的"喜欢"投票）
```

## 四、数据量预估

| 表 | 初期预估 | 说明 |
|----|---------|------|
| user | 200-500 | 一个学期活跃用户 |
| stall | 20-30 | 校内食堂档口 |
| dish | 100-200 | 每档口5-10道菜 |
| dish_tag | 300-800 | 每道菜2-4个标签 |
| dish_promotion | 10-30 | 同时进行的活动 |
| review | 500-2000 | 学生评价 |
| review_useful | 1000-5000 | 投票数据较大 |
| user_feedback | 50-200 | MVP阶段反馈量 |
