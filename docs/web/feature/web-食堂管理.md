## 介绍

维护**食堂（`canteen`）**这一最上层位置容器。食堂是档口的归属：学生端菜品卡上的「食堂名」由 `dish → stall → canteen` 联表得出，故食堂改名会**全站即时生效**。

**职责边界**：本功能只管食堂自身（名称 / 简介 / 排序 / 启停），**不管**档口（B-04）与菜品（B-05）。

**删除约束**：食堂下仍有档口时**禁止删除**，返回 `400` 并提示「请先移除或改挂其下档口」——避免出现无归属的孤儿档口。无档口的食堂可直接删除。

**停用语义**：食堂停用（`status='off'`）**不级联停用其下档口 / 菜品**；公开侧的可见性判据只看 `dish.status='on'`（红线：公开可见性唯一判据）。停用食堂仅影响「新增档口时是否可选该食堂」。

**排序**：`sortOrder` 升序，供管理端列表与将来可能的字典下发使用；**学生端当前无食堂字典端点**，故不对外下发。

**口径边界**：食堂**不维护坐标 / 地址**——公开侧位置表达固定为「食堂名 + 档口楼层」（不读坐标列）。「按距离排序」属演进预留，做之前须重新拍板。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/admin/canteens` | 🔑 | 食堂列表（含停用，按 `sortOrder` 升序；**不分页**——食堂量级为十数条） |
| POST | `/admin/canteens` | 🔑 | 新建食堂 |
| PUT | `/admin/canteens/{id}` | 🔑 | 修改食堂（不存在返回 `4001`） |
| PUT | `/admin/canteens/{id}/status` | 🔑 | 启停切换（幂等） |
| DELETE | `/admin/canteens/{id}` | 🔑 | 删除食堂；其下仍有档口返回 `400` |

## 字段

### 请求 · 新建 / 修改（`CanteenSaveReq`）

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `name` | string | 是 | 食堂名称（1~32 字，全站唯一） |
| `description` | string | 否 | 简介（≤200 字，未传表示不改动） |
| `sortOrder` | number | 否 | 展示顺序（升序，默认 0） |

### 响应 · `CanteenVO`

| 字段名 | 类型 | 中文解释 |
|---|---|---|
| `id` | number | 食堂 ID |
| `name` | string | 食堂名称 |
| `description` | string | 简介（无为空串） |
| `sortOrder` | number | 展示顺序 |
| `status` | string | 状态：`on` 启用 / `off` 停用 |
| `stallCount` | number | **其下档口数**（联表统计，供删除前判断与列表展示） |
| `createdAt` | string | 创建时间 |
| `updatedAt` | string | 更新时间 |

### 错误码

| 码 | 场景 |
|---|---|
| `400` | 名称为空 / 超长 / 重名；删除时其下仍有档口 |
| `4001` | 食堂不存在 |

## 数据（读写）

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `canteen` | 增改删查 + `sort_order`、`status` | 食堂本体 |
| `stall` | 删前计数（`canteen_id` 计数） | 删除约束校验 |

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **新增删除约束**：现有实现可直接删食堂，本功能要求「其下无档口才允许删」。
- **新增 `stallCount` 出参**：现有列表不下发档口数。
- **食堂不维护坐标**：本功能明确不含坐标 / 地址字段（与公开侧口径一致）。
