## 介绍

维护**档口（`stall`）**——菜品的直接归属。档口**必须挂靠一个食堂**（`canteenId` 必填），学生端菜品卡的位置行「食堂名 + 档口楼层」即由档口的归属食堂与 `floor` 拼出。

**与食堂的分工**：食堂是容器（B-03），档口是容器内的具体窗口；档口额外持有**楼层**与**窗口号**，这两项是学生找到实体的关键信息。

**删除约束**：档口下仍有菜品时**禁止删除**，返回 `400` 并提示「请先移除或改挂其下菜品」——避免孤儿菜品（孤儿菜品在公开侧会变成「位置信息缺失」的脏数据）。

**改名影响**：档口改名会**全站即时生效**（菜品详情的位置行走联表），不做历史快照。

**纠错采纳的落点**：学生在纠错里填的档口名是**自由文本**，管理员采纳时若现有档口无匹配，可在此新建档口后回 B-11 完成采纳（两段式档口确认的「另一侧」）。

**停用语义**：档口停用**不级联停用菜品**——公开可见性唯一判据是 `dish.status='on'`（红线）。停用档口仅表示「不再新增菜品挂靠」。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/admin/stalls` | 🔑 | 档口列表（可选 `canteenId` 筛选；按食堂排序 + 档口排序升序；**不分页**） |
| POST | `/admin/stalls` | 🔑 | 新建档口 |
| PUT | `/admin/stalls/{id}` | 🔑 | 修改档口（不存在返回 `4001`） |
| PUT | `/admin/stalls/{id}/status` | 🔑 | 启停切换（幂等） |
| DELETE | `/admin/stalls/{id}` | 🔑 | 删除档口；其下仍有菜品返回 `400` |

### 请求参数（`GET /admin/stalls`）

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `canteenId` | number | 否 | 按食堂筛选；不传 = 全部 |

## 字段

### 请求 · 新建 / 修改（`StallSaveReq`）

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `canteenId` | number | 是 | 所属食堂 ID（必须存在，否则 `400`） |
| `name` | string | 是 | 档口名称（1~32 字） |
| `floor` | string | 否 | 楼层（如 `1F`；≤16 字） |
| `windowNo` | string | 否 | 窗口号（如 `3号窗口`；≤32 字） |
| `sortOrder` | number | 否 | 展示顺序（升序，默认 0） |

### 响应 · `StallVO`

| 字段名 | 类型 | 中文解释 |
|---|---|---|
| `id` | number | 档口 ID |
| `canteenId` | number | 所属食堂 ID |
| `canteenName` | string | **所属食堂名称**（联表带出，列表直接可读，免二次查询） |
| `name` | string | 档口名称 |
| `floor` | string | 楼层（无为空串） |
| `windowNo` | string | 窗口号（无为空串） |
| `sortOrder` | number | 展示顺序 |
| `status` | string | 状态：`on` / `off` |
| `dishCount` | number | **其下菜品数**（联表统计，供删除前判断） |
| `createdAt` | string | 创建时间 |
| `updatedAt` | string | 更新时间 |

### 错误码

| 码 | 场景 |
|---|---|
| `400` | 名称为空 / 超长；`canteenId` 不存在；删除时其下仍有菜品 |
| `4001` | 档口不存在 |

## 数据（读写）

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `stall` | 增改删查 + `canteen_id` / `floor` / `window_no` / `sort_order` / `status` | 档口本体 |
| `canteen` | 读 `name` 校验归属存在、回填 `canteenName` | 所属食堂 |
| `dish` | 删前计数（`stall_id` 计数） | 删除约束校验 |

## 与当前代码的差异

> 本节集中登记与现有代码的差异；清零即写「无」。

- **新增删除约束**：现有实现可直接删档口，本功能要求「其下无菜品才允许删」。
- **新增 `canteenName` / `dishCount` 出参**：现有列表只回本表字段，食堂名由前端另查。
- **`status` 语义收窄**：明确停用**不级联**影响菜品可见性（现有实现未明示，易被误读为「停用档口 = 其菜品下架」）。
