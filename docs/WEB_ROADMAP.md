# Web 管理端迭代路线图（上线后）

> 原则：**小程序先行上线**，Web 端「管理刚需」已具备，以下为上线后按优先级迭代的功能项。
> 决策权：技术负责人 + UI/UX 设计师评审后实施。

---

## P0 · 上线后立即做（影响运营效率/数据安全）

| # | 功能 | 现状 | 价值 | 涉及 |
|---|------|------|------|------|
| W-1 | 学生账号重置密码 | 仅能启用/禁用学生账号，无法重置密码 | 学生忘密码无法自助（无旧密码修改入口），运营需介入；重置密码可降低账号流失 | 后端 `AdminStudentController` 加 reset 接口 + Web 用户管理加按钮 |
| W-2 | 操作日志可检索 | 仅列表/筛选，无操作人搜索 | 异常操作排查效率 | 前端加搜索框（后端已支持参数） |
| W-3 | 默认管理员改密提醒 | 默认 `admin/123456` 明文 | 上线安全红线 | 首次登录强制改密（或登录页提示） |

## P1 · 上线后 1-2 周（体验补强）

| # | 功能 | 现状 | 价值 | 涉及 |
|---|------|------|------|------|
| W-4 | 通知管理入口 | 通知仅系统自动生成，无管理页面 | 管理员无法查看/推送运营通知（如活动公告） | 后端 `AdminNotifyController` + Web 通知管理页 |
| W-5 | 菜品批量编辑 | 单条编辑（详情页） | 食堂改价/改标签需逐条，效率低 | Web 菜品表格加「批量设置价格/标签」 |
| W-6 | 评价导出 | 仅菜品/档口详情内查看 | 舆情分析、数据归档 | 复用 ReportExport 扩展评价导出 |
| W-7 | 档口菜品排序 | 无拖拽排序 | 档口菜品展示顺序不可控 | 后端 sort_order + Web 上移/下移 |

## P2 · 上线后 1 个月（数据驱动）

| # | 功能 | 现状 | 价值 | 涉及 |
|---|------|------|------|------|
| W-8 | 工作台趋势图 | 指标卡仅当日数值 | 无法看增长趋势 | ECharts 折线（近 7/30 天菜品上架/评价/动态/反馈量） |
| W-9 | 学生活跃洞察 | 无 | 运营决策（高频档口/菜品/时段） | 聚合查询 + 图表 |
| W-10 | 反馈分类统计 | 反馈列表无统计 | 快速定位高频问题类型 | Web 加类型占比卡片 |

## P3 · 远期（可评估）

| # | 功能 | 说明 |
|---|------|------|
| W-11 | 多校区数据隔离 | 如未来多校区，需数据按校区过滤 |
| W-12 | 操作审计导出 | operation_log 定期归档导出 |
| W-13 | 小程序端运营位 | 首页运营位（Banner 已支持 target_type，可扩展图文位） |

## 执行顺序

```
P0（W-1~W-3）→ 上线后第 1 周完成，安全+运营刚需
P1（W-4~W-7）→ 第 2-3 周，体验补强
P2（W-8~W-10）→ 第 4 周起，数据驱动
P3（W-11~W-13）→ 按业务发展评估
```

## 完成判定

每项按「技术负责人技术评审 → UI/UX 设计评审 → 质量把控工程师门禁」闭环（遵循 `docs/WORKFLOW.md`）。
