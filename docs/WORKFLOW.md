# 食在交大 · 多 Agent 协作工作流

> 本文件定义多 agent（及用户）如何协作。三份"权威 / 执行"文档各司其职，互不越权。
>
> - **基础规范基线**：`project_spec.md`（最高权威，**仅技术负责人可改**）
> - **执行单元**：`tasks/task-XX.md`（验收标准 + 接口契约 + 依赖）
> - **角色权限**：`.codebuddy/agents/*.md`（各 agent 能改 / 不能改）
> - **经验回流**：`.codebuddy/memory/`（踩坑记录，定期提炼进 spec 红线）

---

## 1. 文档分层与阅读顺序

新 agent / 协作者进入项目，**严格按此顺序阅读**，避免各读各的、漏看红线：

1. `project_spec.md` —— 先懂**不可违背的红线**与跨端边界（最薄、最高权威）
2. `.codebuddy/agents/` 中**自己的角色**文件 —— 懂权限边界（什么能改、什么不能碰）
3. `tasks/` 中认领的 `task-XX.md` —— 懂验收标准与接口契约
4. 本文件 `docs/WORKFLOW.md` —— 懂流程与角色交接

---

## 2. 主链路（需求 → 上线）

```
用户提出需求
  │
  ├─① 技术负责人：讨论定样；必要时修订 project_spec 红线（唯一能改 spec 的角色）
  │      产出：spec 变更 + 任务拆分
  │
  ├─② UI-UX 设计师：与用户逐页讨论 UI/UX 设计，更新 docs/mini-app-ui.md（小程序端）
  │      顺序：先于 task 生成，设计未定稿不派活；产出页面心智模型/交互决策/视觉规范
  │      边界：不修改业务代码；视觉规范变更经技术负责人落 spec §4
  │
  ├─③ 技术负责人：依据定稿的 mini-app-ui.md 写 tasks/task-XX.md
  │      要求：带【验收标准】【接口契约】【依赖】，且必须引用 spec §条款与 UI 文档对应页
  │
  ├─④ 开发工程师（后端 / 小程序 / Web）：按 task 写码
  │      红线：不得修改 spec / tasks / agents / docs/mini-app-ui.md；发现 spec 漏洞 → 提技术负责人，不绕过
  │      产出：代码
  │
  ├─⑤ 质量把控工程师：门禁核对
  │      依据：spec 红线 + task 验收标准 + mini-app-ui.md 设计（可机器核对的硬指标优先）
  │      结论：过关 → 交付；不过 → 退④并指明缺陷 + 依据（spec § / task 验收条 / UI 文档页）
  │
  └─⑥ 踩坑回流：记入 .codebuddy/memory/，定期由技术负责人提炼为 spec 红线
```

---

## 3. 各角色交接物

| 角色 | 产出 | 交接给 |
|------|------|--------|
| 技术负责人 | spec 变更 + task-XX | 开发工程师 |
| UI-UX 设计师 | 定稿 docs/mini-app-ui.md（逐页设计） | 技术负责人（据此拆 task）；不动业务代码 |
| 开发工程师 | 代码 | 质量把控工程师 |
| 质量把控工程师 | 「质量过关 / 退回（含依据）」结论 | 开发工程师（退回时） |
| UI-UX 设计师 | 页面心智模型 / 交互决策 | 技术负责人（落 §UI 规范）；不动业务代码 |
| 用户 | 需求拍板 + **编译与真机 / 模拟器验证** | 全体 |

> **编译与验证归属用户**：agent 不执行 build / run / 真机验证，仅写码 + 给验证指引。

---

## 4. 铁律

1. 一切冲突以 `project_spec.md` 为准；spec 只能由技术负责人修改。
2. 每个 task 必须引用 spec 条款；spec 无对应条款时，先退回技术负责人补，不擅自开工。
3. 开发不得修改 spec / tasks / agents；spec 漏洞走「提技术负责人」通道，不绕过。
4. 踩坑必须回流 memory，并定期提炼为 spec 红线（反模式进基线，避免重复踩）。
5. 文档越薄越权威；不另起与现有层重复的文档。

## 5. 反模式回流示例（持续追加，正式化后移入 spec 红线）

- **小程序双列瀑布流**：禁止「子组件 `wx:for` 内具名 slot 分发」——uni-app 编译到 mp-weixin 后，多个同名 `<slot name="card">` 分发失效，渲染塌缩成单列。必须改为组件内直接 `import` 并渲染子组件（如 `DishCard`），列表经 props 直传。→ **待技术负责人提炼进 `project_spec.md` §UI 规范红线**。
