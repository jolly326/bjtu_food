# 菜品信息纠错 — 页面 UI 设计稿

> 所属端：学生端（微信小程序）
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**；功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 本页采用「**锚定只读（不切换菜品）+ 动态属性 `AttributeGroup`**」形态 —— 进页自动预填菜品全部信息，用户**只改错项**，提交**仅带上改动过的项**（patch）；不进审核前置、**不实时生效**。
> ① 基础信息表单**双列并排**（菜品名称跨整行；售价｜食堂名称、楼层｜档口名称），消除短字段独占整行的纵向留白；② **楼层**由自由文本 input 改为**固定字典底部单选**（`BaseSheet` 弹层，汉字展示），端上做**汉字 ↔ 后端存储值**双向映射；③ `TagChip` 视觉强化（圆角 / 字重 / 删除叉尺寸）。
> 边界：**菜品纠错 = 依附某条菜品数据的专项修正**（自带 `dishId`、字段结构化）；**意见反馈 = 面向小程序本身的通用反馈**（见 [client-意见反馈.md](./client-意见反馈.md)）。两者互不耦合。
> **返工复核（设计侧通过）**：`TagChip` / `AttributeGroup` / `CorrectionForm` / `useCorrection` 的 **P1-1 触达尺寸**、**P1-2（`.ag:first-child` → 父级下传 `first`）** 及技术负责人 6 条建议均已闭环；开发提出的 3 条偏差裁决见「[触达尺寸口径（返工复核裁决）](#触达尺寸口径返工复核裁决)」章节。

- **入口（唯一）**：菜品详情页**信息卡名称行「信息有误?」入口** → `correctionUrl(dishId)`（`utils/routes`，禁止手拼 URL）⇒ 进页即按 `dishId` 拉详情**预填**；**页内不提供切换菜品**。
- 页面：`pages/correction/index`（独立分包 `pages/correction/`；二级页，**无 TabBar**；页底随全局 `page{}` 奶油米白 + `PageWallpaper`；页头 `AppHeader`「菜品信息纠错」+ 返回）。

## 视觉基线

**页面底**：低透明度手绘食物底纹（`PageWallpaper`），底色奶油米白。
**主卡片**：一枚大卡片承载全部表单 —— 底 `--bg-card`、圆角 **16rpx**（`--radius-btn`）+ `--border-color` 细描边 + 柔和低饱和卡阴影（`--shadow-card`）；卡片左右外边距 `--spacing-md`、内边距 `--spacing-lg`；**卡片内不使用分割横线**，靠间距 / 分组区分模块。

**色彩（设计参考值 → 落地口径）**：

| 用途 | 设计参考色值 | 落地口径 |
|---|---|---|
| 页面背景底色 | `#FFFBF5` | 全局 `page{}` 奶油米白（既有 Token） |
| 卡片容器底色 | `#FFFFFF` | `--bg-card`（**实色白卡**） |
| 主题橙（主色） | `#E57A3A` | `--color-primary` |
| 选中标签底 / 描边 | `#FFE7D6` | 底 `--color-primary-soft` / 描边 `--color-primary` |

| 正文文字 | `#3E3A36` | 正文文字 Token |
| 辅助 / 小字说明 | `#8A837B` | 次要文字 Token |
| 输入框默认底线 | `#EDE3D4` | `--border-color`（浅描边） |

> **卡片底口径**：半透底叠在 `PageWallpaper` 上会掉文字对比度，且与全站卡片（`--bg-card`）口径分叉，故本页主卡用**实色 `--bg-card`**，卡内层次改由「`--border-color` 细描边 + `--shadow-card` + `--bg-input` 凹槽」表达。参考色值与现行 Token 不一致时**一律以「落地口径」列为准**。

> **红线**：颜色**一律走语义 Token（`var(--color-*)`），禁裸 hex**（上表色值仅为设计参考，实现须落到 Token；确无对应 Token 时新增，原生 API 不接受 `var()` 的常量集中登记）。图标统一 `IconSvg`，**禁 emoji / 文本 / `content:'+'` 当图标**。

## 触达尺寸口径（返工复核裁决）

**基线**：全站独立可点件 ≥ **88rpx = 44pt**（`1rpx = 0.5pt`，`750rpx = 375pt`）。本页 `.row-field`（下划线输入行）/ `.ag-more`（候选折叠入口）/ `.ag-input-wrap`（自定义输入行）/ `ImagePicker` 添加格与删除钮均按 88rpx 落实。

| 元素 | 视觉尺寸 | 命中区 | 结论 |
|---|---|---|---|
| 属性 chip（选中 / 候选） | 高 ≈67rpx（≈33.5pt）= 内边距 16×2 + 文字行 30.8 + 描边 2×2 | 整 chip 全宽可点 | **登记例外**：属性区密集 chip 放行小于 44pt（见裁决③） |
| chip 删除叉 `.tag-chip-x` | 图标 **24rpx**（R40 由 20rpx 提升，见裁决②末句） | **64rpx × 64rpx**（= 32pt），完全落在 chip 内 | 命中区尺寸**不变**；仅图标放大 |
| 组内节距 | gap `--spacing-sm` = 16rpx | — | 行节距 ≥ 83rpx（≈41.5pt），吸收纵向误触 |
| **楼层 picker 单元格** | 高 **88rpx**（与同行 input 行等高） | 整单元格可点 | **独立可点件**，不适用 chip 例外 |

**例外成立的前提（红线，任一被突破即回退返工）**：
1. chip 内边距恒 `--spacing-sm --spacing-md`（16 / 24rpx），**不得再缩**；
2. 删除叉命中区 **≥ 64rpx**，组内 gap **不得低于 `--spacing-sm`**；
3. 本例外**仅限属性区成组 chip**；独立可点件（提交按钮 / 输入行 / 折叠入口 / 图片添加格与删除钮）仍须 88rpx。

**裁决①（chip 视觉高 67rpx vs 「裁决值」63rpx）— 接受 67rpx。** 「≈63rpx」是漏算选中态 `2rpx × 2` 描边的估算误差；正确算式 = `16×2`（内边距）+ `22 × 1.4 = 30.8`（文字行）+ `4`（描边）= **66.8rpx ≈ 67rpx**。**不得为凑 63rpx 去掉描边**：候选态用 `2rpx solid transparent` 与选中态**保等高**，两态切换时 chip 不跳高（此为刻意设计）。

**裁决②（删除叉命中盒是否外溢 / 是否抬 gap）— 保持现状：不外溢、不抬 gap。** 命中盒 64×64rpx 完全落在 chip 边框内；图标右侧 ≈24rpx 留白即 chip 自身右内边距（`--spacing-md`），不是错位 —— 图标紧贴文字（gap `--spacing-2xs`）反而强化「× 属于本标签」的归属感。外溢方案的代价：① 溢出 ≥16rpx 时命中盒会侵入**相邻 chip** 的标签体 / 删除叉热区 ⇒ **误删相邻标签**（破坏性误触，收益远小于代价）；② 为容下外溢需把 `gap` 抬到 ≥24rpx，选中区 chip 密度与候选面板内 chip 密度分叉。**若真机实测「× 难命准」，首选修法是把整 chip 语义改为「点标签体 = 删除」，或把 × 图标视觉由 20rpx 提到 24rpx——不是外溢热区。**

> **裁决②末句已采纳**：× 图标视觉由 **20rpx 提到 24rpx**（`IconSvg name="close" :size="24"`），命中盒**仍 64×64rpx 不变**。实现约束：命中盒靠 `margin: -17rpx -22rpx -17rpx 0` **负外边距居中抵消** —— 图标放大到 24rpx 后须重算为 `(64 − 24) / 2 = 20rpx` 并垂直方向抵消 chip 内边距，**保证选中 / 候选两态切换时 chip 视觉高不跳变**（裁决①的等高设计不得被本次放大破坏）。

**裁决④（R40 新增：chip 视觉高 67rpx 不受本轮视觉强化影响）— 维持 67rpx。** 本轮 `TagChip` 三项改动全部**不触碰高度**：① 圆角由 `--radius-pill`（999rpx 全圆）改为 `--radius-icon`（24rpx）—— 圆角只影响轮廓，不改变盒高；② 选中态字重由 `--weight-medium`(500) 提至 `--weight-semibold`(600) —— `line-height: 1.4` 不变，文字行仍为 30.8rpx；③ × 图标放大但命中盒尺寸不变、且经负外边距抵消。**故 67rpx 与行节距 ≥83rpx 全部维持，裁决①②③ 结论不变。**

> **字重取值说明**：`--weight-medium` = 500 在部分小程序端会回落至 400（真字重只有 400 / 600 两档时 500 被就近取整），故「强调选中态」必须用 **`--weight-semibold` = 600** 才生效（与 `client-首页菜品浏览.md` 的同源裁决一致）。

**裁决⑤（R40 新增：圆角取值）— 用 `--radius-icon`（24rpx），不新增 28rpx 档位。** 设计稿建议「圆角统一放大至 28rpx」，但 `App.vue` 圆角标度为 `8 / 16(3 个别名) / 24 / 32 / 48 / 999`，**无 28rpx 档**。按「Token 标度内取最近档、不为单页新增标度」的既有原则，取 **`--radius-icon` = 24rpx**。理由：`--radius-tag`(16rpx) 对 chip 过方（全圆 → 16rpx 是「反向圆角」视觉），`--radius-card`(32rpx) 又过于方正；24rpx 兼顾圆润与密度。**禁**在本页裸写 `28rpx`。

**裁决③（chip / × 是否拉到 88rpx）— 不拉，接受属性区更小刻度（chip 67rpx、× 命中 64rpx）。** 88rpx 基线针对**独立可点件**；属性 chip 是**成组密集选择控件**：单个 chip 宽 ≈130–180rpx（≈65–90pt）远超 44pt，纵向由 gap 16rpx 补足（节距 ≥83rpx ≈41.5pt，且点到缝隙不命中任何 chip）。若拉到 88rpx：多维度组的页长膨胀约 1.3 倍，与禁止项 2「防页面过长臃肿」直接冲突，且与全站筛选 chip 刻度分叉。**放行条件 = 上述三条前提全数保持。**

## 卡片结构（自上而下）

1. 顶部提示横幅
2. 菜品锚定信息区（只读，不可编辑）
3. 基础信息表单区（下划线轻量输入）
4. 属性编辑区（`AttributeGroup` ×N，核心）
5. 图片上传区（选填，≤3 张）
6. 提交说明文案
7. 底部提交按钮

### 1. 顶部提示横幅

- 文案：`已自动填充菜品原有信息，只修改存在错误的项目即可，提交后等待人工审核`
- 前导为**提示图标**（`IconSvg name="info"`，键已注册；**不用 emoji**，也不用未注册键如 `bulb` —— 未注册键会静默回退成 `empty` 空盒，观感全错）。
- 样式：底 `--color-primary-soft`、圆角 **16rpx（`--radius-xs`）**、文字 `--color-primary-text`、字号 `--font-tiny`；卡片内上下内边距 12rpx、左右 16rpx（`--spacing-sm`）。

### 2. 菜品锚定信息区（只读）

- 标题「**正在纠错**」；内容：**菜品名称** ｜ **食堂 · 楼层 · 档口**；辅助小字「来自菜品详情页，菜品固定不可切换」（**预填未就绪时**小字为「正在载入菜品信息…」，且此时**只渲染锚定卡、不渲染表单**，防误改误提交）。
- **楼层展示口径**：锚定卡中的楼层段**同样走映射**，展示为汉字（`B1` → 「负一层」），与表单单元格口径一致 —— 同一页内不得一处汉字、一处 `B1`。映射规则与兜底见「[楼层控件（R40 改造）](#楼层控件r40-改造自由文本--固定字典单选)」。
- 样式：底 `--bg-input`、圆角 `--radius-xs` 的浅米色小卡片，**无任何点击交互、无箭头**。
- 作用：防止用户改错菜品（与功能文档「表单内不允许切换」一致）。

### 3. 基础信息表单区（下划线轻量化输入 · R40 起双列并排）

- **行内样式**（不变）：标签在左，输入控件占剩余宽度；**输入框背景透明，仅保留底部横线**（**禁全包围矩形框**）。
- **布局规则**：**菜品名称**独占整行（名称文字长，拆分后每列宽度不足）；其余 4 个短字段**两两并排**，压掉纵向留白。

| 行 | 左列 | 右列 |
|---|---|---|
| 1（**跨整行**） | 菜品名称*　`input` | — |
| 2（双列） | 售价*　`input` + 行尾「元」 | 食堂名称*　`input` |
| 3（双列） | 楼层*　**picker 单元格**（R40 改造，见下） | 档口名称*　`input` |

- **实现口径**：双列用 **flex 两列**（每 `.cell` `flex: 1 1 0` + `min-width: 0`，列间 gap `--spacing-lg`），**不用 CSS grid** —— 本项目 `client/src` **零 grid 先例**（grid 仅 `web/` 使用），避免引入 mp-weixin 基础库差异。
- **标签宽度**：跨整行行 **160rpx**；双列行内 **96rpx**（双列每列 ≈307rpx，扣标签后余 ≈190rpx 供输入）。

| 标签 | 必填 | 呈现 | 预填 / 说明 |
|---|---|---|---|
| 菜品名称 | ✅ | 单行 input（跨整行） | 预填详情 `name`，可改；提交前非空、≤64 字 |
| 售价 | ✅ | 单行 input，digit 键盘，**行尾随单位小字「元」** | 预填详情 `price`（**API 层已完成 `fenToYuan` 分 → 元**，页面不换算金额）；单位「元」是**行尾小字**，不写进输入值、不参与提交；提交前 `yuanToFen` 转分（金额红线） |
| 食堂名称 | ✅ | 单行 input | 预填详情 `canteenName`（自由文本，无 picker / 无字典） |
| 楼层 | ✅ | **底部单选弹层**（R40 由 input 改造，见「楼层控件（R40 改造）」） | 预填详情 `floor`（**归属档口**）；恒存后端存储值，**展示层做映射** |
| 档口名称 | ✅ | 单行 input | 预填详情 `stallName`（自由文本） |

> **原价不纳入纠错**：原价随促销波动、属运营口径，短期打折不构成稳定事实；本页**只纠错现价（`price`）**，不渲染原价行。

- 交互：默认底线 `--border-color` → 聚焦切 `--color-primary`；必填标签的 `*` 与行内错误小字**同走 `--color-error`**（错误色 Token）；提交时校验必填，空值在**对应单元格下方**弹错误色行内小字（`padding-left` **跟随本列标签宽**：跨整行 160rpx / 双列 96rpx，不固定为 160rpx），输入行底线同步切错误色，**错误态优先于聚焦态**。

#### 楼层控件（R40 改造：自由文本 → 固定字典单选）

- **控件类型**：**底部弹出单选弹层**，走公共 `components/BaseSheet.vue`（底部弹层骨架唯一真源：遮罩点击关闭 / grabber / 下滑关闭手势 / 安全区 / 焦点回收），**本页不自建弹层、不用原生 `<picker>`** —— 本项目 `client/src` **零 `<picker>` / `<picker-view>` / `showActionSheet` 先例**，`BaseSheet` 是弹层唯一真源（`zToken` 走默认 `--z-sheet`）。
- **单元格形态**：汉字文案 + 右侧 `IconSvg name="arrow-down"`（`size="24"`，**已注册键**）；下划线样式与同行 input 一致，**高 88rpx**（独立可点件触达基线，见触达尺寸口径）。

**值模型（关键裁决）：`form.floor` 恒存「后端存储值」，映射只发生在展示层。**

这样 diff 比对、必填校验、提交组装**三处逻辑零改动**（无需反查字典、无需判断「是否等于原值」）。映射表（端上常量）：

| 后端存储值 | 页面展示汉字 |
|---|---|
| `B1` | 负一层 |
| `1F` | 一层 |
| `2F` | 二层 |
| `3F` | 三层 |
| `4F` | 四层 |

- **加载预填**：详情返回 `floor` → 单元格查表渲染汉字；**锚定卡同步走映射**（锚定卡展示「食堂 · **负一层** · 档口」，与单元格口径一致）。
- **提交**：用户选中汉字 → 写入 `form.floor` 的**对应存储值**（如 `B1`）；未改动则不产生 diff、不提交。
- **未命中兜底（新增，必需）**：管理端 `stall.floor` 仍是**自由文本**（≤16 字，`docs/web/feature/web-档口管理.md` 明确），故详情值**可能不在字典内**，必须容错：

| 详情 `floor` | 单元格展示 | 提交行为 |
|---|---|---|
| 命中字典（`B1` / `1F` …） | 对应汉字，picker 内该项高亮 | 未动 ⇒ **无 diff**（原值随 `form.floor` 保留） |
| **非空但未命中**（如 `B2` / `5F`） | **原值原样展示** + 次要小字「不在预设范围」；picker 内无选中项 | 未动 ⇒ **无 diff**（不因"无法映射"而清空或报错）；一旦改选字典项 ⇒ 覆盖为该存储值 |
| 空串 | 占位「请选择楼层」 | **必填不放行**（维持现状口径），错误小字落该单元格下方 |

- **禁止**：楼层**不得提供自由输入**（彻底杜绝 `B3` / `5F` 等字母数字格式进入展示层）；**不得**为未知值新造汉字；**不得**在提交时把汉字直接当存储值发出。

### 4. 属性编辑区（核心 · `AttributeGroup` 可复用组件）

> **数据驱动**：`GET /dishes/{id}` 的 `attributes`（键 = 维度 `fieldKey`，值 = 中文文本 / 数组）决定**已选**；`GET /dishes/{id}/attributes`（编辑态**按需**）的 `options` 决定**候选**；`valueType` 决定单选 / 多选。**每一个维度单独一组 `AttributeGroup`**（饮食属性 / 主料 / 口味 / 冷热 ……）。

- **零维度**（详情 `attributes` 为空）⇒ **整段属性编辑区不渲染**（无占位文案、不留空档）；单个维度无原始值时，仅该组已选区为空并显示占位小字「暂无，可从下方选择或直接输入」。
- **属性区无字段级错误**：属性不存在「必填」概念，故不设行内错误位；属性变更只承担「撤下过期失败提示」的职责。

**区域1 · 已选中标签区（常驻，永远可见）**
- 展示当前菜品**原始选中属性**（预填）；标签右上角**橙色关闭叉**（`IconSvg name="close"`，R40 起 `:size="24"`）。
- 选中态 chip：底 `--color-primary-soft`、2rpx `--color-primary` 描边、`--color-primary-text` 文字、**`--weight-semibold`(600)**（R40 强化）；圆角 **`--radius-icon`(24rpx)**（R40，由 `--radius-pill` 改，见裁决⑤）。
- 交互：点标签右上角 × 直接删除该项。
- **标签体本身无点击行为**：已选区 chip **不挂 `role=button`、不挂按压反馈** —— 避免「看着可点、按了什么也不发生」的死 affordance；删除语义唯一且明确地落在 × 上（回归 `AttributeGroup` 传 `:pickable="false"`）。
- 触达：chip 视觉高 ≈67rpx、删除叉命中区 64rpx（属性区密集 chip 的**登记例外**），见「触达尺寸口径」；组内 gap 恒 `--spacing-sm`。

**区域2 · 候选折叠面板（默认折叠）**
- 默认仅展示入口按钮「查看更多候选（共 N 项）▾」（展开后切「收起候选（共 N 项）」+ 箭头 `arrow-up` / `arrow-down` 互换）；点击展开候选标签**流式布局**（自动换行）；入口高度 88rpx。
- **面板底 = `--bg-input`**（比卡片底 `--bg-card` **深一档**，呈凹槽感）；高 240rpx 后纵向滚动。**定高兜底**：用户展开的长列表（>4 项）走 `height: 240rpx` 定高 —— mp-weixin 对 `max-height` **不保证**给 `scroll-view` 定高，无定高则内滚失效；≤4 项自动展开的短列表仍走 `max-height`，引擎不认时退化为自撑高度（内容全可见、不丢候选）。
- 候选（未选中）样式：底 `--bg-soft`、`--text-body` 文字、`--weight-medium`(500)、**2rpx 透明描边**（与选中态**等高**，但无可见描边 —— 描边是「选中态」独占的视觉标识）；圆角同为 `--radius-icon`(24rpx)（R40 两态统一）。
- **候选池含已选项、不去重**：已选项在面板内以**选中态**呈现（一眼看出「这个已经在上面了」），点它即**反选移除**；不隐藏、不置灰、不另排序。
- 点击逻辑：`multi`（多选：饮食属性 / 主料 / 口味）→ 点候选**加入**已选区，再点**取消选中**；`single`（单选：冷热）→ 点候选**直接替换**上方已选标签，**仅保留 1 个**；**`single` 再点当前已选项 = 清空该维度**（追认：允许把单选维度改成「未选」，等价于删掉已选 chip）。
- **数量降级**：候选数 **≤4** 时**默认直接展开、不显示折叠按钮**。
- **边界**：`options` 为空 → 隐藏候选入口（仅留自定义输入）；候选接口失败 → 隐藏候选入口（仅留自定义输入）。

**区域3 · 自定义输入框（每组底部常驻）**
- 占位：`输入自定义<维度名>，回车添加`。
- 规则：回车 / 添加 → 加入上方已选区；**自动去重**，禁空 / 纯空格，长度上限 **10 字**；自定义项**不入后端候选池**，仅存本次表单选中列表；`single` 维度自定义输入遵循单选（替换；输入值与当前已选项相同则视为无变化、不产生 diff）。
- **「添加」按钮**：草稿非空时出现在输入行行尾（**文字按钮**，非图标；视觉高 56rpx，命中区经伪元素纵向扩至**行高 88rpx**）；回车与点「添加」等价；草稿为空时**不渲染**（不留无效按钮）。

### 5. 图片上传区（选填）

- 标题：`补充实拍图片（选填，至多上传 3 张）`。
- 初始态（**与公共 `ImagePicker` 逐项对齐**）：`--bg-input` 浅底虚线框 + `IconSvg name="image"`（**「添加图片」语义，不是相机图标**）+ 文案「**添加图片**」；上传中该格显示环形 loading +「上传中…」。
- 上传后：缩略图三列网格 + 每张**右上角**删除钮（半透明黑圆底 `--badge-dark-bg` + 白叉 `IconSvg name="close"`，**热区 88rpx**）；点击缩略图预览大图（微信原生 `previewImage`）；满 3 张时末位显示 `3/3` 计数格（网格不塌、保留「已选」感知）；**破图走统一 `ImagePlaceholder`（灰底 + `image-broken`）且不进预览**。
- 实现复用公共 `ImagePicker`（多图形态，`max=3`），与**服务端上限 ≤3 一致**；**本页不另写上传 / 预览 / 删除逻辑，也不自绘删除钮位置**（图标、文案、位置一律随公共组件，避免两套口径漂移）。提交中删除钮与添加格同步弱化（0.5）并禁点。

### 6. 提交说明文案

- 文案：`提交修改后将进入人工审核，审核通过才会更新菜品信息`；浅灰小字，无警示色（**不暗示提交即生效**）。

### 7. 底部提交按钮

- 文案「**提交纠错**」（提交中「提交中…」）；**随内容滚动**（非固定底栏）。
- 正常可提交：主色 `--color-primary` 底、`--color-on-primary` 白字、圆角 **16rpx**（`--radius-btn`）、高 **88rpx**（= 44pt）、宽 100%（`AppButton` 公共件）。
- **禁用态**：**复用全站 `.is-disabled`**（`opacity 0.5` + `pointer-events: none` + 轻灰度，**唯一定义在 `App.vue`**）—— 本页**不自设**灰底 / 灰字档位，避免与全站按钮禁用口径分叉（`AppButton` 已按此口径实现）。
- 禁用触发条件（四选一即置灰）：必填项为空 **或** 表单**无任何改动**（无改动 = 无可提交内容）**或** 预填未就绪（`loading`）**或** 限频退避中。
- 置灰点击由**外层热区**兜底 toast（`AppButton` 禁用态 `pointer-events: none`，点击落到 `.submit-area`），文案指名缺失项 / 无改动 / 限频倒计时；提交中 `loading` 态（`opacity 0.6` + 禁点）防重复提交。

## 交互规则

1. **加载**：进页按 `dishId` 拉 `GET /dishes/{id}` 预填全部字段与原始属性；`GET /dishes/{id}/attributes` **按需**拉候选（默认不展开）。**楼层映射为纯前端查表，不额外请求**（R40：字典硬编码在端上，后端不提供楼层字典端点）。
2. **提交策略**：**仅提交改动项**（patch）—— 与初始快照逐字段比对，未改动不传；`attributes` 仅含**改动的维度项**；`price` 以**分**提交。
3. **成功**：Toast「提交成功，等待审核」→ 自动返回上一页（菜品详情）。
4. **失败**：页面底部**错误色文字**（`--color-error`）提示失败原因，**完整保留已填内容**（不清空表单）；用户一旦改动任一文本字段 / 属性 / 图片，即撤下这条过期提示（不改动则不撤，便于回头核对）。
5. **重置**：不单独提供重置按钮；退出页面即丢弃表单。
6. **边界**：某维度无原始属性 → 已选区为空，候选入口与自定义输入仍保留（可新增）；属性候选接口异常 → 隐藏候选入口，仅留自定义输入；**全部维度为空 → 整段属性编辑区不渲染**。
7. **限频退避**：命中 IP 限频（2 条/分钟、10 条/小时）后进入**退避期** —— 提交按钮置灰（`.is-disabled`）**且不发请求**，点击由外层热区 toast「提交过于频繁，请 N 秒后再试」（N = **实时倒计时**）；退避结束自动恢复可提交态；退避期内连点**不叠加请求、不延长封锁**。

## 禁止项（UI 约束）

1. 卡片内部**不使用分割横线**，靠间距 / 分组区分模块，避免割裂感。
2. 候选标签**不得默认全部平铺**，数量多必须折叠，防页面过长臃肿。
3. **不增加多余 Tab**；本页独立，不嵌入意见反馈页。
4. 输入框**禁全包围矩形框**，统一**下划线**轻量样式。
5. **不支持切换菜品**，锚定菜品只读，防提交错误菜品。
6. 颜色走 Token**禁裸 hex**；图标统一 `IconSvg` **禁 emoji**；事件统一 **`@tap`**；按压用 `background` / `opacity` 微降，**禁 `transform: scale`**。
7. **属性区 chip 不得再缩**：内边距恒 `--spacing-sm --spacing-md`、删除叉命中区 ≥ 64rpx、组内 gap 恒 `--spacing-sm`（见「触达尺寸口径」例外前提）；**禁**用「热区外溢」换视觉贴边（会侵入相邻 chip ⇒ 误删）。**圆角恒 `--radius-icon`(24rpx)**（两态统一），**禁**裸写 `28rpx`、**禁**退回 `--radius-pill`。
8. **禁用态不得自设档位**：一律复用全站 `.is-disabled`（`App.vue` 唯一定义）；**禁**本页再写灰底 / 灰字 / 自定义 opacity 作为禁用视觉。
9. **图片区不得离开公共 `ImagePicker`**：删除钮位置（右上角）、初始态图标（`image`）与文案（「添加图片」）**随公共组件**；**禁**本页自绘或改位。
10. **楼层不得提供自由输入**：**禁**在楼层单元格放 `input`、**禁**任何可键入 `B2` / `5F` 的路径；**禁**为字典外值新造汉字；**禁**把汉字当存储值提交。
11. **楼层弹层不得离开公共 `BaseSheet`**：**禁**本页自建底部弹层、**禁**改用原生 `<picker>` / `<picker-view>` / `uni.showActionSheet`（本项目 `client/src` 零此先例，`BaseSheet` 是弹层唯一真源）。
12. **双列布局不得用 CSS grid**：统一 **flex 两列**（`flex: 1 1 0` + `min-width: 0`）；**禁**在本页引入 grid（本项目 `client/src` 零 grid 先例）。

### 有哪些数据要显示、显示在哪个组件

| # | 数据（字段） | 来源 | 中文含义 | 显示位置 | 呈现 |
|---|---|---|---|---|---|
| 1 | `name` / `price` / `canteenName` / `stallName` | `GET /dishes/{id}`（`DishDetailVO`） | 名称 / 现价 / 食堂 / 档口 | `CorrectionForm` 各行（**预填**） | 价格分 → 元（**API 层** `fenToYuan`，页面不换算）；售价行尾「元」小字 |
| 2 | 楼层 | 同上（详情 `DishDetailVO.floor`） | 楼层 | 锚定卡 + 楼层行 | 预填详情 `floor`；提交为 `DishCorrectionReq.floor` |
| 3 | `attributes`（键 / 值） | 同上（**中文值**） | 各维度当前取值 | `AttributeGroup.selected` | 直接渲中文，**不翻译** |
| 4 | `fieldKey` / `valueType` / `options` | `GET /dishes/{id}/attributes`（按需） | 维度的键 / 单多选 / 参考候选 | `AttributeGroup.candidates` | 端上零硬编码 |
| 5 | `images` | 同上（详情） | 菜品图 | `ImagePicker`（≤3） | 预填详情图片数组，可增删 |
| 6 | 提交结果 | `POST /dishes/{id}/correction` 成功（`data` = null） | 成功 | 无界面（Toast + 返回） | — |
| 7 | 失败提示 | `400` / `4001` 的 `message` | 失败原因 | 页面底部**错误色文字**（`--color-error`） | 保留表单，改动即撤提示 |

### 入参提交

`POST /dishes/{id}/correction`（**patch**，仅改动项；`dishId` 在路径；公开匿名、IP 限频 2 条/分钟、10 条/小时）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 改动时传；非空、≤64 字 |
| `price` | number | 改动时传；**整数分**（端上 `yuanToFen`）、> 0 |
| `canteenName` | string | 改动时传；非空（自由文本） |
| `stallName` | string | 改动时传；非空（自由文本） |
| `floor` | string | 改动时传；非空、≤16 字（**归属档口**，采纳写回 `stall.floor`）。**端上以固定字典单选呈现（负一层/一层/二层/三层/四层），但提交仍是后端存储值（`B1`/`1F`/`2F`/`3F`/`4F`）** |
| `attributes` | object | 仅**改动的维度**；键 = 维度 `fieldKey`，值 = 中文文本 / 数组 |
| `images` | string[] | 改动时传；**≤3**（与服务端一致） |

> **空改动**（未提交任何改动项）→ 服务端 `400`「未提交任何改动」；端上应据此**禁用提交**。
> **楼层**：`floor` 为局部提交的改动项（string，传入非空 ≤16）；**归属档口**，采纳时写回 `stall.floor`。

### 错误码

`400` 菜品名称不能为空 / 超长 / 含敏感词 ｜ 价格必须为大于 0 的整数（单位：分）｜ 图片地址不合法 / 超上限 ｜ IP 限频「提交过于频繁（含剩余秒数）」｜ 空请求体「未提交任何改动」；`4001` 菜品不存在 / 已下架。

### 控件类型

`scroll-view`、下划线 `input`（名称跨整行 / 价格 digit 键盘，售价行尾「元」小字）、**楼层 picker 单元格（`BaseSheet` 底部单选弹层，汉字展示）**、**双列并排基础表单（flex 两列）**、`AttributeGroup`（选中 chips + 候选折叠面板 + 自定义输入）、`ImagePicker`（多图形态，`max=3`）、字段级错误定位（**输入行底线切 `--color-error`** + 行内错误色小字 + 首错 `scroll-into-view`）。
