# 意见反馈 — 页面 UI 设计稿

> 所属端：学生端（微信小程序）
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 页面为**一张表单、无页签**，固定「类型（**3 选 1**）+ 具体描述 + 截图」一套字段；
> **菜品信息纠错已迁出为独立页面**（[client-菜品纠错.md](./client-菜品纠错.md)，仅菜品详情页信息卡名称行「信息有误?」进入）——本页不含该类型与其结构化表单。

- 入口：
  - 「我的」页宫格「意见反馈」→ `feedbackUrl()`（缺省）⇒ 类型待用户选、恢复本地草稿；
  - 菜品纠错入口在**菜品详情页信息卡名称行「信息有误?」** ⇒ **独立页面** [client-菜品纠错.md](./client-菜品纠错.md)（`correctionUrl(dishId)`）；本页不承接菜品纠错。
- 页面：`pages/feedback/index`（页底随全局 `page{}` 底色 = 奶油米白 + `PageWallpaper` 壁纸层；页头 `AppHeader`「意见反馈」+ 返回）

## 全局视觉统一规范（全站唯一标准）

- **卡片规范**：纯白 `--bg-card`、圆角 `16rpx`（`--radius-btn`）、轻量化柔阴影 `--shadow-card`（已为低透明度，适配奶油手绘背景）、页面左右 `--spacing-md`、卡内统一内距 `--spacing-lg`。
- **线条统一（全页面 100% 一致）**：所有分割线、输入框边线、单选框描边、图片虚线框统一 `--border-color` + `1rpx` 粗细、低透浅灰；彻底消除粗细不一、实虚混杂。
- **品牌色克制（仅 3 处使用 `--color-primary`，其余控件 / 图标 / 文字禁用橙色）**：① 必填项星号 `*`；② 单选选中态填充 + 白勾；③ 底部提交主按钮。解决原页面多阶橙色混杂、与奶油手绘背景违和的问题。
- **文字层级（Apple HIG 梯度）**：模块标题 / 字段标签 = 中等字重 + 主文本色；选项主文案 = 常规字重 + 主文本色；辅助说明 / 占位 / 字数统计 = 浅灰次级、小一号。禁止标题加粗泛滥、选中文字权重跳动、辅助文字过粗。

## 表单卡（白色大卡片：圆角 **16rpx**（`--radius-btn`）+ `--shadow-card`，内距 `--spacing-lg`，页面左右 `--spacing-md` 留边）

> **卡片内仅收纳三类表单字段**，自上而下：**反馈类型 → 具体描述 → 上传截图**；三者之间以 `--spacing-lg` 上下留白分隔，统一单层卡片承载。
> **【提交反馈】按钮在表单卡片外部下方独立放置**（见下「提交反馈按钮」段），不计入卡片内。

### 1. 反馈类型（必填，竖排单选；整行可点、行高 ≥88rpx；选项**无独立灰色容器**）

必填星号 `*` 用主色 `--color-primary`（**品牌色仅 3 处使用**：选中勾、必填星号、提交按钮；其余一律禁用橙色）。单选控件：**未选中 = `1rpx` 浅灰细描边空心圆（`--border-color`），选中 = `--color-primary` 填充 + `20rpx` 纯白 `check` 图标**（`.type-check`，纯图形对读屏隐藏，选中语义由 `role="radio"` + `aria-checked` 表达）。选项 `label` **始终常规字重、不加粗**（选中态仅靠左侧橙色勾区分，杜绝权重跳动）。三个选项**竖排、纯白背景整行可点、行高 ≥88rpx**；**选项之间以 `1rpx` 细浅分隔线 `--border-color` 分隔**（最上 / 最下不加线），取消原独立灰色背景块，对齐项目「单白色大表单卡片 + 内部分隔线」范式。**按压反馈（iOS 质感）**：整行点击瞬时出现 `8%` 透明度浅灰底色（`rgba(0,0,0,0.08)`），松手恢复、无永久底色。三项（`label` 后括号内为 `hint`，缺省不渲染）：

| 顺序 | `value`（提交值） | `label` | `hint`（卡片副标题） |
|---|---|---|---|
| 1 | `bug` | 程序功能Bug | 页面、图片、评价等程序异常 |
| 2 | `suggestion` | 产品功能建议 | 新功能、交互优化好点子 |
| 3 | `other` | 其他相关问题 | 其余平台相关问题反馈 |

> `value` 必须落在服务端写入白名单内（非法值 400）；文案常量在端上（`types/feedback.ts` 的 `FEEDBACK_TYPES`），若后续要「改文案不发版」，改为服务端下发即可、渲染结构不变。

### 2. 字段区（固定一套，不随类型切换结构）

**A. 类型选择与描述区**

2.1 **具体描述**（必填，多行输入）：上限 **600 字**；**字数 `n/600` 常显在「具体描述」标题行右上角**（等宽数字）。占位文案随选中类型切换：

> 输入框**透明背景、取消灰底**，仅保留**底部 `1rpx` 细横线 `--border-color`** 作输入边界（弱化容器感）；**聚焦态底线切换为 `--color-primary` 高亮**，给予清晰焦点反馈。输入文本 `--text-primary`、占位 `--text-tertiary`、计数 `--text-tertiary`（等宽数字，`font-variant-numeric: tabular-nums` 防跳动）。
> 选中 `other` 时，描述框下方另展示浅灰辅助小字「若发现菜品资料有误，请前往对应菜品详情页提交纠错」—— 原塞在 `placeholder` 的菜品纠错业务提示**移出**单独呈现，占位只做输入引导。

| 类型 | 占位文案 |
|---|---|
| `bug` | 请描述bug现象、复现步骤 |
| `suggestion` | 描述你希望新增或改动的功能想法 |
| `other` | 描述你遇到的平台相关问题 |

（未选类型时占位为通用引导「先选择反馈类型，再描述你的问题」。）

2.2 **上传截图**（选填，**最多 1 张**）：`ImagePicker` 单图形态（`single`）—— 空态 = **透明虚线方框**（200rpx 见方，`1rpx dashed --border-color`，低透明度、非粗线，取消白底）+ 内部加号 +「添加图片」文字；有图 = 缩略图 + 右上角删除叉，点图看大图（微信原生预览）；**破图 → 统一 `ImagePlaceholder`（灰底 + `image-broken`）**，点它不进入预览。

> **菜品纠错**（选菜 + 七字段预填那套）**已迁出为独立页面** → [client-菜品纠错.md](./client-菜品纠错.md)；
> 本页只保留上面这一套通用反馈字段，**无第二套表单、不随类型切换结构**。

## 提交反馈按钮（卡片外部，独立放置）

> 组件 `AppButton`「提交反馈」位于**表单卡片外部下方**，撑满页面左右 `--spacing-md` 留白；按钮不属于表单卡片内部。**卡片底部 → 按钮顶部留白 `--spacing-xl`**（更大留白把按钮与表单在视觉上分开）。按钮为**纯文字极简主按钮**（低饱和暖橙实底 `--color-primary` + 纯白文字、圆角 `16rpx`、无任何装饰图形 / 多余 icon，严格对齐 Apple HIG 主按钮规范）。

未选类型 / 描述为空 ⇒ 置灰（置灰点击由外层热区 toast 缺失项）；提交中禁用防重复；成功 Toast「已提交，感谢反馈」+ 2 秒自动返回上一页。

**本地草稿**：仅缓存「类型 + 描述文本」（`uni.setStorageSync('feedback_draft')`）；图片是 COS 地址、重进可能失效，**不缓存**；提交成功后清除。

## 错误态 UI 规范（对齐 iOS 原生表单）

遵循 HIG 弱提示原则，拒绝粗暴红框 / 大面积警示色干扰：
- 校验错误：**仅字段下方展示浅红小字 `.field-error`**（`--color-error`）；
- **无输入框变红、无粗红边框**（描述框错误态不下红线，仅靠下方文字提示）；
- 自动滚动定位首个错误字段（`scroll-into-view`），逻辑不变。

### 有哪些数据要显示、显示在哪个组件

| # | 数据（字段） | 来源 | 中文含义 | 显示在哪个组件 | 呈现位置 / 形式 |
|---|---|---|---|---|---|
| 1 | 类型三项（`value`/`label`/`hint`/`placeholder`） | **端上常量** `types/feedback.ts` 的 `FEEDBACK_TYPES`（3 项：`bug` / `suggestion` / `other`；提交值受服务端白名单校验） | 类型选项与占位文案 | `IssueForm` 单选 + 描述框占位 | 选中项左侧橙色勾；占位随类型切换 |
| 2 | `content`（本地表单态） | 用户输入 | 具体描述 | `IssueForm` textarea + 计数 | **上限 600 字**，`n/600` 常显标题行右上角 |
| 3 | `images`（本地表单态） | `ImagePicker`（安检上传） | 截图 | `IssueForm` 单图虚线框 | ≤1 张；破图走统一占位 |
| 4 | 草稿（`type` + `content`） | `uni.getStorageSync('feedback_draft')` | 本地草稿 | 进页回填类型与描述 | 图片不缓存 |
| 8 | 字段错误 `errors` | 端上门禁 | 缺失或非法项 | 对应字段下方 `.field-error` + 错误边框 | 首个可定位错误字段 `scroll-into-view` |
| 6 | 提交结果 | `POST /feedback` 成功（`data` = null） | 成功 | 无界面（Toast「已提交，感谢反馈」+ 2 秒自动返回；表单重置、草稿清除） | — |
| 10 | 失败提示 | `400` / `4001` 响应 `message` | 失败原因 | 无界面（Toast 直透，兜底「没发出去，再试一次」） | 停留本页保留草稿 |

**入参提交**
| 接口 | 字段 |
|---|---|
| `POST /feedback` | `type` = `bug` / `suggestion` / `other`（服务端白名单校验）/ `content`（端上 ≤600 字、服务端 ≤1000）/ `images`（**≤1**） |

**错误码**：`400` 反馈类型非法 / 反馈内容不能为空 / 含敏感词 / IP 限频「提交过于频繁」/ 文本安检 `risky`
（菜品纠错的错误码见 [client-菜品纠错.md](./client-菜品纠错.md)）

**控件类型**：`scroll-view`、竖排单选（`role="radiogroup"` + `role="radio"` + `aria-checked`）、`textarea`（600 字 + 右上角计数 + 动态占位）、`ImagePicker`（单图虚线框形态）、字段级错误滚动定位
