# 邮箱认证 — 页面 UI 设计稿

> 所属端：学生端（微信小程序）
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 落点：**独立页面** `pages/auth/index`（分包 `pages/auth/`）——身份认证页（学号 + 邮箱验证码）；入口 = 「我的」页宫格「身份认证」格 / 菜品详情写评价等需认证操作 / 请求层 `4031`（**不置灰、点击跳转认证页、认证成功返回原页后续接原动作**）。

## 一、页面构成

`scroll-view` 纵向滚动，自上而下：

```
AppHeader（左「返回」文字 + 居中标题【身份认证】）
↓
【表单卡（白色圆角卡，承载全部表单内容）】
    学号输入项
    动态邮箱提示（学号合法后才展示）
    邮箱验证码输入项（右侧内联「获取验证码」描边胶囊）
    表单错误提示行（role="alert"，出错才渲染）
    【认证】主按钮
    功能说明小字
    隐私锁说明行
```

- 全部表单控件收拢进**单张白色圆角卡**，不平铺在背景图上。
- 步骤：输入学号 → 点「获取验证码」→ 输入 6 位验证码 → 点「认证」提交。
- 待办续接：由需认证入口跳入时记录的动作（如自动重新打开写评价表单），在**认证成功返回原页后由原页 onShow 续接**；未完成认证离开认证页 → 待办清除。
- **成功提示兼作资料层引导**：成功后 Toast「认证成功，可到「我的主页」完善昵称头像」（`icon: 'none'` 普通提示形态，长文案不截断）；**不跳转、不打断续接**（落点 = 「我的主页」身份卡「编辑个人信息」入口，仅认证态渲染）。

## 二、全局视觉规范

1. **卡片**：纯白底 `--bg-card`，`16rpx` 圆角（`--radius-btn`），轻量柔阴影 `--shadow-card`；左右外边距 `--spacing-md`。
2. **线条**：输入项底线统一 `1rpx` `--border-color`（与意见反馈页同款）。
3. **色彩（低饱和暖橙，克制使用）**
   - 主色落点：可点击控件、聚焦底线、认证主按钮。
   - 错误文字：`--color-error`（不加粗）。
   - 其余文字走三级灰度：主文本 / 次级灰 / 辅助浅灰。
4. **文字层级**
   - 输入文字：常规字重、`--text-primary`。
   - 占位文字：`--text-tertiary`。
   - 辅助说明：`--font-aux` + `--text-tertiary`。
   - 错误文字：`--font-aux` + `--color-error`、不加粗。

## 三、分模块 UI 规范

### 1. AppHeader 公共页头
- 左：文字「返回」，点击 `uni.navigateBack`；未完成认证自动清空待办动作。
- 居中标题：身份认证。
- 无右侧操作按钮。
- 与 `AppTitleBand` 的分工按既有裁定（**有返回用 `AppHeader`、无返回用 `AppTitleBand`，两者不合并**）。

### 2. 输入项（透明底 + 仅底部 1rpx 细线）
> 弱化容器、聚焦输入内容；聚焦时底线切换为主色。

#### ① 学号 `.input-field`
- 占位「学号」，`type="number"`。
- 未聚焦：底部浅灰细线；聚焦：底线切 `--color-primary`。
- 学号合法后，框下方自动出现动态提示小字：验证码将发送至 `xxx@bjtu.edu.cn`（`--text-tertiary`）。
- 学号非法：不阻塞输入，点击获取验证码 / 提交时校验，错误落到错误行；失焦时空 / 含非数字给出原因提示（不发起请求）。

#### ② 邮箱验证码 `.input-field--code`
- 占位「邮箱验证码」，**仅允许数字、最大长度 6**。
- 右侧内联「获取验证码」**描边胶囊** `.code-action`：

| 状态 | 样式 |
| ---- | ---- |
| 可点击 | 1rpx 主色描边 + 主色文字，全圆胶囊 |
| 冷却倒计时（60s） | 置灰（三级灰文字 + 灰描边），不可点击，文案 `58s后重发` |
| 发送在途 | 置灰不可点击，文案「发送中…」 |
| 学号为空 / 非法 | 置灰不可点击 |

- 胶囊视觉高 64rpx，命中区经 `::after` **仅纵向**扩至 ≥88rpx（a11y 44pt 下限，视觉尺寸不变）。

### 3. 表单错误行 `.form-error`（`role="alert"`）
- 默认不渲染；接口报错 / 校验失败才出现，位于输入区下方。
- 样式：**无背景色块**，仅浅红文字 + `IconSvg name="alert"` 小图标（24rpx）。
- 交互：点击即清除；输入新内容自动清除；`aria-invalid` 同步到两输入框。

### 4. 认证主按钮
- 用全站公共 `AppButton`（`type="primary"`）：撑满卡宽、`16rpx` 圆角、主色实底 + 白字、高 88rpx。
- 可提交态：主色实底「认证」。
- 禁用态：表单未填全 / 请求中 → 置灰（全局 `is-disabled`：降透明度 + 轻灰度）、不可点。
- 加载中：文案「认证中…」，防重复提交。

### 5. 底部说明（卡内、按钮下方）
1. 功能说明（`--font-aux` + `--text-tertiary`）
   > 验证码将发送至你的校园邮箱，完成身份认证后即可使用评价等功能
2. 隐私锁说明行（`lock` 图标 24rpx + 文字同行、垂直居中）
   > 仅用于核验本校校园身份，认证后将与当前微信账号绑定，不会用于其他用途

- 两行之间 `--spacing-sm`。

## 四、状态定义

### 状态 1：初始空表单（进入页面默认）
```
学号输入框（浅灰底线）
邮箱验证码输入框（浅灰底线 + 置灰【获取验证码】）
认证按钮（置灰不可点击）
两行说明文字
```

### 状态 2：学号输入合法
```
学号输入框（已输入）
动态提示小字：验证码将发送至 24301122@bjtu.edu.cn
邮箱验证码输入框（浅灰底线 + 可点击【获取验证码】胶囊）
认证按钮（置灰，等待验证码输入）
两行说明文字
```

### 状态 3：获取验证码冷却中
```
学号输入框
动态邮箱提示
邮箱验证码输入框 + 置灰【52s后重发】
认证按钮（置灰）
两行说明文字
```

### 状态 4：表单填写完成（学号 + 验证码均已输入）
```
学号输入框
动态邮箱提示
邮箱验证码输入框
认证按钮（激活，主色实底）
两行说明文字
```

### 状态 5：校验失败
```
学号输入框
动态邮箱提示
邮箱验证码输入框
⚠️ 验证码错误，请重新输入（浅红文字 + 图标，无底色）
认证按钮（置灰）
两行说明文字
```

## 六、交互细节

1. **焦点反馈**：激活时底线高亮为主色，柔和无闪烁。
2. **按压态**：胶囊、主按钮点击降透明度瞬时反馈，松手恢复。
3. **输入自动清错**：输入内容变更即清除错误行。
4. **冷却持久化**：`authStore` 维持 60s 倒计时，页面跳转返回后继续。
5. **成功续接**：认证成功后返回来源页，继续执行待办动作（如打开评价）；同时 Toast 引导「可到「我的主页」完善昵称头像」（资料层引导，不跳转）。

## 八、数据字段映射

| # | 数据（字段） | 来源 | 中文含义 | 显示在哪个组件 | 呈现位置 / 形式 |
|---|---|---|---|---|---|
| 1 | `username`（本地表单态） | 用户输入 | 学号 | 学号 `input`（占位「学号」，`type="number"`） | 输入内容仅本地持有 |
| 2 | `deriveCampusEmail(username)` | 端上派生（`api/user.ts`） | 推导出的校园邮箱 `{学号}@bjtu.edu.cn` | 提示行 `.email-hint` | 「验证码将发送至 {邮箱}」；**仅在学号合法时出现**，位于学号框正下方 |
| 3 | `code`（本地表单态） | 用户输入 | 6 位验证码 | 验证码 `input`（占位「邮箱验证码」） | 仅数字、`maxlength=6` |
| 4 | `codeCooldown`（端上态） | `stores/auth`（60s 冷却） | 发码冷却剩余秒数 | 「获取验证码」胶囊文案与禁用态 | 冷却中不可点（跨页面持久，重进续接），文案 `{n}s后重发` |
| 5 | 发码结果 `message` | `POST /auth/email-code` | 「验证码已发送」 | 无界面（Toast 呈现） | 验证码**不在响应中返回** |
| 6 | `UserInfoVO` 全字段 | `POST /auth/verify-email` | 账号信息（`bindEmail` 已写入） | **无界面**（整体写回 `stores/user`；页面不单独渲染字段） | 成功 → Toast「认证成功，可到「我的主页」完善昵称头像」+ 返回原页 |
| 7 | 错误 `message` | `400` / `401` 响应 | 验证码错误 / 不存在或已过期 / 账号状态异常 / 发码限频 | 表单错误行（`role="alert"`） | 浅红文字 + `alert` 图标、**无底色**；点击清除；`aria-invalid` 同步到两输入框 |
| 8 | 静态说明 | 端内文案常量 | 认证后可用的能力 | 表单下方功能说明 + 底部锁图标行 | 次级灰小字 |

**入参提交**
| 接口 | 字段 | 说明 |
| --- | --- | --- |
| `POST /auth/email-code` | `username` | 学号（端上推导邮箱，**不传 email**） |
| `POST /auth/verify-email` | `code` | 6 位验证码（邮箱由验证码记录推导） |

**错误码**：`400` 验证码错误 / 不存在或已过期 / 账号已被禁用 / 已注销；发码限频（同邮箱 60s 冷却、同 IP 3 次/分 + 10 次/时）｜`401` 未登录
**控件类型**：`scroll-view`、`input`（学号 / 验证码）、行内发码胶囊（冷却态）、全站主按钮、`role="alert"` 错误行
