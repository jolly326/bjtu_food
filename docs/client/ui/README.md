# UI 设计稿总览（按页面拆分）

> 本目录是「**有界面的**页面 UI 设计稿」唯一真源：每个页面（或页内承载物）一份独立文档，文件名以板块前缀开头。
> **与功能文档解耦**：本目录与 [`docs/client/feature/`](../feature/)（功能 / 接口 / 字段 / 数据）**各按自身标准分层** —— 分类标准、命名、粒度均可以不同。**不强制 1:1 对应，也不互相内部链接**；看功能流程 / 接口口径去 `docs/client/feature/`，看页面视觉 / 交互口径看本目录。
> 跨端 UI 口径以**本目录 + 各页设计稿**为准；仓库红线 / 协作纪律见 [`docs/client/feature/README.md`](../feature/README.md) 的「项目约定与红线」段。
> **本目录只写「当前口径」**：逐轮变更过程与**修订轮次均不维护**（如需回溯，从 git 历史查找对应提交）。
> **范围**：只收**有对应界面**的设计稿 —— **无页面 / 无弹层的能力（全局登录态、静默上报、已下线功能）不在此建文档**；**粒度以「一个界面单元」为准**，页内承载物不另立文件。
> **跨页口径另立一份**：[client-公共组件与形态基线.md](./client-公共组件与形态基线.md)（全站形态基线 + 公共组件规格 + 身份卡），**不在各页重复登记**。

## 跨页通用口径

### 跨页形态与组件口径

**跨页复用的形态口径（形状 / 间距 / 字号 / 色彩 / 状态 / 交互）、17 个公共组件的视觉规格、图片占位、身份卡（用户信息模块）统一口径 —— 一律以 [client-公共组件与形态基线.md](./client-公共组件与形态基线.md) 为唯一真源。**

| 口径 | 落点 |
|---|---|
| 全站形态基线（页面骨架 / 圆角 / 间距 / 字号 / 色彩 / 阴影 / 输入项 / 卡片 / 分隔线 / 状态 / 动效 / 层级 / 图标 / 图片占位） | 基线 §一 |
| 17 个公共组件视觉规格 | 基线 §二 |
| 身份卡（「我的」页用户信息模块 ↔ 「我的主页」用户信息卡） | 基线 §三 |
| 原生 API 例外登记（不接受 `var()` 的常量） | 基线 §1.16 |

本目录的页面设计稿**不得复述**上表规格 —— 只写页面级布局与**本页用法**（传什么、在哪、做什么）。

## 与功能文档的关系（解耦）

- 两套体系**各自独立**：本目录 = 页面视觉 / 交互；[`docs/client/feature/`](../feature/) = 功能流程 / 接口 / 字段 / 数据。**分类标准、命名、粒度互不约束，文档间不互相内部链接**。
- **粒度差异是正常的**（差异源于「一个界面单元」vs「一个功能/端点数」），当前两处：

| 功能侧（`docs/client/feature/`） | UI 侧（本目录） | 差异原因 |
|---|---|---|
| 写评价 / 删除本人评价 / 举报评价 = **3 份** | **1 份**「菜品详情 · 页内承载物」 | 功能各有独立端点与校验；UI 上是同一宿主页的三个承载物 |
| 隐私政策与用户协议 = **1 份** | **2 份**（隐私政策 / 用户协议） | UI 上是两个真实页面（共用 `DocPage` 外壳） |
