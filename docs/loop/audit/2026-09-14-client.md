## 缺失的业务原则

1. **排序口径原则**：首页/搜索的排序维度必须**单一且端上可见**——不得存在「有映射无入口」的排序能力，也不得让定位静默改变排序（重复 §7.17 第 2 条的端上版）。
2. **可点元素必须闭环**：任何具备可点外观或无障碍可点语义的控件，必须绑定真实动作；「占位按钮」不得以可点语义交付。
3. **接口消费原则**：`api/` 中对外导出的方法必须存在至少一个真实调用点，或明确标注为「预留（含拍板依据）」；禁止零消费死接口长期驻留。
4. **状态真源唯一原则**：同一展示能力（如标签、距离、取消状态）在三端只允许一个真源，不得 API 层与页面层各实现一次。
5. **错误码端上闭环原则**：后端可能返回的每个业务状态（含 403 的「无 openid」子情形）端上必须有可执行的恢复路径或明确降级，不得只 toast 后端 message 后卡死。
6. **类型零逃逸原则**：跨端 DTO 必须显式定型，平台运行时句柄（`wx`）之外不得引入 `any`（反馈页食堂树即违反）。
7. **UGC 安检不可绕原则**：凡产生公开可见内容的图片上传必须唯一走安检链路（`uploadUgcImage`），任何「无安检上传」函数只能用于头像等已登记例外，且命名须自证用途。
8. **死代码零容忍原则**：拍板后失效的分支（排序映射、品类、停用的状态位、已下线能力的注释/字段）应在同一变更内删除，不得以注释「留档」形式长期驻留。
