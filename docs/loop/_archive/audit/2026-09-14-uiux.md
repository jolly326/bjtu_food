## 缺失的业务原则

以下为**反复引发交互扯皮的业务原则缺位**（每条均为「因为没有这条原则，导致交互决策反复/两处口径不一」）：

1. **未定义「同一信息在端上只出现一次」的展示原则** → 评分/评价数在详情页两张卡各显示一次，每次改版都要重新讨论是否重复（UX-06 / UX-12）。
2. **未定义「点按必有反馈」的死控件禁令** → 出现了无 `@tap` 的「筛选」胶囊伪装成可点按钮，无原则可依、无门禁可拦（UX-03）。
3. **未定义「排序能力的可见性口径」** → 排序状态存在但无入口、默认序与文档口径不一致，用户对列表顺序无解释（UX-04）。
4. **未定义「提交类操作成功后的下一步指引」标准** → 反馈提交后用长文案 + 2s 自动返回草草收尾，用户不知去哪看进度（UX-05）。
5. **未定义「列表/信息区三态（空/失败/加载）在详情内联区的最低要求」** → 评价区无空态引导、失败静默，与列表页四态口径不统一（UX-07）。
6. **未定义「需认证能力的入口可见性统一口径」** → 主场景（详情评价）隐藏点赞、通知页游客见空白页，同一「认证门槛」在不同页表现三种样子（UX-02 / UX-08）。
7. **未定义「贡献/UGC 引导的单一话术与出现时机」** → 首页卡与搜索无结果 CTA 各写一套文案、出现时机不一（UX-10）。
8. **未定义「筛选/排序维度上线时的端上入口对等要求」** → 后端支持 `sort`/`spiceLevel` 等维度，端上入口时有时无（本次已补辣度，排序仍缺），每次新增维度都要临时拍板（UX-03 / UX-04）。
