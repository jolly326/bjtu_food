# poster — 海报

**用途**：档口的竖版展示海报 —— 学生端「橱窗」（发现 tab）一屏一张的取数来源。一档口可挂**多张**（N→1 [`stall`](./stall.md)）；**是否上橱窗、展示先后由运营在「海报管理」页独立控制**。

## 列定义

| 列 | 类型 | 可空 | 默认 | 键 | 说明 |
|---|---|---|---|---|---|
| `id` | BIGINT | NO | AUTO_INCREMENT | PK | 海报 ID |
| `stall_id` | BIGINT | NO | 无 | KEY, FK→stall | 所属档口；**必填、无默认值**（无「未归属」态） |
| `image` | VARCHAR(255) | NO | 无 | | **竖版海报图**（相对路径，单张）；必填 —— 无「空海报」态，清除图 = 删除海报 |
| `sort` | INT | NO | 0 | | **全局排序值**：升序展示、**小者靠前**；同值按 `id` 升序（创建顺序） |
| `status` | VARCHAR(32) | NO | `'on'` | KEY | 上下架：`on` 上橱窗 / `off` 不展示 |
| `updated_at` | DATETIME | NO | `CURRENT_TIMESTAMP ON UPDATE` | | 更新时间（管理端列表出参） |

## 索引

| 索引名 | 列 | 类型 | 用途 |
|---|---|---|---|
| `PRIMARY` | `id` | 主键 | — |
| `idx_poster_stall` | `stall_id` | 普通 | 按档口取海报（同时是外键所需索引） |
| `idx_poster_status` | `status` | 普通 | 学生端「只查上架」的过滤（`WHERE status='on'`） |
| `fk_poster_stall` | `stall_id` | **外键** | `REFERENCES stall(id)`，**`ON DELETE CASCADE`** |

## 关键设计

### 展示序 = 运营手排的**固定序**（不随机）

- 学生端 `GET /posters` 顺序 = `ORDER BY sort ASC, id ASC` —— **固定序、不重掷**；顺序完全由运营在「海报管理」页控制。
- `sort` 是**全局序**（橱窗为一条序列，不按档口分组）；同值并列按创建顺序稳定排。
- 新建未指定 `sort` ⇒ 自动取**当前全局最大值 + 1**（排到最后）；编辑不传 `sort` ⇒ **保持原值**（不重算）。
- **不为排序建索引** —— 海报量级小，计算排序代价可忽略。

### 上下架 `status`（与 `dish.status` 同口径）

- `on` = 上橱窗；`off` = 学生端**等价于不存在**（不出现在 `GET /posters`）。
- 存可读字符串是既定口径；`on` / `off` 之外的脏值由应用层拦截。

### 图片

- `image` 存**相对路径**：运营经 `POST /admin/images` 上传得绝对 URL，**入库时转相对**；出参经路径工具转绝对 URL。
- 🔴 **海报不叠加任何文本** —— 档口名称 / 所属食堂 / 位置**必须画进海报图**（见 [`ui/client/档口海报.md`](../ui/client/档口海报.md)）；素材一律 **3:4**（竖版）。

## 关联

| 方向 | 目标表 | 关系 | 级联 |
|---|---|---|---|
| N→1 | `stall.id` | 所属档口 | **`ON DELETE CASCADE`** —— 删档口时其海报一并清理（海报无下游引用、纯档口附属） |

## 注意事项

- `status = 'off'`（不展示）对 `GET /posters` **等价于不存在**。
- 删行只删库记录，**COS 图片文件不做回收**（与菜品图同口径）。
- 管理端维护入口：运营端「海报管理」（`/admin/posters*` 全套 CRUD + 排序 + 上下架）。
