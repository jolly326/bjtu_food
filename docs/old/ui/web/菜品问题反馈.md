# 菜品问题反馈

> 所属端：**管理后台（Web）** ｜ 页面 / 单元：**菜品问题反馈**（**按 `type` 分 Tab** 的列表 + 处置 / 详情抽屉）｜ 目标路由：`/corrections`
> **覆盖**：B4 菜品问题反馈管理（`correction` 的**阅读 + 标记已处理 / 驳回**）。
> **不覆盖**：列表通用骨架（基础列 / 详情抽屉 / 六态 / 分页 / 交互与状态）→ [列表页模板.md](./列表页模板.md) §一 与 §B4；组件规格 → [公共组件与形态基线.md](./公共组件与形态基线.md)；字段 / 端点 / 回执文案 → [B4 功能文档](../../func/web/B-UGC治理/B4-菜品问题反馈管理.md)；菜品本体编辑见 [菜品管理.md](./菜品管理.md)、取值登记见 [属性维度与取值.md](./属性维度与取值.md)。

## 一、页面构成

```
[ h2 菜品问题反馈            (全部 | 信息有误 | 已经下架) ]   ← 类型 Tab，置于页头右侧
[ 状态▾ | 菜品 ID ]                           [ 查询 ] [ 重置 ]
┌ .table-wrap ───────────────────────────────────────────────────────┐
│ 类型 │ 目标菜品 │ 提交人 │ 状态 │ 提交时间 │ 操作           │
│ 信息有误 番茄炒蛋  食客1234  待处理    …      处理           │
│ 已经下架 麻辣香锅  食客5678  待处理    …      处理           │
└────────────────────────────────────────────────────────────────────┘
                                        [ 共 N 条 · 页码 ]
   ↳ 表格脚注：「类型 / 目标菜品 / 提交人 / 状态」是快速查阅列；
      提交项对照、`gone` 的用户佐证与处置入口都在行内「处理 / 详情」内。」

＋ 处置 / 详情抽屉（640，**同一抽屉两态**：`pending` 处置态 / 已处理只读态）
```

| # | 区域 | 要点 |
|---|---|---|
| 1 | **页头** | `h2`「菜品问题反馈」；**无主按钮**（反馈由学生提交）。右侧挂**类型 Tab**（`.tabs` + `.tab`，`margin-left: auto` 靠右）：`全部` / `信息有误` / `已经下架`，`role="tablist"` + 每项 `role="tab"` + `aria-selected`；选中项 `.tab.active`（主色描边 + 浅色底）。切换 Tab **立即 `reloadFirstPage()`** |
| 2 | **筛选区** | **状态**▾（全部 / 待处理 / 已处理；`status` 仅两档，已处理内的已受理 / 拒绝结论由状态列展示）+ **菜品 ID** 输入 + 「查询」+「重置」（**重置含 Tab**，回到「全部」） |
| 3 | **列（基础列）** | `类型`（`StatusTag kind="correctionType"`）→ `目标菜品`（`dishName`；菜品已删除 → 「菜品已删除」+ `--text-muted`）→ `提交人`（`userName`，**直接渲染、页面不做兜底**；注销账号 → 「已注销用户」）→ `状态` → `提交时间`（`formatDateTime`）→ `操作`（`处理` / `详情`） |
| 4 | **状态列** | **恒用 `StatusTag`**（`kind='correction'`）：页面按 `status` + `outcome` 派生档位 —— `pending` → `待处理`（中性灰）／`handled` 且 `outcome='handled'` → `已受理`（绿）／`handled` 且 `outcome='rejected'` → `已拒绝`（红）；**页面不自写 `.tag-*`** |
| 5 | **类型列** | **恒用 `StatusTag`**（`kind='correctionType'`）：`field` → `信息有误`／`gone` → `已经下架`，**两档同为中性灰**（类型是「用户在说什么」，不是处理结论；「已经下架」不表示已处理） |
| 6 | **行操作** | `待处理` → `处理` ｜ 已处理 → `详情`（只读回显）—— 同一个抽屉，态由**行状态**决定 |
| 7 | **列表不展开内容** | 列表只给「谁、对哪道菜、什么类型、什么状态」；**提交项对照、`gone` 的补充说明与图片、处理回复全部在抽屉**（避免列表重且难扫） |

## 二、处置 / 详情抽屉（**核心界面**）

**载体**：`BaseDrawer`（常规 640；提交项对照表外包 `.table-wrap` ⇒ 窄屏横向滚动，**不另开宽抽屉**）。抽屉标题：待处理 → `field`「处理反馈」/ `gone`「处理下架反馈」；已处理 → 「反馈详情」。

```
┌ 抽屉头：番茄炒蛋 · 食客1234  [信息有误] ──────────────────────┐
│ ① 用户反馈（仅 gone）                                          │
│    补充说明 │ 这个窗口换成麻辣香锅了                            │
│    反馈人数 │ 3 人反馈已下架（仅参考，是否下架由人工判断）       │
│    图片     │ [56×56 缩略图，**点击开大图**]                    │
│ ② 提交项对照（仅 field）                                        │
│    字段     │ 当前值   │ 用户提交的新值 │ 是否一致               │
│    菜品名称 │ 蕃茄炒蛋 │ 番茄炒蛋      │ 不一致                 │
│    楼层     │ 二层     │ 三层          │ 不一致                 │
│ ③ 处理结论（单选，仅 pending）                                  │
│    ( ) 标记已处理（接受）                                       │
│    (•) 驳回（拒绝，必填原因）                                    │
│ ④ 回执标题 [input ≤40，可选]                                    │
│ ⑤ 处置文案 [textarea ≤600；「驳回」= 必填即不采纳原因；           │
│    「标记已处理」= 可选处理附注；右下角 n / 600]                  │
│                       [ 取消 ] [ 确认 ]                        │
└────────────────────────────────────────────────────────────────┘

已处理 → 只读态：提交项对照**无结论区**，结论与对照均以 `.detail-meta` 呈现
          回显（记录 ID / 提交人 / 处理结论 / 处置人 / 回执标题 /
          处置文案 / 提交时间 / 处置时间）＋ 底部只有 [ 关闭 ]
```

| 项 | 口径 |
|---|---|
| **`gone` 用户反馈区** | 定义列表（`.gone-info`，左标签 72px + 右内容）：`补充说明`（`note`，空显 `--text-muted`「未填写」）｜ `反馈人数`（`goneUserCount` + 固定尾注「（仅参考，是否下架由人工判断）」）。**必现** —— 「变成了别的菜 / 换窗口了 / 今天临时没供」三种情况的处置动作完全不同，只看人数会误下架 |
| **`gone` 图片区** | `images[]` 非空时以 `56×56` 缩略图并排（`.ctx-thumbs`），**只读**（不提供上传 / 删除），**点击即开 `ImagePreview` 大图** |
| **处理结论（单选）** | `field` / `gone` 统一两项：`标记已处理`（接受）｜ `驳回`（拒绝）。`.tag-option` 单选（`role="radiogroup"` + `aria-checked`） |
| **`gone` 下架不在本抽屉** | 下架是**菜品本体动作**，在 [菜品管理](./菜品管理.md) 手动执行；本抽屉只做「标记已处理 / 驳回」。可给 `--color-warning` 一行提示：「如需下架该菜品，请到『菜品管理』操作（可重新上架、评价保留）」🔴 **本抽屉任何状态都不出现「删除」字样** |
| **`gone` 提交可用性** | 两项结论均**恒可提交**（无可勾选项） |
| **提交项对照** | 列 = `字段`（`label`，中文名）｜ `当前值`（`oldValue`，**实时回查**）｜ `提交值`（`newValue`）｜ `是否一致`（`same`，`不一致` 用 `--color-warning` 高亮）。**仅 `field` 型渲染**；**只读，无勾选框** |
| **空值呈现** | 任一侧为空 → 显 `—`（`--text-muted`）；`differences` 为空时表格内给一行「无提交项对照」 |
| **主按钮** | `.btn-primary`；**驳回时**若处置文案为空则禁用（服务端 `400`，UI 从源头避免）；`标记已处理` 不作此约束 |
| **驳回原因字段** | 标签「处置文案（必填，≤600 字）」（`field`）/「仍在售的原因（必填，≤600 字）」（`gone`）—— **内联字段，不另开弹窗**；纯空白由服务端 `400`「请填写不采纳原因」，UI 亦做提交前必填校验 |
| **处理附注** | `标记已处理` 分支：`replyContent` **可选**（**≤600 字**），随回执下发；缺省用固定文案。标签「处理附注（可选，≤600 字）」，右下角 `n / 600`；**驳回分支同字段变必填**（即不采纳原因，见上） |
| **只读态** | 已处理行打开时：提交项对照只读、无结论区、底部只有 `关闭`，并回显处置人（`handledByName`）/ 处置时间（`handledAt`）/ 回执标题（`replyTitle`）/ 处置文案（`replyContent`） |

## 三、交互与状态

| 场景 | 口径 |
|---|---|
| 打开抽屉 | `GET /admin/corrections/{id}` 取按 `type` 的内容（**`field`**：`differences[]` 提交项对照，含实时 `oldValue` + `same`；**`gone`**：`note` + `images` + `goneUserCount`）→ 抽屉内先显 `StateBox` 加载态；失败给错误态可重试 |
| 标记已处理成功 | `ElMessage.success('已受理')` → 关抽屉 → `reload()`；**回执「已收到你的反馈 / 感谢反馈，我们已核实处理」**由服务端下发（UI 不拼） |
| 驳回成功 | `ElMessage.success('已驳回')` → 关抽屉 → `reload()`；**回执含「不采纳原因」**由服务端下发（UI 不拼） |
| 重复处理 | 服务端 `400`「该反馈已处理」→ 原文透出 → `reload()`（列表状态刷新） |
| 处置文案校验 | 驳回时 `replyContent` 纯空白由服务端 `400`「请填写不采纳原因」，UI 亦做提交前必填校验（主按钮 `:disabled`） |
| 本页不做 | 批量处理、编辑用户提交的原始快照、反馈项的手工改写（管理员若要改菜品 / 下架，走 [菜品管理](./菜品管理.md)）；🔴 **本流程不提供「删除」**（物理删除会级联清空该菜评价，仅在「菜品管理」由管理员主动执行） |

## 五、数据字段

- `correction.type`：`field` / `gone`（`StatusTag kind="correctionType"` 的取值）；列表筛选与抽屉分派均以此为判据。
- `CorrectionAdminVO` / `CorrectionDetailVO`、`differences[]`（提交项对照：`field` / `label` / `oldValue` / `newValue` / `same`）、标记已处理请求 `DishCorrectionHandleReq`（`replyTitle` / `replyContent` 可选）、驳回请求 `ModerationHandleReq`（`outcome='rejected'` / `replyTitle` / `replyContent` 必填）与错误码：见 [api/web/corrections.md](../../api/web/corrections.md)（接口契约唯一真源）。
- **`gone` 型专用字段**：`note`（补充说明，处置时**必现**）、`images[]`（只读缩略图）、`goneUserCount`（参考值，**非下架阈值**）；`differences` 恒空。
- **`differences[].field` 取值**：`name` / `price` / `canteenName` / `stallName` / `floor` / `images` / `attributes.<维度ID>`（仅作展示键，**不回传**）。
- **金额**：`price` 的 `oldValue` / `newValue` 均为**分** → 界面按 `¥x.xx` 展示（只读，**本页不编辑金额**）。
- **属性**：快照里是**中文**（用户提交原样）；取值字典翻译与新值登记发生在 A3 菜品编辑链路 —— UI 不做翻译。
- **图片**：快照为**绝对 URL 数组**，只读对比展示、可点开大图。
- **时间**：`createdAt` / `handledAt` 一律经 `formatDateTime`（[列表页模板 §1.6](./列表页模板.md)）。
