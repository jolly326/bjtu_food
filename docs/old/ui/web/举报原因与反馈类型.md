# 一、页面构成（**沿用通用骨架**，本族差异如下）

| 项 | 差异 |
|---|---|
| 筛选区 / 分页 | **无**（字典不分页，全量按 ID 升序，**含已停用**） |
| **计数徽标** | 页头 `h2` 旁显示 `.tag`「**启用 N / 8**」—— 上限 8 的自证；**N = 1 时**计数转 `--color-warning`，并在页头下方附一行 `.page-note.warn-note`「至少保留 1 条启用」 |
| **主按钮** | 页头「**新建原因**」（`.btn-primary`）→ `BaseModal`「新建原因」：单字段「原因名称」（`maxlength=32`，placeholder「如 垃圾广告 / 营销刷屏」）；空名提交 → `ElMessage.warning`「请填写中文名」；成功「已新建」并刷新列表（新项按 ID 排在末尾、默认启用） |
| 列 | `原因`（`name`） ｜ `引用举报`（`usageCount`，数字） ｜ `状态`（`StatusTag kind="onoff"`） ｜ `更新时间`（`formatDateTime`） ｜ `操作`（`详情`） |
| 表格脚注 | 「原因 ID 是历史举报的数据锚点（由后端生成，不可修改）；下线一律用「停用」；列表按原因 ID 升序。」 |

# 二、抽屉与动作

| 项 | 口径 |
|---|---|
| **详情抽屉（view）** | 两组 `.detail-group`：**投放信息**（名称 ／ 状态 `StatusTag kind="onoff"` ／ 引用举报数 + 括注「（被引用时不可删除，请改用「停用」）」）；**标识与时间**（原因 ID `#num` —— 历史举报的数据锚点、不可修改；更新时间） |
| 详情抽屉（edit） | 「原因改名」单字段（`maxlength=32`，`Enter` 保存）+ `.hint`「改名免费：历史工单的「原因」会同步显示新文案（数据锚在 ID）」；脏数据走 `BaseDrawer` 的 `dirty` 二次确认 |
| 详情内动作 | `改名`（→ edit 态）｜ `启用 / 停用`（随行状态切换）｜ `删除`（`.link.danger`，仅 `canDelete()`） ｜ 行内只有 `详情` |
| 启停确认 | 启用：「确认启用「{名称}」？举报弹层将再次出现该选项（启用数上限 8 条）。」；停用：「确认停用「{名称}」？停用后举报弹层不再展示该选项（历史工单仍能翻译出中文），但不能停用最后一条启用。」→ 成功「已启用 / 已停用」 |
| 删除确认 | 被引用（`usageCount > 0`）：「该原因已被 {N} 条工单引用，不能删除（删掉会让历史工单翻不出中文）—— 请改用「停用」。」（提交后服务端 `400`，原文一致）；未被引用：「确认删除该原因？删除后举报弹层不再出现该选项。」→ 成功「已删除」并关抽屉 |
| 受阻动作 | 重名 / 超长 / 停用最后一条启用 / 启用数已达上限 8 / 删除仍被引用 ⇒ **前端不预判**，服务端 `400` 原文透出（[列表页模板 §1.4](./列表页模板.md)） |

# 三、A7 / A8 文案差异（**形态完全同构，仅文案不同**）

| 项 | A7 举报原因 | A8 反馈类型 |
|---|---|---|
| 页头 / 抽屉 | 「举报原因」；新建「**新建原因**」；抽屉「原因详情」/「原因改名」 | 「反馈类型」；新建「**新建类型**」；抽屉「类型详情」/「类型改名」 |
| 计数徽标 | 「启用 N / 8」，N = 1 附「至少保留 1 条启用」 | 同左（同一页面体，徽标逻辑共用） |
| 引用列 | `引用举报`（`usageCount` —— 被举报记录引用次数） | `引用反馈`（`usageCount` —— 被反馈记录引用次数） |
| 新建 placeholder | 「如 垃圾广告 / 营销刷屏」 | 「如 程序功能Bug」 |
| 空态 | 「暂无举报原因」 | 「暂无反馈类型」 |
| 确认文案 | 「举报弹层」；「历史举报」；「原因 ID」 | 「反馈页」；「历史反馈」；「类型 ID」 |
| 表格脚注 | 「原因 ID 是历史举报的数据锚点……」 | 「类型 ID 是历史反馈的数据锚点（由后端生成，不可修改）；下线一律用「停用」；列表按类型 ID 升序。」 |

> 两页的**契约同形**：`OptionAdminVO` 出参形状、不变量（引用即禁删 / ≥1 启用 / 启用 ≤8 / 名称应用层唯一）完全一致，差异只在「被哪张工单表引用」与文案。
