# A8 · 反馈类型管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：**数据锚在类型 ID**；**被反馈记录引用过就禁止删除**（下线用停用）；**启用 ≤8 条**；**强制至少保留 1 条启用**。

## 介绍

维护 client **意见反馈页的「反馈类型」单选字典**（[`GET /feedback-options`](../../../api/client/feedback.md) 的数据源）—— `id`（类型 ID）+ 中文名（`name`）+ 启停；**顺序按 `id` 升序**（不设排序位）。

**定位**：反馈类型是**可维护字典**，新增类型**免发版、免客户端改动**（端上零硬编码，只消费 `id` / `name`）。

**职责边界**：只管反馈类型字典。**反馈记录的处置**在 B2（意见反馈管理）；本页不碰反馈记录本身。与**举报原因字典**（[A7](./A7-举报原因管理.md)）**同族**：表结构同形、不变量与出参形状完全一致，差异只在「被哪张工单表引用」。

**删除约束**：**被反馈记录引用过就禁止删除**（`feedback.option_id` 存的就是类型 ID）—— 删掉会让**历史反馈翻不出中文**。下线一律用**停用**。

**关键不变量**：**至少保留 1 条启用** —— 全部停用会让反馈表单的类型选择变空、**反馈入口瘫痪**（UGC 表达断链）。

**条数上限**：**启用 ≤8 条** —— 反馈类型是单选列表，太长不好选。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/feedback-options.md**](../../../api/web/feedback-options.md)（反馈类型契约唯一真源）。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `feedback_option` | 增删改查 | 反馈类型字典本体 |
| `feedback` | **只读**：统计 `usageCount`（`feedback.option_id = id`） | 引用计数（删除前判断 + 列表展示） |

> 列口径见 [schema/feedback_option.md](../../../schema/feedback_option.md)。

## 客户端可见性

[`GET /feedback-options`](../../../api/client/feedback.md) 出参恰 `{ id, name }` 两项、无分页，内容由字典表驱动：

- 只下发 **`status='on'`** 的类型；
- 顺序 = `id` 升序；
- **反馈提交白名单查表**：提交时校验「该类型 ID 存在且**启用**」—— 停用的类型**不能再被提交**（但历史已提交的记录仍能翻译出中文）。

## 备注（架构取舍）

- **数据锚在类型 ID、管理员只填中文**：`name` 改名免费（历史反馈的翻译随表实时生效）；与 [A4](./A4-菜品属性维度管理.md) 的维度 / 取值 ID、[A7](./A7-举报原因管理.md) 的原因 ID 同源口径。
- **删除用「引用即禁删」而非级联**：与 A1 / A2 / A4 / A6 / A7 一致 —— 管理员必须显式把历史记录归到别的类型（或直接停用），不做静默改写历史。
- **强制至少 1 条启用**：意见反馈是 UGC 表达的入口，不接受「把入口配空」这种状态。
- **顺序按 `id` 升序、不设排序位**：反馈类型是选择范围很小的封闭字典（启用 ≤8 条），顺序稳定即可；端上与后台同一口径（全站唯一保留排序位的是 `banner`）。
- **上限 8 条**：单选表单的可用性约束（不是技术约束）。
