# A4 · 菜品属性「维度与取值」管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**A 主数据维护**
> **口径要点**：维度 + **取值字典**（数据锚在 ID，改名免费）。

## 介绍

维护菜品属性的**维度**（`dish_attribute_dimension`）与**取值字典**（`dish_attribute_value`）。

**模型**：
- **维度**：维度 ID + 中文名 + 单/多选 —— 定义「有哪几行、每行叫什么、单选还是多选」；**菜品 `attributes` JSON 的键 = 维度 ID**。
- **关系**：描述维度与菜品是 **m:n**（可多值、可空），取值存 `dish.attributes` JSON；菜品「种类」是**另一实体**（1:1、单值必填，[A6](./A6-首页筛选视图管理.md)），不进本页。
- **取值**：每个维度下的一组可选值（中文名 `name`）；**菜品存的是取值的 ID**，出参时服务端翻译成中文 ⇒ **客户端契约不变**。
- **顺序一律按 `id` 升序**：维度与取值**均不设排序位**，列表顺序 = 建档顺序（端上渲染与管理端列表同一口径）。
- **名称全部可改、且免费**：维度名、取值名都只是展示，数据锚在**维度 ID / 取值 ID** ⇒ 改名**不影响任何菜品数据**。
- **单 / 多选可切换**：后端在同一事务内自动迁移该维度下菜品的数据形状（单值 `id` ↔ 多值 `[id]`）。
- **灵活取值**：
  - 管理端录入菜品时**可直接输入新值 → 自动登记**进取值字典；
  - **菜品问题反馈**提交的新值**不入库**（仅作提交记录）—— 管理员在 [A3 菜品管理](./A3-菜品管理.md) 编辑菜品时按中文查字典（命中即用；**未命中自动新建一行**）并写入菜品（反馈侧只读对照，见 [B4](../B-UGC治理/B4-菜品问题反馈管理.md)）。
- **删除约束**：维度 / 取值**被菜品引用时禁止删除**（`400`），防止静默丢数据。

## 备注（架构取舍）

- `dish.attributes` **保持 JSON 列**（存取值 ID），**不引入关联表**：改动最小，且「按取值计数」（`dishCount` / 删除约束）是低频管理操作，扫描可接受。
- **顺序按 `id` 升序、不设排序位**：维度与取值都是**低频、封闭**的字典（维度个位数、取值十数条），顺序稳定即可；端上与管理端同一口径，无拖拽 / 无批量排序端点。
- 若将来需要「**按属性筛选菜品**」，应迁移为关联表（如 `dish_attribute_ref(dish_id, value_id)`）——登记为演进预留。
- **客户端侧文档**：`docs/func/client/A-浏览与发现/A3-菜品详情.md`、`docs/func/client/B-UGC表达与治理/B6-菜品问题反馈.md`、`docs/ui/client/菜品详情.md` 与 `docs/api/client/dishes.md` 均为「服务端按**取值 ID** 翻译后下发中文」口径；**客户端展示契约不变**。
