# B4 · 菜品问题反馈管理

> 所属端：**管理后台（Web）** ｜ 鉴权：管理端 JWT 登录（见 [C1](../C-账号与访问/C1-管理员登录与访问控制.md)）
> 归属：**B UGC 治理**
> **口径要点**：管理员**阅读**反馈后，处置**统一两个动作** —— **标记已处理**（接受）或 **驳回**（拒绝，必填原因）；两者**都不改写菜品**，只归档结论并投递**站内回执**。详情给出「**当前值 / 提交值 + 是否一致**」的**提交项对照**供阅读判断。
> 处置对象含 `type=gone`（已经下架）（依据：内容供给与维护闭环——下架反馈天然含误报，须人工核实，避免一次误报即永久删除菜品全部历史评价）。

## 介绍

处理学生提交的**菜品问题反馈**（独立资源 `correction`，**只存提交事实**）—— **两类**：

| `type` | 语义 | 用户提交形态 |
|---|---|---|
| **`field`** | **信息有误** | **改动项快照**（未改动列留 NULL） |
| **`gone`** | **已经下架** | **一键提交**（各差异项列恒 NULL），说明与图片**选填** |

结果均向提交人投递**站内回执**。菜品本体修改（`field` 改资料 / `gone` 可逆下架）由管理员**在 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md) 手动执行**，**本流程不自动写回**。

### 🔴 红线：本流程**不得提供「删除」菜品**

| 操作 | 语义 | 数据层 | 评价 | 可逆 |
|---|---|---|---|---|
| **下架** | 暂时不在售 | `status=off` | **保留** | ✅ **可重新上架** |
| **删除** | 彻底移除 | **物理删除** | 🔴 **级联删除**（`ON DELETE CASCADE`） | ❌ **不可逆** |

> **`gone` 反馈天然含误报**（用户可能看错窗口、菜品只是临时售罄）。若本流程提供「删除」，则「**一次误报 + 一次点错 = 该菜全部历史评价永久消失**」。
>
> ⇒ **删除只允许在 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md) 由管理员主动执行**（带二次确认，明示「将一并删除 N 条评价」）；**本流程不出现「删除」按钮**，`gone` 的「下架」亦在 A3 手动完成（可逆）。

### ⚠️ 无「下架阈值」：`≥1 条即进待办，是否下架由人工决定`

| 环节 | 规则 |
|---|---|
| **进入待办队列** | **≥1 条即进**（按 `user_id + dish_id` 去重后）—— 去重是**防单人刷队列**，**不是决策门槛** |
| **是否下架** | **管理员人工决定**；系统**不自动下架** |
| **驳回** | 必填处置文案（不采纳原因），回执告知用户「经核实仍在售」 |

> **依据**：进队列 ≠ 自动下架；管理员看到的是「有人反馈 + 可选说明/图片」，判断成本本就很低。设门槛只会让**用户的反馈石沉大海**。

## 处置流程（阅读 → 标记已处理 / 驳回）

```
列表（api/web/corrections.md）
        ↓
   打开详情抽屉：提交项对照（当前值 / 提交值 + 是否一致）
   · field：逐项对照
   · gone ：note + images + goneUserCount（无对照项）
        ↓
   ┌────────────────────────────┐
   │ 管理员阅读判断              │
   └───┬────────────────────┬───┘
       │                    │
   标记已处理（接受）     驳回（拒绝，必填原因）
       │                    │
   moderation_task       moderation_task
   outcome=handled       outcome=rejected
       └────────┬───────────┘
                ↓
          站内回执投递
（都不改写菜品；菜品修改/下架由管理员去 A3 手动执行）
```

**动作恰好两个**：**标记已处理**（接受，归档 `outcome='handled'`）或 **驳回**（拒绝，必填原因）；结果向提交人投递**站内回执**。**两者都不改写菜品数据** —— 菜品本体修改（`field` 改资料 / `gone` 可逆下架）由管理员**在 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md) 手动执行**。

**`field` 型反馈范围（七项）**：名称 / 现价（分）/ 食堂 / 档口 / 楼层 / 属性 / 图片（**≤3 张**）；字段清单见 [api/web/corrections.md](../../../api/web/corrections.md)。

- **不含菜品种类**（`dish.category_id`）—— 种类是**独立字典表** `dish_category` 的行、由管理员在 A3 直接改，不在反馈范围（client 反馈页也没有该字段）；
- **不纠正原价** —— 原价随促销波动、属运营口径（见 [client B6](../../client/B-UGC表达与治理/B6-菜品问题反馈.md)）。

**`gone` 型无提交项可对照** —— 详情只给 `note` + `images` + `goneUserCount`；是否下架由管理员核实后**去 A3 手动下架**（可逆），再回本流程**标记已处理**或**驳回**。

**职责边界**：只管反馈记录的阅读与处置归档；**菜品本体编辑**在 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md)，**档口楼层**在 [A2 档口管理](../A-主数据维护/A2-档口管理.md)，**属性取值字典**在 [A4](../A-主数据维护/A4-菜品属性维度管理.md)。

## 接口

端点 / 入参 / 出参 / 错误码见 [**api/web/corrections.md**](../../../api/web/corrections.md)（菜品问题反馈契约唯一真源）。

## 数据

| 表 | 读写什么 | 中文解释 |
|---|---|---|
| `correction` | 读（类型 / 改动项快照 / 说明 / 图片） | 问题反馈提交事实本体，**处置不改写** |
| `moderation_task` | 读写（`status` / `outcome` / `reply_title` / `reply_content` / `handled_by` / `handled_at`） | 处置状态机与处置文案真源（多态键 `type='correction'`，1:1） |
| `dish` | **只读**（提交项对照的当前值 + 菜名 + 上下架状态） | 目标菜品；**本流程不写**（菜品修改 / 下架在 A3 手动执行） |
| `stall` | **只读**（`floor` 对照的当前值） | 归属档口；**本流程不写**（楼层在 A2 手动修改） |
| `notification` | **写**（处置回执快照） | 站内回执 |
| `user` | **只读**（提交人昵称） | 提交人 |

> 列口径见 [schema/correction.md](../../../schema/correction.md) 与 [schema/moderation_task.md](../../../schema/moderation_task.md)。
> **本流程只读 `dish` / `stall` 作对照，不写任何主数据**：菜品资料修改（含属性取值 ID 解析与字典登记）在 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md)、楼层在 [A2 档口管理](../A-主数据维护/A2-档口管理.md) 完成，均不属本反馈处置流程。

## 回执文案

| 结论 | 标题 | 正文 |
|---|---|---|
| **标记已处理**（`field` / `gone` 通用） | 已收到你的反馈 | 缺省「感谢反馈，我们已核实处理」；管理员填了附注则附于其后 |
| 驳回（`field`） | 菜品信息未采纳 | **不采纳原因**（`replyContent`，必填，纯空白 → `400`） |
| 驳回（`gone`） | 菜品仍在售 | **不采纳原因**（必填，如「今日临时售罄，明天恢复」） |

- **投递口径**：提交入口**一律需登录** ⇒ 提交人**恒有可归属 `userId`**，回执**一律投递**（含静默登录的游客）；投递与处置**同一事务** —— 见 [web/README](../README.md) 的「处置回执」。

## 备注（架构取舍）

- **处置只归档、不改菜品**：`标记已处理` / `驳回` 都只写 `moderation_task` + 投递回执；菜品资料与上下架的修改统一回到 [A3 菜品管理](../A-主数据维护/A3-菜品管理.md)，把「用户说了什么」与「菜品最终是什么」解耦，避免自动写回带来的误操作与跨域复杂度。
- **对照只列「用户提交过的项」**：`field` 型只提交改动项，故 `differences[]` 逐项给「当前值（实时回查）/ 提交值 + `same` 是否一致」。
- **楼层连带影响在 A2 承担**：`floor` 属档口，改楼层连带同档口所有菜品 —— 该提示落在 [A2 档口管理](../A-主数据维护/A2-档口管理.md) 改楼层处。
- **`outcome` 是任务表的物理列**：`handled`（已受理，管理员已手动处理）/ `rejected`（不采纳）可从行本身判定；**文案只有一列**（`replyContent`），不采纳原因并入其中。
- **不做批量处理**（与 B2 / B3 同口径，一期不做）。
