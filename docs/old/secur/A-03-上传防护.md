# A-03 · 上传防护

> **等级 A（纵深缓解）** —— 缺失不直接失守，但上传是**唯一有外部成本的入口**（微信机审 + 对象存储），也是「图片马 / 炸弹 / 路径穿越」的唯一入口。
> **范围**：扩展名白名单、魔法字节、尺寸与像素上限、UUID 重命名、云端安检。
> **真源**：本文档。内容机审判定见 [S-05](./S-05-内容安全机审.md)；上传限频见 [S-04](./S-04-限频与可用性.md) §3。

---

## 1 · 防护措施

| 措施 | 口径 |
|---|---|
| 扩展名白名单 | `jpg` / `jpeg` / `png` / `webp` |
| 魔法字节嗅探 | 按文件头判定真实类型，**不信扩展名** |
| 尺寸上限 | 管理端 multipart **5MB**；学生端云存储链路 **≤1MB**（下载封顶 + 机审前置双重约束） |
| 像素上限 | **4000 × 4000** |
| 编号重命名 | **UUID 文件名**（不沿用原名，防路径穿越）；写入侧做路径归一化 |
| 云端内容安检 | `imgSecCheck` 在转存对象存储**之前** |

## 2 · 两条上传链路

| 链路 | 尺寸上限 | 安检 |
|---|---|---|
| 学生端 `POST /upload/cloud-image` | ≤1MB | 云端 `imgSecCheck` → 转存 COS |
| 管理端 multipart | 5MB | 同一条 `imgSecCheck` 链路 |

> 头像与 UGC 配图走**同一条**链路，**不存在「头像可绕过」的旁路**（见 [S-05](./S-05-内容安全机审.md) §2）。

## 3 · 静态资源映射

| 项 | 口径 |
|---|---|
| 映射方式 | 上传根目录直映射 |
| 写入侧 | 已做路径归一化 + UUID 重命名 |
| 读取侧 | 依赖框架 `PathResource` 默认防穿越 |
| 结论 | 当前安全 |

## 4 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 图片马 / 图像炸弹 / 路径穿越 | 扩展名 + 魔法字节 + 尺寸 + 像素上限 + UUID 名 | `400` 拒绝 | 告警（高频时） |
| 头像绕过安检 | 同一条链路（无旁路） | `400` / `500` | — |
| 上传配额被刷 | IP + 账号双维度限频（6/分 · 30/时） | `429` | — |
