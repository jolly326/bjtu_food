# secur · 安全设计真源

> **性质**：**安全设计真源**。回答「谁能进、能做什么、挡住了什么、边界在哪」。
> **与其他文档的分工**：本目录只写**安全机制与威胁边界**；业务口径见 [`func/`](../func/client/README.md)、接口契约见 [`api/`](../api/README.md)、库表见 [`schema/`](../schema/README.md)、页面形态见 [`ui/`](../ui/client/README.md)。
> **实施主体**：所有防线的**执行者都是服务端**；端侧只承担约束（见 [A-06](./A-06-端侧约束与反向证据.md)），不是「客户端要做安全」。

## 1 · 分级：按「缺失后果」定级

文件名前缀即等级。定级判据只有一条：**这条防线缺失后，攻击门槛有多低、后果有多重**。

| 等级 | 含义 | 判据 | 处置原则 |
|---|---|---|---|
| **S** | **核心防线** | 缺失即直接失守，且攻击门槛低（不需要漏洞，用合法身份即可试） | 动它必须先改本篇；回归即安全事故 |
| **A** | **纵深缓解** | 缺失不直接失守，但显著提高攻击成本 / 缩小爆炸半径 / 让事件可发现 | 按需加强，削减需说明理由 |
| **B** | **边际与留痕** | 收益有限，或属「明确不做」的否决记录 | 可议；但**否决记录必须保留**（防后人重复尝试死路） |

> 📌 **分级是「重要性」排序，不是「实现与否」排序** —— S 级全部已落地；B 级里既有已实现的边际措施，也有明确不做的事。

## 3 · 设计前提

| 前提 | 含义 |
|---|---|
| **客户端不可信** | 小程序包可被反编译 —— 请求结构、字段名、枚举值全部暴露。任何「前端隐藏」都不算防护 |
| **网络不可信** | 非微信链路（H5 / 抓包代理）流量可被观察与重放 |
| **用户身份不可信** | 攻击者可自己走一遍静默登录拿到合法 JWT，再用合法身份尝试越权 |
| **openid 不可信** | 仅服务端 `code2Session` 换取可信；客户端传入的任何 openid 一律忽略 |

⇒ **一切鉴权、授权、参数校验、归属判定都在服务端强制，且假设客户端会发送任意构造的请求。**

## 4 · 双安全区对比

| 维度 | Zone A · 管理端（`/admin/**`） | Zone B · 小程序端（学生接口） |
|---|---|---|
| 路径前缀 | `/admin/**` | `/auth`、`/dishes`、`/reviews`、`/feedback`、`/reports`… |
| 鉴权 | 管理端 JWT（独立密钥）+ 账密登录 | 学生 JWT（独立密钥）+ 微信静默登录 |
| 身份源 | `admin`（BCrypt 口令） | `user`（服务端 `code2Session`） |
| 流量特征 | 低频、单人、**高权限且破坏不可逆** | 高频、多用户、最小权限 |
| 防御重心 | 凭证攻击（爆破）+ 接口滥用 + **实时告警** | 越权 / 篡改 / 爬取 / UGC 滥用 / 灌库 |
| 设计姿态 | 允许自由操作数据，但**破坏性操作有护栏、关键安全事件实时告警** | **默认拒绝**：能不给的能力不给，给了也必须服务端强校验 |

> 📌 **web 只跑本地，对公网攻击毫无帮助** —— 它只是给你用的界面，不是一道防线；攻击者直接打公网 `/admin/**`。

## 5 · 威胁模型（总览）

按「谁能打、打什么、后果、谁挡」四段划分，每条指向具体防线文档（括号内为等级）。

| # | 攻击面 | 后果 | 主防线 | 归属 |
|---|---|---|---|---|
| T1 | **管理端凭证泄露** | 🔴 **物理删菜品 + 级联删评价，不可逆** | 账密登录（前端不持有口令）+ 可吊销 JWT | [S-01](./S-01-身份与凭证.md) · [S-03](./S-03-管理端登录与防爆破.md) |
| T2 | **暴力猜管理员密码** | 同上 | IP + **账号双维度**限频、渐进锁定、退避、**改密即吊销** | [S-03](./S-03-管理端登录与防爆破.md) |
| T3 | **狂打 `/admin/**`** | 线程打满 ⇒ **小程序用户也进不来** | IP 限频（位于鉴权之前）+ token 维度写限频 | [S-03](./S-03-管理端登录与防爆破.md) · [S-04](./S-04-限频与可用性.md) |
| T4 | **狂打业务公开接口** | 连接池 / 线程耗尽 | 双维度限频 | [S-04](./S-04-限频与可用性.md) |
| T5 | **验证码枚举 / 发码轰炸** | 绑定他人邮箱 | IP 限频 + 邮箱冷却 + 尝试次数封禁 | [S-04](./S-04-限频与可用性.md) |
| T6 | **学生 token 冒充管理员** | 越权进管理端 | 两套 JWT **独立密钥** + 独立账号表 | [S-01](./S-01-身份与凭证.md) |
| T7 | **管理端 JWT 被窃** | 有效期内冒用 | 逐请求状态回查可即时吊销 + 实时告警可发现 | [S-01](./S-01-身份与凭证.md) · [A-05](./A-05-告警与破坏性操作防护.md) |
| T8 | **IDOR（篡改 id 操作他人资源）** | 删他人评价 / 改他人反馈 | **对象级归属校验**（以 JWT 内 userId 为准） | [S-02](./S-02-鉴权与归属校验.md) |
| T9 | **参数篡改 / 字段注入** | 越权字段生效 | DTO 约束 + **拒绝未声明字段** | [A-01](./A-01-参数与字段校验.md) |
| T10 | **恶意爬取**（高频拉列表 / 顺序枚举 ID） | UGC 资产外泄 | 读限频 + ID 枚举检测 + 蜜罐探针 + 分页上限 | [A-02](./A-02-爬取与枚举防护.md) · [S-04](./S-04-限频与可用性.md) |
| T11 | **UGC 灌库**（刷评价 / 反馈 / 举报） | 审核配额耗尽、数据污染 | 写入口 **IP + 账号双维度限频** | [S-04](./S-04-限频与可用性.md) |
| T12 | **违规内容漏放** | 校园场景合规事故 | 机审 **fail-closed**（上游不可达即拒收；生产缺凭据启动失败；无 openid 不放行） | [S-05](./S-05-内容安全机审.md) |
| T13 | **数据库直连公网** | 🔴 **全量数据泄露 / 删库** | 应用账号**仅 DML** + 口令轮换 + 私网连接 | [S-06](./S-06-凭据与数据边界.md) |
| T14 | **上传型攻击**（图片马 / 炸弹 / 穿越） | 任意文件 / 资源耗尽 | 白名单 + 魔法字节 + 尺寸上限 + 重命名 + 云端安检 | [A-03](./A-03-上传防护.md) |
| T15 | **限流 / 吊销绕过（多实例）** | 限额被放大 N 倍 | 触发条件：**≥2 实例前下沉 Redis** | [S-04](./S-04-限频与可用性.md) |
| T16 | **内部信息探测**（异常 message / 调试面） | 结构探测线索 | 受控文案 + 调试面生产关闭 | [A-04](./A-04-信息暴露与注入基线.md) |

## 7 · 残余风险（已知但未消除，明确记录而非假装不存在）

| # | 端 | 风险 | 为何暂不消除 / 缓解 | 重评条件 |
|---|---|---|---|---|
| C-R1 | 小程序 | **token 明文落本地存储**（`uni.setStorageSync` 无加密、无 `httpOnly` 等价物） | 微信平台限制。缓解 = 短时效 + **全局吊销**（[S-01](./S-01-身份与凭证.md) §4） | 平台提供加密存储 |
| C-R2 | 全域 | **限频与吊销计数为进程内实现**，多实例下各自计数 | 单容器云托管，重启清零可接受 | **云托管扩到 ≥2 实例前必须下沉 Redis**，否则限额被放大 N 倍 |
| C-R3 | 小程序 | **机审对「疑似（`review`）」一律放行** | UGC 治理闭环口径：微信全量检测 + 举报兜底，MVP 内容量小 | 出合规事故或量级增长 |
| C-R4 | 小程序 | **UGC 正文草稿明文落本地存储** | 属用户本人设备上的本人草稿；提交成功后即清理 | — |
| W-R1 | 管理端 | **管理端 JWT 泄露即可冒用**（有效期内） | token 可吊销（停用账号逐请求生效）；web 本地 + `sessionStorage` 使泄露面很小 | 管理端迁到公网托管 |
| W-R2 | 管理端 | **无网络层 IP 白名单** | 🔴 **平台不支持**：微信云托管无安全组概念；且校园网出口 IP 共享 ⇒ 白名单退化为「全校可访问」（见 [B-02](./B-02-设计边界与否决记录.md)） | 换到有安全组的平台 |
| W-R3 | 管理端 | **`admin.jwt.secret` 泄露 ⇒ 可伪造管理端 token** | 走环境变量、不入库不入仓；弱密钥启动阻断 | — |
| W-R4 | 管理端 | **角色划分依赖人工赋值**（`admin.role` 直连库维护，无管理入口） | 账号行由数据库维护、库内**仅 1 行**；引入管理入口会新增「谁能改角色」的自指权限问题 | 管理端账号数增长到需要自助管理 |
| S-R1 | 后端 | **数据库端口公网可达**，应用当前以 **root** 连接 | 微信云托管强制开公网（应用账号仅 DML + 口令轮换为已定口径，切换为待授权运维动作） | 平台提供私网连接（见 [S-06](./S-06-凭据与数据边界.md)） |

**跨端共同的两条**：

| # | 风险 | 触发重评的条件 |
|---|---|---|
| 1 | **限频 / 黑名单 / 封禁计数为进程内实现**，多实例时各自计数 | **云托管扩到 ≥2 实例** ⇒ 必须下沉 Redis，否则限额被放大 N 倍 |
| 2 | **无网络层 IP 白名单 / 安全组** | 换到有安全组的平台；或管理端不再单人 |

## 8 · 约定

1. **密钥永不入库**：所有 secret / 口令 / 密钥一律走**环境变量**，不写入文档、不提交仓库。
2. **文档只写当前口径**：变更轮次从 git 历史查（沿用 [`docs/README.md`](../README.md) 总约定）；设计已定而代码未同步的条目，登记在**各篇文末「与当前代码的差异」**节（清零写「无」）。
3. **新增防线必须登记进本 README 的威胁模型表** —— 否则「挡住了什么」无从回答。
4. **平台约束优先于理论最优**：托管平台的限制会否决某些加固手段，此类**否决理由必须记录**（见 [B-02](./B-02-设计边界与否决记录.md)），避免将来反复尝试同一条死路。
5. **涉及决策的取舍**（尚未拍板的安全口径）集中登记在 [`docs/测试/安全待决策项.md`](../测试/安全待决策项.md)，**不散落**在各篇正文里。
6. **定级变更须同步本 README §1 与文件名前缀** —— 等级是「缺失后果」的判断，不是实现进度。
