# S-01 · 身份与凭证

> **等级 S（核心防线）** —— 缺失即失守：密钥不隔离 ⇒ 学生 token 可冒充管理员；凭证不可吊销 ⇒ 泄露即 24 小时内任意破坏。
> **范围**：身份从哪来、两套 JWT 密钥隔离、凭证形态与存储、全局吊销触发点、密钥环境变量化。
> **真源**：本文档。归属与角色判定见 [S-02](./S-02-鉴权与归属校验.md)；登录防爆破见 [S-03](./S-03-管理端登录与防爆破.md)；数据边界见 [S-06](./S-06-凭据与数据边界.md)。

## 1 · 身份从哪来

```
小程序启动 → wx.login 取 code
  → POST /auth/wechat-login（服务端 code2Session）
  → 服务端取 openid，建号或查号 ⇒ 签发学生 JWT（含 userId）
  → 端上存 token，后续请求带 Authorization: Bearer <jwt>
```

```
管理员在登录页输账号密码
  → POST /admin/auth/login
  → 服务端查 admin，比对 BCrypt 哈希
  → 通过 ⇒ 用 admin.jwt.secret 签发管理端 JWT（含 accountId）
  → 前端存 sessionStorage，后续请求带 Authorization: Bearer <jwt>
```

| 项 | 口径 | 理由 |
|---|---|---|
| 学生身份权威 | **仅服务端 `code2Session`** | 客户端传入 openid 一律忽略（客户端不可信）；`WechatLoginReq` 只有 `code` 一个字段，无 openid 入口 |
| 管理端密码存储 | **BCrypt**（cost 10） | 不可逆 + 自带盐 + 计算成本可调 |
| 账号来源 | **独立 `admin` 表**，与学生 `user` 身份体系**完全隔离** | 学生体系的任何问题不外溢到管理端 |
| 双 JWT 密钥 | 学生 `JWT_SECRET` ≠ 管理端 `ADMIN_JWT_SECRET` | 🔴 共用则学生可自签管理端 token 冒充 |
| 当前用户取值 | 一律 `SecurityUtil.getCurrentUserId()` | 🔴 **禁信任前端传 `userId`** —— 全仓无任何写端点 DTO 含 `userId` / `openid` 入参字段 |
| 管理端 JWT 有效期 | 24 小时 | 使用场景为「一人偶尔用」；配「逐请求状态回查」后，过期并非唯一止损手段 |

## 2 · 密钥强度与 fail-fast

| 项 | 口径 |
|---|---|
| 学生 `JWT_SECRET` | `@PostConstruct` 校验：缺失 / 短于 32 字节 / 命中开发默认值 ⇒ **启动失败** |
| 管理端 `ADMIN_JWT_SECRET` | 同上；**必须固定**（每次启动重新生成会使已登录 token 全部失效，用户被反复踢出） |
| 生产配置 | `application-prod.yml` 无默认值占位符 ⇒ 缺配置直接起不来 |
| 口令校验依赖 | 仅 `spring-security-crypto` 的 `BCryptPasswordEncoder`；不依赖 starter-security 的自动配置与过滤器链 |

## 3 · 凭证存储与传输

| 通道 / 项 | 口径 |
|---|---|
| 小程序 | `wx.cloud.callContainer` —— 微信内网加密链路，不受公网 / CORS 约束 |
| 管理端 token 存储 | **`sessionStorage`**（关标签页即失效），**不用 `localStorage`** —— 少一份持久化泄露面。前提是**全站零 XSS**（见 [A-06](./A-06-端侧约束与反向证据.md)） |
| 小程序 token 存储 | `uni.setStorageSync`（= `wx.setStorageSync`），App 沙箱隔离但**平台不提供加密存储**，亦无 `httpOnly` 等价物 ⇒ 纵深放在服务端 |
| H5（本地联调） | 生产构建缺 API 基址即**拒绝启动**（fail-closed）；开发态允许 localhost |
| H5（对外发布） | **不发布** —— 明文 HTTP 回落会泄露 `Bearer` token |
| token 位置 | `Authorization` 请求头，**不进 URL / Query**（避免被日志与 Referer 记录） |

## 4 · 全局吊销（「发现异常 → 立即止损」的操作位）

`TokenBlacklist` 支持 **token 维度**与 **userId 维度**失效，过滤器逐请求双侧判定。触发点：

| # | 触发点 | 位置 |
|---|---|---|
| 1 | **注销账号**（本人 / 管理员） | `AccountCloser` |
| 2 | **账号被禁用** | `UserServiceImpl#updateStatus` |
| 3 | **邮箱换绑**（本人认证 / 管理员解绑） | `AuthServiceImpl` · `UserServiceImpl` |
| 4 | **管理员人工踢下线**（`POST /admin/users/{id}/kick`） | `UserServiceImpl` |

> 🔴 **全局吊销是唯一能让「已泄露 token」立刻失效的手段**，不必等 24h 自然过期。与之配套的可发现性见 [A-05](./A-05-告警与破坏性操作防护.md)。

## 5 · 密钥与凭据环境变量清单

真值只经环境变量注入（本地由 spring-dotenv 加载 `server/.env`），**不入库、不入仓、不进文档、不进 commit message**；`.env.example` 只放占位符；出网调用日志对 `secret` 参数脱敏。

| 变量 | 用途 | 备注 |
|---|---|---|
| `JWT_SECRET` | 学生 JWT 签名 | 生产无默认值；弱值启动阻断 |
| `ADMIN_JWT_SECRET` | 管理端 JWT 签名 | 固定值；弱值启动阻断 |
| `CORS_ALLOWED_ORIGINS` | 管理端本地地址 | 为空则拒绝一切带 `Origin` 的浏览器请求（定位见 [B-02](./B-02-设计边界与否决记录.md)） |
| `ALERT_WEBHOOK_URL` / `ALERT_WEBHOOK_SECRET` | 告警推送地址 / 签名密钥 | 未配置则告警通道不启用（启动 WARN） |
| `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD` | 数据库连接 | 见 [S-06](./S-06-凭据与数据边界.md) |

## 6 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| **JWT 伪造 / 改签** | 签名校验失败 | `401`（fail-closed） | 源 IP 标记 |
| **JWT 盗用 / 重放** | 黑名单（token / userId 维度） | `401` + 全局吊销 | 告警 |
| **学生 token 冒充管理员** | 两套 JWT 密钥独立 | `401` | — |
| **身份自述**（请求体传 `userId` / openid） | 服务端只认 JWT 与 `code2Session` 结果 | 忽略 / `400` | — |
| **弱密钥自签 token** | 启动时长度 / 默认值校验 | 启动失败 | — |
