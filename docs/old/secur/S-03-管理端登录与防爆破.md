# S-03 · 管理端登录与防爆破

> **等级 S（核心防线）** —— 管理端是全站**唯一不可逆破坏面**（物理删菜品 + 级联删评价）。密码一旦被字典命中即失守，故凭证攻击防护属核心而非纵深。
> **范围**：双维度限频、账号渐进锁定、指数退避、改密即吊销、`/admin/**` 全域限流。
> **真源**：本文档（管理端的**设计依据与语境**）。**限流规则全量清单见 [S-04](./S-04-限频与可用性.md) §3**，本文数值以该清单为准；身份与凭证见 [S-01](./S-01-身份与凭证.md)；告警见 [A-05](./A-05-告警与破坏性操作防护.md)；口令复杂度见 [B-01](./B-01-口令策略与超期.md)。

## 1 · 为什么必须双维度

**纯 IP 维度可被换 IP 绕过**（校园网多出口 / 代理池），而 **admin 用户名固定且可猜**（评论、文档、协作记录都可能泄露），密码一旦被字典命中即失守 —— 而管理端破坏**不可逆**。

⇒ 登录防护 = **IP 维度**（防单源狂打）× **账号维度**（换 IP 也累加）。

| 层次 | 拦住什么 |
|---|---|
| IP 限频 | 单来源高速试探 |
| **账号锁定** | 换 IP 的分布式试探（计数按 `username` 累加，跨 IP 仍生效） |
| 指数退避 | 「少量尝试」也变得不经济 |

## 2 · 登录限制（三层）

### 2.1 · IP 维度限频

| 端点 | 阈值 | 位置 |
|---|---|---|
| `POST /admin/auth/login` | **5/分 · 20/时** per IP | 进入口令校验**之前** |

### 2.2 · 账号维度渐进锁定

| 连续失败次数 | 锁定 | 说明 |
|---|---|---|
| 5 | **5 分钟** | 起锁 |
| 10 | **1 小时** | 升级 |
| 20 | **24 小时** | 上限 |

- **成功登录即清零**该 `username` 的失败计数（避免误伤本人）。
- 锁定期间该账号**一律拒绝**（即使密码正确、即使来自新 IP）。
- 计数按 `username` trim + 转小写归一化，**与 IP 维度并行**，任一超限即拒。

### 2.3 · 指数退避

自第 **3** 次连续失败起，登录响应**人为延迟 +500ms/次，封顶 3 秒** —— 让「少量尝试」也付出时间成本。

### 2.4 · 硬约束

| # | 约束 |
|---|---|
| 1 | 锁定与退避的通知文案**不得**区分「账号不存在 / 已锁定 / 密码错误」的差异语义（防枚举）；对本人可提示「尝试过于频繁，请稍后再试」 |
| 2 | 失败日志**分级**：同源前 2 次 WARN、第 3 次起 DEBUG（首条必留可观测，狂打不刷爆日志） |
| 3 | 计数与锁定为**进程内内存**（与全域限频同款）；多实例须一并下沉 Redis |

## 3 · 接口限流（`/admin/**` 全域）

| 维度 | 阈值 | 目的 |
|---|---|---|
| **IP** | `/admin/**` **60/分 · 600/时**（scope `admin-api`） | 防狂打导致 Tomcat 线程打满 ⇒ **小程序用户也进不来** |
| **token（写操作）** | **20/分** per `adminId`（scope `admin-api:write`） | 防 token 泄露后被脚本批量调用（批量删除 / 停用）；命中即 WARN 留痕 |
| 读操作 | 沿用 IP 闸 | 管理端「读多写极少」，写单独收紧既不误伤本人，又能掐断脚本滥用 |

**关键设计**：

| 项 | 口径 | 理由 |
|---|---|---|
| 位置 | **验签「之前」** | 未鉴权流量恰是攻击主体；置于其后则失败请求仍逐条进过滤器、逐条打日志 |
| 阈值 | **刻意放宽**（业务接口为 30/分） | 管理端单人使用，正常操作远低于此；每分钟闸挡脚本狂打，每小时闸防慢速持续渗透 |
| scope | `admin-api`（与业务限频命名空间隔离） | 额度互不串扰 |
| 拒绝方式 | `BusinessException` → `GlobalExceptionHandler` → **`429`** | 与业务限频完全相同的响应路径，不另造格式 |

## 4 · 改密即吊销（止损操作位）

| 项 | 口径 |
|---|---|
| 机制 | 改密自增 `credential_version`，`AdminAuthFilter` **逐请求比对** ⇒ 旧 token 全部失效 |
| 响应 | 回一枚**新 token** 供本端续用，其余端需重新登录 |
| 端点 | `POST /admin/auth/password`（自助，不受角色门控） |

> 口令泄露后的止损手段是**改密**（自增凭证版本 ⇒ 既有 token 全部失效）与**人工核查**，而不是提高口令复杂度。

## 5 · fail-closed

| 场景 | 行为 |
|---|---|
| 未配置 `ADMIN_JWT_SECRET` / 弱密钥 | **启动失败** |
| 缺 token / URI 解析异常 | 一律拒绝（按 `401` 处理） |
| 账号已停用 | **逐请求**回查 `admin.status`（不缓存，停用即刻生效） |

## 6 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 单源高速猜密码 | IP 失败计数 | `429` | 告警（阈值） |
| 换 IP 分布式猜密码 | **账号维度**失败计数（跨 IP 累加） | 账号渐进锁定 + 指数退避 | 告警 + 锁定记录（内存态） |
| 密码泄露后冒用 | 新 IP / 异常时段登录检测 | 改密即吊销既有 token | **登录成功亦告警**（防「撞对了无人知」） |
| token 泄露被脚本滥用 | 写操作频次（token 维度） | token 维度写限频（20/分） | WARN 留痕（疑似滥用）+ 一键停用账号 |
| 狂打 `/admin/**` 拖垮全站 | IP 计数 | `429` | 告警 |
| 用户名枚举 | 统一文案 + 统一耗时 | `401` | 高频失败 ⇒ 告警 |

## 7 · 与当前代码的差异

> 登记设计已定、代码尚未同步的条目；清零即写「无」。

| # | 差异 | 涉及 |
|---|---|---|
| 1 | **账号不存在时未执行一次 BCrypt 比对**（`account != null && matches(...)` 短路，无 dummy 哈希）⇒「统一耗时」不成立，可按响应时间枚举管理员用户名 | `AdminAuthController` |
| 2 | 锁定态返回 `429` + 「登录失败次数过多」，与账号不存在 / 密码错误的 `401` 文案可区分；锁定计数对不存在的用户名同样累加，不构成用户名枚举 | `AdminAuthController` |
| 3 | 登录凭证失败路径无「前 2 次 WARN / 第 3 次起 DEBUG」分级（仅鉴权失败 401 路径实现） | `AdminAuthController` |
