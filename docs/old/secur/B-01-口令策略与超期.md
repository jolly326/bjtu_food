# B-01 · 口令策略与超期

> **等级 B（边际）** —— 在本威胁模型下，**真正的防线是账号锁定 + 指数退避 + 改密即吊销**（见 [S-03](./S-03-管理端登录与防爆破.md)）；口令复杂度与超期提示是叠加项，收益有限但成本低，故保留并如实标注为边际。
> **范围**：口令复杂度、轮转、超期提示、等时比较与统一耗时。
> **真源**：本文档。改密即吊销见 [S-03](./S-03-管理端登录与防爆破.md) §4。

---

## 1 · 管理员口令策略

**落地位置**：`POST /admin/auth/password`（改密端点是强度校验的**唯一入口** —— 账号由直连库登记，不存在「初始化设弱口令」的旁路）。

| 项 | 口径 |
|---|---|
| 最小长度 | **≥12 位** |
| 复杂度 | **含三类字符**（大写 / 小写 / 数字 / 符号中至少三类） |
| 校验位置 | **服务端强制**（前端提示只是体验；绕过前端直接调接口同样被拦） |
| 轮转 | **不强制轮转** —— 单人场景下强制轮转的收益不抵运维摩擦（忘改导致自己进不去） |
| 超期提示 | 距上次改密（从未改密则按建号时间）**>180 天** ⇒ `GET /admin/auth/me` 回 `passwordAging=true`，端上提示改密（**不强制踢出**） |
| 历史复用 | 不设历史密码表（不强制轮转 ⇒ 无复用判据） |
| 改密后 | **吊销既有 token** —— 自增 `credential_version`，过滤器逐请求比对 ⇒ 旧 token 全部失效；响应回一枚**新 token** 供本端续用，其余端需重新登录 |

> 口令泄露后的止损手段是**改密**（自增凭证版本 ⇒ 既有 token 全部失效）与**人工核查**，而不是提高口令复杂度。

## 2 · 等时比较与统一耗时

**威胁**：`String.equals()` / `==` 在首字节不同处提前返回，攻击者可据响应时间差逐步缩小口令空间；同理，登录路径若对「账号不存在」快速返回，即可枚举用户名。

**当前口径**：

| 项 | 现状 |
|---|---|
| 口令比对 | 委托 `BCryptPasswordEncoder.matches` —— BCrypt 算法本身按设计恒定耗时 |
| JWT 验签 | 委托 jjwt 的 MAC 校验（常量时间比较） |
| 统一耗时 | **账号不存在时未执行一次 dummy BCrypt 比对**（`account != null && matches(...)` 短路）⇒ 可据响应时间区分「账号不存在」与「密码错误」 |

> 📌 本条在本威胁模型下属**边际**：枚举用户名还需先过 IP 限频（5/分）与账号锁定；但补齐成本极低（对一个固定 dummy 哈希跑一次 `matches` 再返回统一文案）。

## 3 · 危险访问路径：识别 / 拦截 / 响应

| 路径 | 识别 | 拦截 | 响应 |
|---|---|---|---|
| 靠响应时间差缩口令空间 | — | BCrypt / jjwt 库内等时性 | — |
| 用户名枚举（统一耗时不成立） | 账号不存在时快速返回 | 待补齐 dummy 比对 | — |
| 弱口令被字典命中 | 改密端点强度校验 | `400` | — |
