# B-02 · 设计边界与否决记录

> **等级 B（边际与留痕）** —— 本篇登记「**明确不做**」的事与「已确认此路不通」的手段。**否决记录必须保留**：它把「我想这么加固」变成「已确认此路不通」，避免每个后来者重新论证一遍。
> **范围**：请求签名、IP 白名单、反代藏凭证、确认令牌、CORS 定位、已知取舍。
> **真源**：本文档。平台约束细节见 [`secur/`](./README.md) §7 与运维文档。

---

## 1 · 不做请求级签名（防重放）

**不做** `timestamp + nonce + HMAC` 一类的请求级签名 / 防重放：

| 理由 | 说明 |
|---|---|
| 密钥必随包分发 | 签名密钥必须分发到客户端，反编译即得 ⇒ 对「懂逆向的对手」**不构成真防护**，只是提高门槛 |
| 真实风险位已被覆盖 | 参数篡改由服务端校验（[A-01](./A-01-参数与字段校验.md)）与归属校验（[S-02](./S-02-鉴权与归属校验.md)）兜底；重放对写操作由**限频**压制（[S-04](./S-04-限频与可用性.md)） |
| 成本收益不匹配 | 每请求多一次签名计算 + nonce 存储，换来的边际安全极低 |

**触发重评的条件**：出现「重放导致实际损失」的事故。

## 2 · IP 白名单 / 安全组不可行

❌ **不可行**，两个独立原因，任一即否决：

| 原因 | 说明 |
|---|---|
| 平台不支持 | 微信云托管控制台**无安全组概念**，无入站 IP 白名单配置入口；无端口级暴露 / 映射能力；无内网穿透隧道（托管环境无 shell 权限、无法控制出网策略） |
| **校园网出口 IP 共享** | 与校内同学可能**共用同一个出口 IP** ⇒ 白名单等于允许**全校**访问，退化为无防护 |

**云托管提供的网络管控只有两个开关**：公网访问开关（控制是否拥有公网 HTTPS 域名，**唯一的外部流量总闸**）与内网访问开关（控制是否分配内网域名）。

> 📌 若将来换到有安全组的平台，且有固定 IP，可重新评估。

## 3 · 反向代理藏管理端凭证已否决

❌ **负优化**。让反向代理对每个请求自动注入管理端凭证 = 把凭证交给入口层白送：

| 维度 | 结论 |
|---|---|
| 攻击者需要什么 | 🔴 **什么都不需要**（入口层白送） |
| 攻击请求能否到 DB | 🔴 每请求都到（打连接池） |
| 拖垮谁 | 🔴 **小程序用户** |

**两条硬结论**：① 入口层只能「保管 / 藏」凭证，**绝不能「判断」** —— 判断必须在应用层（要查库、验签）。② **入口层自动注入凭证 + 扩大暴露面 = 负优化** ⇒ 要上云必须「入口层不注入凭证 + 应用层账密登录」**整套一起做**。

## 4 · 不引入一次性确认令牌

**明确不引入** `X-Confirm-Token` 类一次性确认令牌：收益主要在「防误操作」，而前端二次确认已覆盖；代价是显著增加正常使用摩擦。破坏性操作的真护栏是**后端写限频 + 引用校验 + 仅 `super` 删除**（见 [A-05](./A-05-告警与破坏性操作防护.md) §2）。

## 5 · CORS 的定位：不是安全防线，是可用性前提

| 项 | 口径 |
|---|---|
| 安全贡献 | **接近零** —— 攻击者直接打公网 `/admin/**` 不需要过 CORS；小程序走微信内部链路，**不带浏览器 `Origin`，不受此约束** |
| 配置 | `CORS_ALLOWED_ORIGINS` 环境变量，**默认空** |
| 空值行为 | 🔴 **拒绝一切带 `Origin` 的浏览器请求**（fail-closed） |
| 真实作用 | 管理端（web 跑本地 + backend 公网）能连上的**前提**；置空会使管理端全站 CORS 403 |
| 凭证 | `allowCredentials = false` |
| 非暴露风险 | 放行 `localhost` **不是对外开放** —— 浏览器 `Origin` 由页面自身决定，外部站点无法伪装成 `localhost` |
| 预检放行 | 🔴 **`OPTIONS` 预检不携带凭证**，须在**三处**放行：① 安全配置全局放行 `OPTIONS /**`；② 学生端 JWT 过滤器对 `OPTIONS` 直接放行；③ 管理端过滤器 `shouldNotFilter` 对 `OPTIONS` 返回 true。**任缺一处，预检返回 401 且不含 CORS 头，浏览器判定「跨域被拦」**（CORS 过滤器排在安全链之后，无法补救） |
| 出网请求 | 全部微信出网请求统一携带 `User-Agent` —— 微信网关 WAF 对「multipart + 空 UA」的 POST 直接回 **412** |
| 集中管理 | 全站**无散落的 `@CrossOrigin`**，CORS 统一由配置类收口 |

## 6 · 已知取舍（集中登记）

| # | 取舍 | 理由 | 重评条件 |
|---|---|---|---|
| 1 | 机审对「疑似（`review`）」一律放行，无人工复核队列 | UGC 治理闭环口径：微信全量检测 + 举报兜底，MVP 内容量小 | 出合规事故或量级增长 |
| 2 | 限频 / 黑名单 / 封禁计数为进程内内存 | 单容器云托管，重启清零可接受 | **云托管扩到 ≥2 实例前必须下沉 Redis** |
| 3 | 口令不强制轮转、不设历史密码表 | 单人场景收益不抵运维摩擦 | 多人共管 |
| 4 | 增强告警规则未实现（单 token 速率、单次批量删除条数） | 以 token 维度写限频 WARN 留痕替代 | 管理端迁公网或账号数增长 |
