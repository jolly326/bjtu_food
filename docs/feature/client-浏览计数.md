## 介绍

统计菜品热度：**每次获取菜品详情即计一次浏览，每次均 +1**（**PV 口径 = 页面浏览量**）。计数由**菜品详情接口承担**——`GET /dishes/{id}` 每次成功返回详情即计一次，**端上无须发起任何上报请求**（对用户与端上代码均无感知）。每次计数同步写入**访问日志**，作为后续按时间窗口（如近一个月）统计最热菜品的数据基础。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/dishes/{id}` | **🔓 公开** | 菜品详情（契约与字段见 [client-菜品详情](./client-菜品详情.md)）。**副作用：每次成功响应（`code=200`）浏览量 +1，并写入一条访问日志**。**无幂等语义：每次请求均计数**；`4001`（菜品不存在）、参数错误与网络失败**不计数** |

> 本功能**无独立端点**：计数内聚于详情接口的成功响应路径，游客与已认证用户的计数行为完全一致（不传任何身份信息亦计）。

## 字段

计数无独立请求 / 响应字段——详情接口的请求与响应契约见 [client-菜品详情](./client-菜品详情.md)；本功能仅约定以下**行为口径**：

### 计数与防护口径

| 项 | 口径 |
|---|---|
| **计数口径** | **无幂等语义** —— 不区分登录态、不按用户、不按时间窗口，每次成功获取详情均计数 |
| **计数时机** | 仅 `code=200` 计数；`4001`（菜品不存在，含已下架）、参数错误、网络失败一律不计数 |
| **IP 维度限频** | 复用 `IpRateLimiter`（滑动窗口、进程内实现）：同 IP **每分钟 ≤30 次、每小时 ≤300 次**。计数内聚于匿名高频读接口，故由 IP 限频承担防刷兜底 —— 只限制**同一 IP 的请求速率**，不限制「谁」「何时」 |
| 阈值依据 | 阈值刻意宽松：正常浏览（连续翻菜）远低于此、用户**无感**，但可挡住脚本级刷量 |

### 副作用（写库）

| 目标 | 变化 | 中文解释 |
|---|---|---|
| `dish.view_count` | **+1（每次成功响应）** | 菜品浏览量（**PV 口径，全历史累计**）；热度排序（`heatScoreExpr`）的输入之一 |
| `view_log` | **INSERT 一行（每次成功响应）** | **访问日志（append-only）**：记录 `user_id`（游客 = 0）/ `target_type='dish'` / `target_id` / `created_at`（访问时间），**每次访问新增一行、不做更新与合并**。作为按时间窗口聚合最热菜品的数据基础 |

### 时间窗口聚合（数据消费口径）

最热菜品（近一个月 / 任意窗口）由访问日志聚合得出：

`SELECT target_id, COUNT(*) AS pv FROM view_log WHERE target_type='dish' AND created_at >= :窗口起点 GROUP BY target_id ORDER BY pv DESC`

- 窗口起点由查询方指定（如近 30 天 / 近 7 天 / 全部）；
- 查询端点（管理端 / 端上榜单）为**独立能力，另行拍板后落地**，本功能仅承载数据写入；
- `dish.view_count`（全历史累计）与窗口聚合**并存不混用**：前者供现有热度排序（`heatScoreExpr`），后者供窗口统计。

## 数据（读写）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `dish` | UPDATE `view_count` | 浏览量（PV，全历史累计），热度排序（`heatScoreExpr`）的输入之一 |
| `view_log` | INSERT（每次一条） | 访问日志（append-only）；游客亦写入（`user_id=0`）；每行仅有 `created_at` 一个时间字段，无更新语义 |

> **热度权重**：`heatScoreExpr = view_count * 1 + rating_count * 100 + avg_rating * 20`
> —— 浏览量权重为 **1**（10 条评价 = 1000 分）→ **刷浏览对排序的影响有限**。
