## 介绍

统计菜品热度：**每次进入菜品详情页即上报一次浏览，每次均 +1**（**PV 口径 = 页面浏览量**）。上报由端上在进入详情页时**自动**发起一次 `POST /dishes/{id}/views`，**失败静默**（埋点不阻塞详情展示）。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/dishes/{id}/views` | **🔓 公开**（无需登录；用户身份若可识别则仅用于写浏览足迹） | 浏览量 **+1**，并（在可识别用户时）记录浏览足迹。**无幂等语义：每次调用均计数** |

> **计数由端上显式 POST 承担（有意设计，修改须重新拍板）**：`GET /dishes/{id}` 保持**纯读、幂等**——
> 可被预取 / 爬虫 / CDN / 浏览器重放，具备缓存 / CDN 友好属性；计数埋点若携带副作用会被放大，
> 故由端上在进入详情页时**显式上报**一次。

## 字段

### 请求

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `id` | number | **是** | 菜品 ID（路径参数，如 `/dishes/1/views`）。**无请求体**；若携带 token 则从中取 userId，**游客可无 token 调用** |

### 响应 · `POST /dishes/{id}/views`（`data` = `null`）

统一信封 `{ code, message, data }`，本接口 `data` 恒为 `null`：

| 字段名 | 类型 | 中文解释 |
|---|---|---|
| `code` | number | 业务码：`200`=成功（每次调用均计数）；`4001`=菜品不存在（含已下架） |
| `message` | string | 提示文案，成功恒为 `操作成功` |
| `data` | null | 恒 `null`（`Result<Void>`）；本接口无响应载荷，浏览结果只体现在下面「副作用」的库表变化 |

### 计数与防护口径

| 项 | 口径 |
|---|---|
| **计数口径** | **无幂等语义** —— 不区分登录态、不按用户、不按时间窗口，每次调用均计数 |
| **IP 维度限频** | 复用既有 `IpRateLimiter`（滑动窗口、进程内实现）：同 IP **每分钟 ≤30 次、每小时 ≤300 次**。本端点为**匿名写接口**，故由 IP 限频承担防刷兜底 —— 只限制**同一 IP 的请求速率**，不限制「谁」「何时」 |
| 阈值依据 | 阈值刻意宽松：正常浏览（连续翻菜）远低于此、用户**无感**，但可挡住脚本级刷量 |

### 副作用（写库）

| 目标 | 变化 | 中文解释 |
|---|---|---|
| `dish.view_count` | **+1（每次）** | 菜品浏览量（**PV 口径**）；热度排序（`heatScoreExpr`）的输入之一 |
| `view_log` | **upsert（可识别用户时）** | 浏览足迹：按 `userId + targetType='dish' + targetId` 定位，已有行只刷新 `updated_at`、不新增行。**游客不写足迹**（无 userId 可写） |

## 数据（读写）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `dish` | UPDATE `view_count` | 浏览量（PV），热度排序（`heatScoreExpr`）的输入之一 |
| `view_log` | INSERT / UPDATE `updated_at` | 浏览足迹；游客不写入 |

> **热度权重**：`heatScoreExpr = view_count * 1 + rating_count * 100 + avg_rating * 20`
> —— 浏览量权重为 **1**（10 条评价 = 1000 分）→ **刷浏览对排序的影响有限**。
