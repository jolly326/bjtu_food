# 浏览计数（A-05）

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔓 公开页自动触发，接口需登录**
> 返回：[功能总览](./README.md)

## 干什么

统计菜品热度：进详情页自动上报一次浏览，**同一用户对同一菜品每个自然日只计 1 次**（当日重复上报幂等，不重复计数）。

## UI

无独立界面（进菜品详情页自动触发，用户无感知）。

## 操作

无需操作。进入菜品详情页时端上自动调一次 `POST /dishes/{id}/views`；**失败静默**（埋点不阻塞详情展示）。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/dishes/{id}/views` | 需登录（token 取当前用户） | 浏览量 +1，并记录浏览足迹；当日重复调用幂等返回成功。**2026-09-20 §7.30 RESTful 化：原 `.../view` → `.../views`** |

## 字段

### 请求

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `id` | number | **是** | 菜品 ID（路径参数，如 `/dishes/1/view`）。**无请求体**；用户身份从 JWT 取，端上不传 userId |

### 响应 · `POST /dishes/{id}/view`（`data` = `null`）

统一信封 `{ code, message, data }`，本接口 `data` 恒为 `null`：

| 字段名 | 类型 | 中文解释 |
|---|---|---|
| `code` | number | 业务码：`200`=成功（含「当日已浏览过」的幂等返回）；`401`=未登录（token 失效，需静默重登） |
| `message` | string | 提示文案，成功恒为 `ok` |
| `data` | null | 恒 `null`（`Result<Void>`）；本接口无响应载荷，浏览结果只体现在下面「副作用」的库表变化 |

> **幂等语义**：同一用户同一菜品当日重复调用，仍返回 `code=200`，但**不自增 `view_count`、不重复写足迹**。

### 副作用（写库）

| 目标 | 变化 | 中文解释 |
|---|---|---|
| `dish.view_count` | +1 | 菜品浏览量（仅当日首次浏览时自增） |
| `view_log` | upsert | 浏览足迹：按 `userId + targetType='dish' + targetId` 定位；已有行只刷新 `updated_at`（不新增行） |

**去重口径**：以 `view_log.updated_at >= 当日零点（Asia/Shanghai）` 判定「今天是否已浏览过」；重复则是幂等返回。

## 数据（读写）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `dish` | UPDATE `view_count` | 浏览量，热度排序（`sortBy=heat`）与热搜词条的输入之一 |
| `view_log` | INSERT / UPDATE `updated_at` | 浏览足迹，**同时是当日去重的唯一判据** |
