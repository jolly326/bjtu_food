# 写评价（A-06）

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔐 认证**（需学号邮箱认证）
> 返回：[功能总览](./README.md)

## 介绍

给一道菜打星 + 写文字 + 最多 3 张配图。**先发后审**：文本与图片通过微信内容安全检测即**立即公开**，无人工复核；后续如被举报，由管理员事后处置。

**提交是一个动作、两种模式**：对未评价的菜为**首次提交**（`POST /dishes/{id}/reviews`，新建）；对已评价的菜为**重新评价**（`PUT /reviews/{id}`，覆盖式重写）——端上为同一个评价表单，业务逻辑完全相同，差异见 §字段「重新评价与首次提交的差异」。「是否已评价」的判定发生在**点击「写评价」之后、表单打开前**（已评价 → 预填本人旧值并以重评模式打开、明示覆盖原评价；未评价 → 空表单），详情页首屏不做任何用户态判定。提交流程：选星级（1~5 必填）→ 文字（可跳过）→ 配图（≤3 张，逐张压缩上传取 COS URL 后随评价提交）；检测不通过则提示错误、不发布。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/upload/cloud-image` | 需登录（游客亦可） | **前置调用**：配图逐张转存（微信内容安检 + 转存 COS） |
| POST | `/dishes/{id}/reviews` | **🔐 认证**（`@RequireVerified`；未认证 → 4031） | **首次提交**（新建评价；路径 `{id}` = 菜品 ID，body 不收 `dishId`）。每人对同一菜品仅一条评价（唯一键 `uk_review_user_dish`）；`risky` 内容 → 400 |
| PUT | `/reviews/{id}` | **🔐 认证**（`@RequireVerified`；**作者本人**，非本人 → 403） | **重新评价（覆盖式）**：路径 `{id}` = 本人评价 ID，**归属锁定不可换菜**。除 §字段「差异表」外与首次提交完全同逻辑 |

## 字段

### 请求 · `ReviewReq`（首次提交与重新评价**共用**）

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `rating` | number | **是** | 评分，**1~5 星**（超出范围 → 400） |
| `content` | string | 否 | 文字评价，最长 **500 字**（可只打星不写文字） |
| `images` | string[] | 否 | 评价配图 URL 数组，**最多 3 张**；元素须为经 `POST /upload/cloud-image` 转存后的 COS 绝对地址 |

| 路径参数 | 首次提交 | 重新评价 |
|---|---|---|
| `{id}` | 菜品 ID（`POST /dishes/{id}/reviews`） | 本人评价 ID（`PUT /reviews/{id}`） |

### 响应

| 模式 | `data` | 中文解释 |
|---|---|---|
| 首次提交（POST） | `{ "id": number }` | **新评价 ID**——端上提交成功后本地写回「我的评价」态（底栏就地切为「重新评价」），无须回读 |
| 重新评价（PUT） | `null` | 无载荷（评价 ID 端上已持有）；成功即 `code=200`（失败按错误码提示 `message`） |

### 重新评价与首次提交的差异

| 项 | 差异口径 |
|---|---|
| 落库 | **覆盖更新同一行**（非删行重建）：唯一键 `uk_review_user_dish` 不变、无并发窗口；旧内容不留残留 |
| `created_at` | **刷新为当前时间**（「重评即新发布」，时间倒序下自然置顶） |
| `is_hidden` | **重置为 0**（旧评价作废、新评价从零开始） |
| 鉴权 | 额外要求**作者本人**（非本人 → 403） |
| 次数 | **不限次**（一人一菜只有一票，改多少次也只是一票） |

> 除上表差异外，重新评价与首次提交**逻辑完全相同**：安检口径、配图规格与前置上传、4031 分流、评分聚合事件均一致。

### 前置调用字段 · `POST /upload/cloud-image`

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| `fileId` | string | **是** | 微信云存储文件标识（`wx.cloud.uploadFile` 返回的 `cloud://...`） |
| → 响应 `url` | string | — | 安检通过并转存后的 **COS 绝对 URL**（收集后随 `images` 提交） |

### 内容安全（提交闸门，不落库）

| 环节 | 判定 | 中文解释 |
|---|---|---|
| 文本 `msgSecCheck` v2（`scene=2`） | `pass` / `review` → **放行**；`risky`（含未知/缺失态）→ **400 拦截、不落库** | 内容安全检测即终局，**无人工复核** |
| 图片 `imgSecCheck` | 违规（微信码 `87014`）→ 400 | 单张失败只跳过该张，不中断其余图片上传 |

### 错误码

| code | 含义 | 中文解释 |
|---|---|---|
| 400 | 参数/业务校验失败 | 含内容安检违规（提示违规文案）、配图超 3 张、评分越界等 |
| **4031** | 邮箱未认证 | 区别于 403：前端据此跳转身份认证页 |
| 403 | 非本人评价（重新评价） | 归属校验失败 |

## 数据（落库）

| 表 | 变化 | 中文解释 |
|---|---|---|
| `review` | **INSERT**（首次提交）/ **UPDATE**（重新评价覆盖同一行） | 写入 `user_id`（当前登录用户，**禁止信任前端**）、`dish_id`、`rating`、`content`、`images`（JSON 数组，COS URL）；重评覆盖同一行的评分 / 文字 / 配图，并刷新 `created_at`、`is_hidden` 重置 0 |
| `dish.avg_rating` / `dish.rating_count` | **异步** UPDATE | 通过 `ReviewSubmittedEvent` → `RatingUpdateListener`（`@Async` AFTER_COMMIT）重算；**口径：仅计 `is_hidden=0` 的评价** |
