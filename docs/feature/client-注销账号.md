# 注销账号（A-15）

> 所属端：**学生端（微信小程序）** ｜ 鉴权：**🔓 公开**（游客态与已认证态都可注销）
> 返回：[功能总览](./README.md)

## 干什么

用户主动注销当前账号（合规硬需求）。语义为**匿名化，而非物理删除**：身份信息全部清空、账号标记 `deleted`、token 立即失效；**历史评价与反馈保留**（昵称自然变为「已注销用户」，评分聚合不破坏）。

## UI

- 入口：**个人资料页底部**「注销账号」。
- 点击 → **二次确认**弹窗（说明后果：昵称头像清空、评价保留但去身份化、**不可恢复**）。
- 当前实现为小字号文字链（UI 重设计建议见 `README.md`「需拍板的待办清单」第 5 项）。

## 操作

1. 个人资料页底部点「注销账号」→ 二次确认弹层。
2. 确认 → 调 `DELETE /auth/account`（**跳过 401 静默登录重试**：静默登录会建出新游客号，重试会误删新账号）。
3. 成功 → 清本地 token 与用户信息 → 回到首页（重新打开小程序会以新游客号静默登录）。
4. 幂等：已注销账号重复调用 → 400「账号已注销」。

## 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| DELETE | `/auth/account` | 需登录 | 注销当前账号（匿名化）+ token 立即失效 |

## 字段

### 请求

| 字段名 | 类型 | 必填 | 中文解释 |
|---|---|---|---|
| — | — | — | **无请求体、无参数**；注销对象 = JWT 中的当前用户，端上**不传 userId** |

### 响应

| 字段名 | 类型 | 中文解释 |
|---|---|---|
| `data` | null | 无载荷；成功即 `code=200` |

### 副作用 · `user` 表各列变化（匿名化清单）

| 字段名 | 变化后 | 中文解释 |
|---|---|---|
| `nickname` | `'已注销用户'` | 历史评价/反馈经 join 取昵称自然匿名化 |
| `username` | `'deleted_{id}'` | 释放用户名唯一键占用（不改会导致后续建号撞唯一键） |
| `avatar` | NULL | 清空头像 |
| `email` | NULL | 清空邮箱（NULL 不占唯一索引，允许原邮箱再次认证） |
| `openid` | NULL | **解绑微信**，允许同一微信重新静默登录建新游客号 |
| `bind_email` | NULL | 解绑认证关系 |
| `verified_at` | NULL | 清认证时间 |
| `verified` | 0 | 认证状态复位 |
| `status` | `'deleted'` | 与登录拦截、UGC 写拦截形成持久化兜底 |

### 副作用 · 其他表

| 表 | 变化 | 中文解释 |
|---|---|---|
| `email_verification_code` | DELETE | 按该用户的 `email` 与 `bind_email` 两批清理，避免残留验证码被他端消费 |
| `review` / `user_feedback` / `notification` / `view_log` | **保留** | 评价与反馈保留（去身份化展示）；评分聚合不破坏；通知与足迹保留 |
| Token 黑名单 | 加黑 token + userId | 当前 token 立即 401「账号已注销，请重新登录」；同用户其余设备历史 token 一并失效 |

### 错误码

| code | 含义 | 中文解释 |
|---|---|---|
| 400 | 账号已注销 | 重复调用（幂等保护） |
| 400 | 账号已被禁用，无法注销 | `disabled` 状态不允许注销 |
| 401 | 请先登录 | 无有效登录态 |

## 数据（落库）

见上「副作用」两张表。**注销 ≠ 删除数据**：不物理删除 user 行，也不删评价/反馈，保证口碑数据与评分聚合不被破坏。
