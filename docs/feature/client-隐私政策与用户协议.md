## 干什么

合规入口：向用户说明**收集哪些信息、用途、存储与删除权利**。属静态展示页，不产生任何业务数据。

## UI

- 入口：「我的」页**底部信息区唯一可点元素**。
- 页面：`pages/privacy/index`，两个 tab（**隐私政策** / **用户协议**）。
- 纯展示，无表单、无按钮交互（仅 tab 切换与滚动）。

## 操作

查看即可。切 tab 阅读两份文本，无提交动作。

## 答疑

### Q：这个板块是否要保留？我认为没用，你的建议

**A：建议保留，且不建议弱化——它不是产品功能，是合规硬需求。**

理由：① 上架/年审与《个人信息保护法》要求「收集个人信息必须有隐私政策并明示」，而本项目确实收集了**微信标识（openid）、校园邮箱、昵称头像、浏览足迹、UGC 内容（评价/反馈/配图）**，并且提供了「注销账号」（A-15）——这些都必须有对应的政策文本与入口；② 微信平台对小程序隐私接口（登录、头像昵称、上传）有强制配置要求，缺失会直接限制相关能力；③ 删掉它产品不会更好用（收益 0），但上架/审核风险不为 0。

**可优化的是呈现，不是存废**：
① 保留入口，与「注销账号」共同构成「法律与安全」区；
② **真正的风险点是文案与实现不符**——请让隐私政策逐条对齐真实数据面（收集项 / 用途 / 存储 / 删除权利 / 注销方式 / 联系方式），文案与实现一致比「有没有这一页」更关键；
③ 建议把它当静态资源管理（内容纳入走查清单），避免与代码脱节。

**结论：保留；本轮只做 §4 视觉规范化 + 文案与数据面核对，不做删除。**
