# 菜品管理 — 页面 UI 设计稿

> 所属端：管理端（Web 后台）
> 落点：`/dashboard/content`（`DishManageView`，**后台默认落地页**）；新增 / 编辑走 `DishFormDialog` 弹窗（不跳页）；行点击进 `DishDetailView`（`/dashboard/content/dishes/:id`）。

## 1. 页面构成（自上而下）

| 区块 | 内容 |
|---|---|
| 页头 | `PageHeader` 标题「菜品」（朱砂竖条 + H1）；右侧 `#actions` 主操作「**新增菜品**」（主色实底 + Plus 图标） |
| 筛选条 | `FilterBar`：左槽 4 个下拉 —— **大类**（150px）/ **食堂**（170px）/ **档口**（170px）/ **状态**（150px）；右槽 = 关键词搜索框（200px，有值显清除钮）+ 批量动作区 |
| 表格 | `DataTable`（可选中 + 整行可点）：复选列 48px → 图片 72px（居中）→ 菜品名称（可排序）→ 大类 104px → 位置 → 价格 120px（居中，可排序）→ 评分 80px（居中，可排序）→ 状态 110px（居中）→ 操作列 140px（编辑 / 删除）→ 行尾箭头 40px |
| 分页 | **客户端分页**（默认每页 10，可选 10/20/50/100）：`total > pageSize` 时显示「共 N 条 + 每页条数 + 翻页」，否则仅右对齐「共 N 条」 |
| 弹窗 | `DishFormDialog`（宽 640，标题随「新增 / 编辑」切换，确认「保存」） |
| 批量区 | 仅 `selectedIds.length > 0` 时出现：「已选 N 项」+ 批量上架 / 批量下架 / 批量删除 |

**筛选选项来源**：食堂 = `adminStore.canteens`；档口 = 按所选食堂过滤（**未选食堂时下拉为空且禁用**，占位「请先选食堂」）；大类 = 后端字典 `GET /dishes/meal-types` + 列表出现但字典未覆盖的兜底项；状态 = **页内固定项**（全部 / 在售 / 已下架）。

## 2. 三态（全部由 `DataTable` 承担）

| 态 | 呈现 |
|---|---|
| 加载中 | `.state-box` 转圈 + 「加载中…」，替换整表 |
| 失败 | `.state-box.state-err`：`{{ error }}，请刷新页面重试` |
| 空 | `.empty-state`（min-height 240px）：图标（本页未传）+ 文案「暂无菜品」 |
| 正常 | 表格 + 分页栏 |

> 失败态文案要求刷新但**页内无重试按钮** ⇒ 已在实现上补「重试」动作（见 §6 交互）。

## 4. 数据映射

| # | 字段 | 来源 | 中文含义 | 显示在哪个组件 | 呈现形式 |
|---|---|---|---|---|---|
| 1 | `name` | `GET /admin/dishes` | 菜品名称 | 菜品名称列 | 加粗 + `title` 兜底 |
| 2 | `image` | 同上（`\|\|\|` 分隔取首张） | 首图 | 图片列 | 52×40 缩略图；无图 → 灰底「图」占位 |
| 3 | `mealType` | 同上；标签来自 `GET /dishes/meal-types` | 菜品大类 | 大类列 | 字典中文标签，空 → 「—」 |
| 4 | `canteenName` / `stallName` | 同上（联表直出） | 位置 | 位置列（合并一列） | 「食堂 · 档口」，缺省「—」 |
| 5 | `price` | 同上（API 已分转元） | 现价 | 价格列 | `¥X.XX`，主色加粗 |
| 6 | `originalPrice` | 同上 | 原价 | 价格列 | 仅 `> price` 时划线 + 红底「折扣」标 |
| 7 | `avg_rating` | 同上 | 评分 | 评分列 | 星图标 + 一位小数，0 → 「—」 |
| 8 | `status` | 同上 | 状态 | 状态列 | `el-switch` + 文字「在售 / 已下架」 |

| 10 | `id` | 同上 | 主键 | 多选 / 编辑 / 删除 / 跳转详情 | 零可见 UI |

## 5. 交互清单

- 新增 / 编辑 / 删除（删除前二次确认，文案含连带评价数）
- 行内状态开关 → 立即上下架（期间该行 loading + 禁用）→ Toast「「X」已上架 / 已下架」
- 复选（行 / 表头全选**仅作用于当前页**）→ 批量上架 / 下架 / 删除（二次确认，串行请求，结束统一刷新；失败项保留选中便于重试）
- 筛选联动：**切换食堂静默清空档口**；全部筛选为**前端本地过滤**并即时重算
- 排序：表头点击循环 升序 → 降序 → 取消（名称 / 价格 / 评分）
- 行点击（含 Enter / Space，行尾箭头除外）→ 菜品详情；**状态列开关点击须阻止冒泡**（否则误跳详情）
- 深链：`?q=<菜名>` 预填关键词；`?tab=dish` 忽略
- 关键词输入：**本地即时过滤**（数据已在内存，无需防抖）；依赖全量拉取，量大数据时首屏偏慢属已知取舍

## 6. 接口与错误呈现

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/dishes` | 全量拉取（`pageSize=100` 循环），筛选在端上 |
| POST | `/admin/dishes` | 新增 |
| PUT | `/admin/dishes/{id}` | 行内开关 / 批量上下架 |
| DELETE | `/admin/dishes/{id}` | 单条 / 批量删除 |
| GET | `/admin/canteens`、`/admin/stalls` | 筛选字典 |
| GET | `/dishes/meal-types` | 大类字典（失败**静默**，不升级为页面错误） |

- 页面级失败：取首个 rejected 的 `message`，兜底「加载菜品列表失败」，并提供**重试**
- 写操作失败：一律 `toast.error(message || 默认文案)`（删除 / 状态更新 / 保存各有兜底文案）
- 无按错误码分支

## 7. 已知取舍（保留现状）

- 客户端分页 + 全量拉取：数据量小时体验最好，量大时首屏偏慢（服务端分页 + 筛选参数属待办项）
- 状态筛选项为页内固定值（与字典类筛选的来源不一致，但语义稳定）
- 无「重置筛选」入口、无筛选 active 计数
