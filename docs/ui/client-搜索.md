## 0. 与首页的一致性对照（跨页同源，禁各画一套）

| 搜索行 | 左搜索胶囊 + 右「搜索」按钮 | **左搜索胶囊 + 右「搜索」按钮（完全同款）** | ✅ 高度 / 圆角 / 内距 / 间距 / 字号 / 颜色全部相同（见 §2，引用首页 §1.2） |

## 1. 页面结构（自上而下）

1. **固定标题带（左上角 = 返回 icon）**：`position: fixed`、永久固定在页面左上角、与微信胶囊同一水平带；**不含标题文字**；带表面**始终为页面底**（本页无 Banner，无需透明态）；
2. **搜索行**（标题带下方）：**左 = 搜索胶囊**（白底、放大镜 + 灰色占位「**搜索菜品、食堂、档口**」）+ **右 = 「搜索」按钮**（填充档主色 + 白字）；点击胶囊或按钮均进入可输入态并聚焦；
   - **占位文案口径（2026-09-23 修订）**：占位**只列真实可搜的维度**。搜索走 `GET /dishes?keyword`，服务端**只匹配「菜名 / 档口名 / 食堂名」三处**（`project_spec.md` §7.35 第 1 条）；**「套餐」不是可搜维度**——项目无套餐实体，「套餐盖饭」只是 `meal_type` 大类，而**大类不参与关键词匹配**（搜「套餐」不会返回全部套餐盖饭），故**不得**写入占位文案；
   - **提交中禁用态（2026-09-23 新增）**：「搜索」按钮在**请求进行中** SHALL 降透明（`opacity: 0.6`）+ 禁点，且此时不响应按压态；请求结束（含失败）后恢复。依据 `ui-ux-pro-max` §2 `loading-buttons` / §8 `submit-feedback`——异步操作期间无反馈会读作「点了没反应」，并诱发重复提交。**MVP 不引入 spinner / 骨架**（`client-ui-motion` 拍板），故仅以禁用态表达「已受理」；状态清除 SHALL 受竞态守卫约束（仅最新一次请求可解除，过期请求返回不得复位）；
3. **搜索记录**（未输入关键词时显示）：
   - 数据**纯本地**（`uni.setStorageSync`，键 `find_search_history`），**不上服务端、不做跨设备同步**；
   - 上限 **4 条**（`HISTORY_MAX`），**去重、最新在前**，超过后淘汰最旧；
   - 交互：点条目 → 以该词发起搜索；提供**清空**动作（二次确认不做弹窗，直接清空 + 轻提示）；无记录时**整块不渲染**（不显示空标题）；
   - **按压反馈（2026-09-23 新增，两组 chip 通用）**：chip SHALL 有点按反馈（`hover-class` → 底色加深一档：记录 chip → `--bg-placeholder`、推荐 chip → `--bg-soft-orange`），并 SHALL 声明 `touch-action: manipulation`（消除移动端点击延迟）。依据 `ui-ux-pro-max` §2 `press-feedback`（**CRITICAL** 级）：可点元素必须有点按反馈——旧实现只写了 `transition: background` 却**没有任何按压态**，等于「点了完全没反应」，同时其 `transition` 也无从生效；
4. **猜你喜欢**（未输入关键词时显示，位于搜索记录之下）：
   - 数据来自 **`GET /dishes/for-you`**（2026-09-22 由 `GET /dishes/hot-search` 改名，语义升为「**猜你喜欢**」）——**当前实现 = 每次随机推送在售菜品名**（无推荐算法、无热度排序、无个性化，**完全随机**）；**契约留扩展位**：将来升级为个性化 / 推荐算法时，**端上契约不变**（仍 `keyword` 列表），只换服务端取数逻辑；
   - 形态：**chip 组**（换行排列）；chip 文案 = 返回的 `keyword`，**端上不写死词条、不排序**（按返回渲染）；
   - **条数上限（2026-09-23 定稿）**：**由后端限制返回 ≤ 6 条**。理由：该接口当前为**纯随机**推送（无推荐算法），8 条以上会占满发现态首屏、把「搜索记录」这个真正的个性化入口挤出可视区；端上仍**不截断、不排序**（上限是数据源职责，端上零逻辑）；
   - 交互：点 chip → 以该词发起搜索（并写入本地记录）；
   - 返回空数组 / 请求失败 → **整块不渲染**（不显示标题、不做骨架）；
5. **结果列表**（输入关键词并搜索后显示）：单列结果行（`FindResults`），左缩略图 + 右信息（菜名 / 评分 / 价格 / 位置行），复用首页菜品视觉语言；
   - **命中片段弱强调（2026-09-23 定稿）**：菜名 / 位置行中与关键词命中的片段 SHALL 以**字重加深**（`--weight-heavy`）区分，**SHALL NOT 上主色**——主色是价格专用强调色（见 §3）。理由：用户搜「糖醋里脊」、结果菜名恰为「糖醋里脊」时，若完全不标记命中位置则**扫读性为零**。旧口径「命中既不上色也不加字重」过度削弱了搜索反馈；端上分段逻辑已有（`FindResults` 的 `splitHighlight`），本次仅启用其视觉表达；
6. 页面最底部：**TabBar 不出现**（本页为二级页，返回靠左上角返回 icon / 系统手势）。

## 4. 状态

| 状态 | 呈现 |
|---|---|
| 未输入（发现态） | 搜索记录（有则显示）+ 猜你喜欢（有则显示）；**两者都空 → 内容区留空**（不显示空文案、不做骨架） |
| 输入中 | 仅结果区变化；搜索行文案不截断（超长省略） |
| 结果态（有结果） | 单列结果行列表 |
| **结果态（少量结果，如仅 1 条）** | **结果区垂直居中**，使留白分布于首卡上下两侧；**SHALL NOT 追加任何填充内容 / 结果计数 / 引导文案**（沿用「内容组件不承载空态」口径）。**2026-09-23 定稿**：旧实现单条时卡片悬于顶部、下方留白约 70% 屏高，读作「还没加载完」 |
| 结果态（无结果） | **呈现「无结果引导」**（**非静默**）：图标 + 「没搜到「{关键词}」相关的菜」+ 副文案 + 「推荐这道菜」按钮（跳反馈页并预选「推荐菜品」，`from=find`）。**2026-09-23 修正**：旧口径写「静默」与代码实况不符——该引导属全站**两处显式空态例外之二**（`openspec/specs/client-page-structure`），亦见 `search-result-presentation`「成功且无结果时呈现静态换词引导」 |
| 失败态 | 结果区渲染「加载失败 · 点击重试」块（`searchFailed`，MP-012），与「没搜到」区分 |
| 猜你喜欢请求失败 | **整块不渲染**（不阻塞搜索能力） |

## 5. 硬性约束（回归检查清单）

1. 左上角**必须是返回 icon**（占原「知行食记」位置），与微信胶囊同水平带、同高、互不遮挡；**其光学尺寸 SHALL 与同位置标题相仿**（画布 88rpx → 绘制高 44rpx = `--font-title`，见 §2）——**SHALL NOT** 出现「图标远小于标题」的失衡；
2. **搜索行必须与首页完全同位同款**（左胶囊 + 右「搜索」按钮；高度 / 圆角 / 内距 / 间距 / 字号全部引用首页 §1.2）——**不得**再使用「橙色整条 header + 内嵌输入框」的旧头部；**占位文案不得写入不可搜的维度**（如「套餐」，见 §1 第 2 条）；
3. 主题色**必须与首页同源**（首页 §4.1，本节不另立色值）——不得在本页自建第二套色值；**评分星 SHALL 用 `--color-star`**，不得用任何主色档；
4. 「搜索记录」**只能存本地**，不得上传服务端、不得跨设备同步；上限 4 条、去重、最新在前；
5. 「猜你喜欢」文案与条数**全部来自后端**（**后端限制 ≤ 6 条**，见 §1 第 4 条），端上不写死、不截断、不排序；**不得**引入推荐算法 / 个性化口径；
6. 本页**无筛选入口**（食堂 / 价格筛选已于 2026-09-22 全量下线，见首页功能文档 K 项）；
