# 搜索 — 页面 UI 设计稿

> 所属端：学生端（微信小程序） ｜ 归属功能文档：[client-搜索.md](../feature/client-搜索.md)
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 落点：`pages/find/index`（主包 · **二级页**，由首页顶部搜索框 `navigateTo` 进入，非 Tab 页；留主包以**避免分包加载闪断**）。
>
> **口径总则（本文档为 UI 唯一真源）**：① 页面构成**四块**——`搜索框` / `搜索记录` / `猜你喜欢` / `结果列表`；② 头部为「**固定标题带（左上角放返回 icon）+ 搜索行**」：**返回 icon 占页面标题位**（左上角、与微信右上角胶囊同一水平带）；③ **搜索框位置、尺寸、间距、圆角、字号与首页完全一致**（引用首页 §1.2）；④ **主题色与首页统一**——用色口径见 [client-首页菜品浏览.md](./client-首页菜品浏览.md) §4「全站色板（暖橙黄）」。

## 0. 与首页的一致性对照（跨页同源，禁各画一套）

| 维度 | 首页 | 搜索页（本页） | 一致性 |
|---|---|---|---|
| 固定标题带 | 左上角「知行食记」（`--font-title` 黑色粗体） | 左上角**返回 icon**（同位置 / 同高度 / 同水平带，与胶囊同线） | ✅ **同口径，仅替换内容物**：带高 = 状态栏 + `navBarHeight`，右侧同样按胶囊避让 |
| 搜索行 | 左搜索胶囊 + 右「搜索」按钮 | **左搜索胶囊 + 右「搜索」按钮（完全同款）** | ✅ 高度 / 圆角 / 内距 / 间距 / 字号 / 颜色全部相同（见 §2，引用首页 §1.2） |
| 页面底色 / 主色 / 文字色 | 首页 §4 全站色板 | 同 | ✅ |
| 顶部滚动行为 | Banner 正常流 + 搜索区/标签栏吸顶 | **无 Banner**：标题带与搜索行**常驻固定**（不吸顶、不滚动、不做纱式过渡） | 差异（本页没有可滚出屏幕的顶部大图） |

> **为什么返回 icon 占标题位**：全站「左上角固定标题带」是同一视觉锚点，位置一致用户才不会在页面切换时「找不到自己在哪里」——首页把它用作页面标题，二级页把它用作返回入口（**不额外增加一行 header**，避免顶部被两行挤占）。

## 1. 页面结构（自上而下）

1. **固定标题带（左上角 = 返回 icon）**：`position: fixed`、永久固定在页面左上角、与微信胶囊同一水平带；**不含标题文字**；带表面**始终为页面底**（本页无 Banner，无需透明态）；
2. **搜索行**（标题带下方）：**左 = 搜索胶囊**（白底、放大镜 + 灰色占位「**搜索菜品、食堂、档口**」）+ **右 = 「搜索」按钮**（填充档主色 + 白字）；点击胶囊或按钮均进入可输入态并聚焦；
   - **占位文案口径**：占位**只列真实可搜的维度**。搜索走 `GET /dishes?keyword`，服务端**只匹配「菜名 / 档口名 / 食堂名」三处**（`project_spec.md` §7.35 第 1 条）；**「套餐」不是可搜维度**——项目无套餐实体，「套餐盖饭」只是 `meal_type` 大类，而**大类不参与关键词匹配**（搜「套餐」不会返回全部套餐盖饭），故**不得**写入占位文案；
   - **提交中禁用态**：「搜索」按钮在**请求进行中** SHALL 降透明（`opacity: 0.6`）+ 禁点，且此时不响应按压态；请求结束（含失败）后恢复。依据 `ui-ux-pro-max` §2 `loading-buttons` / §8 `submit-feedback`——异步操作期间无反馈会读作「点了没反应」，并诱发重复提交。**MVP 不引入 spinner / 骨架**（`client-ui-motion` 口径），故仅以禁用态表达「已受理」；状态清除 SHALL 受竞态守卫约束（仅最新一次请求可解除，过期请求返回不得复位）；
3. **搜索记录**（未输入关键词时显示）：
   - 数据**纯本地**（`uni.setStorageSync`，键 `find_search_history`），**不上服务端、不做跨设备同步**；
   - 上限 **4 条**（`HISTORY_MAX`），**去重、最新在前**，超过后淘汰最旧；
   - 交互：点条目 → 以该词发起搜索；提供**清空**动作（二次确认不做弹窗，直接清空 + 轻提示）；无记录时**整块不渲染**（不显示空标题）；
   - **按压反馈（两组 chip 通用）**：chip SHALL 有点按反馈（`hover-class` → 底色加深一档：记录 chip → `--bg-placeholder`、推荐 chip → `--bg-soft-orange`），并 SHALL 声明 `touch-action: manipulation`（消除移动端点击延迟）。依据 `ui-ux-pro-max` §2 `press-feedback`（**CRITICAL** 级）：可点元素必须有点按反馈；
4. **猜你喜欢**（未输入关键词时显示，位于搜索记录之下）：
   - 数据来自 **`GET /dishes/for-you`**（语义为「**猜你喜欢**」）——**每次随机推送在售菜品名**（无推荐算法、无热度排序、无个性化，**完全随机**）；**契约与取数解耦**：取数逻辑升级为个性化 / 推荐算法时，**端上契约不变**（仍为 `keyword` 列表）；
   - 形态：**chip 组**（换行排列）；chip 文案 = 返回的 `keyword`，**端上不写死词条、不排序**（按返回渲染）；
   - **条数上限**：**由后端固定返回 6 条**。理由：该接口为**纯随机**推送（无推荐算法），超过 6 条会占满发现态首屏、把「搜索记录」这个真正的个性化入口挤出可视区；端上仍**不截断、不排序**（条数是数据源职责，端上零逻辑）；
   - 交互：点 chip → 以该词发起搜索（并写入本地记录）；
   - 返回空数组 / 请求失败 → **整块不渲染**（不显示标题、不做骨架）；
5. **结果列表**（输入关键词并搜索后显示）：单列结果行（`FindResults`），左缩略图 + 右信息（菜名 / 评分 / 价格 / 位置行），复用首页菜品视觉语言；
   - **命中片段弱强调**：菜名 / 位置行中与关键词命中的片段 SHALL 以**字重加深**（`--weight-heavy`）区分，**SHALL NOT 上主色**——主色是价格专用强调色（见 §3）。理由：用户搜「糖醋里脊」、结果菜名恰为「糖醋里脊」时，若完全不标记命中位置则**扫读性为零**。命中标记由端上分段逻辑（`FindResults` 的 `splitHighlight`）实现；
6. 页面最底部：**TabBar 不出现**（本页为二级页，返回靠左上角返回 icon / 系统手势）。

## 4. 状态

| 状态 | 呈现 |
|---|---|
| 未输入（发现态） | 搜索记录（有则显示）+ 猜你喜欢（有则显示）；**两者都空 → 内容区留空**（不显示空文案、不做骨架） |
| 输入中 | 仅结果区变化；搜索行文案不截断（超长省略） |
| 结果态（有结果） | 单列结果行列表 |
| **结果态（少量结果，如仅 1 条）** | **结果区垂直居中**，使留白分布于首卡上下两侧；**SHALL NOT 追加任何填充内容 / 结果计数 / 引导文案**（沿用「内容组件不承载空态」口径） |
| 结果态（无结果） | **呈现「无结果引导」**（**非静默**）：图标 + 「没搜到「{关键词}」相关的菜」+ 副文案 + 「推荐这道菜」按钮（跳意见反馈页，落缺省「反馈问题」模式）。该引导属全站**两处显式空态例外之二**（`openspec/specs/client-page-structure`），亦见 `search-result-presentation`「成功且无结果时呈现静态换词引导」 |
| 失败态 | 结果区渲染「加载失败 · 点击重试」块（`searchFailed`，MP-012），与「没搜到」区分 |
| 猜你喜欢请求失败 | **整块不渲染**（不阻塞搜索能力） |

## 5. 硬性约束（回归检查清单）

1. 左上角**必须是返回 icon**（占页面标题位），与微信胶囊同水平带、同高、互不遮挡；**其光学尺寸 SHALL 与同位置标题相仿**（画布 88rpx → 绘制高 44rpx = `--font-title`，见 §2）——**SHALL NOT** 出现「图标远小于标题」的失衡；
2. **搜索行必须与首页完全同位同款**（左胶囊 + 右「搜索」按钮；高度 / 圆角 / 内距 / 间距 / 字号全部引用首页 §1.2）；**占位文案不得写入不可搜的维度**（如「套餐」，见 §1 第 2 条）；
3. 主题色**必须与首页同源**（首页 §4.1，本节不另立色值）——不得在本页自建第二套色值；**评分星 SHALL 用 `--color-star`**，不得用任何主色档；
4. 「搜索记录」**只能存本地**，不得上传服务端、不得跨设备同步；上限 4 条、去重、最新在前；
5. 「猜你喜欢」文案与条数**全部来自后端**（**后端限制 ≤ 6 条**，见 §1 第 4 条），端上不写死、不截断、不排序；**不得**引入推荐算法 / 个性化口径；
6. 本页**无筛选入口**（见首页功能文档 K 项）；
7. 顶部**不做纱式淡出 / 不做吸顶切换**（本页没有可滚出屏幕的顶部大图）；
8. **两个区块的 chip 必须可区分**（搜索记录 = 中性底、猜你喜欢 = 暖黄底，见 §3）——**SHALL NOT** 出现两区块 chip 完全同款；
9. **每一处块间间距 SHALL 只有一个来源**（不得「外层 padding + 内层 margin」各出一层，见 §2 间距表）——实测值须与该表一致；
10. 结果区在**少量结果**时垂直居中、在**无结果**时呈现引导（见 §4）——**SHALL NOT** 追加结果计数或填充内容。

## 7. 接口数据字段（UI 精修用）

**页面**：`pages/find/index`

**出参消费**
| 接口 | 字段 | 端上用途 |
|---|---|---|
| `GET /dishes/for-you` | `keyword` | 「猜你喜欢」chip 文案（端上不排序、不截断） |
| `GET /dishes`（`PageResult<DishListItemVO>`） | `records[].id` / `name` / `coverImage` / `canteen` / `stallName` / `price` / `rating` | 结果行：主键 / 菜名（命中片段加粗）/ 缩略图 / 位置行两段 / 价格 / 均分 |
| | `records[].originalPrice` | 判折扣（`originalPrice > price` → 划线） |
| | `total` | 结果计数/空态判定（分页壳仅 `records` / `total`；页码由请求侧掌握） |

**入参提交**：`GET /dishes` → `keyword` / `page=1` / `pageSize=50`

**UI 组件**：公共 `AppTitleBand`(返回) / `SearchBar`(input) / `IconSvg` / `RetryBlock` / `SectionTitle` / `CardSection`；页内私有 `FindResults`
**控件类型**：`scroll-view`（结果区内）、`input` 搜索框、chip（记录 / 推荐两套样式）、`uni.showModal`（清空记录确认）
