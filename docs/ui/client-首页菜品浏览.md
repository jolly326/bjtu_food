> **顶部结构（本文档为 UI 唯一真源）**：**页面标题走「固定标题带」**（§1）：左上角、与微信右上角**原生胶囊处于同一水平带、同高对齐**，且**永久固定在页面左上角、不随页面滚动移动**（跨页统一位置、文案按页配置——首页为「知行食记」）。**标题带之下**是**滚动区**：首块 Banner = **一张四周留白（左右各 12px）的圆角图片卡（轮播容器，素材由后端 `GET /banners` 下发）**，其下是**吸顶容器（搜索区 + 大类标签栏，一个组件）**，再往下是双列网格。自上而下恒为「**固定标题带（常驻）→ 滚动区：Banner（四周留白 + 四角圆角）→ 吸顶容器（搜索区 + 大类标签栏）→ 双列网格」。**Banner 随页面上滑、在标题带下沿被裁掉**；滚动区终点在菜单栏上沿 ⇒ **标题带与菜单栏背后都没有内容经过**（都不需要表面）；只有吸顶容器需要表面（切片，§11.1）。Banner 宽高比定为 **16:10**（按**可用宽 = 屏宽 − 左右各 12px** 计算）；顶部各块间距见 **§7**；**吸顶容器 = 搜索区 + 大类标签栏（一个组件、一起吸顶）**；它是全页**唯一需要表面**的一条（卡片会从它背后滚过）：**未吸顶 = 完全透明**，**吸顶后 = 背景图切片**（位置 = 背景图去掉顶部标题带那一段，与页底逐像素同源；偏移基准 = 标题带高 `titleBandPx`，与 `AppTitleBand` 及页面 `padding-top` **同源**，§11.1）。**标题带恒透明**（滚动区起点就在它下沿，内容不从它背后经过）。
>
> **筛选维度口径**：**首页无任何筛选入口**（无「筛选」按钮、无筛选面板）；搜索页（find）无食堂 / 价格筛选胶囊（见 §5.2）。功能 / 接口口径见功能文档。
>
> **骨架口径（2026-09-27 结构性决议）**：① 页面是一个 flex 列：`padding-top` = 标题带高、`padding-bottom` = 菜单栏 + 安全区，中间是**滚动区**（`flex: 1`），内含 **Banner → 吸顶容器（搜索区 + 大类标签栏）→ 双列网格**；② 吸顶容器用**原生粘性定位**（`sticky` + `top: 0` = 滚动区顶 = 标题带下沿），**不监听滚动、不做逐帧对齐、无状态**；③ **标题带 / TabBar 恒透明**（滚动区不从它们背后经过）；④ 吸顶容器是唯一需要表面的一条：**未吸顶透明**、**吸顶后铺背景图切片**（去掉顶部标题带那一段）；⑤ 间距（§7.1）：标题带 → Banner **12**、Banner → 搜索区 **16**、搜索区 ↔ 标签栏 **12**、标签栏 → 网格 **16**（8 padding + 行底余量 ≈8）。

## 0. 设计判断与目标

### 0.1 原页面主要问题（本版要修的 5 点）

| # | 问题 | 本版处置 |
|---|---|---|
| 1 | **顶部信息层偏平**——标题带 / Banner / 搜索 / 标签四块平铺，缺少主次节奏，读作「模块堆叠」 | §0.3 定义 4 档视觉强度：搜索区 = 高、Banner = 中高、网格 = 中、标签栏 = 低 |
| 2 | **搜索区与标签栏关系不够紧**——两者视觉边界模糊，用户不知「搜索完下一步该干嘛」 | 搜索区与标签栏**同属常驻工具栏**、以「块内 12px / 块间 16px」的间距层级区分（§4 / §7） |
| 3 | **卡片信息密度偏高**——菜名 / 食堂 / 档口 / 评分 / 价格同现，字号层级不清则第一眼无落点 | §6 固定四段阅读顺序与字号刻度（菜名 32 > 位置 = 评分 28，价格 36 右对齐） |
| 4 | **暖橙主题容易做成廉价感**——橙面积失控、或星级 / 价格 / 按钮共用同一档橙 | §10 **主色语义分档**：按钮 = 填充档、价格 / 选中态 = 文字档、下划线 = 图形档、星 = 独立语义色（各司其职，禁止混用） |
| 5 | **缺少可开发的细节感**——胶囊高度、下划线位置、卡片内边距、字基线、阴影层级 | §7 间距 / §8 字体 / §9 圆角阴影 / §12 组件拆分全部 token 化 |

### 0.2 设计原则（保留 / 不新增 / 不改字段）

- **保留**：固定标题带、16:10 Banner、搜索胶囊 + 搜索按钮、大类标签栏、双列菜品卡、底部 TabBar；
- **不新增**：筛选入口、食堂列表、推荐模块、活动入口、底部安全区之外的功能；
- **不改变字段**：菜名 / 食堂 / 档口 / 评分 / 价格 / 分类 / Banner / 标签均沿用既有接口（见文末「接口数据字段」）；
- **本版目标只有 4 个**：① 顶部更清爽 ② 搜索更突出 ③ 卡片更有食欲与秩序 ④ 整套视觉像真实校园信息小程序，而非练习稿。

### 0.3 页面视觉节奏（4 档，不平均用力）

| 区域 | 角色 | 视觉强度 | 承担手法 |
|---|---|---|---|
| Banner | 氛围入口 | 中高 | 16:10 实拍大图（唯一「整块图」） |
| **搜索区** | **主要行动入口** | **高** | 白胶囊浮起 + **唯一填充色按钮**（全页唯一实心主色块） |
| 大类标签栏 | 分类导航 | 低 | 纯文字 + 短下划线，无底色、无边框 |
| 菜品网格 | 信息主体 | 中 | 白卡 + 极轻投影 + 大图占 52% |

> 用户进入首页的自然读序：**Banner → 搜索 → 分类 → 菜品列表**。

## 1. 固定标题带（跨页统一）

- **定位**：`position: fixed`——**永久固定在页面左上角**，不随页面滚动、不随 Banner 滚出、不参与任何吸顶位移。页面滚动到任意位置，它都在同一处；
- **垂直对齐**：与微信右上角**原生胶囊同一条水平线**——标题带高 = 状态栏高 + 与胶囊同高的一行（`--capsule-h`），标题垂直中心 = 胶囊中心（同一水平带，互不遮挡）；
- **水平起点**：页面级 gutter（`--spacing-md`，与搜索行、标签栏、卡片网格同轴）；右侧为胶囊避让区，标题**不得进入胶囊水平范围**（超长省略号截断）；
- **文案：跨页统一位置、按页配置**——首页 = 「知行食记」，搜索页 / 我的等其他页面各填自己的文案（本文件只定义首页文案）。**位置、高度、对齐方式、配色全站一致**，各页只换文案；
- **配色**：`--text-primary` **`#2D1F14`** 粗体大号（`--font-title` 44rpx / `--weight-bold`）；**不做白字、不描边、不加遮罩层**——它落在**页底「壁纸 + 一层统一纱」**上（`fixed` 壁纸铺满视口、含标题带那一条，见 §11.1 / §11.2），故不依赖素材提供浅色底；
- **交互**：纯文本，**无点击行为**（不做返回 / 菜单入口）；
- **层叠**：`z-index` 高于滚动区内容；`AppTitleBand` 自身**恒透明、背后不铺任何表面**（2026-09-27 结构性决议）。滚动区从常驻工具栏下沿开始 ⇒ **不会有内容从标题带背后经过**（与 §11.2 同口径）；
- **常驻性**：标题带与常驻工具栏**始终在同一位置**（不随滚动移动）；两者不重叠、不叠图；
- **表面（无过渡）**：标题带**恒透明、无任何表面**（**也不再铺任何切片**，2026-09-26 决议）；从带下滚过的 Banner **直接可见**（不再遮盖）；**不做透明度过渡、不做纱式淡出**（原 `veilOpacity` 已随「零消费即删」移除；完整口径见 **§11.2**）。

## 3. Banner 区

### 3.1 定位与结构

- **四周留白**：左右各 `--spacing-md`（12px，与搜索行 / 标签栏 / 网格同轴）、**上缘距固定标题带下沿** `--spacing-md`（12px，由滚动区 `padding-top` 承担）、**下缘距搜索区** `--spacing-lg`（16px，由吸顶容器 `padding-top` 承担）；**四角圆角** `--radius-card`（32rpx）——它是滚动区首块**一张「浮起来」的图片卡**（随页面上滑、在标题带下沿被裁），不是通栏满屏图；
- **它不在固定标题带背后**：固定标题带（§1）在其**上方**独立一行（与微信胶囊同一水平带）；Banner 顶部不再承载标题，**素材无需再为标题留浅色带**；
- **上滑时**，Banner 尾部与下方卡片从固定标题带**下方滑过**（被标题带切片遮住属预期；遮盖方式 = 不透明壁纸切片，见 §11.2，**不再是纱式淡出**）；
- **那个位置就是一张图，无任何文案层**（端上不渲染「今日推荐」等硬编码文本；素材里的「今日推荐 / 副标题 / 菜品插画」均为**图片素材自身内容**，由设计出图，端上零文本）；
- **Banner 上无点击交互**（v1 纯展示、无跳转；出参无 `targetType` / `targetId` / `targetUrl`；要做跳转须先在本文件定义交互并另立 change）。

### 3.2 素材方向（设计约定）

| 项 | 约定 |
|---|---|
| 主体 | 热气腾腾的牛肉面 / 奶茶 / 家常菜等**真实校园食堂感食物摄影** |
| 氛围 | 暖橙光线、干净桌面、轻微景深 |
| 构图 | 食物主体居中偏下、四周留白干净（**不再需要为标题留浅色带**——标题在 Banner 上方） |
| 质感 | 真实摄影感，**不做插画式营销海报**（本产品是校园美食**信息**工具，不是外卖平台） |
| 比例 | **一律 16:10**（如 1500×938 / 1200×750）；混比例会导致切换时撑高 / 压扁 Banner |
| 素材边界 | 四周留白干净、**画面内不出现任何端上文字**（标题在 Banner 上方，**不再需要为标题预留浅色带**） |

**素材落位（本地图片 / 背景图）**：本地图片素材一律放 **`client/src/static/images/`**（uni-app 约定目录：构建时**原样拷贝**到 `dist/<platform>/static/`，引用写 **`/static/images/xxx.jpg`**——绝对路径、不走打包哈希、不加 `@/` 前缀；`utils/image.ts` 已对 `/static/` 前缀原样放行）。命名用小写 kebab-case，单张 ≤ **300KB**。

⚠️ **小程序端硬约束**：WXSS 的 `background-image: url()` **不支持包内本地路径**（真机报「本地资源图片无法通过 WXSS 获取」）——本地图只能用：① 绝对定位的 `<image>` 层；② base64 内联（仅极小装饰图）；③ 网络 URL。**不得**写 `background-image: url(/static/images/…)`——开发工具可能能预览，真机必不显示。

**本页已落地：整屏壁纸（走 ① `<image>` 层）** —— 素材 `client/src/static/images/home-bg.jpg`（750×1501、≈115KB，源图 1471×2943 PNG 压得），实现见 §11.1；纱（可读性 + 同源）仍是纯 `linear-gradient`（0 字节、无请求）。

### 3.3 宽高比为什么取 16:10（而非 16:9）

- **它是「一张卡」，比例直接决定首屏节奏**：Banner 总高 = **可用宽 × 10/16**，其中**可用宽 = `min(屏宽, 720) − 左右各 12px`**（`720` 与 `App.vue` 宽屏限宽的 `.scroll-wrap { max-width: 720px }` **同源**——Banner 在滚动区**内部**，定高必须用被限宽后的宽度；否则 ≥768px 窗口下比例会失真：1024 宽时卡片 696 × 625 ≈ **1.11:1**、桌面 H5 甚至变竖图）—— 375 宽机型 = 351 × 0.625 ≈ **219px**。太扁（16:9 → ≈197px）画面局促、食物主体易被裁；太高（4:3 → ≈263px）会把搜索区与第一行卡片挤出首屏；
- **首屏菜品曝光达标**（2026-09-27 结构性改造后**不变**）：标题带 88 + 上间距 12 + Banner 219 = Banner 下缘 **319px**（= 吸顶容器锁定点 `L`），+ 吸顶容器 100（16 + 搜索行 32 + 标签行 44 + 8）= 网格首行自 **419px** 起排，在 812px 高机型上首屏仍能露出**第一行双列菜品卡**（可用区 309px ≥ 单卡 ≈211px，另露出第二行 ≈100px）；吸顶后网格可继续滚动，可视区随吸顶扩大到约 393px；
- **素材一律 16:10 出图**（如 1500×938 / 1200×750），端上**恒定按此比例定高**、绝不按图片真实比例自适应；加载中 / 失败用**同高占位**，保证滚动区内容不跳变。

### 3.4 轮播容器（接口下发）

- 整块 Banner 即一个 `<swiper>` 图片轮播，每一项是一个 `<image mode="aspectFill">` 铺满；**图片清单来自后端 `GET /banners`**（服务端已按 `sort_order` 升序、只返回启用项），端上**严格按返回顺序渲染、不排序、不写死任何 URL**；
  - **多张**：自动轮播（间隔 `AUTOPLAY_INTERVAL = 4000ms`，组件常量定义于 `pages/home/HomeBanner.vue`）、循环、底部居中指示点；手动左右滑动可切换；
  - **仅一张**：不自动轮播、**不显示指示点**（避免「只有一个点」的假轮播）；
  - **空数组 / 请求失败**：整块退化为**与首页菜品卡图片占位同款灰底的空态**——`var(--bg-soft)` 灰底 + 居中**中性 `empty` 图标**（`IconSvg name="empty"`，色 `--text-tertiary`，尺寸按 Banner 整块等比放大，建议 120）；**图标键取中性 `empty`、不得用 `dish`**（Banner 是运营位轮播，容器语义 ≠ 菜品，依 `project_spec.md` §4.9）；**不渲染「Banner 占位图」等任何文字说明、不加白卡 / 投影 / 渐变**；Banner 请求与菜品列表**并行发起**，Banner 失败**不阻塞**首屏网格；
  - **单张图加载失败**：**该张**显示同一套灰底 + 中性 `empty` 空态（无须整块回退，可随重试恢复），其余张不受影响、轮播继续。
- **块高恒定**：总高 = `max((min(屏宽, 720) − 左右各 12px) × 10/16, 最小高度兜底 160px)`（页面常量 `BANNER_ASPECT_RATIO` / `BANNER_GUTTER_PX` / `BANNER_MIN_HEIGHT_PX` / `CONTENT_MAX_WIDTH_PX`，宽屏同源说明见 §3.3）；加载中 / 失败一律用**同高**占位，**不因加载状态改变块高**（否则下方内容会整体跳动）。

## 4. 搜索区

> 本区是首页的**第二视觉中心**，也是全页**唯一的行动号召**（唯一实心主色块）。

### 4.1 结构（恒为两件，不得合并）

| 项 | 设计值 |
|---|---|
| 结构 | 左侧搜索胶囊 + 右侧独立「搜索」按钮，**同高、同一行、间距 `--spacing-sm`** |
| 搜索胶囊 | 白底 `--bg-card` + `--radius-pill` + `--shadow-float`（轻阴影）；左放大镜图标 `--text-tertiary` |
| 胶囊占位文案 | 「**搜索菜品、食堂、档口**」（`--text-tertiary` `#7F6A55`，见 §8 偏差登记第 1 条） |
| 搜索按钮 | 填充档主色 `--color-primary-fill` **`#B4531A`** + 白字 `--color-on-primary`，`--radius-pill`，**按文字定宽、不与胶囊等分** |
| 高度 | 两者均 = `--capsule-h`（与微信原生胶囊同高） |
| 触达 | 胶囊与按钮的可点区域均 ≥ 88rpx 高（`::after` 透明扩张，不改变视觉尺寸） |

### 4.2 关键设计调整（三条）

1. **胶囊宽度更大**——`flex: 1` 占满剩余宽度，明显承担「主要搜索入口」，不做窄小输入框；
2. **按钮保持独立胶囊形**——不做矩形、不与输入框贴死；「左胶囊 + 右胶囊」并列结构（§13 第 14 条）；
3. **搜索区与标签栏之间加视觉切分**——两者同属常驻工具栏，靠**间距层级**（块内 12px / 块间 16px，§7）与标签栏的无底色纯文字形态区分，**不加分隔线、不加容器底色**。

### 4.3 占位文案口径（两页同源）

占位**只列真实可搜的维度**。搜索走 `GET /dishes?keyword`，服务端**只匹配「菜名 / 档口名 / 食堂名」三处**；**「套餐」不是可搜维度**——项目无套餐实体，「套餐盖饭」只是 `meal_type` 大类，而**大类不参与关键词匹配**，故**不得**写入占位文案。该文案由 **`components/SearchBar.vue` 的默认 `placeholder` 单点承载**，首页与搜索页共用，**改动须两页同批**。

### 4.4 取色说明（按钮填充底为何取「深橙」）

设计稿明确按钮为**深橙**填充 + 白字；本页取**填充档 `#B4531A`**——与实测对比度互相印证，**无偏差**：

| 组合 | 实测 | 门槛 | 判定 |
|---|---|---|---|
| 白字 on `#B4531A`（本版采用） | **5.01:1** | 4.5:1 | ✅ |
| 白字 on `#E67E22`（亮橙，**不采用**） | **2.85:1** | 4.5:1 | ❌ 不可作填充底 |

→ 「行动 = 橙」由**唯一实心主色块**（全页仅此一处实心填充）承担；亮橙 `#E67E22` 保留给**关键图标**（图形档，不承载文字）。详见 §10.2「取色边界」。

## 5. 大类标签栏

### 5.1 规格

| 项 | 设计值 |
|---|---|
| 标签集合（7 项） | `全部` ｜ `套餐盖饭` ｜ `家常小炒` ｜ `面食粉类` ｜ `香锅干锅` ｜ `风味小吃` ｜ `汤饮甜品` |
| 数据来源 | `GET /dishes/meal-types` 下发（接口形状 `[{ value, label, order }]`）：文案、顺序、子集、增删**全由后端决定，端上一个不写死**；首项「全部」= 不传 `mealType`，端上固定渲染。⚠️ **端上只消费 `value` / `label` 两字段**：`order` 是服务端排序用字段（`web` 端需要），端上按返回顺序渲染 → 已按「零消费即删」从 `types/dish.ts` 的 `MealType` 与 `api/dish.ts` 映射中**移除** |
| 空类自动隐藏 | 后端只下发当前有在售菜品的大类（某类空了隐藏、有菜自动出现），端上零改动 |
| 标签样式 | **纯文字导航**——无胶囊底色、无边框、无背景块 |
| 未选中 | 字色 `--text-body` **`#4A3520`**、`--weight-regular` |
| 选中 | 字色 `--text-title` **`#2D1F14`**、`--weight-semibold` |
| 选中下划线 | `--color-primary-amber` **`#F5A623`**，高 6rpx、全圆角、**长度贴合文字宽度**（`width: 100%`）、紧随文字 4rpx（`--spacing-xs`） |
| 交互 | 横向可滑动 + **单选**；点击切换 → 列表刷新；点击已选中项不发请求；v1 不显示计数 |
| 背景 | **无底色（完全透明）** —— 属常驻工具栏，滚动区不与它重叠 ⇒ 不需要任何表面（见 §11.1） |

### 5.2 光学间距（唯一来源）

- 标签行高 **88rpx（触达下限，不得压低）**；标签文字在行内**上偏置 24rpx**（`padding-top`），下划线紧随文字 **4px**（`--spacing-xs`）。行内偏置是「搜索区 → 标签文字」间距的**唯一来源**（≈ **12px**）；「下划线 → 卡片首行」= 容器下 padding（`--spacing-sm` 8px）+ 行底余量（≈8px）≈ **16px**。两者满足「下行距 ≥ 上行距」，且**不与标签行外 padding 叠加**。**下划线不得吸到行底**——那会让它离文字 ≈16px、与标签脱开。标签栏行高不变 → §11 的 `H_s` 不受影响。

### 5.3 设计判断

首页**没有筛选面板**，标签栏是唯一的分类导航，故取**轻**形态（纯文字 + 短下划线）：胶囊按钮式标签会让它显得「在频繁切换功能」，与信息导航的语义不符。横向可滑动的首 / 末项文字缘 = 页面级 gutter `--spacing-md`（与搜索行、网格同轴）。

### 5.4 筛选维度口径（首页与搜索页均无筛选）

- **首页**：**无任何筛选入口**（无「筛选」按钮、无筛选面板），**唯一筛选维度是大类标签栏**（§5.1）；
- **搜索页（find）**：头部为「输入框 + 结果」，**无食堂 / 价格筛选胶囊**；
- **保留项**：搜索关键词**同时匹配菜名 / 档口名 / 食堂名**；卡片上的 `食堂名 | 档口名` 展示不变；
- **接口侧**（详见功能文档）：`GET /dishes` 参数集恰为 `page` / `pageSize` / `keyword` / `mealType`；
- **防回退**：首页不得出现筛选入口，搜索页不得出现食堂 / 价格筛选胶囊（§13 第 13 条）。

### 5.5 分类的展示与切换逻辑（实现口径，逐条对齐代码）

**展示**

1. 渲染项 = **端上固定第一项「全部」**（`value = null` ⇒ 不传 `mealType`）+ **字典响应原序展开**（`mealTypeList`，后端已按 `order` 升序且只含有在售菜品的大类）；**端上不排序、不过滤、不写死任何中文**（`HomeMealTabs.tabs`）；
2. 横向可滑动（`scroll-view scroll-x`，隐藏滚动条）；**选中项自动滚入视口**（`scroll-into-view` → `mt-tab-{value}` / `mt-tab-all`，稳定 id 规则）；
3. 选中下划线为**常驻节点 + opacity 切换**（不做 v-if 显隐）→ 避免行高跳动；下划线纯装饰（`aria-hidden`），选中语义由字重 + `aria-label="筛选大类：{label}"` 表达。

**切换（一次点击的完整链路）**

| 步骤 | 行为 | 依据 |
|---|---|---|
| ① 点击 | 若 `value === activeValue` → **直接 return，不发请求** | `HomeMealTabs.onSelect` |
| ② 写态 | `dishStore.setHomeMealType(value)`：`filterMealType = value`，并 `fetchHomeDishes(true)` | `pages/home/index.vue.onMealTypeSelect` |
| ③ 保留旧列表 | 重置分页但**不清空 `homeList`**（`keepList`）——若清空，内容塌成 0 会让 `scroll-view` 把滚动位置**钳回顶部**（用户可见 bug：切标签弹回首页顶部） | `stores/dish.ts` + `LOADING_KEY_HOME_SWAP` 与 `LOADING_KEY_HOME` 分开登记 |
| ④ 分页复位 | `homePage=1`、`homeFinished=false`、`homePageLimited=false`、`homeError=false` | 同上 |
| ⑤ 竞态守卫 | `homeFetchSeq++`；**过期响应一律丢弃**（快速连点多个大类时，先发的旧请求晚到不会覆盖新列表） | 同上 |
| ⑥ 不重置滚动 | 页面**不**调用任何回顶 / 恢复滚动位置的逻辑（保持当前滚动位置） | `onMealTypeSelect` |
| ⑦ 在途表现 | 切类**不触发**「静默加载中」判定（`HomeContent` 只订阅 `LOADING_KEY_HOME`）→ 旧列表继续在屏，无闪白、无骨架屏 | `HomeContent.loading` |
| ⑧ 结果 | 新页数据到达后替换列表（同一热度序的子序列）；失败 → `homeError=true`，列表有数据则**静默保留**，列表为空才渲染 `RetryBlock` | `HomeContent.loadFailed` |

**字典自身的可用性**

- 首屏 `onLoad` **不 await** 字典（`void fetchMealTypes()`）→ 字典失败**不阻塞**列表；降级表现 = 标签栏只剩「全部」，列表仍展示全部菜品；
- `onShow` 兜底重试（**仅「从未成功」时**发请求，store 内自带守卫）；
- `fetchMealTypes` 内**顺带校正选中项**：所选大类已不在字典（该类当前无在售菜）→ 自动回落「全部」，避免请求一个空类。

### 5.6 排序口径（唯一：服务端热度倒序；端上**无**排序入口）

| 项 | 口径 |
|---|---|
| **默认排序** | **服务端固定热度倒序**：`heatScoreExpr = view_count × 1 + rating_count × 100 + avg_rating × 20`（`project_spec.md` §7.27） |
| **可选排序** | **无**。首页**没有**「排序」按钮 / 面板 / 下拉 / 胶囊，**不传任何排序参数** |
| **传参** | `GET /dishes` 的参数集**恰 4 项**：`page` / `pageSize` / `keyword` / `mealType`（`sortBy` / `sortOrder` / `canteenId` / 价格区间**已全部删除**，见 `api-slimming`） |
| **翻页一致性** | 每一页都是**同一热度序**的下一段 ⇒ 触底加载不会出现「第 2 页比第 1 页更热」的错乱 |
| **防回退** | **不得**新增「综合 / 最新 / 价格↑↓ / 距离」排序入口（距离能力已下线，无坐标字段）；如确需恢复，须**另立 change** 并同步后端参数与 `project_spec.md`（PR-04 恢复须重新拍板） |

## 6. 菜品卡片（四段固定排版）

> 本页最重要的组件：从「信息展示卡」升级为「有食欲、有秩序的推荐卡」。

### 6.1 阅读顺序与视觉权重

**菜品图 → 菜名 → 食堂/档口 → 评分/价格**

| 层级 | 元素 | 处理方式 |
|---|---|---|
| 第一 | 菜品图 | 大图、真实摄影，占卡片 ≈**52%** 高 |
| 第二 | 菜名 | 卡片**文字层**第一级：32rpx + `--weight-semibold` + `--text-title`（深棕、可 2 行）——**「第一级」由位置（左上）/ 字重 / 深色表达，不等于字号最大**（价格是「强调档」，字号更大且粗，见 §6.2 注） |
| 第三 | 食堂 / 档口 | 浅灰小字、纯文字（无图标、无标签块） |
| 第四 | 评分 / 价格 | 评分左（暖黄星 + 数字，**常规字重**、安静）、价格右（文字档橙、**粗体 36rpx、全卡最大字号**——它是「信息强调」不是「标题」） |

### 6.2 四段规格（自上而下）

| 段 | 内容 | 样式 |
|---|---|---|
| 1 | 菜品实拍图 | 圆角与卡片一致；比例 **3:2**（≈卡片高 52–55%，介于 4:3 与 16:10 之间，兼顾信息密度与 CLS=0）；无图 / 加载失败 → **灰底（`var(--bg-soft)`）+ 居中菜品 icon（`IconSvg name="dish"`，`--text-tertiary`）** 空态（**菜品图语义 → `dish` 键合法**；Banner 失败占位复用同款**灰底**、但图标取中性 `empty`，见 §3.4） |
| 2 | 菜品名称 | `--font-subtitle`（**32rpx / 16px**）**半粗** `--weight-semibold`、`--text-title` `#2D1F14`，卡片**文字层第一级**（超 2 行省略）；**不压在图片上** |
| 3 | `食堂名称 \| 档口名称` | **`--font-body`（28rpx / 14px）**、`--text-subtitle` `#7F6A55` 常规，**纯文字**——无图标、无彩色背景标签；超长单行省略 |
| 4 | 左：**黄色实心五角星 + 数字评分**；右：**价格** | 同一行、两端对齐；评分文字 `--font-body`（28rpx）**`--weight-regular`**、`--text-body` `#4A3520`；**星形 34rpx**（= 评分文字 + 6rpx 光学补偿，星形自带留白）、`--color-star` `#FBBF24`；价格 `--font-h3`（36rpx / 18px）`--weight-bold`、`--color-price` `#B4531A` |

> **组内间距层级**：菜名 → 位置行 = **4px**（同一「文字组」，紧）；位置行 → 评分/价格行 = **8px**（跨组，松）。
>
> **卡片字重预算（全卡只有两处「重」）**：菜名 `--weight-semibold`、价格 `--weight-bold`——位置行常规、**评分行常规**（设计稿「字体层级」表：评分 28rpx **常规**）。这条直接回应设计稿提出的第 3 个问题「信息密度偏高」：一屏 4 行文字若 3 行都在加深加粗，用户第一眼不知道该看什么。**价格允许比菜名更大**（36 > 32）二者不冲突：价格的职责是「信息强调」，菜名的「第一级」由位置（左上）+ 深棕 + 可 2 行表达。

### 6.3 容器与按压

- 卡片表面 = `--bg-card` 白底 + `--radius-card`（32rpx）+ `--shadow-card`（**极轻**，`0 2px 12px rgba(0,0,0,.04)`）；`overflow: hidden`（图片裁进圆角）；
- 按压反馈 = `hover-class` 透明度微降（`opacity: .88`），**不用 transform: scale**（避免与图片淡入的合成层叠加抖动）；
- **不引入「月售 XXX 份」**（无订单 / 销量数据源）；列表末尾**无引导 / 补录类组件**。

### 6.4 卡片与列表的实现口径（动态渲染 / 懒加载 / 价格与标签 / 点击 / 响应式）

**① 列表动态渲染（`HomeContent` + `DishCard`）**

- 数据源 = `dishStore.homeList`（`DishListItem[]`）；渲染用**奇偶分列**（`splitList`：一次 `forEach` 分出左右两栏，O(n)），**右列绝不空、两列宽度恒定**（卡片图为固定 3:2 容器，故无需按图片比例做列内等高平衡）；
- 列表项 `key` = **`wf-${id}`**（仅业务主键 `DishListItem.id`）——**不掺列内序号**，否则「加载更多」会让列内序号重排、已渲染卡片整列重建（闪烁 / 掉帧）；
- `HomeContent` 为**纯展示组件**：不持有分页状态，`homeList` / 分页 / 加载态全在 store；页面只负责编排（`onLoad` 首拉 + `onShow` 字典兜底 + `RetryBlock` 重试 + 触底加载）；
- 在途与三态：首屏 / 切类在途**整块不渲染**（无骨架屏、无 loading 指示，§4.8 红线）；触底加载更多是**另一个 loading key** → 只在列表末尾出「正在加载更多…」，不遮挡已有内容；失败且无数据 → `RetryBlock`（失败 ≠ 空态）。

**② 分页与封顶（`stores/dish.ts`）**

| 项 | 值 / 口径 |
|---|---|
| 单页条数 | `HOME_PAGE_SIZE = 10`（首页固定传 10） |
| 结束判据 | **本页返回条数 < `pageSize`**（⚠️ **不读 `total`**） |
| 页数上限 | `HOME_MAX_PAGES = 10` ⇒ **最多保留 100 条**（防止 `homeList` 无上限增长导致列分配每次全量重算、低端机掉帧） |
| 达顶表现 | `homePageLimited = true` → 列表末尾「已展示前 100 个结果，切换大类可查看更多」（**不静默截断**） |
| 触底提前量 | `LOWER_THRESHOLD_PX = 300`（把网络时延藏进滚动过程） |

**③ 图片懒加载与占位（`DishCard`）**

- `<image lazy-load>`（滚动进近视口才加载）+ 列表缩略图走 **`getThumbUrl(coverImage)`**（`_thumb` 规格）+ `getImageUrl`（相对路径 → 绝对）→ 弱网下流量 / 时延显著下降；**详情页大图才用原图**；
- 加载完成 `@load` → 加 `.loaded` 类做 `opacity` 淡入（`--duration-slow`）；`@error` → `imgOk = false` → 回落**灰底（`var(--bg-soft)`）+ `IconSvg name="dish"`**（禁裂图，禁无限空转）；
- 容器为**固定 3:2 等比盒**（0 高 + `aspect-ratio: 3/2`）→ 加载前后**块高一致**（CLS = 0、瀑布流不重排）。

**④ 价格格式**

- `price` 经 API 层 `fenToYuan` 转「元」；展示恒为 **`¥{formatPrice(price)}`**（`utils/money`，全站两位小数口径统一）；**页面 / 组件内禁止裸算金额**；
- **本卡不展示划线原价**：`originalPrice` 在首页**零消费**（仅搜索页结果行消费）；折扣表达不在卡片上出现；
- 价格是卡片**唯一高饱和强调**（`--color-price` 文字档 + `--weight-bold` + `--font-h3`）。

**⑤ 标签格式**

- **本卡无标签**：没有标签行、没有 chips、没有角标、没有大类文字 —— 位置行是**纯文本** `食堂名称 | 档口名称`（分隔符 `|`，G3 决议），`--text-subtitle` 常规字重、超长单行省略；
- 菜品大类（`mealType`）**不在卡片上出现**（大类不进公开菜品出参；选择只体现在标签栏，见 §5）；
- 防回退：不得给卡片加彩色标签块 / 「折扣」「新品」角标（§14 第 1 条与「信息密度」红线）。

**⑥ 点击交互**

- **整卡可点**：`role="button" tabindex="0"` + `aria-label="{菜名}，{价格}元"`；`hover-class` 按压反馈 = `opacity .88`（**不用 `transform: scale`**）；
- 链路：`DishCard` `@tap` → `emit('select', dish)` → `HomeContent.goToDetail(dish)` → `uni.navigateTo({ url: dishDetailUrl(dish.id) })`（跳 `pages/detail/dish?id=`）；
- 卡片内**无任何二级可点件**（无收藏 / 无点赞 / 无加购 / 无档口跳转）。

**⑦ 响应式适配**

| 维度 | 方案 |
|---|---|
| 常规尺寸 | 全量 **`rpx`**（以 750 设计宽为基准等比缩放），无固定 `px` 布局值 |
| Banner 定高 | 用**实测 `windowWidth`**：`contentWidth = min(窗口宽, 720)`（`720` 与 `App.vue` 的 `@media (min-width: 768px) { .scroll-wrap { max-width: 720px } }` **同源**）→ `卡片宽 = contentWidth − 2×12px` → `高 = max(卡片宽 × 10/16, 160px)`；⚠️ 改限宽值须同步 `CONTENT_MAX_WIDTH_PX`，否则宽屏下 16:10 失真 |
| 双列网格 | `display: flex` + 两列 `flex: 1 1 0`（等分）+ `gap: 12px` → 窄屏不掉列、宽屏不拉长 |
| 壁纸层 | `heightPx` 用**实测 `windowHeight`**（禁 `vh`；全站只有页面级一处，§11.1） |
| 安全区 | 滚动区底部预留 `var(--tabbar-height) + env(safe-area-inset-bottom)`；TabBar 自身亦含 `safe-area-inset-bottom` |
| 横向标签栏 | `scroll-x` + 隐藏滚动条 → 页面**不出现横向滚动条** |
| 触达 | 搜索胶囊 / 按钮 `::after` 扩至 ≥88rpx；标签行高 88rpx；卡片整卡 |

## 7. 间距系统（唯一真源）

> 全部用 token 表达，**禁止裸值近似**。左右外边距恒为页面级 gutter `--spacing-md`（与标签栏首项文字缘、双列网格同轴）。

### 7.1 顶部各块

| 相邻关系 | 间距 | token |
|---|---|---|
| **固定标题带下沿 → Banner 上缘** | **12px** | `--spacing-md`（滚动内容顶部占位 = 标题带高 + 本间距） |
| **Banner 左右缘 → 屏幕左右缘** | **12px** | `--spacing-md`（四周留白，与搜索行 / 标签栏 / 网格同轴） |
| **标题带下沿 → Banner 上缘** | **12px** | `--spacing-md`（滚动区 `padding-top`） |
| **搜索胶囊 ↔ 右侧「搜索」按钮** | 8px | `--spacing-sm` |
| 搜索胶囊 / 按钮的左右外侧 → 屏幕左右缘 | 12px | `--spacing-md` |
| **搜索区下沿 → 标签文字** | **≈12px** | 标签行 `padding-top` 24rpx（行内偏置，**唯一来源**） |
| **标签栏下沿 → 网格首行上沿** | **≈16px** | 容器 `padding-bottom` `--spacing-sm`(8px) + 标签行自身 ≈8px 行底余量 |
| 网格左右外边距 | 12px | `--spacing-md` |
| **卡片间距（行 / 列）** | **12px** | `--spacing-md` |
| 常驻工具栏位置 | 标题带下沿起（页面 `padding-top` = 标题带高），**不锁定、不吸顶** | 见 §11 |

> **间距层级规则**：**块之间 > 块内部**，且**块之间 > 卡片间距** —— 块间 = 16px（`--spacing-lg`）、块内 = 8px（`--spacing-sm`）、卡片间距 = 12px（`--spacing-md`）。

> **标签栏纵向留白规则**：**行内偏置 / 行底余量与行外 padding 不叠加** —— 标签行自身高 88rpx（触达下限，不可压低）内含 24rpx 行内上偏置 + ≈16rpx 行底余量；**行外上间距 = 0、行外下间距 = `--spacing-sm`(8px)**，由行内偏置与行底余量补足 → 实测 **12px / ≈16px**。

| 位置 | 间距 | token |
|---|---|---|
| 图片底 → 菜名 | **8px** | 信息区 `padding-top` `--spacing-sm` |

| 卡片底部内边距 | **12px** | `--spacing-md` |

> **卡片内部不平均留白**：图片区最大 → 文字区紧凑 → 底部留出舒适安全区。

### 7.3 触达尺寸

## 11. 页面骨架与滚动交互（常驻工具栏 + 收缩滚动区）

> ⚠️ **结构性决议（2026-09-27）**：首页**不再有吸顶容器**。搜索区 + 横向大类标签栏改为**常驻工具栏**（页面 flex 列里一个恒定不动的行），滚动区收缩到「工具栏下沿 ↔ 菜单栏上沿」之间。**因此没有任何内容会经过任何横条背后** —— 全页不需要任何表面 / 切片 / 材质，也不监听滚动（`@scroll` 已删除）。

**结构前提（原布局 + 吸顶切片，2026-09-27）**：`.home-page` 是一个 **flex 列**——
① **固定标题带**（`position: fixed`，永久固定左上角、**不随滚动移动**，§1）；
② **滚动区**（`scroll-view`，`flex: 1`），内含：
   · **Banner**（首块，四周留白 + 四角圆角，**随页面上滑、在标题带下沿被裁**）；
   · **吸顶容器 = 搜索区 + 横向大类标签栏**（**一个组件**，`position: sticky` + `top: 0` = 滚动区顶 = 标题带下沿）；
   · **双列网格**（紧随吸顶容器）。
边界由页面的 `padding-top`（= 标题带高）与 `padding-bottom`（= 菜单栏 + 底部安全区）让出 ⇒
**标题带与菜单栏背后没有任何内容经过**（都不需要表面）；**只有吸顶容器**会有卡片从它背后滚过 ⇒
它是全页唯一需要表面的一条：**未吸顶透明、吸顶态铺背景图切片**（§11.1）。

**触发规则**：本页**只有一种布局状态**（不再有「未吸顶 / 已吸顶」两态）。垂直滑动只让滚动区内部滚动；
标签栏横向拖动、Banner 轮播左右滑动都不改变任何布局状态。

**滚动阈值**：不再有「锁定点 / 吸顶阈值」（历史常量 `L`、`B_b` 的吸顶语义随之作废）。

### 11.1 背景：全站**唯一**的 `fixed` 页底壁纸（零表面）

> **为什么不需要任何表面**：**不是**因为"表面做得和页底一样"，而是因为**根本没有内容会走到横条背后** ——
> 滚动区被结构性地夹在「工具栏下沿 ↔ 菜单栏上沿」之间，标题带 / 工具栏 / TabBar 背后**始终只有页底壁纸本体**。
> 于是横条一律不铺表面即天然连续，**「接缝 / 错位 / 撕裂 / 切换穿帮」这一类问题整体消失**
> （历史四种表面方案的全部失败记录见本节末尾「历史留痕」）。

**本页背景的实际构成：整屏壁纸 + 纱**

| 层 | 内容 | 落位 / 实现 |
|---|---|---|
| ① **壁纸** | 本地图 `client/src/static/images/home-bg.jpg`（750×1501、≈115KB） | 公共组件 `components/PageWallpaper.vue` 的 `<image mode="aspectFill">`。**本地图必须走 `<image>`**：小程序 WXSS 的 `background-image: url()` **取不到包内本地路径**（真机报「本地资源图片无法通过 WXSS 获取」，开发工具却可能正常预览）。盒子 = 满宽 × **实测视口高**（内联 `heightPx`，由页面 / TabBar 用 `wx.getWindowInfo().windowHeight` 实测下发；**不用 `vh`**）—— 全站**只有这一处**壁纸层，不再有需要「同尺寸对齐」的其它实例（切片已全部取消，2026-09-26） |
| ② **纱**（wash） | **全站 token `--page-wash`** = `rgba(255,248,239,0.4)`（唯一定义处 = `App.vue` 的 `page{}`） | 同组件内一个 `<view>` 的 `background-color`（纯色，**不受** WXSS 本地图限制）。**铺满整张壁纸、处处相同**（无分段、无渐变）—— 这是「降低背景突出度」的唯一手段。⚠️ **2026-09-26 三次修正**：① 删去原先铺到页底的 `0.9 / 0.62 / 0.5` 三段白纱（Banner 底部读作「发白 + 白色渐变」）；② 顶部 α=1 → 浅纱（让壁纸铺到屏幕最顶端）；③ **由「只盖顶部一条」改为「整张统一」** —— 只盖顶部那版会在画面中段留下一条可见的明暗突变（实测：看起来只有「知行食记」那一条有遮罩）。**α 是「背景突出度 ↔ 文字可读性」的唯一旋钮，改 `App.vue` 一处即全站生效** |
| ③ **内容** | 常驻工具栏（搜索 + 标签）/ 滚动区（Banner + 网格） | flex 列：工具栏 `flex: none`、滚动区 `flex: 1`。层级：`.home-page-bg` z-index 0 ＜ `.scroll-wrap` z-index 1（**绝对定位层默认画在流内内容之上，必须显式压回**） |

**同源机制（全站仅一处渲染、零表面）** —— `fixed` 页底壁纸即整屏背景；**标题带 / 工具栏 / TabBar 一律不铺表面**（2026-09-27 结构性决议）：

|---|---|
| **页面底** `<PageWallpaper class="home-page-bg" fixed />` | 偏移 **0**（视口坐标原点）；`fixed` 铺满视口 ⇒ 连标题带 / 工具栏 / 菜单栏那几条也一并覆盖，**壁纸天然铺满整屏**（旧「切片」就是为了补这几条，现已确认完全多余） |
| **标题带 / TabBar** | **无表面**：滚动区起点在标题带下沿、终点在菜单栏上沿 ⇒ **内容不从它们背后经过**（都不需要任何表面） |
| **吸顶容器**（唯一有表面的一条） | **背景图原样切片**：`v-if="pinned"` 只在吸顶态渲染；外层 `overflow: hidden` 裁切 + 内层**页底同款壁纸**（同 `src`（命中缓存）、同实测盒高），按 **实测基准**上移贴回视口原点 ⇒ 显示的就是"背景图去掉顶部标题带那一段"里本容器所在的那一条，**与页底逐像素同源**。未吸顶时完全透明（背后即页底壁纸本体） |

> ##### 历史留痕（全部已废止，勿回退）
> 曾经的思路是「让横条表面假装成透明的」，共试过六种做法，**全部失败**——根因是：只要内容从横条背后滚过，横条就必须"自己画一块东西"，而任何"复制/近似/渐变"都会在某个时刻被看见。
> ① **渐变切片**：逐帧基准经「滚动回调 → setData」下发滞后 1–2 帧 → 位图**撕裂** ✗；② **提前 24px 铺位图** → 「突变成切片」✗；③ **提前 12px 渐显** → 「上滑仍看到渐显切片」✗；④ **恰在锁定点硬切换**（像素零误差）→ 仍被判「组件背景不透明就有割裂感」✗；⑤ **纯色底 `--bg-wallpaper`**（壁纸纯底色 × 纱，与页底同色）→ 平坦区不可辨，但插画经过处会露出"被擦掉"的边界 ✗；⑥ **页底壁纸的原样切片**（视口对齐、常量偏移）→ 理论上最正确，但 1–2px 的对齐误差仍被肉眼读出接缝 ✗。
> **2026-09-27 结论**：不继续"把表面做得更像"，而是**改结构让内容压根不到横条背后**（常驻工具栏 + 收缩滚动区）。问题从根上消失：**零表面、零切片、零滚动监听、零状态**。

**接入方式与范围（全站）**

**硬性要求**：

1. 壁纸 SHALL 由 `<image>` 层渲染（包内本地图）；**SHALL NOT** 写成 WXSS `background-image: url(/static/…)`。纱 SHALL 由全站 token **`--page-wash`**（`App.vue` 的 `page{}`）**单点**承载，并随壁纸**整张统一**铺满（各实例逐像素同源）；
2. 壁纸盒子的 `heightPx` SHALL 由调用方**实测下发**（`windowHeight`）；**SHALL NOT** 用 `vh` 或由多个组件各自测算（全站只此一处，已不存在「多处取值必须一致」的对齐风险）；
3. **标题带 / TabBar SHALL NOT 铺任何表面**（滚动区不与它们重叠）；**吸顶容器 SHALL：未吸顶完全透明、吸顶态铺「背景图原样切片」**（`v-if="pinned"`，切片位置 = 背景图**去掉顶部标题带那一段**，即内层按**标题带高 `titleBandPx`**上移 —— 与 `AppTitleBand` 的 `height`、页面 `padding-top` **三者同源**，不再二次测量）；**SHALL NOT** 用磨砂 / 纯色底 / 半透明蒙版，也**SHALL NOT** 在未吸顶阶段渲染表面（那正是历史做法撕裂的根因）；内层 SHALL 为 `absolute`（`fixed` 会逃出裁切）；全站壁纸层**有且仅有一处**（`PageWallpaper`，`fixed`）＋ 吸顶态复用同一 `src` 的切片（无额外素材）；
4. 滚动区**背后无定格图片**（Banner 是滚动区首块、滚出即消失；壁纸是**页面级静态层**，不属于内容流、不随内容滚动）；
5. **滚动区 SHALL `flex: 1`**、页面 SHALL 用 `padding-top`（= 标题带高）与 `padding-bottom`（= 菜单栏 + 安全区）界定其上下边界 —— **SHALL NOT** 让滚动区在标题带 / 工具栏 / 菜单栏之下延伸；
6. 壁纸**体积 ≤300KB、宽度 ≥750**（= `750rpx` 的 2x，主包上限 2MB）；换壁纸 = 换文件（或改 `PageWallpaper.vue` 的 `src` 默认值），**不改任何布局代码**；
7. **可读性取舍**：整站只有**一层**统一纱（`--page-wash`，α **0.4**），它同时负责「背景不抢内容」与「标题 / 标签 / TabBar 文字可读」。若素材偏暗 / 过花 → **调大 `--page-wash` 的 α**（唯一旋钮，全站生效）；**不要**给某条横条单独加底色、也不要加第二层纱（会立刻产生可见突变 —— 这正是 2026-09-26 三次修正的原因）。

### 11.2 标题带的遮盖：**不需要遮盖**（滚动区不在它背后）

> **原方案（已废止）**：标题带表面是半透明渐变，透明度随 `scrollTop` 在 `[B_b − 60, B_b]` 由 0 → 1 渐显，靠「纱」柔化滚过的 Banner。
>
> **现行方案（2026-09-27 结构性决议）**：标题带**恒透明、不铺任何表面**。
> · **为什么可行**：滚动区从「标题带 + 常驻工具栏」之下开始 ⇒ **没有内容从带背后经过**，带背后直接露出 `fixed` 页底壁纸
>   ⇒ 视觉上「根本没有头部」，深棕标题**在任何滚动位置都可读**；
> · **为什么不需要开关**：本带位置恒定、背后无内容 ⇒ 无需 `@scroll`、无需判定"是否吸顶"、无需任何表面切换；
> · **纱的职责**：全站只有**一层**统一纱（`--page-wash`，整张壁纸上一层的纯色遮罩）负责「降低背景突出度 + 文字可读性」；
>   横条不额外加第二层纱 / 第二层底色（结构性决议后连托底色都不需要）。

**常量（全部由页面常量推导，禁硬编码裸值）**

> 卡片不会跑到任何区块背后 ⇒ **没有"遮挡"这件事**，也不需要任何表面。

**为什么这样最稳（三条硬理由）**

1. **没有「遮挡」这个动作**：内容只在滚动区内滚动、在工具栏下沿被裁切 ⇒ 全站不需要任何表面，也就不存在「接缝 / 错位 / 撕裂 / 切换穿帮」这一类问题；
2. **零状态、零滚动驱动**：首页**没有任何** `@scroll` 回调 / 逐帧基准 / 计时器 / 吸顶状态 —— 不存在跨线程延迟导致的滞后与闪现；
3. **背景天然连续**：全站只有**一处** `fixed` 页底壁纸、横条一律透明 ⇒ 壁纸从屏幕顶端铺到菜单栏上沿，**没有第二条图层需要对齐**。

**硬性要求**：

1. 标题带**SHALL 恒透明、SHALL NOT 铺任何表面**（切片 / 纯色底 / 半透明蒙版 / 额外纱层一律禁止）；带背后即 `fixed` 页底壁纸；
2. 标题的字色 / 字重 / 不透明度**恒定**（不随滚动做任何淡化 —— 首页不再向 `AppTitleBand` 下传任何透明度类 prop）；
3. 纱 SHALL 只有**一层**（全站 token `--page-wash`，铺满整张壁纸、处处相同）；**SHALL NOT** 再出现「只盖顶部一条」的渐变 / 蒙版（会被读作「Banner 底部发脏」，2026-09-26 修正；旧的 `--home-page-grad` 已废弃）；
4. **搜索区 / Banner / 大类标签栏 SHALL 常驻**（页面 flex 列的普通行、`flex: none`），**SHALL NOT** 再放进滚动区做 `position: sticky`；
5. **滚动区 SHALL 位于「工具栏下沿 ↔ 菜单栏上沿」之间** —— **SHALL NOT** 让内容进入任何横条背后；若将来必须让内容穿过某条横条，须另立 change 重做结构评审（不得退回"给横条加表面"的老路）；
6. `AppTitleBand` **不提供**任何「纱 / 渐变 / 透明度」能力（原 `veilOpacity` 已按「零消费即删」移除）；若未来恢复任何表面方案，必须重新评审（当前一律禁止）。

### 11.3 单态组件清单（只有一种布局状态）

1. **固定标题带**：「知行食记」固定在页面左上角，与微信胶囊同一水平带（恒透明，背后即页底壁纸）；

**边界行为（必须处理）**：

1. **快速猛滑**：滚动由渲染层原生完成，无逻辑层介入、无额外过渡动画；
2. **横向拖动标签栏 / Banner 轮播左右滑动**：不改变滚动位置、不改变任何布局状态；
3. **点击标签切换分类**：仅重新请求并刷新列表，**不重置滚动区位置**；
4. **上拉加载更多菜品**：新增卡片追加在列表底部，滚动位置不变；
5. **Banner 数据未到手 / 加载失败**：占位**高度仍按 16:10 计算**，不得因加载状态改变块高。

> ⛔ **页面级下拉刷新：本页不提供**（搜索页 / 系统通知 / 我的主页同）——下拉表现为普通滚动回弹。数据更新走「首屏拉取 + 进入页面（`onShow`）兜底 + 失败时『加载失败 · 点击重试』块」。如需「回到顶部」入口，须另立 change 单独拍板。

**一句话精简版**：屏幕左上角「知行食记」是固定标题带（永久不动）；它下面是**常驻工具栏**（搜索胶囊 + 搜索按钮 + 大类标签栏，永远在同一处、不铺任何背景）；再下面是滚动区（Banner 圆角卡 → 双列菜品网格）。上滑时只有滚动区内部在动，Banner 与卡片在工具栏下沿被裁切，**不会跑到标题带 / 搜索区 / 菜单栏背后**，所以全页背景始终连续、没有接缝。

3. 上滑超过阈值（**Banner 上间距 + Banner 高**）后，**「搜索区 + 标签栏」必须同组常驻吸顶**、不能消失，且**锁定位置在固定标题带下沿**（不得压到标题带）；
4. 所有菜品卡片**完整显示**，禁止半截截断；
5. 底部导航只保留**首页、我的**；
6. UI 布局**不得遮挡**右上角微信胶囊原生控件；
7. 首页内容流**无引导 / 补录类组件**；
8. **顶部顺序固定为「固定标题带 → Banner（四周留白的圆角图片卡）→ 吸顶容器（搜索区 + 大类标签栏）→ 双列网格」**，不得插入其它块、不得颠倒；Banner **随页面上滑、在标题带下沿被裁**；吸顶容器是**一个组件**（搜索与筛选不得拆开）；
9. **固定标题带**（左上角、**常驻不随滚动移动**、与微信右上角胶囊同水平带 / 同高、互不遮挡）是顶部**唯一由端上渲染的文本**；文案按页配置（首页 = 「知行食记」），位置 / 高度 / 对齐 / 配色跨页一致；Banner 图上不出现任何端上文本；
10. **Banner 宽高比锁定 16:10**（总高 = `(min(屏宽, 720) − 左右各 12px) × 10/16`，另有最小高度兜底；**左右各 12px 留白 + 四角 `--radius-card` 圆角，上距固定标题带 12px**）——不得用自由高度 / 16:9 / 4:3，**不得改回通栏贴顶**；⚠️ 定高的**取宽必须与 `App.vue` 的宽屏限宽（720px）同源**，否则 ≥768px 窗口下比例失真；
11. **Banner 是正常流首块（且不在固定标题带背后）**：滚出视口后不得在**任何横条**背后残留图片 / 不得做定格背景（滚动区不与横条重叠，结构性决议）；**固定标题带是独立固定层**，不因 Banner 滚出而消失、也不随 Banner 一起移动；
12. **Banner 素材一律 16:10**，且加载中 / 失败时**块高不变**；**空 / 失败占位沿用首页菜品卡图片占位的灰底样式**——`var(--bg-soft)` 灰底 + 居中**中性 `IconSvg name="empty"`**（`--text-tertiary`），**无文字说明、无白卡、无渐变**（图标键取中性 `empty`，依 `project_spec.md` §4.9 不得用 `dish` 冒充中性占位）；
13. **首页不得存在任何筛选入口**（无「筛选」按钮、无筛选面板、无食堂 / 价格筛选维度）；搜索页无食堂 / 价格筛选胶囊；
14. **搜索区必须保持「左搜索胶囊 + 右独立『搜索』按钮」两件结构**：胶囊与按钮同高、间距 `--spacing-sm`、同为 `--radius-pill`，按钮为**填充档**主色 + 白字；**不得合并为一颗输入框、不得等分为两块**；
15. **顶部各块间距以 §7 为唯一真源**（标题带→Banner 12px、Banner 左右 12px、Banner→搜索区 16px、搜索区→标签文字 ≈12px（行内偏置）、标签栏→网格 视觉 ≈16px、左右 gutter 12px、卡片间距 12px）——**不得用裸值近似**；**纵向间距不得在标签行内外各叠一层 padding**；
16. **标题带 / TabBar SHALL 恒透明**（滚动区起点在标题带下沿、终点在菜单栏上沿 ⇒ 无内容从它们背后经过）；**吸顶容器（搜索区 + 大类标签栏，一个组件）SHALL：未吸顶完全透明，吸顶态铺「背景图原样切片」**（去掉顶部标题带那一段，按 `titleBandPx` 同源对齐、**不逐帧**）；**SHALL NOT** 用磨砂 / 纯色底 / 半透明蒙版，也**SHALL NOT** 逐帧下发偏移（会滞后 1–2 帧 ⇒ 撕裂）；全站只有**一处** `fixed` 页底壁纸与**一层**统一纱 `--page-wash`；
17. **吸顶容器的位移 SHALL 由原生粘性定位承担**（`position: sticky` + `top: 0`，写在滚动区内部的内容流里）；**SHALL NOT** 用「滚动回调 + `setData` 下发 `transform` / `top`」模拟位移——跨线程延迟会让容器比内容慢半拍，读作「位置是临时算出来的」并易闪现；其**表面 SHALL 用常量偏移的切片层**，**SHALL NOT** 逐帧下发偏移（会滞后 1–2 帧 ⇒ 撕裂）；
18. **字号 / 间距刻度**：① 卡片字号固定为「菜名 32rpx（半粗）＞ 位置行 = 评分 28rpx（**两行均常规**）；价格 36rpx（粗体，强调档、允许大于菜名）」；② 任何正文级文本**不得低于 12px**；③ 搜索区控件内距按 §4（图标↔文字 8px、按钮左右 16px）；④ 标签栏光学间距按 §5.2（上行距 ≈12px / 下行距 ≈16px，下划线紧随文字 4px、**不得吸底**）；
19. **色彩必须语义分档**（§10.1 三条硬规则）：价格不得用 `#E67E22`、星不得用 `#F5A623`、「搜索」按钮填充底不得用 `#E67E22`（白字对比度不足）；
20. **背景 = 本地壁纸 + 纱（§11.1，全站）**：壁纸 SHALL 由 `<image>`（`components/PageWallpaper.vue` → `/static/images/home-bg.jpg`）渲染，**不得**写成 WXSS `background-image: url(/static/…)`；**页面级**统一用 `<PageWallpaper fixed />`（自带 `z-index: -1`，接入不得要求页面改层级）；**页面级**壁纸层**有且仅有一处**（`fixed` 视口锚定；`heightPx` 用实测 `windowHeight`，禁 `vh`）——**不得复制第二份**（横条一律透明，§11.1）；纱 SHALL 由**全站 token `--page-wash`**（`App.vue` 的 `page{}`）**单点**承载；壁纸 ≤300KB、宽度 ≥750，换图不改布局代码；
21. **全站接入范围**：**全部 11 页 SHALL 已接入**（主包 home / find / mine；分包 detail/dish、profile、auth、notifications、feedback、my-reviews、privacy、privacy/agreement），每页一行 `<PageWallpaper fixed />`；分包页的固定横条（`AppHeader` / `dish-nav` / `action-bar` / `submit-bar`）按 2026-09-26 决议**保持实底**；新增页面 SHALL 同样在根节点第一行接入；

> **图片占位策略（本期所有图片先占位，禁止无限空转加载）**：① 菜品图——失败立即回退**灰底 + 菜品 icon** 空态（`var(--bg-soft)` + `IconSvg name="dish"`，唯一真源 = `pages/home/DishCard.vue`）；② Banner 轮播图——`GET /banners` 返回空 / 请求失败 / 单张加载失败 → **复用同一灰底 + 中性 `empty` 图标**（不写文字说明），**占位块高仍按 16:10**；③ 列表请求失败 → 失败重试块（`RetryBlock`）。**预览排查**：若标签栏只剩「全部」或不出现 → 字典请求失败，依次检查：后端是否在线（`GET /dishes/meal-types` 应返回 6 项）、开发者工具是否勾选「不校验合法域名」、是否使用了最新构建产物（`dist/build/mp-weixin`）；若 Banner 恒为占位图 → 检查 `GET /banners` 是否返回非空数组、图片 URL 是否可达。

## 14. 不建议做的设计（防回退）

1. **不做彩色标签块**——标签栏保持纯文字 + 短下划线；
2. **不做多种橙色混用**——按钮 / 价格 / 星级 / 下划线各司其职（§10.1）；
3. **不做强阴影卡片**——校园工具要轻，不做电商促销卡；
4. **不做满屏渐变**——全站只有「一层统一纱」（`--page-wash`，整张壁纸铺满的纯色遮罩），不额外做任何渐变层；
5. **不把菜名压在图片上**——图片就是图片，文字就是文字。
