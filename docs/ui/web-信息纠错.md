# 信息纠错 — 页面 UI 设计稿

> 所属端：管理端（Web 后台） ｜ 归属功能文档：[web-信息纠错.md](../feature/web-信息纠错.md)
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 落点：`/dashboard/corrections`（`CorrectionView`）；导航名为「**信息纠错**」。

- 导航「信息纠错」→ `/dashboard/corrections`（导航项带**待处理徽标**）；支持 `?cid=<id>` 深链直达单条（列表落地后按 id 定位并自动打开对比抽屉；不在当前页时按菜品名服务端检索）。
- 筛选：状态（**默认待处理** / 已采纳 / 已拒绝 / 全部状态）。
- 表格列：目标菜品（`dishName` 链接 → 菜品详情页 `/dashboard/content/dishes/:dishId`，含已下架；已物理删除退回「菜品#id」占位）/ 提交摘要（提交名称 · 价格〔分→元〕· 食堂 · 档口，超长截断）/ 提交人（昵称或「游客」）/ 提交时间（可排序）/ 状态（`StatusTag`）。
- **对比抽屉**（`FormDialog`）：
  - 元信息块（提交人 / 提交时间 / 目标菜品）+ **字段级对比卡**——标题「菜品信息纠错对比」+ 目标菜品名；字段行对比（名称 / 价格〔分→元〕/ 食堂 / 档口 / 口味 / 食材〔机器值经字典译中文、未命中回落原值〕：左「当前菜品」→ 右「用户提交」；**有差异字段两侧 warning 底色高亮 +「已修改」标**）+ 图片行（「当前菜品」vs「用户提交」两组缩略对比，点击放大预览）；原菜品**按 `dishId` 精确定位**（含已下架），定位失败（已物理删除）时降级为仅展示提交内容并提示。
  - 底部动作：
    - 「**一键采纳**」（主按钮）：二次确认「提交内容将写回目标菜品」→ 服务端档口未决（`needStallConfirm`）时进入**两段式档口确认对话框**——标题「确认档口」；候选 `candidates` 以 **radio 单选**呈现（默认无选中），另设「按提交档口名新建档口」独立选项（对应 `createIfMissing=true`）；选定后回传 `stallId` 或确认新建完成采纳；取消 = 不执行任何写回、纠错保持待处理。
    - 「**不采纳**」：进入子流程（返回 + 确认不采纳；回复必填 1~1000 字 + 不采纳原因必填 1~200 字，`outcome` 固定 `rejected`）。
  - 已处理：只读回看（处理时间 / 历史回复 / 不采纳原因回显）+「关闭」。
