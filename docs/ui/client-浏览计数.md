# 浏览计数 — 页面 UI 设计稿

> 所属端：学生端（微信小程序） ｜ 归属功能文档：[client-浏览计数.md](../feature/client-浏览计数.md)
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 落点：**无独立界面** —— 纯计数（获取菜品详情即计），无任何可见 UI；本文档记录「为什么没有界面」与计数口径。


无独立界面（获取菜品详情自动触发，用户无感知）。

> **计数口径（见功能文档）**：计数由 `GET /dishes/{id}` 承担，**每次成功响应即 +1**
> （PV 口径，不做人员 / 时间限制），**端上无须发起任何上报请求**；
> 唯一的服务端兜底是 **IP 维度限频**，正常浏览速率下**用户无感** —— 故本页仍**无任何可见 UI**。

## 接口数据字段（UI 精修用）

**页面**：无独立界面（副作用内聚于菜品详情 `pages/detail/dish/index`，用户无感知）

### 组件清单（本界面需要哪些组件）

**无** —— 本功能不新增任何组件、控件、弹层或图标；计数完全内聚于详情接口的成功响应路径。

| 项 | 归属组件 | 说明 |
|---|---|---|
| 计数触发点 | 无（`pages/detail/dish/useDishPage.ts` 的详情拉取 / 提交后刷新） | `GET /dishes/{id}` 每次 `code=200` 即 +1（PV 口径） |
| 计数展示位 | **无** | 全站**不展示浏览次数**（无「N 次浏览」类文案与组件） |

### 有哪些数据要显示、显示在哪个组件

| 数据 | 来源 | 显示在哪个组件 | 说明 |
|---|---|---|---|
| 浏览量 `dish.view_count` | 服务端写：`GET /dishes/{id}` 成功即 +1 | **不显示**（字段不出参） | 仅作服务端热度排序输入（`heatScoreExpr`），端上零读取、零渲染 |
| IP 限频剩余秒数 | `400` 响应 `message` | 无独立组件（请求层 Toast 直透） | 超频时「操作过于频繁，请 X 秒后再试」，**不计数** |

**出参消费**：无（响应不含计数值——计数是响应副作用，不是出参字段）
**入参提交**：无（端上**不发起任何上报请求**；无埋点、无 beacon、无额外接口）
**错误码**：`4001` 菜品不存在（**不计数**）｜`400` IP 限频（**不计数**）
**控件类型**：无（用户无感知）
