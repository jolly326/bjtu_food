# 菜品问题反馈

> 所属端：**管理后台（Web）** ｜ 页面 / 单元：**菜品问题反馈**（**按 `type` 分 Tab** 的列表 + 处置 / 详情抽屉）｜ 目标路由：`/corrections`
> **覆盖**：B4 菜品问题反馈管理（`dish_correction` 的**逐项采纳** / 拒绝 / **下架**）。
> **不覆盖**：列表通用骨架（基础列 / 详情抽屉 / 六态 / 分页 / 交互与状态）→ [列表页模板.md](./列表页模板.md) §一 与 §B4；组件规格 → [公共组件与形态基线.md](./公共组件与形态基线.md)；字段 / 端点 / 两段式档口确认 / 回执文案 → [B4 功能文档](../../func/web/B-UGC治理/B4-菜品问题反馈管理.md)；菜品本体编辑见 [菜品管理.md](./菜品管理.md)、取值登记见 [属性维度与取值.md](./属性维度与取值.md)。

## 一、页面构成

```
[ h2 菜品问题反馈            (全部 | 信息有误 | 已经下架) ]   ← 类型 Tab，置于页头右侧
[ 状态▾ | 菜品 ID ]                           [ 查询 ] [ 重置 ]
┌ .table-wrap ───────────────────────────────────────────────────────┐
│ 类型 │ 目标菜品 │ 提交人 │ 状态 │ 提交时间 │ 操作           │
│ 信息有误 番茄炒蛋  食客1234  待处理    …      处理           │
│ 已经下架 麻辣香锅  食客5678  待处理    …      处理           │
└────────────────────────────────────────────────────────────────────┘
                                        [ 共 N 条 · 页码 ]
   ↳ 表格脚注：「类型 / 目标菜品 / 提交人 / 状态」是快速查阅列；
      改动项对照、楼层影响、用户佐证与处置入口都在行内「处理 / 详情」内。」

＋ 处置 / 详情抽屉（640，**同一抽屉两态**：`pending` 处置态 / 已处理只读态）
```

| # | 区域 | 要点 |
|---|---|---|
| 1 | **页头** | `h2`「菜品问题反馈」；**无主按钮**（反馈由学生提交）。右侧挂**类型 Tab**（`.tabs` + `.tab`，`margin-left: auto` 靠右）：`全部` / `信息有误` / `已经下架`，`role="tablist"` + 每项 `role="tab"` + `aria-selected`；选中项 `.tab.active`（主色描边 + 浅色底）。切换 Tab **立即 `reloadFirstPage()`** |
| 2 | **筛选区** | **状态**▾（全部 / 待处理 / 已采纳 / 已拒绝）+ **菜品 ID** 输入 + 「查询」+「重置」（**重置含 Tab**，回到「全部」） |
| 3 | **列（基础列）** | `类型`（`StatusTag kind="correctionType"`）→ `目标菜品`（`dishName`；菜品已删除 → 「菜品已删除」+ `--text-muted`）→ `提交人`（**匿名提交 `userId = 0` → 服务端回落「游客」**）→ `状态` → `提交时间`（`formatDateTime`）→ `操作`（`处理` / `详情`） |
| 4 | **状态列** | **恒用 `StatusTag`**（`kind='correction'`）：`pending` → `待处理`（中性灰）／`adopted` → `已采纳`（绿）／`rejected` → `已拒绝`（红）；**页面不自写 `.tag-*`** |
| 5 | **类型列** | **恒用 `StatusTag`**（`kind='correctionType'`）：`field` → `信息有误`／`gone` → `已经下架`，**两档同为中性灰**（类型是「用户在说什么」，不是处理结论；「已经下架」不表示已处理） |
| 6 | **行操作** | `待处理` → `处理` ｜ 已处理 → `详情`（只读回显）—— 同一个抽屉，态由**行状态**决定 |
| 7 | **列表不展开内容** | 列表只给「谁、对哪道菜、什么类型、什么状态」；**改动项对照、楼层影响、`gone` 的补充说明与图片、处理回复全部在抽屉**（避免列表重且难扫） |

## 二、处置 / 详情抽屉（**核心界面**，按 `type` 分派）

**载体**：`BaseDrawer`（常规 640；差异对照表外包 `.table-wrap` ⇒ 窄屏横向滚动，**不另开宽抽屉**）。抽屉标题：待处理 → `field`「处理反馈」/ `gone`「处理下架反馈」；已处理 → 「反馈详情」。

```
┌ 抽屉头：番茄炒蛋 · 食客1234  [信息有误] ──────────────────────┐
│ ① 用户反馈（仅 gone）                                          │
│    补充说明 │ 这个窗口换成麻辣香锅了                            │
│    反馈人数 │ 3 人反馈已下架（仅参考，是否下架由人工判断）       │
│    图片     │ [56×56 缩略图，**点击开大图**]                    │
│ ② 差异对照表（仅 field）                                        │
│    ☑ │ 差异项   │ 当前值 │ 用户提交的新值 │ 影响               │
│    ☑ │ 菜品名称 │ 蕃茄炒蛋 │ 番茄炒蛋      │                    │
│    ☐ │ 楼层     │ 二层     │ 三层          │ 将连带同档口其它菜品 │
│ ③ 处理结论（单选，仅 pending）                                  │
│    ( field ) 采纳     │  ( gone ) 下架该菜品                   │
│    ( ) 不采纳          │  ( ) 驳回（仍在售）                    │
│ ④ 档口归属确认（仅 field 型、且提交的档口名未匹配时 · 内联块）    │
│    档口名「XX」未匹配 → [候选档口▾]  ☐ 按提交的档口名新建档口后挂靠 │
│ ⑤ 不采纳原因 [input ≤200，仅「不采纳 / 驳回」时显示，必填]        │
│ ⑥ 处理回复 [textarea ≤600，可选]                               │
│                       [ 取消 ] [ 确认 ]                        │
└────────────────────────────────────────────────────────────────┘

已处理 → 只读态：差异对照表**无勾选框**、无结论区，结论与差异均以 `.detail-meta` 呈现
          回显（记录 ID / 提交人 / 处理结论 / 处理回复 / 不采纳原因 /
          提交时间 / 处理时间）＋ 底部只有 [ 关闭 ]
```

| 项 | 口径 |
|---|---|
| **`gone` 用户反馈区** | 定义列表（`.gone-info`，左标签 72px + 右内容）：`补充说明`（`note`，空显 `--text-muted`「未填写」）｜ `反馈人数`（`goneUserCount` + 固定尾注「（仅参考，是否下架由人工判断）」）。**必现** —— 「变成了别的菜 / 换窗口了 / 今天临时没供」三种情况的处置动作完全不同，只看人数会误下架 |
| **`gone` 图片区** | `images[]` 非空时以 `56×56` 缩略图并排（`.ctx-thumbs`），**只读**（不提供上传 / 删除），**点击即开 `ImagePreview` 大图** |
| **结论文案按类型切换** | `field`：`采纳` ｜ `不采纳`；`gone`：`下架该菜品` ｜ `驳回（仍在售）`。两组**均为 `.tag-option` 单选**（`role="radiogroup"` + `aria-checked`） |
| **`gone` 下架说明** | 选中「下架该菜品」时在结论区下方给出 `--color-warning` 一行：「下架仅把该菜品置为『已下架』，可重新上架、评价完整保留；删除请到『菜品管理』由管理员主动执行。」—— 🔴 **本抽屉任何状态下都不出现「删除」** |
| **`gone` 提交可用性** | 选中「下架该菜品」时**恒可提交**（无可勾选项）；请求体只带可选 `reply`，服务端直接置 `dish.status=off` |
| **对照表** | 列 = `☑ 采纳` ｜ `字段`（`label` 中文名）｜ `原值`（`oldValue`，**实时回查**）｜ `提交值`（`newValue`）；`affectsOthers` 时该行下附 `--color-warning`「将连带同档口其它菜品」。**仅 `field` 型渲染**；`pending` 时首列为勾选框，已处理时该列不渲染 |
| **默认勾选** | **全部勾选**（管理员的任务是「去掉不采纳的」，比「逐个勾上」更省事；与「显式优先」平衡：取消勾选即显式排除） |
| **空值呈现** | 任一侧为空 → 显 `—`（`--text-muted`）；`differences` 为空时表格内给一行「已无待采纳差异项」 |
| **主按钮** | `.btn-primary`；**`field` 型未勾选任何项时禁用**（空数组服务端会 `400`，UI 从源头避免）；`gone` 型不作此约束 |
| **驳回原因字段** | `field` 型标签「不采纳原因（必填，≤200 字）」；`gone` 型标签「仍在售的原因（必填，≤200 字）」—— **内联字段，不另开弹窗** |
| **档口两段式确认** | 采纳请求返回 `needStallConfirm` 时，抽屉内**内联**展开 `stall-confirm` 块：候选档口下拉（`candidates`）+ 「按提交的档口名新建档口后挂靠」复选；选定后**再次调用采纳**。**不做静默新建** —— 这是「错别字 → 重复档口」的唯一防线 |
| **处理回复** | `reply` **可选**（**≤600 字**），随回执下发；缺省用固定文案。**两类一致**，标签恒为「处理回复（可选，≤600 字）」，右下角 `n / 600` |
| **只读态** | 已处理行打开时：对照表变只读（无勾选框）、无结论区、底部只有 `关闭`，并回显处理时间 / 回复 / 不采纳原因 |

## 三、交互与状态

| 场景 | 口径 |
|---|---|
| 打开抽屉 | `GET /admin/corrections/{id}` 取按 `type` 分派的内容（**`field`**：`differences[]`，含实时 `oldValue`；**`gone`**：`note` + `images` + `goneUserCount`）→ 抽屉内先显 `StateBox` 加载态；失败给错误态可重试 |
| 下架成功（`gone`） | `ElMessage.success('已下架')` → 关抽屉 → `reload()`；**回执「已下架，感谢反馈」**由服务端下发（UI 不拼）；误下架可在「菜品管理」重新上架 |
| 驳回成功（`gone`） | `ElMessage.success('已驳回')` → 关抽屉 → `reload()`；**回执「经核实，该菜品仍在售：<原因>」**由服务端下发 |
| 采纳成功 | `ElMessage.success('已采纳')` → 关抽屉 → `reload()`；**回执提及「哪几项未采纳」**由服务端按 `acceptedFields` 生成（UI 不拼） |
| 采纳后目标菜品已删除 | 服务端 `4001` → 原文透出 + 提示「该菜品已被删除」→ `reload()` |
| 重复处理 | 服务端 `400`「该菜品问题反馈已处理」→ 原文透出 → `reload()`（列表状态刷新） |
| 拒绝后 | 同上流程；`rejectReason` 纯空白由服务端 `400`，UI 亦做提交前必填校验（主按钮 `:disabled`） |
| 本页不做 | 批量采纳 / 批量下架、编辑用户提交的原始快照、反馈项的手工改写（管理员若要改菜品，走 [菜品管理](./菜品管理.md)）；🔴 **`gone` 处置不提供「删除」**（物理删除会级联清空该菜评价，仅在「菜品管理」由管理员主动执行） |

## 五、数据字段

- `dish_correction.type`：`field` / `gone`（`StatusTag kind="correctionType"` 的取值）；列表筛选与抽屉分派均以此为判据。
- `DishCorrectionAdminVO` / `DishCorrectionDetailVO`、`differences[]`、`DishCorrectionAdoptReq`（`acceptedFields` / `stallId` / `createIfMissing` / `reply`）、`DishCorrectionHandleReq`（`rejectReason` / `reply`）、`StallConfirmVO` 与错误码：见 [api/web/corrections.md](../../api/web/corrections.md)（接口契约唯一真源）。
- **`gone` 型专用字段**：`note`（补充说明，处置时**必现**）、`images[]`（只读缩略图）、`goneUserCount`（参考值，**非下架阈值**）；`differences` 恒空。
- **`acceptedFields` 的取值 = `differences[].field`**（原样回传，UI 不构造）：`name` / `price` / `canteenName` / `stallName` / `floor` / `images` / `attributes`。
- **金额**：`price` 的 `oldValue` / `newValue` 均为**分** → 界面按 `¥x.xx` 展示（只读，**本页不编辑金额**）。
- **属性**：快照里是**中文**（用户提交原样）；采纳时由服务端按「维度 + 中文」查取值字典（命中即用、**未命中新建**）—— UI 不做翻译。
- **图片**：快照为**绝对 URL 数组**，只读对比展示、可点开大图。
- **时间**：`createdAt` / `handledAt` 一律经 `formatDateTime`（[列表页模板 §1.6](./列表页模板.md)）。
