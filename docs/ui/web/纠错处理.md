# 纠错处理

> 所属端：**运营端**
> 返回：[UI 总览](./README.md) ｜ 归属功能：[B2](../../func/web/B-反馈数据/B2-纠错查看.md) ｜ 接口：[api/web/issues.md](../../api/web/issues.md)

> **本页只管「处置」** —— 选项字典的增删改在独立页 [纠错选项.md](./纠错选项.md)。

## 1 · 页面结构

| 区块 | 内容 |
|---|---|
| 顶栏 | 标题「纠错处理」（🔴 **无「新建」** —— 纠错由学生产生，运营不建） |
| 筛选区 | **处理状态**下拉（**默认「未处理」**）· **菜品**下拉 —— 两档**即选即查** |
| 列表卡片 | 菜品 + 错误类型 tag（主行）｜ 食堂 · 档口（归属路径行）｜ 提交于 · 处理于（指标行）；🔴 **卡面无操作按钮** |
| 卡片操作 | 🔴 **长按浮层**（与其他页同构，见[基线](./公共组件与形态基线.md) §2.3）：未处理 ⇒ 「**去改菜品**」「标记已处理」｜ 已处理 ⇒ 「撤销处理」 |
| 分页 | 共 N 条 + 上一页 / 页码 / 下一页 |

## 2 · 交互

| 动作 | 口径 |
|---|---|
| 🔴 **去改菜品**（一键直达） | 长按浮层「去改菜品」⇒ 跳「[菜品管理](./菜品管理.md)」并**带 `dishId` 参数**，落地后**自动打开该菜的编辑弹窗** —— 免去「切菜单 + 再搜一次」 |
| **标记已处理** | 长按浮层「标记已处理」⇒ `PATCH { handled: true }`；成功 `ElMessage.success('已标记')` ⇒ 刷新（默认视图下该行随之消失） |
| **撤销处理** | 已处理行长按浮层「撤销处理」⇒ `PATCH { handled: false }`；成功 `ElMessage.success('已撤销')` ⇒ 刷新 |
| 🔴 **系统不自动更正** | 「去改菜品」只是**导航** —— 字段怎么改、改不改，由运营决定；本页**不代改任何字段** |
| 🔴 **无回执** | 本页**没有任何「通知学生」的入口**（设计上就不给回执） |
| 错误类型 | **只读**展示（中文由选项字典翻译）—— 维护选项请去 [纠错选项](./纠错选项.md) |
| 空态 | 未处理视图下为空 ⇒ 「暂无待处理的纠错」（一句话） |
| 加载失败 | `ElMessage.error`（服务端 `message`） |

## 3 · 视觉规格

| 项 | 取值 |
|---|---|
| 错误类型 tag | 主行内 `.tag`（中性弱化） |
| 处理状态 | 未处理 ⇒ **无标签**，「处理于」整段**不显示**｜ 已处理 ⇒ 处理时间文本（弱化） |
| 操作入口 | 🔴 **无卡面按钮** —— 长按 / 右键 / 键盘唤起底部浮层（`CardActionSheet` 的 `actions` 动作列表） |
| 顺序 | 服务端按提交时间**降序**（无客户端排序，见[基线](./公共组件与形态基线.md) §1.6） |

## 4 · 处置动线（一键直达）

```
本页看到纠错  →  长按卡片「去改菜品」 ⇒ 直达该菜的编辑弹窗，改对字段（菜名 / 价格 / 图 / 位置 / 下架）
              →  回到本页长按「标记已处理」
```

> 「已经下架」这类选项 ⇒ 在编辑弹窗里把状态切到「已下架」，再回来标记。
> 这条动线是🔴 **全站唯一的跨菜单跳转**（其余操作一律在本页弹窗内完成）。
