# 纠错处理

> 所属端：**运营端**
> 返回：[UI 总览](./README.md) ｜ 归属功能：[B2](../../func/web/B-反馈数据/B2-纠错查看.md) ｜ 接口：[api/web/issues.md](../../api/web/issues.md)

> **本页只管「处置」** —— 选项字典的增删改在独立页 [纠错选项.md](./纠错选项.md)。

## 1 · 页面结构

| 区块 | 内容 |
|---|---|
| 顶栏 | 标题「纠错处理」（🔴 **无「新建」** —— 纠错由学生产生，运营不建） |
| 筛选区 | **处理状态**下拉（**默认「未处理」**）· **菜品**下拉 + 「重置」—— 两档**即选即查** |
| 表格 | 菜品 ｜ 食堂 ｜ 档口 ｜ **错误类型** ｜ 提交时间 ｜ 处理时间 ｜ 操作 |
| 行内操作 | 未处理 ⇒ 「**去改菜品**」「标记已处理」｜ 已处理 ⇒ 「撤销」 |
| 分页 | 共 N 条 + 上一页 / 页码 / 下一页 |

## 2 · 交互

| 动作 | 口径 |
|---|---|
| 🔴 **去改菜品**（一键直达） | 点击 ⇒ 跳「[菜品管理](./菜品管理.md)」并**带 `dishId` 参数**，落地后**自动打开该菜的编辑弹窗** —— 免去「切菜单 + 再搜一次」 |
| **标记已处理** | `PATCH { handled: true }`；成功 `ElMessage.success('已标记')` ⇒ 刷新（默认视图下该行随之消失） |
| **撤销** | 已处理行的操作按钮；`PATCH { handled: false }`；成功 `ElMessage.success('已撤销')` ⇒ 刷新 |
| 🔴 **系统不自动更正** | 「去改菜品」只是**导航** —— 字段怎么改、改不改，由运营决定；本页**不代改任何字段** |
| 🔴 **无回执** | 本页**没有任何「通知学生」的入口**（设计上就不给回执） |
| 错误类型 | **只读**展示（中文由选项字典翻译）—— 维护选项请去 [纠错选项](./纠错选项.md) |
| 空态 | 未处理视图下为空 ⇒ 「暂无待处理的纠错」（一句话） |
| 加载失败 | `ElMessage.error`（服务端 `message`） |

## 3 · 视觉规格

| 项 | 取值 |
|---|---|
| 错误类型列 | `.tag`（中性弱化） |
| 处理状态 | 未处理 ⇒ **无标签**，处理时间列显示 `—`｜ 已处理 ⇒ 处理时间文本（弱化） |
| 操作列 | 未处理行**两个按钮**：「去改菜品」｜「标记已处理」（放最右） |
| 顺序 | 服务端按提交时间**降序**（表头不可点，见[基线](./公共组件与形态基线.md) §1.5） |

## 4 · 处置动线（一键直达）

```
本页看到纠错  →  点「去改菜品」 ⇒ 直达该菜的编辑弹窗，改对字段（菜名 / 价格 / 图 / 位置 / 下架）
              →  回到本页点「标记已处理」
```

> 「已经下架」这类选项 ⇒ 在编辑弹窗里把状态切到「已下架」，再回来标记。
> 这条动线是🔴 **全站唯一的跨菜单跳转**（其余操作一律在本页弹窗内完成）。
