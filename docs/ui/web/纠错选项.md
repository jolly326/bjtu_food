# 纠错选项

> 所属端：**管理端（运营）**
> 返回：[UI 总览](./README.md) ｜ 归属功能：[B3](../../func/web/B-反馈数据/B3-纠错选项管理.md) ｜ 接口：[api/web/issues.md](../../api/web/issues.md)

## 1 · 页面结构

| 区块 | 内容 |
|---|---|
| 顶栏 | 标题「纠错选项」+ 主操作「新建选项」 |
| 筛选区 | **无**（量级固定小，全量列出） |
| 表格 | 选项文案 ｜ 引用次数（只读）｜ 更新时间 ｜ 操作（编辑｜删除） |
| 分页 | **无**（全量） |

## 2 · 交互

| 动作 | 口径 |
|---|---|
| **新建** | 居中弹窗（见[基线](./公共组件与形态基线.md) §2.2）：单字段「选项文案」（必填） |
| **编辑（改名）** | 同弹窗；🔴 弹窗内**固定提示**「**改名后全站生效（含历史记录的中文翻译）**」 |
| 保存 | `POST` / `PUT`；成功 `ElMessage.success('已保存')` ⇒ 关弹窗 + 刷新列表 |
| **删除** | 🔴 引用次数为 `0` 时**才可点**；确认文案：「删除后学生端将不再出现该选项。」 |
| 删除被拒 | 引用次数 `> 0` ⇒ 删除按钮**禁用**并提示「**已被 N 条纠错提交引用，无法删除**」—— 前端只做提示，🔴 **最终仍由服务端拒绝**（前端不预判） |
| 空态 | 「暂无选项」（正常不会出现 —— 有 5 条初始数据） |

## 3 · 视觉规格

| 项 | 取值 |
|---|---|
| 引用次数列 | 只读统计，弱化；`> 0` 时更浅以提示"不可删" |
| 操作列 | 右侧固定，「编辑」｜「删除」文字按钮 |
| 排序 | 按 `id` 升序（服务端已定）；🔴 **不做拖拽排序** —— 选项无 `sort_order` |

## 4 · 为什么单独一页

选项字典是**独立的字典资源**（有自己的增删改查），与「看纠错列表、标记已处理」是**两件不同的工作**：

| 工作 | 性质 | 页面 |
|---|---|---|
| 处置学生提交 | **流程**（看 → 改菜品 → 标记已处理） | [纠错处理.md](./纠错处理.md) |
| 维护选项字典 | **字典 CRUD** | **本页** |

⇒ 给独立菜单入口，而不是藏在纠错列表页的下半部分。
