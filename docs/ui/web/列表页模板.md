# 一、通用骨架（**本目录所有列表页共用**，唯一描述处）

```
┌ 页头 .page-header ─────────────────────────────────────────┐
│ h2 页面标题        [ 说明/计数 ] [ 次级动作 ] [ 新建 XX ]    │
├ 筛选区（可选） .card ──────────────────────────────────────┤
│ [ 筛选控件… ]            [ 查询 ] [ 重置 ]                  │
├ 列表主体 ─────────────────────────────────────────────────┤
│ ① 加载 / ② 错误 / ③ 空态     ← StateBox（三态盒）           │
│ ④ .table-wrap > table.table  ← **只放基础检索列**（§1.2）    │
│ ⑤ .pager 共 N 条 + 页码（分页页才渲染）                      │
└───────────────────────────────────────────────────────────┘
＋ 详情抽屉（BaseDrawer，**同一抽屉两态**：查看 ⇄ 编辑）—— §1.3
＋ 处置弹窗（BaseModal，如「隐藏评价」「复制菜品」的短表单）
＋ 删除确认（ElMessageBox）
```

## 1.1 区域构成

| # | 区域 | 规格（引用） | 说明 |
|---|---|---|---|
| 1 | **页头** | [基线 §1.2](./公共组件与形态基线.md) | 标题 = 菜单名；右侧**至多一枚** `.btn-primary`（新建类动作）+ 若干 `.btn-secondary`（次级入口，如「管理分类」）；C2 **无主按钮**（用户不可新建） |
| 1b | **说明 / 计数** | `.tag` / `.page-note`（`--font-sm --text-muted`） | 上限类约束的**自证**（A5「启用 N/6」、A7「启用 N/8」）与**页内口径说明**（A5 的「轮播组合」）——见各差异节；无需要则不渲染 |
| 2 | **筛选区** | [基线 §1.7](./公共组件与形态基线.md) | 单个 `.card` 内**一行**控件（`flex-wrap`）；控件宽度统一 `160px`（**本页登记的页面例外** —— 基线的 `.form-input` 默认 `max-width: 320px`，筛选行内收窄以便一行放下 5 个控件）；末尾「查询」`.btn-primary` + 「重置」`.btn-secondary`。**无筛选的菜单不渲染本区** |
| 3 | **列表主体** | [基线 §1.4 / §1.5 / §1.6](./公共组件与形态基线.md) | 六态齐备（加载 / 错误 / 空 / 有数据 / 分页 / **会话失效**） |
| 4 | **详情抽屉** | [基线 §1.10 / §1.15](./公共组件与形态基线.md) | **本页的字段与操作承载**：表格放不下的字段、以及**编辑 / 删除类操作**一律在这里（§1.3） |
| 5 | **删除确认** | [基线 §1.12](./公共组件与形态基线.md) | `ElMessageBox.confirm`，`type: 'warning'`；文案含**影响面**（见各差异节） |

## 1.2 表格列序（**只放基础检索列**）

```
`拖拽手柄（仅排序菜单）` → 主标识列 → 归属 / 分类列 → 计数列 → 状态列 → 时间列 → 操作列
```

- **表格的职责 = 「快速查阅 + 定位到详情」**，**SHALL NOT** 把全部字段塞进一行：
  - **留在表格的**：主标识（名称 / 图片 / 头像+昵称）、**归属与分类**（检索入口）、**计数**（数量级判断）、**状态**（`StatusTag`）、**时间**、操作；
  - **移入详情抽屉的**：长文本（描述 / 正文 / 回复）、配图与预览、属性 / 差异对照、排序位 / 顺序、原文快照、创建与更新时间明细、**以及全部编辑 / 删除类操作**。
- 主标识列：A1/A2/A3/A4/A7 = 名称；A5 = 缩略图；C2/B1 = 头像 + 昵称。
- 状态列恒用 `StatusTag`（[基线 §2.3](./公共组件与形态基线.md)）。
- 时间列**一律经 `formatDateTime` 出 `YYYY-MM-DD HH:mm:ss`**（§1.6）。
- 操作列恒为最后一列（`.actions`），内容为 `详情` / `处理` / `处置` 等**入口型**动作。
- **可保留的行级快速动作**：高频且可逆的**无表单**动作（如 C2 的启用 / 禁用、A3 的上下架）—— 是否下沉到行内由各差异节登记；**编辑 / 删除类一律进详情抽屉**。

## 1.3 详情抽屉（**同一抽屉两态**）

> 全部列表页的**字段承载与操作入口**。规格 = [基线 §1.10 / §1.15](./公共组件与形态基线.md)；本节只定**行为口径**。

| 项 | 口径 |
|---|---|
| 载体 | `BaseDrawer`（恒用；含只读内容区块 ⇒ 按 [基线 §1.10](./公共组件与形态基线.md) 判据即应走抽屉而非弹窗） |
| 打开 | 行内 `详情`（或 `处理` / `处置`）→ 同一抽屉设 `view` 态 |
| 两态 | **`view`**（只读：字段全览 + 底部动作）/ **`edit`**（表单：新建或编辑）—— **不新开第二个浮层** |
| 底部动作（view） | 该行的全部业务动作：`编辑` → `专属动作`（启停 / 上下架 / 改名 / 管理取值 …）→ `删除`（`.link danger`，恒最后） |
| 底部动作（edit） | `取消`（`.btn-secondary`）+ `保存`（`.btn-primary`，提交中 `:disabled`） |
| 取消语义 | 编辑态点「取消」：有历史行 → **退回 `view` 态**（不关抽屉）；新建 → 关抽屉 |
| 脏数据保护 | `BaseDrawer` 的 `dirty` = `edit` 态且表单 ≠ 进入编辑态时的快照 ⇒ 关闭前二次确认「放弃未保存的修改？」 |
| 保存成功 | `ElMessage.success('已保存' / '已新建')` → `reload*()` → **编辑态退回 `view` 态并按 id 回填刷新后的行**（不留旧快照）；新建则关抽屉 |
| 详情数据来源 | 列表行**字段不全**的页面（A3 菜品：列表是瘦身 VO；B4 纠错：详情走独立端点）**必须**在开抽屉时回查详情端点；抽屉内空/错/加载态用 `StateBox` |
| 删除后 | 行已不存在 ⇒ 抽屉**一并关闭**（不留空壳） |

**为什么「操作」也进抽屉**：列表行的动作区越堆越长（A3 曾有 4 个动作、C2 曾有 3 个），横向挤压基础列；且「删除」紧贴「上下架」这类高频动作容易误点。抽屉里动作**纵向排列 + 上方就是被操作对象的全字段**，判断成本最低。

## 1.4 交互与状态（全部列表页统一）

| 场景 | 口径 |
|---|---|
| 进入页面 | **依赖数据**（下拉候选等）与**列表**并行加载；依赖失败**不阻塞**列表 |
| 筛选变化 | **立即 `reloadFirstPage()`**（回第 1 页）；输入框额外支持 `Enter` 提交；「查询」按钮做同样的事 |
| 「重置」 | 清空**全部**筛选条件 → `reloadFirstPage()` |
| 保存成功 | `ElMessage.success('已保存')` → 关窗 / 退回查看态 → **`reloadFirstPage()`**（回第 1 页，让改动可见） |
| 保存失败 | 原文透出服务端 `message`（`ElMessage.error`），**窗体不关**、输入保留 |
| **受阻动作（引删 / 超限 / 重名）** | **前端不预判、不禁用** —— 一律提交后由服务端裁决，`400` 的 `message` 原文透出（**单一真源**，避免前后端两套规则） |
| 并发保护 | 提交中主按钮 `:disabled`；**该行（或抽屉当前行）的动作置灰**（防重复点击）。**统一由公共 composable `useRowAction` 承担**（视图内只调一次，同一文件的多个动作共用同一把锁）；模板置灰恒经 `isBusy(row.id)` / `isBusy(current?.id)`，**SHALL NOT** 直接读 `busyId`。固定执行顺序：`置锁 → action() → 成功提示 → refresh() → closeDrawer() → 回填抽屉`，后三步按需声明 |
| **按角色隐显入口** | `viewer` **不显示**写入口（新增 / 编辑 / 处置 / 启停）；**删除入口仅 `super` 可见**。判据收敛在 `@/utils/permissions`（`canWrite()` / `canDelete()`），模板只写 `v-if`，**SHALL NOT** 在页面内自行解析角色。角色缺失 / 未知按只读处理（fail-closed）。**这只是体验** —— 真正的门控在服务端（越权一律 `403`）|

## 1.5 排序交互（**有排序的菜单才用**）

| 项 | 口径 |
|---|---|
| 组件 | **`useReorder`**（[基线 §2.5 #3](./公共组件与形态基线.md)） |
| 手柄 | 主标识列左侧，6 点图标（`12×12`、`--text-muted`）；**仅手柄可拖**（避免误触行内操作） |
| 拖拽中 | 被拖行 `--bg-hover` + `--shadow-pop`；占位行留空 |
| 落下 | 立即**乐观更新**本地顺序 → 调 `PUT .../sort`（整体提交 `[{id, order}]`）→ 失败则**回滚顺序** + `ElMessage.error` |
| SHALL NOT | 用「上移 / 下移」按钮、或在编辑表单里手填 `order` 数字 |
| 适用菜单 | A4 维度 · A4 取值 · A5 Banner · A6 视图 · A7 举报原因 · **A3 分类**（抽屉内） |
| **例外（本页登记）** | **A1 食堂 / A2 档口**的 `sortOrder` **不是**拖拽排序：它们是「排序位」型数值（改序频率极低），作为**普通数值字段**放在详情表单内维护，**SHALL NOT** 为它们单独引入拖拽交互 |

## 1.6 时间展示（**全站唯一格式**）

- 出参契约的时间格式是 `yyyy-MM-dd HH:mm:ss`（[api/README §时间](../../api/README.md)）。
- **端上一律经 `utils/datetime` 的 `formatDateTime(value, placeholder?)` 渲染**，**SHALL NOT** 直接把后端字符串塞进模板：
  - 幂等归一：目标形态原样（截断到秒），ISO 形态（`2026-10-05T12:09:17`）去掉 `T` 与毫秒 / 时区尾巴，其余可解析形态按本地时区补齐；
  - 空值（`null` / 空串）与不可解析 → 回落占位符（默认 `—`，需要留白时传 `''`）。
- 时间列 / 详情抽屉的「创建时间」「更新时间」「处理时间」**全部**走它；`ClampText` / `.ellipsis` 不承担时间格式化职责。

# 二、各菜单差异（**只写差异**，未提及项一律沿用 §一）

## §A1 食堂管理

| 项 | 差异 |
|---|---|
| 筛选区 | **无**（量级十数条，不分页） |
| 分页 | **无**（`GET /admin/canteens` 不分页；排序 = `sortOrder` 升序 → `updatedAt` 降序，**无排序入口**，见 §1.5 例外） |
| 列 | `食堂` ｜ `档口数`（`stallCount`） ｜ `更新时间` ｜ `操作`（`详情`） |
| **详情抽屉（view）** | 图片（`detail-thumbs`，点击开 `ImagePreview` 看大图；无图显示「暂无图片」）、食堂 ID、名称、地点、描述、排序位、档口数、更新时间 |
| 详情抽屉（edit） | 名称（1~64 字，全站唯一）+ 地点（≤128 字）+ 描述（≤512 字）+ 排序位（整数，升序）+ 图片（有序、首图封面、≤5 张） |
| 主按钮 | 「新建食堂」（同上表单，独立打开） |
| 详情内动作 | `编辑` ｜ `删除`（`.link.danger`） ｜ 行内只有 `详情` |
| 删除确认文案 | 「确认删除食堂「{名称}」？其下仍有档口时将无法删除。」 |
| 表格脚注 | 「食堂名称」是快速检索列；其余字段与编辑 / 删除入口都在「详情」内 |

## §A2 档口管理

| 项 | 差异 |
|---|---|
| 筛选区 | **食堂下拉**（`canteenId`，首项「全部食堂」= 不传） |
| 分页 | **无**（不分页；排序 = `canteenId` → 档口名 → `updatedAt` 降序，**无排序入口**） |
| 列 | `档口` ｜ `所属食堂` ｜ `菜品数`（`dishCount`） ｜ `更新时间` ｜ `操作`（`详情`） |

## §A3 菜品管理（含**分类**维护抽屉）

| 项 | 差异 |
|---|---|
| 筛选区 | 菜品名 / 食堂 / 档口 / **分类（A6 种类字典驱动）** / 状态 + 查询 + 重置 |
| 分页 | **有**（`AdminPageResult`，`pageSize` 20，**页码 + 共 N 条**） |
| 列 | `菜品` ｜ `分类`（`mealTypeLabel`） ｜ `现价` ｜ `状态`（`StatusTag kind="dish"`） ｜ `更新时间` ｜ `操作`（`详情`） |
| **详情抽屉（view）** | 配图（`detail-thumbs` + 大图预览，标注「首图为封面」）、菜品 ID、名称、现价、原价、分类（含 `mealTypeId`）、归属「食堂 / 档口」、状态、描述、**描述属性**（按维度名逐行展开，**不含菜品种类**）、评分（含评价数）、创建时间、更新时间 |
| 详情数据来源 | 🔴 **必须回查 `GET /admin/dishes/{id}`**（列表行是瘦身 VO，不回查会让保存把 `description` / `images` / `attributes` 清空） |
| 详情抽屉（edit） | 名称 / 所属档口 / 现价 / 原价 / 分类 / 描述 / 配图（≤5 张、有序、首图封面）/ 动态属性子表单（字典建议 + 自由输入；**系统维度不出现**） |
| 主按钮 | 「新建菜品」 |
| 详情内动作 | `编辑` ｜ `复制`（开 `BaseModal` 只填新菜名） ｜ `下架 / 上架` ｜ `删除`（`.link.danger`） ｜ 行内只有 `详情` |
| 删除确认文案 | 「确认删除菜品「{名称}」？其全部评价将一并删除且不可恢复。」 |
| **页头次级动作** | **「管理分类」**（`.btn-secondary`）→ **分类抽屉**（见下） |

**分类抽屉**（**菜品种类字典** —— 系统维度取值的别名面维护入口，**不单设菜单项**；契约见 [api/web/categories.md](../../api/web/categories.md)）：

| 项 | 口径 |
|---|---|
| 区域 | 顶部一行「分类名 + 登记」；下方 `.table--compact` 紧凑表格 |
| 列 | `⠿` 手柄 ｜ `分类名` ｜ `引用菜品`（`dishCount`） ｜ `更新时间` ｜ `操作`（`改名`） |
| 编辑 | **行内改名**（输入框 + 保存 / 取消）—— 只改 `label`，改名免费 |
| 排序 | **拖拽**（`useReorder` → `PUT /admin/dish-categories/sort`，整体提交全量行） |
| 无删除 | **不提供删除入口**：种类是 `dish.meal_type_id` 的锚点，下线一律「改名 + 把菜品改到别的种类」（见 [api/web/categories.md](../../api/web/categories.md)） |
| 表格脚注 | 「菜品种类是系统维度取值：改名免费（菜品存的是取值 ID）；拖拽排序整体提交全量行。」 |

## §A4 属性维度与取值

| 项 | 差异 |
|---|---|
| 筛选区 / 分页 | **无**（维度量级极小） |
| **排序** | **有**（维度拖拽，`order` 升序，见 §1.5） |
| 列 | `⠿` ｜ `维度`（`name`） ｜ `取值类型` ｜ `取值数` ｜ `关联菜品` ｜ `更新时间` ｜ `操作`（`详情`） |
| **详情抽屉（view）** | 维度 ID（= 菜品 `attributes` 的键）、维度名、取值类型、顺序位、取值数、关联菜品（被引用时不可删维度）、更新时间 |
| 详情抽屉（edit） | 维度名称 + 取值类型（切换会**自动迁移**该维度下菜品的数据形状）；**系统维度**（价格标签「系统」）：取值类型置灰不可改 |
| **系统维度行** | 名称旁显示「系统」标签（`--font-xs --text-muted`）；详情内「取值类型」「删除」置灰并注明「系统维度：取值被菜品种类引用，不可改类型、不可删」 |
| **详情抽屉（values）** | **取值管理态**（第三个态，不新开浮层）：顶部「新增取值」一行 + `.table--compact`（`⠿` ｜ `取值` ｜ `引用菜品` ｜ `更新时间` ｜ `操作`）；行内改名、删除、**拖拽排序**（提交该维度下全量取值）；底部动作 = `返回维度详情` |
| 主按钮 | 「新建维度」 |
| 详情内动作（view） | `管理取值` ｜ `编辑` ｜ `删除`（`.link.danger`） ｜ 行内只有 `详情` |
| 删除确认文案 | 「确认删除维度「{名称}」？其下 {N} 个取值、{M} 个菜品正在使用；被引用时将无法删除。」 |

## §C2 用户管理

| 项 | 差异 |
|---|---|
| **主按钮** | **无**（用户不可新建） |
| 筛选区 | **状态下拉**（`active` / `disabled` / `deleted`，首项「全部状态」）+ **关键词输入**（placeholder 字面 = `昵称 / 账号 / 邮箱`，与后端「昵称 / 账号 / 绑定邮箱」模糊匹配逐词对应；**不加「支持…」前缀**，`180px` 内会被截断） |
| 分页 | **有**（`AdminPageResult`，`pageSize` 20，**页码 + 共 N 条**） |
| 列 | **`用户`**（表头二字；**单元格内容** = 头像 + 昵称合并一格）｜ `账号`（`username`）｜ `认证`｜ `状态`｜ `注册时间`｜ `更新时间`｜ `操作` |
| 「认证」列 | `bindEmail` 非空 → 显示该邮箱（`--font-sm`）；空 → 「未认证」（`--text-muted`）。**不单独出认证字段**（派生口径与小程序端一致） |
| **保留的行级动作** | `禁用` / `启用`（高频、可逆、无表单）+ `详情`；**提交中该行动作置灰**（§1.4） |
| **详情抽屉（view，只读）** | 身份（头像 + 昵称）、用户 ID、账号、状态、微信绑定（**只给布尔**，不回显 `openid`）、认证邮箱、注册时间、更新时间 |
| 详情内动作 | `禁用 / 启用` ｜ `解绑邮箱`（**仅已认证行**） ｜ `删除账号`（`.link.danger`，恒最后） |
| 行内快速动作 | `启用 / 禁用`（`PUT /{id}/status`）—— 高频且可逆，故**留在行内**；`viewer` 隐藏（§1.4 角色隐显）|
| 抽屉脚注 | 「管理端不代改资料（昵称 / 头像由用户本人维护）；可在此禁用 / 启用、踢下线、解绑认证邮箱或注销账号。」 |
| `deleted` 行 | 状态标签「已注销」；**无任何处置动作**（终态）—— 行内只留 `详情`，详情内无动作按钮 |
| 禁用确认 | 「禁用后：该用户无法再登录，已登录的会话立即失效（写操作被拒）；已发表内容保留，可随时启用恢复。确认禁用「{昵称}」？」—— 只写**已核对的四项事实**（拒新登录 / 已签发 token 即时失效 / 写操作被拒 / **已发表内容保留且照旧公开可见**），**不承诺**站内提醒 |
| 启用 | **直接执行（无二次确认）**：`PUT /admin/users/{id}/status { status: 'active' }` → 成功提示「**已启用**」→ `reload()`（留在当前页）。理由：恢复类操作、风险低且可逆 |
| 解绑确认 | 「解绑后：该用户立即回落为未认证状态，无法发表评价与反馈，需重新邮箱认证恢复；登录与已发表内容不受影响。确认解绑「{昵称}」的认证邮箱 {bindEmail}？」；确认按钮「**解绑**」→ 成功提示「**已解绑**」→ `reload()` |
| 删除确认 | 「注销后：账号立即失效且不可恢复——无法再登录，微信与邮箱解绑，昵称显示为「已注销用户」；已发表内容保留且照旧公开可见。确认注销「{昵称}」？」—— **不可逆终态**；确认按钮「**注销**」→ 成功提示「**已注销**」→ `reload()` |

## §C3 安全告警

| 项 | 差异 |
|---|---|
| **定位** | **只读回看页**：本页**无任何写入口**（告警记录只追加 —— 能改告警的人就能抹掉自己的痕迹），`viewer` 角色同样可查看 |

| 空态文案 | 「暂无告警记录」 |
| 覆盖范围 | 告警的类型与级别口径见 [`secur/web/审计与告警.md`](../../secur/web/审计与告警.md)；端点与出参见 [api/web/alerts.md](../../api/web/alerts.md) |
