# UI 设计稿总览（管理后台 Web）

> 本目录是「**管理后台视觉与交互**」的唯一真源：跨页基线 + 设计变量 + 各页面设计稿。
> **与功能文档解耦**：[`docs/func/web/`](../../func/web/README.md)（接口 / 字段 / 数据 / 处置口径）写「**为什么这么算**」；本目录写「**长什么样、怎么交互**」。两套体系**各按自身标准分层**，分类与粒度均不强制 1:1。
> **只写当前口径**：逐轮变更过程与修订轮次**不维护**（回溯请查 git 历史）。
> **命名**：本目录文件**一律不带端 / 层前缀**（目录已表明是"管理后台的 UI"），文件名**直接取菜单名**并力求一眼看懂（见 §三 规范 7）。

## 一、页面归属与防冲突（**本目录最重要的规则**）

### 1.1 三条硬规则

1. **一屏一篇、唯一归属**：每个**菜单页（界面单元）恰好归属一篇**（见 §1.2 归属表）；**同一屏不得在两篇里各写一半**。
2. **跨页规格只写在基线**：可复用形态（表格 / 表单 / 抽屉 / 对话框 / 按钮 / 状态标签 / 三态盒 / 拖拽排序 / 条件行…）**只在 [公共组件与形态基线.md](./公共组件与形态基线.md) 定义一次**；页面稿只写「**本页怎么用**」（传什么、放哪、点了做什么），**SHALL NOT 复述尺寸 / 颜色 / 圆角 / 状态样式**。
3. **同构菜单收在一篇内分节**：「[列表页模板.md](./列表页模板.md)」既是**形态模板**（通用列表骨架），**也是 A1 / A2 / A5 / A7 / C2 / C3 六个同构菜单的归属文档** —— 其结构固定为「**§通用骨架**（引用基线）→ **§各菜单差异**（一菜单一节，只写差异：列、筛选、专属动作）」。**禁止**给这几个菜单各开一篇（会造成同一规则写多遍、改一处漏多处）。

## 三、编写规范（本目录统一遵守）

0. **只写目标态（本目录的立足点）**：现有 `web/` 将**整体重构** —— 本目录**不参照、不描述**现有实现，一切依据 [`docs/func/web/`](../../func/web/README.md) 的功能文档 + [设计变量.md](./设计变量.md) + [公共组件与形态基线.md](./公共组件与形态基线.md)。**不写「与当前代码的差异」**。
1. **元信息头**：每篇首行写「所属端 + 页面 / 单元（+ 目标路由，可选）」，随后**紧跟 §1.4 的「覆盖 / 不覆盖」两行**。
2. **不复述真源**：组件视觉规格一律**引用**基线；token 取值一律**引用**设计变量。页面稿只写**本页用法**。
3. **节序**：覆盖 / 不覆盖 → 页面构成 → 视觉规格（引用）→ 交互与状态 → 组件清单 → 数据字段。
4. **参数必须可执行**：涉及尺寸 / 色值一律写 **token 名**（`--space-4`）或 **token 值**（`16px`）；**禁止**「适当」「略大」这类不可执行描述。
5. **引用必须可解析**：不得指向不存在的文档。
6. **一屏一篇**：新增菜单页时，先在本文件 §1.2 登记归属，再决定「开新篇」还是「并入既有篇的差异节」；**能并入就不新开**。
7. **命名（不带上下文前缀、一眼看懂）**：
   - **不加端 / 层前缀** —— 目录已表明是「管理后台 UI」，`web-` / `ui-` 之类前缀一律不写；
   - **一篇一菜单 → 直接用菜单名**：`运营看板.md`、`菜品管理.md`、`评价管理.md`、`菜品问题反馈.md`、`首页筛选视图.md`；
   - **一篇多菜单（同构合并）→ 菜单名并列或概括**：`反馈与举报.md`（B2 + B3）、`列表页模板.md`（5 个同构菜单）；
   - **跨页真源 → 「XX + 基线 / 变量」**：`公共组件与形态基线.md`、`设计变量.md`（与 [`docs/ui/client/`](../client/README.md) 同名同构）；
   - **能望文知义**：名字要能让人猜到"里面是什么"（如 `属性维度与取值.md` 明示含「取值」），**禁止**缩写、代号、`misc` / `part2` 一类。
