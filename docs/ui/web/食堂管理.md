# 食堂管理

> 所属端：**运营端**
> 返回：[UI 总览](INDEX.md) ｜ 归属功能：[A1](../../func/web/A-主数据维护/A1-食堂管理.md) ｜ 接口：[api/web/canteens.md](../../api/web/canteens.md)

## 1 · 页面结构

| 区块 | 内容 |
|---|---|
| 顶栏 | 标题「食堂管理」+ 右侧主操作「新建」 |
| 筛选区 | **无** —— 食堂数量少，直接分页全量 |
| 列表卡片 | 名称（主行）｜ 档口数（指标行，只读）｜ 状态 tag（正常 / 已停用）—— 卡面无操作按钮（点击卡片进编辑，删除在编辑界面内） |
| 分页 | 共 N 条 + 上一页 / 页码 / 下一页 + **跳页**（见[基线](./公共组件与形态基线.md) §2.3） |

> 卡片**不展示 `id`**（也不展示更新时间）—— 运营不需要它。

## 2 · 交互

| 动作 | 口径 |
|---|---|
| 新建 / 编辑 | **居中弹窗**（见[基线](./公共组件与形态基线.md) §2.3）：「名称」（必填）·「状态」（正常 / 已停用，默认正常） |
| 保存 | `POST` / `PUT`；成功 `ElMessage.success('已保存')` ⇒ 关弹窗 + 刷新列表 |
| 保存失败 | 同名 ⇒ **直接展示服务端 `message`**（🔴 不在前端判重） |
| **删除** | 入口在**编辑界面内**（`.btn--danger`）—— `ElMessageBox.confirm` 文案：「删除后不可恢复。**若该食堂下仍有档口，删除会被拒绝。**」 |
| 删除成功 | `ElMessage.success('已删除')` ⇒ 刷新列表（末页删空则回退一页） |
| 删除被拒 | 展示服务端 `message`（如「该食堂下仍有档口」） |

## 3 · 视觉规格

| 项 | 取值 |
|---|---|
| 档口数 | **只读统计**，指标行弱化展示（`.list-card__stats`） |
| 操作 | 卡面无操作按钮 —— **点击卡片**（或键盘聚焦 + `Enter` / `空格`）**直接进入编辑界面**（见[基线](./公共组件与形态基线.md) §2.3）；删除在编辑界面内，另走二次确认 |
| 顺序 | 服务端按 `id` 升序（无客户端排序，见[基线](./公共组件与形态基线.md) §1.6） |
