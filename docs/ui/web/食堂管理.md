# 食堂管理

> 所属端：**运营端**
> 归属功能：[A1](../../func/web/A-主数据维护/A1-食堂管理.md) ｜ 接口：[api/web/canteens.md](../../api/web/canteens.md)

## 1 · 页面结构

| 区块 | 内容 |
|---|---|
| 页头 | 标题「食堂管理」+ 右侧主操作「新建」；吸顶于内容区上界 |
| 筛选区 | **无** —— 食堂数量少，直接分页全量 |
| 列表卡片 | 16:9 封面（无图同形占位）｜ 标题行（名称 + 状态 tag：正常 / 已停用）｜ 单行元信息（档口数）—— 卡面无操作按钮（点击卡片进编辑，删除在编辑界面内） |
| 分页 | 共 N 条 + 上一页 / 页码 / 下一页 + **跳页**（`PaginationBar`） |

> 卡片只呈现名称、状态与档口数；编号、更新时间与日期类信息不进入卡面。

## 2 · 交互

| 动作 | 口径 |
|---|---|
| 新建 / 编辑 | **宽版弹窗**（`.dialog--wide`）：「名称」·「状态」（正常 / 已停用，默认正常）·「食堂图片」（16:9，选图仅本地预览、保存时上传）；字段走 `.edit-grid` 两列栅格，名称与状态同行、图片跨列 |
| 保存 | `POST` / `PUT`；成功 `ElMessage.success('已保存')` ⇒ 关弹窗 + 刷新列表 |
| 保存失败 | 同名 ⇒ **直接展示服务端 `message`**（🔴 不在前端判重） |
| **删除** | 入口在**编辑界面内**（`.btn--danger`）⇒ **整卡内容切换**为「确认删除」视图（取消回到表单）；文案：「删除后不可恢复。**若该食堂下仍有档口，删除会被拒绝。**」 |
| 删除成功 | `ElMessage.success('已删除')` ⇒ 刷新列表（末页删空则回退一页） |
| 删除被拒 | 展示服务端 `message`（如「该食堂下仍有档口」） |

## 3 · 视觉规格

| 项 | 取值 |
|---|---|
| 卡片结构 | `ListCard` 两层结构（卡片本体 → 内容区）：标题与状态同行，元信息单行弱化；视觉层级靠字号与文字色，页面容器不套第二层卡片 |
| 元信息 | 档口数为**只读统计**，单行弱化展示 |
| 操作 | 卡面无操作按钮 —— **点击卡片**（或键盘聚焦 + `Enter` / `空格`）**直接进入编辑界面**；删除为弹窗内整卡切换确认 |
| 编辑弹窗 | 与菜品编辑同构：宽版卡片 + `.edit-grid` 两列字段栅格；桌面居中 / 窄屏贴底，标题与操作区常驻、字段区在 `.dialog__body` 内单独滚动（操作区不遮挡字段与上传按钮）；≤`767px` 收为单列；输入与按钮触控目标 ≥44px、间距 ≥8px |
| 顺序 | 服务端按 `id` 升序（无客户端排序） |
