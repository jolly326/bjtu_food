# 菜品管理

> 所属端：**管理后台（Web）** ｜ 页面 / 单元：**菜品管理**（列表 + 详情抽屉两态 + 分类抽屉）｜ 目标路由：`/dishes`
> **覆盖**：A3 菜品管理（`dish` 的列表 / 新增 / 编辑 / 复制 / 上下架 / 删除）＋ **菜品种类字典**（系统维度取值）的维护入口。
> **不覆盖**：列表通用骨架（六态 / 分页 / 基础列 / 详情抽屉 / 交互口径）→ [列表页模板.md](./列表页模板.md) §一 与 §A3；组件规格 → [公共组件与形态基线.md](./公共组件与形态基线.md)；字段 / 校验 / 端点 → [A3 功能文档](../../func/web/A-主数据维护/A3-菜品管理.md)（种类字典见 [api/web/categories.md](../../api/web/categories.md)）；描述属性取值字典见 [A4](./属性维度与取值.md)。

| # | 区域 | 差异要点 |
|---|---|---|
| 1 | **页头** | `h2`「菜品管理」+ **次级按钮**「管理分类」（打开分类抽屉）+ 主按钮「新建菜品」 |
| 2 | **筛选区** | 5 个控件：**关键词**（菜名 / 档口名 / 食堂名）、**食堂**▾、**档口**▾（**按已选食堂联动过滤**；未选食堂时列全部）、**分类**▾（候选 = 菜品种类字典）、**状态**▾（全部 / 在售 / 下架）；末尾「查询」+「重置」 |
| 3 | **列（基础列）** | `菜品`（`name`）→ `分类`（`mealTypeLabel`，中文名）→ `现价` → `状态`（`StatusTag` `kind="dish"`，在售 / 已下架）→ `更新时间`（`formatDateTime`）→ `操作`（`详情`） |
| 4 | **详情内动作（4 个）** | `编辑` ｜ `复制` ｜ `上架` / `下架`（文案随状态切换）｜ `删除`（`.link.danger`，恒最后）；**行内只有 `详情`** |
| 5 | **详情 / 编辑载体** | **抽屉**（`BaseDrawer`，常规 640）—— 同一抽屉 `view` / `edit` 两态（字段 8 组，超弹窗容量） |
| 6 | **复制载体** | **弹窗**（`BaseModal`，单字段），从详情内打开 |

## 二、详情抽屉字段（A3）

**`view` 态（只读全字段，来源 = `GET /admin/dishes/{id}`）**

| 项 | 说明 |
|---|---|
| 配图 | `140px` 缩略图（有序，**首图即封面**），**点击开 `ImagePreview` 大图**；无图显示「暂无配图」 |
| 基础 | 菜品 ID / 名称 / 现价 / 原价（`null` = 「—（无折扣）」）/ 分类（中文名 + `mealTypeId`）/ 归属「食堂 / 档口」（+ `stallId`）/ 状态 |
| 描述 | 全文（不截断） |
| 描述属性 | 按**描述维度**中文名**逐行**展开（键 = 维度 ID，服务端已把值翻译成中文）；未设置显示「未设置」；**系统维度（菜品种类）不在此列**（它由「分类」行承载） |
| 评分 | `avgRating`（零评价 `—`）+ 「（{ratingCount} 条评价）」 |
| 时间 | 创建时间 / 更新时间 |

> 🔴 **必须回查详情端点**：列表行是瘦身 VO（不含 `description` / `images` / `attributes`），而 `PUT` 是整体替换 —— 不回查会让保存把这些字段当成「未传 / 空」而清空。

**`edit` 态（A3 表单）**

| 区块 | 字段 | 控件与规格 |
|---|---|---|
| 基本 | **名称** | 输入框（1~64 字），必填 |
| | **所属档口** | 下拉，选项按**食堂分组**（`食堂 · 档口`），必填；候选来自 [A2](../../func/web/A-主数据维护/A2-档口管理.md)，**不提供自由输入** |
| | **现价 / 原价** | 价格控件：以**元**输入（`step=0.01`，两位小数）；提交前换算为**分**；并排两列（`原价` 可空；校验 `原价 > 现价`，否则字段级报错） |
| | **分类** | 下拉（候选 = 菜品种类字典，值 = 种类取值 ID）；新分类在「分类」抽屉登记（口径见 [A6](./首页筛选视图.md) 值管理）；必填 |
| | **描述** | `textarea`（≤512 字），可空；右下角字数计数（`--font-xs --text-muted`） |
| 媒体 | **图片** | `ImageUpload`（`:max="5"`、有序、首图作封面；非首图提供「设为封面」= 移到首位）；`ratioHint`「建议 4:3，首图作封面」；0 张合法 |
| 属性 | **描述属性** | 按 [A4](./属性维度与取值.md) 的**描述维度**定义**动态渲染**：`single` → 下拉（可输入新值）；`multi` → 多选（可输入新值）；**每维一行**，标签 = 维度中文名，顺序 = 维度 `order`；**留空 = 该菜没有这个属性**（不写该键）；**系统维度（菜品种类）不出现在本区块** |
| 底部 | 动作区 | `.modal-actions` 语义（吸底）：`取消`（`.btn-secondary`）+ `保存`（`.btn-primary`，提交中 `:disabled`） |

**属性区块的空态**：可渲染的（非系统）维度为空时，整块**不渲染**（不显示空标题）。

## 三、分类抽屉（**菜品种类字典** —— 系统维度取值的维护入口）

> 菜品分类是**引用的字典**（`dish.meal_type_id` 存取值 `id`），故入口挂在菜品页而**不单设菜单项**（[基线 §1.1 导航口径](./公共组件与形态基线.md)）。契约见 [api/web/categories.md](../../api/web/categories.md)。

| 项 | 规格 |
|---|---|
| 打开 | 页头「管理分类」（`.btn-secondary`）→ 抽屉打开并拉取种类取值列表 |
| 新增行 | `分类名`（1~32 字，必填）+ 「登记」（ID 由后端生成、顺序由拖拽维护） |
| 列 | `⠿` ｜ `分类名` ｜ `引用菜品`（`dishCount`） ｜ `更新时间` ｜ `操作`（`改名`） |
| 改名 | **行内编辑**：点「改名」→ 该行变输入框 + `保存` / `取消`；`Enter` 保存、`ESC` 取消；**改名免费**（菜品存的是取值 `id`，零迁移） |
| 排序 | **拖拽**（`useReorder` → `PUT /admin/dish-categories/sort`，整体提交全量行） |
| **无删除入口** | 分类是 `dish.meal_type_id` 的锚点；下线一律「改名 + 把菜品改到别的分类」（[api/web/categories.md](../../api/web/categories.md)） |
| 表格脚注 | 「菜品种类是系统维度取值：改名免费（菜品存的是取值 ID）；拖拽排序整体提交全量行。」 |
| 保存后 | 分类列表、筛选 / 表单的分类下拉**同源刷新**（同一份 `categories` 状态） |

## 五、交互与状态

| 场景 | 口径 |
|---|---|
| **保存成功** | `ElMessage.success('已保存')` → `reload()` → **退回 `view` 态并重新取详情回填**（不留旧快照） |
| **保存失败** | `ElMessage.error(message)` 原文透出；**抽屉不关、输入保留** |
| **上下架** | 详情内文字动作 → 成功后 `reload()` + 重取详情；失败原文透出 |
| **复制** | 从详情内打开弹窗，只填**新名称** → 成功提示「已复制（副本默认下架，确认内容后再上架）」→ 关抽屉 → `reload()`；其余字段整体复制（含图片 / 属性 / 分类 / 价格） |
| **删除** | `ElMessageBox.confirm` 文案：**「确认删除菜品「{名称}」？将一并删除该菜品的至少 {ratingCount} 条评价，且不可恢复。」** —— 影响面必须给出（取详情出参 `ratingCount`）；确认后删除 → 关抽屉 → `reload()` |
| **分类下拉的新值** | 种类取值只在「管理分类」抽屉内登记（本页**不在分类控件里自由输入**）；登记后筛选 / 表单下拉即时可选 |
| 属性新值 | **描述属性**支持**自由输入**：随保存一并登记为取值；取消 / 保存失败不留痕 |
| 详情回填 | 打开详情即调 `GET /admin/dishes/{id}`（列表 VO 瘦身，**不含**描述 / 图片全量 / 属性）；抽屉内先显 `StateBox` 加载态，失败给错误态与重试 |
| 新建 | 页头「新建菜品」→ 抽屉直接进 `edit` 态；点「取消」即关抽屉（无历史行） |

## 七、数据字段

- 列表行 `DishAdminListItemVO`、详情 `DishAdminVO`、`DishSaveReq` / `DishCopyReq` / `DishStatusReq` 与错误码：见 [api/web/dishes.md](../../api/web/dishes.md)。
- **金额**：出参 `price` / `originalPrice` 为**分**；端上展示 `¥12.00`（`元 = 分 / 100`，两位小数）。
- **图片**：出参 `images` 为**绝对 URL 数组（有序）**；列表的 `coverImage` 取首图。
- **分类**：出参 `mealTypeId` + `mealTypeLabel`（中文名），列表与详情都直接可读（**端上零翻译**）；值域 = **菜品种类字典**（系统维度取值）。
- **属性**：详情出参 `attributes` 的**值已是中文**（服务端按取值 ID 翻译）、键 = **描述维度** ID；入参键 = 描述维度 ID、值提交**取值 ID 或中文**（系统维度键 → `400`）。
