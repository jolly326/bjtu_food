# 反馈与举报

> 所属端：**管理后台（Web）** ｜ 页面 / 单元：**意见反馈**（`/feedbacks`）与**举报管理**（`/reports`）—— **两个独立菜单、两个独立资源**（各自成表、各自成端点、各自成页）
> **覆盖**：**B2 意见反馈管理** 与 **B3 举报管理** 的全部界面（列表 + 处置 / 详情抽屉）。
> **不覆盖**：列表通用骨架（基础列 / 详情抽屉 / 六态 / 分页 / 交互与状态）→ [列表页模板.md](./列表页模板.md) §一 与 §B2 / §B3；组件规格 → [公共组件与形态基线.md](./公共组件与形态基线.md)；字段 / 端点 / 回执文案 → [B2 功能文档](../../func/web/B-UGC治理/B2-意见反馈管理.md) / [B3 功能文档](../../func/web/B-UGC治理/B3-举报管理.md)（契约唯一真源 [api/web/feedback.md](../../api/web/feedback.md) / [api/web/reports.md](../../api/web/reports.md)）；对评价的**隐藏后恢复**在 [评价管理.md](./评价管理.md)。

## 一、两页的共同部分（**同构骨架**）

| 项 | 口径 |
|---|---|
| 骨架 | 完全沿用 [列表页模板.md](./列表页模板.md) §一（页头 / 筛选区 / 六态 / 分页 / 基础列 / 详情抽屉） |
| 页头 | `h2`（「意见反馈管理」/「举报管理」）；**无主按钮**（两页都不产生数据） |
| 筛选区 | ① **状态**▾（全部状态 / 待处理 / 已处理）② 页面私有筛选（见 §B2 / §B3）③ 「查询」+「重置」④ **已生效筛选回显**（`ActiveFilters` 胶囊：状态 / 类型 / 提交人 / 关键词逐枚展示，可单个清除，末位「清空全部」） |
| 列表列（**基础列**） | 提交人 / 举报人 → **页面私有列**（见 §B2 / §B3）→ `状态`（`StatusTag kind="feedback"`）→ `提交时间`（`formatDateTime`）→ `操作` |
| 状态列 | **恒用 `StatusTag`**：`feedback`（`pending` → `待处理` 中性灰 ／ `handled` → `已处理` 绿）。**不引入红色标「待处理」**（待处理不是错误）；**页面不自写 `.tag-*`** |
| 行操作 | `待处理` 行 → `处理`（B3：`处置`）｜ `已处理` 行 → `详情`（只读回显）—— 同一个抽屉，态由**行状态**决定；`viewer` 角色不显示写入口（[列表页模板 §1.4](./列表页模板.md)） |
| 分页 | `AdminPageResult`，`pageSize` 20，**页码 + 共 N 条** |
| 六态 | `ListState` 编排（加载 / 错误 / 空 / 有数据 / 分页 / 会话失效）；空态文案「暂无反馈」/「暂无举报」 |
| **进详情的内容** | 正文全文 / 被举报评价原文、配图、处置结论 / 回执标题 / 处置文案 / 处置人 / 处置时间 —— 表格**只留能定位的检索列**（[列表页模板 §1.2](./列表页模板.md)） |
| 处置状态口径 | `status` **以处置任务表为判据**（`pending` / `handled`）；「未处置」是显式 `pending` 行 |

## 二、处置抽屉（两页共用结构：只读内容区 + **三输入**处置表单）

**载体**：`BaseDrawer`（常规 640 —— 含**只读内容区块** ⇒ 按 [基线 §1.10](./公共组件与形态基线.md) 判据走抽屉）；同一抽屉按行状态两态；处置表单本体 = 公共 **`ModerationHandleForm`**（两页共用同一组件，仅选项文案与「回执接收方称谓」不同）。

```
┌ 抽屉头：处理反馈 / 反馈详情（B3：处置举报 / 举报详情）───────────────┐
│ ① 只读内容区块 .ctx                                            │
│    B2：类型 · 提交人 · 状态标签 + 正文全文 + 配图（56px，点击开大图）│
│    B3：被举报评价（菜品名 + #reviewId + 正文全文 + 可见性标签）     │
│        ＋ 举报原因（.readonly 只读行）                            │
│ ② 处置表单（仅 pending，ModerationHandleForm 三输入）            │
│    处理结论   ● 通过 / 已处理   ○ 不采纳 / 退回（B3：受理 / 不予处理）│
│    [B3 专有] ☑ 同时隐藏被举报评价（仅「受理」分支出现）             │
│    回执标题   [input ≤40 字，可选]                               │
│    处置文案   [textarea ≤600 字；结论 = 不采纳时标签变「必填」]     │
│    hint：n / 600                                                │
│                                        [ 取消 ] [ 提交处置 ]     │
│ ②' 已处理 → 只读详情（两组 .detail-group）                       │
│    处理结果：处理结论 / 提交人 / 处置人 / 回执标题 / 处置文案        │
│    时间与标识：反馈 ID（举报 ID）/ 提交时间 / 处置时间   [ 关闭 ]   │
└──────────────────────────────────────────────────────────────┘
```

### 处置表单三输入（`ModerationHandleForm`，规格唯一落点）

| 输入 | 口径 |
|---|---|
| **处理结论 `outcome`** | 单选（两枚 `.tag-option` 按钮，`role="radiogroup"` + `aria-checked`）：**打开抽屉默认选中第一枚（handled）**。B2 = 「通过 / 已处理」（绿语义）与「不采纳 / 退回」（黄语义）；B3 = 「受理」与「不予处理」 |
| **回执标题 `replyTitle`** | 可选，`input` `maxlength=40`，标签「回执标题（可选，≤40 字）」；留空按（类型 + 结论）用缺省文案 |
| **处置文案 `replyContent`** | `textarea` `maxlength=600`（4 行）；**标签随结论切换**：handled → 「处置文案（可选，≤600 字）」；rejected → 「不采纳原因（必填，≤600 字）」；placeholder「将随站内回执下发给{提交人 / 举报人}；留空则回执用缺省文案」；下方计数 hint「n / 600」 |
| **`hideReview` 复选（仅 B3）** | 结论 = **受理** 分支才出现（不予处理时整块消失）；默认**勾选**；被举报评价已隐藏（`reviewHidden=true`）⇒ **置灰锁定 + 恒为勾选**，文案尾缀「（该评价已隐藏）」，未隐藏尾缀「（默认勾选）」；**不予处理不下发该参数** |

| 项 | 口径 |
|---|---|
| 提交前置校验 | 结论 = 不采纳 / 不予处理 且 `replyContent` 纯空白 ⇒ `ElMessage.warning`（B2「不采纳时必须填写不采纳原因」/ B3「不予处理时必须填写不采纳原因」），**抽屉不关** |
| 提交成功 | `ElMessage.success`（B2「已处理」/ B3「已处置」）→ 关抽屉 → `reload()` |
| 已处置再处理 | 服务端 `400`「该记录已处理」原文透出，抽屉不关 |
| **已处理（只读回显）** | 两组 `.detail-group`：**处理结果**（处理结论：`通过 / 不采纳`、`受理 / 不予处理`；提交人 / 举报人含 `#userId`；**处置人** `handledByName`，无值「—」；**回执标题** `replyTitle`，无值「—」；**处置文案** `replyContent` 占满整行，空「—」）＋ **时间与标识**（反馈 ID / 举报 ID `#num`、提交时间、**处置时间** `handledAt`）；底部只有 `关闭` |

## §B2 意见反馈（`/feedbacks`）

反馈是**独立资源**（[api/web/feedback.md](../../api/web/feedback.md)）：列表**只有反馈一种**，**无板块分流参数**。

| 项 | 口径 |
|---|---|
| **筛选区** | 状态▾ ＋ **类型**▾（首项「全部类型」；候选 = **反馈类型字典** `GET /admin/feedback-options`，**含已停用** —— 停用类型的历史反馈仍需能筛能译）＋ **提交人 ID**（数字输入，placeholder「提交人 ID」）＋ **关键词**（placeholder「正文 / 处置文案」，对反馈正文或处置文案模糊匹配）＋ 查询 / 重置 |
| **页面私有列** | `类型`（`optionName`，由反馈类型字典**实时翻译**，停用类型仍可译出）—— 行内有配图时附**配图角标 `.img-flag`**（图片图标 + 张数，审核高频判据） |
| **抽屉只读内容区块** | `类型 · 提交人` + 状态标签 → 正文全文（**不截断**；空显「（无内容）」）→ 配图（56px 缩略图，**点击开 `ImagePreview` 大图**） |
| 抽屉标题 | 「处理反馈」（待处理）/「反馈详情」（已处理） |
| 结论文案 | 「通过 / 已处理」/「不采纳 / 退回」 |
| 空态 | 「暂无反馈」 |

## §B3 举报管理（`/reports`）

举报是**独立资源**（[api/web/reports.md](../../api/web/reports.md)）：举报**无正文、无补充说明、无配图**——结论以**结构化原因单选**为准；列表**内嵌被举报评价**。

| 项 | 口径 |
|---|---|
| **筛选区** | 状态▾ ＋ **举报人 ID**（数字输入，placeholder「举报人 ID」）＋ 查询 / 重置（**无类型筛选、无关键词**） |
| **页面私有列 ①** | `举报原因`（`optionName`，由举报原因字典**实时翻译**，停用原因仍可译出） |
| **页面私有列 ②：被举报评价** | `reviewDeleted = true` → **整格只显「被举报评价已删除」置灰占位**（摘要与可见性均为空，不伪造内容）；否则 → **摘要单行截断**（`.review-summary`，`max-width: 280px` + 省略，完整内容进抽屉）＋ 次级行：菜品名 + `#reviewId` + **可见性 `StatusTag kind="review"`**（显示中 / 已隐藏 —— 一眼看出是否已处置过、避免重复处理） |
| **抽屉只读内容区块** | **被举报评价**（`.ctx-label` = 「被举报评价 · 菜品名 + `#reviewId`」；正文全文不截断；已删除 → 正文区显「被举报评价已删除」占位、**不渲染可见性标签**；未删除 → `.ctx-meta` 内显可见性 `StatusTag kind="review"`）＋ **举报原因**（`.readonly` 只读行，`optionName`） |
| **处置抽屉增量** | 三输入之外多一枚 **「同时隐藏被举报评价」复选**（见 §二 `hideReview` 行：仅受理分支、默认勾选、已隐藏置灰锁定）；**受理 + 本次确实隐藏了评价**时回执正文会写明「已隐藏该评价」（服务端组装，UI 不拼） |
| 抽屉标题 | 「处置举报」（待处理）/「举报详情」（已处理） |
| 结论文案 | 「受理」/「不予处理」 |
| 表格脚注 | 「举报原因 / 被举报评价 / 举报人 / 状态」是快速查阅列；评价原文与处置入口都在行内「处置 / 详情」内。 |
| 空态 | 「暂无举报」 |

## 三、组件清单（**本页用法**）

| 组件 | 本页用法 | 规格 |
|---|---|---|
| `ListState` | 列表六态编排（加载 / 错误 / 空 / 有数据 / 分页 / 会话失效） | [列表页模板 §1.4](./列表页模板.md) |
| `ActiveFilters` | 已生效筛选回显胶囊（单个清除 + 全清） | [基线「ActiveFilters」节](./公共组件与形态基线.md) |
| `StatusTag` | 状态列（`kind="feedback"`）；B3 另用 `kind="review"` 表达被举报评价可见性 | [基线 §2.3](./公共组件与形态基线.md) |
| `BaseDrawer` | 处置 / 只读详情（**同一抽屉两态**） | [基线 §1.10 / §1.15](./公共组件与形态基线.md) |
| `ModerationHandleForm` | 处置表单三输入（两页共用；B3 传 `show-hide-review` / `hide-locked`） | 本文件 §二 |
| `ImagePreview` | B2 配图大图入口（只读配图，**可点开**） | [基线 §1.15](./公共组件与形态基线.md) |
| `DetailMetaRow` | 已处理详情的「处理结果 / 时间与标识」两组元信息 | [基线 §1.15](./公共组件与形态基线.md) |
| 只读内容区块 | 公共类 `.ctx` / `.ctx-label` / `.ctx-body` / `.readonly` | [基线 §1.15](./公共组件与形态基线.md) |

> 两页**不使用**：`ImageUpload`（无上传）、`useReorder`（无可排序位）、`BaseModal`（处置与详情都在抽屉内完成）。

## 四、数据字段

- `FeedbackAdminVO` / `ReportAdminVO`、`ModerationHandleReq`（`outcome` / `replyTitle` / `replyContent` / `hideReview`）与错误码：契约唯一真源见 [api/web/feedback.md](../../api/web/feedback.md) / [api/web/reports.md](../../api/web/reports.md)；功能口径见 [B2](../../func/web/B-UGC治理/B2-意见反馈管理.md) / [B3](../../func/web/B-UGC治理/B3-举报管理.md)。
- **`outcome` 是处置任务的物理列**（`handled` / `rejected`），**不由文案派生** —— 只读详情按它回显结论；文案**只有一列** `replyContent`（不采纳原因并入其中，无独立「拒绝理由」）。
- **`status` 只有两态**（`pending` / `handled`）；B3 的「受理 / 不予处理」是 `outcome`，**不要**与 `status` 混用。
- **`hideReview` 仅举报处置携带**（仅受理时消费；已隐藏 / 已删除时联动幂等）。
- **B2 `images`**：绝对 URL 数组（≤3），只读展示、可点开大图；B3 无任何配图。
- **时间**：`createdAt` / `handledAt` 一律经 `formatDateTime`（[列表页模板 §1.6](./列表页模板.md)）。
