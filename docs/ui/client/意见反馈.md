# 意见反馈 — 页面 UI 设计稿

> 所属端：学生端（微信小程序） ｜ 页面：`pages/feedback/index`（分包 `pages/feedback/`） ｜ 代码落点：`pages/feedback/index.vue`、`pages/feedback/IssueForm.vue`
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 视觉口径真源：[公共组件与形态基线.md](./公共组件与形态基线.md)（形态 §一 / 组件 §二）· [设计变量.md](./设计变量.md)（设计变量）
> 页面为**一张表单、无页签**，固定「类型（**字典单选**）+ 具体描述 + 截图」一套字段；
> **菜品问题反馈是独立页面**（[菜品问题反馈](./菜品纠错.md)，入口为菜品详情页信息卡名称行「菜品有问题?」）——本页不含该功能与其结构化表单。

- 入口：
  - 「我的」页宫格「意见反馈」→ `feedbackUrl()`（缺省）⇒ 类型待用户选、恢复本地草稿；
  - 菜品问题反馈入口在**菜品详情页信息卡名称行「菜品有问题?」** ⇒ **独立页面** [菜品问题反馈](./菜品纠错.md)（`correctionUrl(dishId)`）；本页不承接菜品问题反馈。
- 页面：`pages/feedback/index`（页底随全局 `page{}` 底色 = 奶油米白 + `PageWallpaper` 壁纸层；页头 `AppHeader`「意见反馈」+ 返回）

## 全局视觉统一规范（全站唯一标准）

- **表面规范（极简无卡片）**：**不设白色大卡片**。三个表单区块各自一块 `.module-wrap`（暖奶米半透 `--module-bg` + 圆角 `--radius-card` + 极淡暖棕阴影 `--module-shadow` + 内距 `--spacing-lg`），区块之间**只靠页面留白 `--spacing-lg` 分组**（容器 flex gap）；模块内**不设分割线**。
- **线条统一（全页面 100% 一致）**：所有分割线、输入框边线、单选框描边、图片虚线框统一 `--border-color` + `1rpx` 粗细、低透浅灰；彻底消除粗细不一、实虚混杂。
- **品牌色克制（除下列用途外，控件 / 图标 / 文字禁用橙色）**：① 单选选中态填充 + 白勾；② 底部提交主按钮；③ **输入行聚焦底线**（下划线语言，见 [公共组件与形态基线.md](./公共组件与形态基线.md) §1.7）；三处用途之外一律禁用橙色，避免多阶橙色混杂、与奶油手绘背景违和。
- **文字层级（Apple HIG 梯度）**：模块标题 / 字段标签 = 中等字重 + 主文本色；选项主文案 = 常规字重 + 主文本色；辅助说明 / 占位 / 字数统计 = 浅灰次级、小一号。禁止标题加粗泛滥、选中文字权重跳动、辅助文字过粗。

## 表单模块（三块 `.module-wrap`，**无外层大卡片**）

> 三个字段区块自上而下：**反馈类型 → 具体描述 → 上传截图**；每块各自一块模块，**区块之间以 `--spacing-lg` 页面留白分隔**，模块内不设分割线。
> **【提交反馈】按钮在所有模块之外、**常驻底部**（固定，不随内容滚动；见下「提交反馈按钮」段），不计入任何模块容器。

### 1. 反馈类型（必填，竖排单选；整行可点、行高 ≥88rpx；选项**无独立灰色容器**）

必填星号 `*` 用 **`--color-error`**（错误色 token，与全站必填标记一致，见 [公共组件与形态基线.md](./公共组件与形态基线.md)）。单选控件：**未选中 = `1rpx` 浅灰细描边空心圆（`--border-color`），选中 = `--color-primary` 填充 + `20rpx` 纯白 `check` 图标**（`.type-check`，纯图形对读屏隐藏，选中语义由 `role="radio"` + `aria-checked` 表达）。选项 `label` **始终常规字重、不加粗**（选中态仅靠左侧橙色勾区分，杜绝权重跳动）。选项**竖排、整行可点、行高 ≥88rpx**；**选项之间不设分割线**，改用 `--spacing-md` 的**上下内边距留白分组**，选项**不设独立灰色容器**。**按压反馈（iOS 质感）**：整行点击瞬时出现 `--bg-soft` 浅灰底色（全站按压底色语言，**禁裸色值**），松手恢复、无永久底色。

**选项 = 字典驱动**：反馈类型选项**实时取自后端字典**（数据契约见 [api/feedback.md](../../api/client/feedback.md) 的 `GET /feedback-options`；页面类型区只渲染 `name`，**无副标题、无占位 hint**），展示顺序 = 服务端下发次序（按 `id` 升序的启用项），端上**零硬编码、不排序**；选中项 `id` 作为 `optionId` 上送（`0` = 未选）。

**字典三态**（类型区同一个位置切换）：
- **加载中**：居中一行次级浅灰小字「加载中…」（`--font-small` + `--text-tertiary`，行高 ≥88rpx）；
- **加载失败 / 字典为空**：同一位置换为「反馈类型加载失败，点击重试」——**整行可点**（`role="alert"` + `aria-live="polite"`），点击重走同一条拉取路径；
- **就绪**：渲染单选列表。

### 2. 字段区（固定一套，不随类型切换结构）

**A. 类型选择与描述区**

2.1 **具体描述**（必填，多行输入）：上限 **600 字**；**字数 `n/600` 常显在「具体描述」标题行右上角**（等宽数字）。

> 描述输入框 = **模块内输入项变体**：底色 `--module-input-bg`（比模块底更浅一档，用于区分层级）+ 圆角 `--radius-icon` + **底部 `1rpx` 细横线 `--border-color`** 作输入边界；**聚焦态底线切换为 `--color-primary` 高亮**，给予清晰焦点反馈。输入文本 `--text-primary`、占位 `--text-tertiary`、计数 `--text-tertiary`（等宽数字，`font-variant-numeric: tabular-nums` 防跳动）。
>
> **占位文案恒定一条**：「请具体描述你遇到的问题或建议」——**不随选中类型切换**、描述框下方**无任何业务引导行**（菜品资料有误走独立入口，见页头边界说明）。

2.2 **上传截图**（选填，**最多 3 张**）：公共 `ImagePicker` 多图形态（`max=3`，满额显示 `n/3`）—— **添加格 / 缩略图 / 删除叉 / 破图占位一律随公共组件**（规格见 [公共组件与形态基线.md](./公共组件与形态基线.md) §2.12，本页**不复述**）；点缩略图看大图（微信原生预览）。

> **菜品问题反馈**（选菜 + 七字段预填那套）为**独立页面** → [菜品问题反馈](./菜品纠错.md)；
> 本页只保留上面这一套通用反馈字段，**无第二套表单、不随类型切换结构**。

## 提交反馈按钮（表单模块之外，独立放置）

> 组件 `AppButton`「提交反馈」位于**全部表单模块之外**（常驻底部操作条），撑满页面左右 gutter；按钮不属于任何模块容器。**最后一个模块底部 → 按钮顶部留白 `--spacing-xl`**（更大留白把按钮与表单在视觉上分开）。按钮为**纯文字极简主按钮**（低饱和暖橙实底 `--color-primary` + 纯白文字、圆角 `16rpx`、无任何装饰图形 / 多余 icon，严格对齐 Apple HIG 主按钮规范）。

未选类型 / 描述为空 ⇒ 置灰（置灰点击由外层热区 toast 缺失项）；提交中禁用防重复；成功 Toast「已提交，感谢反馈」+ 2 秒自动返回上一页。

**键盘避让（必声明）**：描述 `textarea` 聚焦时「提交反馈」按钮**不得被键盘遮挡** —— 页面走 `scroll-view` + 微信默认 `adjust-position`（整页上顶），并保证**上顶后按钮仍可滚动可见**；键盘收起恢复原位。

**本地草稿**：进页自动回填「类型 + 描述文本」（`uni.setStorageSync('feedback_draft')`）；**图片不缓存**——草稿里的 COS 地址是临时转存结果，重进小程序可能已失效，缓存它只会让用户提交时报「图片地址不合法」；提交成功后清除草稿（失败时保留，便于改后重试）。

## 错误态 UI 规范（对齐 iOS 原生表单）

遵循 HIG 弱提示原则，拒绝粗暴红框 / 大面积警示色干扰：
- 校验错误：**仅字段下方展示浅红小字 `.field-error`**（`--color-error`）；
- **无输入框变红、无粗红边框**（描述框错误态不下红线，仅靠下方文字提示）；
- 自动滚动定位首个错误字段（`scroll-into-view`），逻辑不变。

### 组件清单（本界面需要哪些组件）

> 组件自身规格（尺寸 / 圆角 / 颜色 / 状态 / 交互）以 [公共组件与形态基线.md](./公共组件与形态基线.md) §二 为唯一真源；**本表只写「本页用法」**。

| # | 组件 | 在本页做什么 |
|---|---|---|
| 1 | `AppHeader` | 页头：居中标题「意见反馈」+ 返回（有返回栈则 `navigateBack`，否则回首页） |
| 2 | `IssueForm` | 类型竖排单选（字典驱动 + 加载 / 失败重试态）+ 具体描述（600 字 + 右上角计数）+ 截图（≤3 张） |
| 3 | `ImagePicker` | 截图上传（`max=3`；空态为虚线添加格，满额显示 `n/3`） |
| 4 | `AppButton` | 提交按钮（「提交反馈」/「提交中…」；`disabled` = 门禁不通过）；**位于表单卡片外部下方，撑满页面左右 `--spacing-md` 留白，不计入卡片内** |
| 5 | `AppIcon` | 类型选中勾 `check` / 选择行箭头 `arrow` / chips 删除叉 `close` |
| 6 | 提交区 `.submit-area`（页内内联） | 承接「置灰态点击」的缺失项 Toast |
| 7 | `useFeedback.ts` | 类型字典拉取与重试 + 类型选择 + 草稿 + `canSubmit` 门禁 + 提交与 2 秒自动返回 |

### 有哪些数据要显示、显示在哪个组件

| # | 数据（字段） | 来源 | 中文含义 | 显示在哪个组件 | 呈现位置 / 形式 |
|---|---|---|---|---|---|
| 1 | 反馈类型选项（`id` + `name`） | **字典** `GET /feedback-options`（仅启用项，顺序 = 下发次序） | 类型选项 | `IssueForm` 单选列表（只渲染 `name`） | 选中项左侧橙色勾；端上零硬编码、不排序 |
| 1b | 字典加载态（`optionsLoading` / `optionsFailed`） | 端上拉取状态 | 在途 / 失败 | `IssueForm` 类型区状态行 | 「加载中…」/「反馈类型加载失败，点击重试」（失败整行可点重拉） |
| 2 | `content`（本地表单态） | 用户输入 | 具体描述 | `IssueForm` textarea + 计数 | **上限 600 字**，`n/600` 常显标题行右上角；占位恒定一条 |
| 3 | `images`（本地表单态） | `ImagePicker`（安检上传） | 截图 | `IssueForm` 多图网格 | **≤3 张**；破图走统一占位 |
| 4 | 草稿（`optionId` + `content`） | `uni.getStorageSync('feedback_draft')` | 本地草稿 | 进页回填类型与描述 | 草稿携带的类型 ID **待字典就绪且命中启用项**后回填（停用项回落未选）；图片不缓存 |
| 8 | 字段错误 `errors` | 端上门禁 | 缺失或非法项 | 对应字段下方 `.field-error` + 错误边框 | 首个可定位错误字段 `scroll-into-view` |
| 6 | 提交结果 | `POST /feedback` 成功（`data` = null） | 成功 | 无界面（Toast「已提交，感谢反馈」+ 2 秒自动返回；表单重置、草稿清除） | — |
| 10 | 失败提示 | `400` / `429` 响应 `message`（类型非法 / 内容空白或超长 / 配图超限 / 含敏感词 / IP 限频 / 文本安检） | 失败原因 | 无界面（Toast 直透，兜底「没发出去，再试一次」） | 停留本页保留草稿 |

**控件类型**：`scroll-view`、竖排单选（`role="radiogroup"` + `role="radio"` + `aria-checked`）、`textarea`（600 字 + 右上角计数 + 恒定占位）、`ImagePicker`（多图形态，`max=3`）、字段级错误滚动定位、字典失败重试行
