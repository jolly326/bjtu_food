# UI 设计稿总览（按页面拆分）

> 本目录是「**有界面的**页面 UI 设计稿」唯一真源：每个页面（或页内承载物）一份独立文档，文件名以板块前缀开头。
> **与功能文档解耦**：本目录与 [`docs/func/client/README.md`](../../func/client/README.md)（功能 / 接口 / 字段 / 数据）**各按自身标准分层** —— 分类标准、命名、粒度均可以不同。**不强制 1:1 对应，也不互相内部链接**；看功能流程 / 接口口径去 `docs/func/client/`，看页面视觉 / 交互口径看本目录。
> 跨端 UI 口径以**本目录 + 各页设计稿**为准；仓库红线 / 协作纪律见 [`docs/func/client/README.md`](../../func/client/README.md) 的「项目约定与红线」段。
> **本目录只写「当前口径」**：逐轮变更过程与**修订轮次均不维护**（如需回溯，从 git 历史查找对应提交）。
> **范围**：只收**有对应界面**的设计稿 —— **无页面 / 无弹层的能力（全局登录态、静默上报等）不在此建文档**；**粒度以「一个界面单元」为准**，页内承载物不另立文件。
> **跨页口径另立一份**：[公共组件与形态基线.md](./公共组件与形态基线.md)（全站形态基线 + 公共组件规格 + 身份卡），**不在各页重复登记**。

## 文档编写规范（本目录 14 份文档统一遵守）

1. **元信息头**：每份页面设计稿首行须写「所属端 + 页面 / 承载物 + 代码落点」，与上表清单**一对一可对齐**。
2. **不复述真源**：跨页复用的形态 / 组件 / 变量规格一律**引用**（链接 + 章节号），不得复述。
3. **节序**：页面构成 → 视觉规格（引用真源）→ 交互与状态 → 组件清单 → 数据字段 → 与代码差异。
4. **参数必须可执行**：涉及尺寸 / 色值时写 **token 名**（`--spacing-lg`）或 **token 值**（`32rpx`）；**禁止**「适当」「略大」「若干」这类不可执行描述。
5. **引用必须可解析**：不得指向不存在的文档。
6. **视觉值只经 token**：页面 / 组件不得私有色值与裸尺寸；新增变量先入 `theme/tokens.ts`，再在 [设计变量.md](./设计变量.md) 登记。

> **自检**：裸色值 / 裸尺寸 / `@click` / 不可执行描述由 `npm run check:ui` 守住；**静态风格与死代码**由 `npm run lint`（ESLint flat config）守住 —— 两者均已并入 `npm run verify`（契约 / UI token / 文档一致性 / **ESLint** / 类型 / 单测**六道**）。
