# 菜品详情 — 页面 UI 设计稿

> 所属端：学生端（微信小程序） ｜ 页面：`pages/detail/dish/index`（分包 `pages/detail/`） ｜ 代码落点：`pages/detail/dish/index.vue`、`DishInfoCard.vue`、`DishReviewSection.vue`、`ReviewComposer.vue`、`ReportModal.vue`、`ImageSwiper.vue`
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**，功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 视觉口径真源：[公共组件与形态基线.md](./公共组件与形态基线.md)（形态 §一 / 组件 §二）· [设计变量.md](./设计变量.md)（设计变量）


- 页面：`pages/detail/dish/index`
  - 图片轮播（`images` 多图）：**仅手动滑动**（关闭自动轮播 `autoplay`）；多图显示指示点、单图不显示；无图显示中性占位。
  - 信息卡条目与顺序（自上而下；全卡只允许 1 条分隔线）：
    ① **名称行**（flex 横向、**基线对齐**：同行不同字号文本底部齐平，口径见 [公共组件与形态基线.md](./公共组件与形态基线.md) §1.4）：**菜名**（**最多 2 行截断、末尾省略**；卡片内最大字号）→ **「菜品有问题?」入口**（小图标 + 小号文字，**视觉权重压低**，位于价格左侧；**图标与文字同色 = `--text-tertiary`**）→ **价格**（`.price-text` 现价 + `originalPrice` 原价划线）；
    ② **评分 + 位置**（同一行、左右排布）：左 = 「黄星 + 均分」（判据：`avgRating` 恒非空，**恒渲染**；**不展示评价条数**）；右 = 定位小图标 + 「食堂 · 楼层 · 档口」；
    ③ **菜品简介**（`description` **固定最多 2 行截断、超出省略**，文本独占卡片整宽；**为空字符串则整块隐藏、不占用页面空间**）；
    ④ **唯一一条浅灰分隔线**（仅渲染在简介与四维之间；简介隐藏时这条线一并消失）；
    ⑤ **描述四维**（无底色 / 无边框 / 无内边距，4 列水平等分居中，**每列「值在上（主字号）、标签在下（浅灰小字）」**）。
    - **模块垂直间距 `--spacing-md`；简介与分隔线间距 `--spacing-sm`**；除第 ④ 条外**禁止任何分割线**（模块靠垂直留白区分）；四维块自持 `--spacing-md` 上间距 ⇒ 简介缺失（分隔线同步消失）时留白仍成立。
    - 卡内可点件仅「**菜品有问题?**」（**文字 + 小图标形态，禁实色填充按钮**）；卡片内不做分享按钮（复用微信原生右上角分享）。
    - **「菜品有问题?」= 全页唯一菜品问题反馈入口** —— 点击跳**独立菜品问题反馈页**并携带当前菜品（落点唯一构造函数 `correctionUrl(dishId)`，禁止手拼 URL，见 [菜品问题反馈](./菜品纠错.md)）；`POST /dishes/{id}/correction` 属**需登录**（免邮箱认证）⇒ 静默登录后即可提交，落点不经 `requireAuth`。
    - **不显示**：评分进度条 / 分布条、标签 chips、「信息更新于 X」、窗口号、距离。
  - 四维指标（**描述四维**）渲染口径：**逐维渲染，缺项不占位**——某维无值时不渲染该列（**不得**出现 `-` 空列凑满四列）；**维度名与值都取自出参 `attributes[]`**（每项 `{dimensionId, name, value}`：`name` = 维度中文名、`value` = 中文值），**不按具名字段取数**（维度可由管理端新增，端上无固定字段名）。**容器呈现**：**无底色 / 无边框 / 无内边距**，4 列水平等分居中，每列「**值在上、标签在下**」，标签贴底对齐（长值换行时各列标签仍在同一基线）；SHALL NOT 用输入框样式粗边框、SHALL NOT 用底色块包裹。
    - **取值形态（R4：值即中文、端上零翻译）**：四维的 `value` **为中文文本**，由**服务端按取值 ID 翻译后下发**，端上直接渲染 —— **端上不维护「机器值 → 中文」映射表**（翻译在服务端完成）。`single` 维度该值为字符串、`multi` 维度为字符串数组（端上按 `Array.isArray(value)` 判定，**不依赖维度的具体字段名**），多值以 `、` 连接后单行展示，超长按既有 `-webkit-line-clamp: 2` 换行收起。**判据为「该值即用户可读的展示文案」**：取值以**取值字典**（[dish_attribute_value](../../schema/dish_attribute_value.md)）维护（管理端录入 / 反馈采纳时登记），但**服务端已翻译为中文**，端上只负责渲染、零映射。口径与依据见功能文档 [A3 菜品详情](../../func/client/A-浏览与发现/A3-菜品详情.md) 的 `attributes` 字段表与 R4 说明。
  - **价格字号 = 菜名字号**（`--font-title`）：详情页的价格是本页主决策信息，与菜名同级才不显得「标题大字 + 旁注小字」（列表卡的价格仍保留小字层级 —— 那是列表的扫描性设计）。
- 价格口径：**展示唯一数据源 = `price`（常显现价）**；`originalPrice` 有值时并列**原价划线**；**不以任何第三个字段判折扣**（禁止双源写法——会导致不同步行展示过期价、折扣丢失），判据恒为 `originalPrice > price`。
  - 不展示独立「折扣价」——是否有折扣由「原价 × 现价」两态表达，无需第三个价格字段。
  - 评分口径：**只显示「⭐ 均分」** —— 保持简洁，**不展示评价条数**。
    - **记法说明**：本文与各页稿中的「⭐」均为 **AppIcon `star-filled`（`--color-star`）图形**的速记 —— **SHALL NOT** 在任何 UI 文案 / 标签里渲染 emoji 字符「⭐」「★」（全站图标语言唯一，见 [公共组件与形态基线.md](./公共组件与形态基线.md) §二）。
    - **出参恒非空**：详情出参 `avgRating` **恒为数字**（零评价下发 `5.0`）—— 冷启动期大量菜品零评价，评分位**不得空缺**，恒渲染。
    - 🔴 **兜底值只在展示层**：`5.0` **不落库**（`dish.avg_rating` 零评价仍为 NULL）、**不参与排序**（评分无排序消费方），见 [schema/dish.md](../../schema/dish.md)。
    - **该列为缓存列**（`dish.avg_rating`，由评价写操作在**提交响应返回前同步重算** + 每日定时对账兜底），提交者本人重拉详情即读到新值。
  - 评分分布条与评价条数不渲染 —— 按用户规格「保持简洁设计」；对应字段**不在详情出参内**。
  - **零评价时评价区的号召文案**（与卡片 `⭐ 5.0` 配套，消除矛盾）：
    - 菜品详情页评分位恒显示「⭐ 5.0」（出参兜底），而评价区此时**无任何评价** ⇒ 两者并置会显得矛盾（卡片说5 分、详情说没人评）；
    - ⇒ 零评价时评价区显示 **`star-filled` 图标 + 「快来抢首评」+ 数字「5.0」（tabular-nums）**（图形 + 纯文案组合，**不作为可点件**；SHALL NOT 用 emoji 字符 ⭐），把「矛盾」转为**冷启动号召**；
    - 呼应决议②' 的设计意图：零评价菜品的 `5.0` 正是邀请首个评价者的钩子；
    - 有评价后（或筛选后有结果）恢复正常：显示「评价 + 数字」标题 + 筛选条 + 列表。
  - **评价区星级筛选**（`filter by rating`，类似美团）：
    - **位置**：评价区**标题行下方**横向 `scroll-x` 筛选条，独立于标题行（不挤占「评价 + 数字」标题块）；
    - **选项**：`全部` / `5星` / `4星` / `3星` / `2星` / `1星`（**6 项固定枚举**，端上硬编码，**无服务端字典**；chip 内**纯文字**，SHALL NOT 用 emoji 星「⭐」—— 小尺寸 chip 内图标 + 数字过挤，文字「N星」即达意）；
    - **形态**：轻量 chip / 标签，单选；选中态 `--color-primary-soft` 底 + `--color-primary` 描边（与 [公共组件与形态基线.md](./公共组件与形态基线.md) §二 TagChip 一致）；
    - **高度**：`min-height ≥88rpx`（独立可点件基线），横向可滚动、不换行；
    - 🔴 **零评价时筛选条不渲染**：无任何评价可筛⇒ 显示筛选条会让用户点出空结果。零评价态只渲染上述「快来抢首评」文案；
    - **交互**：点选即提交 → **重置 `page=1`** 并重拉列表（服务端过滤，见 [api/dishes.md](../../api/client/dishes.md)）；
    - **空结果**：筛选后无匹配评价 → 纯文案「暂无 X 星评价」，**不显示**「暂无评价」（那是零评价态的文案，两者语义不同）；
    - 🔴 **不新增任何字段**：筛选只改查询参数，**不新增出参列**（`rating_count` / 有用数均不出参）。
  - 评价区：
    - **标题行**：**左 = 「评价 + 数字」合并为一个标题块** —— 数字与标题**同色**（SHALL NOT 用 `--text-tertiary` 灰字：灰字会把总数读成附属信息）、字号小半号（h2 40rpx → h3 36rpx）、等宽数字；**不用「评价（N）」括号式**；在途 / 失败态**不渲染数字**。
      **右 = 「写评价」轻量入口（主色线性笔形图标 `edit` + 主色文字，非按钮形态）** —— **无边框 / 无底色 / 无阴影 / 无胶囊槽**（视觉权重低于任何按钮，只表达「点击可写评价」）；**随评价卡片一同滚动（不吸顶、不固定）**；**文案恒为「写评价」—— 无「重新评价」双态**。
    - 评价条目（`ReviewItem` 的 `flat` 形态）：① 头像 + 昵称（600 档）+ 右上角 ⋮ 更多（ActionSheet：举报 / 删除）；② 星级（黄色实心）+ 分值 + **日期（仅 `YYYY-MM-DD`，不含时分 —— 菜品评价时效性弱）**同行；③ 正文；④ 配图 ≤3 张（有图才渲染）。**条目之间为 1rpx `--border-color` 分隔线（`--spacing-md` 行内距），SHALL NOT 加独立卡片边框**。
    - 排序：**时间倒序（新评价在前），唯一排序，无切换**
  - 状态呈现（强制，遵守既有红线）：① **加载中不呈现骨架屏 / loading 指示**（仅限「页面级首屏」；**用户主动点击「重新加载」**时可在公共 `RetryBlock` 内给**转圈**在途反馈）——数据未返回时内容区空白静默；② **菜品不存在 / 详情拉取失败**须给出明确文案与恢复路径（**不得只留纯空白页**）；③ 评价区失败态沿用既有**可重试块**。
  - 交互与无障碍（本模块强制）：可点元素触控目标 **≥ 88rpx（44pt）**；「写评价」入口与「菜品有问题?」入口均带 `role="button"` + `aria-label`（命中区经 `::after` **仅纵向**扩至 88rpx，视觉尺寸不变）；轮播容器与评价头像带 `aria-label`；`prefers-reduced-motion` 下动效降级为直接显示。
- **页面底部无任何常驻操作栏** —— 滚动区底部 **取消 `calc(var(--action-bar-height) + env(safe-area-inset-bottom))` 预留**，回归常规底部留白。**已拍板：首屏不加浮动 CTA** —— 写评价入口**唯一**在评价区标题行，保持首屏克制。
- 「**写评价**」入口（**唯一落点 = 评价标题行右侧**；文案**恒为「写评价」**，无「重新评价」双态）—— 点击**直接打开空表单弹层**。
- **无任何写前判定**：弹层打开前**不调** `GET /my/reviews?dishId=`、**不预填本人旧评价**、**不显示「覆盖原评价」提示**；详情页**零用户态请求**。
- **提交口径**：恒 `POST /dishes/{id}/reviews` —— **同一用户对同一菜品的重复提交由服务端覆盖旧评价**（端上不区分首评 / 重评）。
- 未认证点「写评价」→ 跳转身份认证页 `pages/auth/index`（认证成功返回本页后由 onShow 续接，自动重新打开写评价表单）。
- **菜品问题反馈入口**：「**菜品有问题?**」（信息卡名称行，见上「信息卡条目与顺序」）—— 全页唯一；写评价弹层内**不含**菜品问题反馈入口。
- **分享**：由**微信右上角原生菜单**承担（`onShareAppMessage` 保留：分享菜名 + 现价 + 本页路径），分享能力不弱化。

### 有哪些数据要显示、显示在哪个组件

| # | 数据（字段） | 来源 | 中文含义 | 显示在哪个组件 | 呈现位置 / 形式 |
|---|---|---|---|---|---|
| 1 | `id` | `GET /dishes/{id}`（`DishDetailVO`） | 菜品 ID | 无界面（页面 `key` / 请求路径 / 分享路径） | 零可见 UI |
| 2 | `name` | 同上 | 菜名 | ① `DishInfoCard` 名称行 ② `AppTitleBand` 居中标题（滚动后渐显） ③ `ReviewComposer` 副标题 ④ 分享标题 | 名称行**最多 2 行截断**；导航标题按滚动量淡入 |
| 3 | `price` | 同上（元） | 现价 | `DishInfoCard` 价格行 `.price-text` | **唯一价格数据源**（主色）；不以第三字段判折扣 |
| 4 | `originalPrice` | 同上 | 原价 | `DishInfoCard` 价格行 `.origin-price` | 仅 `originalPrice > price` 渲染，三级灰 + 删除线 |

### 三、举报评价（`ReportModal` 底部弹层）

入口 = 菜品详情页评价卡片右上角**三点菜单** → 「举报评价」（危险红色态）。

  1. 处理承诺行：「请选择举报原因，我们会及时处理，感谢你的监督」（次级浅灰小字）；
  2. **原因单选列表**：选项来自后端字典 `GET /report-reasons`（弹层打开时实时拉取，**服务端只下发启用中的原因**，停用项不下发；端上零硬编码；展示顺序 = 后端下发次序）；每行整行热区（`min-height` = `--tap-target-size`），底色取**浅白半透 `--module-input-bg`**（与属性弹层 / 纠错表单字段行同源），选项之间靠 `--spacing-sm` 留白分组、**无分割线**；**单选**——选中行 = 主色浅底 + 左侧主色竖条（`inset` 阴影，不引发布局位移）+ **橙色勾标记** + 文字转主色加粗（**不只靠底色表达**，便于色觉障碍与读屏辨认；选中语义同时由 `aria-checked` 承载）；**无文本输入框**；
