# 菜品问题反馈 — 页面 UI 设计稿

> 本页承载「**菜品问题反馈**」：详情页入口为「**菜品有问题?**」，进页**先选问题类型**，再按类型渲染表单（`field` 走锚定只读 + 动态属性的完整表单；`gone` 走**一键提交**形态，见文末「`gone` 型 UI」）。
> 本页文件名 `菜品纠错.md`（对外引用方众多，文件名不变）；功能文档见 [B6 菜品问题反馈](../../func/client/B-UGC表达与治理/B6-菜品问题反馈.md)。

> 所属端：学生端（微信小程序） ｜ 页面：`pages/correction/index`（分包 `pages/correction/`） ｜ 代码落点：`pages/correction/index.vue`、`CorrectionForm.vue`、`AttributeGroup.vue`、`AttributePickerSheet.vue`、`FloorPickerSheet.vue`、`TagChip.vue`
> **口径分工**：**页面 UI 设计口径以本文件为唯一真源**；功能流程 / 接口 / 字段 / 数据落库口径以功能文档为准。
> 视觉口径真源：[公共组件与形态基线.md](./公共组件与形态基线.md)（形态 §一 / 组件 §二）· [设计变量.md](./设计变量.md)（设计变量）
> 本页采用「**锚定只读（不切换菜品）+ 动态属性 `AttributeGroup`**」形态 —— 进页自动预填菜品全部信息，用户**只改错项**，提交**仅带上改动过的项**（patch）；不进审核前置、**不实时生效**。
> ① 基础信息表单**双列并排**（菜品名称跨整行；售价｜食堂名称、楼层｜档口名称），消除短字段独占整行的纵向留白；② **楼层**为**固定字典底部单选**（`BaseSheet` 弹层）：**字典项即汉字、显示与提交都是同一个汉字**（`负一层` / `一层` / `二层` / `三层` / `四层`，真源见 [schema/stall.md](../../schema/stall.md)），**无映射**；③ **属性区 = 「字段行 + 底部弹层」**：每个维度一行 picker 单元格（当前值摘要 + 单 / 多选标注 + 箭头），点开即该维度的弹层，**候选全览 / 本地搜索 / 手动输入 / 清空全在弹层内**，属性 chip 仅出现在弹层内；④ **去冗余提示**：无页首提示条、无「正在菜品问题反馈」标题与「菜品不可切换」小字、无组内重复操作说明，锚定行即表单首行纯文本；⑤ **键盘避让**：`BaseSheet` 的 `keyboard-lift`（`uni.onKeyboardHeightChange`）让**含输入框的弹层**随键盘抬升（`AttributePickerSheet` 唯一消费方）。
> 边界：**菜品问题反馈 = 依附某条菜品数据的专项修正**（自带 `dishId`、字段结构化）；**意见反馈 = 面向小程序本身的通用反馈**（见 [意见反馈.md](./意见反馈.md)）。两者互不耦合。

- **入口（唯一）**：菜品详情页**信息卡名称行「菜品有问题?」入口** → `correctionUrl(dishId)`（`utils/routes`，禁止手拼 URL）⇒ 进页**先选问题类型**；选 `field` 则按 `dishId` 拉详情**预填**；选 `gone` 则**无需拉详情**，直接呈现一键提交形态；**页内不提供切换菜品**。
- 页面：`pages/correction/index`（独立分包 `pages/correction/`；二级页，**无 TabBar**；页底随全局 `page{}` 奶油米白 + `PageWallpaper`；页头 `AppHeader`「菜品问题反馈」+ 返回）。

## 视觉基线

**页面底**：低透明度手绘食物底纹（`PageWallpaper`），底色奶油米白。
**主卡片**：一枚大卡片承载全部表单 —— 底 `--bg-card`、圆角 **`--radius-card`**（24rpx）+ `1rpx` `--border-color` 细描边（结构线唯一档）+ 柔和低饱和卡阴影（`--shadow-card`）；卡片左右外边距 `--spacing-md`、内边距 `--spacing-lg`；**卡片内不使用分割横线**，靠间距 / 分组区分模块。

**色彩（只列落地 token —— SHALL NOT 记参考色值）**：

| 用途 | token |
|---|---|
| 页面背景底色 | `--bg-page`（全局 `page{}` 奶油米白） |
| 模块容器底色 | `--module-bg`（**暖奶米半透**） |
| 主题橙 | `--color-primary`（填充档）/ `--color-primary-text`（文字档） |
| 选中标签底 / 描边 | 底 `--color-primary-soft` / 描边 `--color-primary` |
| 默认候选标签底 | `--bg-soft` |
| 正文 / 辅助文字 | `--text-body` / `--text-secondary` |
| 输入框底线（常态 / 聚焦 / 错误） | `--border-color` / `--color-primary` / `--color-error` |
| 错误提示文字 | `--color-error` |

> **模块底口径**：全站内容块统一走暖奶米半透 `--module-bg`（规格见基线 §1.8.1），卡内层次改由「`--border-color` 细描边 + `--module-shadow` + `--module-input-bg` 凹槽」表达。

> **红线**：颜色**一律走语义 Token（`var(--color-*)`），禁裸 hex**（上表色值仅为设计参考，实现须落到 Token；确无对应 Token 时新增，原生 API 不接受 `var()` 的常量集中登记）。图标统一 `AppIcon`，**禁 emoji / 文本 / `content:'+'` 当图标**。

## 触达尺寸口径

**基线**：全站独立可点件 ≥ **88rpx = 44pt**（`1rpx = 0.5pt`，`750rpx = 375pt`）。本页**全部**可点件都在这条基线上：`.row-field`（下划线输入行）/ **属性字段行 `.ag-field`**（与楼层单元格同构的 picker 单元格）/ `ImagePicker` 添加格与删除钮 / **属性弹层内的一切可点件**（候选 chip、清空搜索、手动输入行与「添加」、清空 / 不填、确认）。


| 元素 | 视觉尺寸 | 命中区 | 结论 |
|---|---|---|---|
| **属性字段行** `.ag-field` | 高 **88rpx** + 底部横线（与楼层 / 输入行同构同高） | 整行可点（左标签不参与点击） | **独立可点件** |
| **弹层内候选 chip**（`TagChip`） | 视觉高 **88rpx**（`min-height` 抬起；内边距 `--spacing-sm --spacing-lg`） | 整 chip 全宽可点 | **独立可点件**；行距 gap `--spacing-sm` 吸收纵向误触 |
| 弹层内「手动输入」行 / 输入框 | 行高 **88rpx** | 整行可点 / 可打 | 独立可点件 |
| 弹层内「添加」文字钮 | 视觉高 **56rpx** | `::after` 纵向透明扩至 **88rpx**（不改视觉） | 纯文字钮靠透明扩展兜触达 |
| 弹层底部「清空全部 / 不填该项」/【确认】 | ≥ **88rpx**（确认 `min-width: 240rpx`） | 整件可点 | 独立可点件 |
| **楼层 picker 单元格** | 高 **88rpx**（与同行 input 行等高） | 整单元格可点 | **独立可点件** |

**弹层 chip 的两态等高（原「67rpx 算式」的继承者）**：`min-height: 88rpx` + `box-sizing: border-box` ⇒ 内边距（`--spacing-sm --spacing-lg`）、文字行（`22 × 1.4 = 30.8`）、描边（4rpx）全部算在 88rpx 内 ⇒ **选中 / 候选两态切换时 chip 不跳高**（候选态用 `2rpx solid transparent` 占住描边位，刻意设计：描边是「选中」独占的视觉标识）。三项视觉强化同样**不触碰高度**：① 圆角 `--radius-pill`（全圆胶囊）只影响轮廓；② 选中态字重 `--weight-semibold`(600) 在 `line-height: 1.4` 下不改文字行高；③ 勾选对勾（`AppIcon name="check" :size="24"`）与文字同排、不撑高。

> **字重取值说明**：`--weight-medium` = 500 在部分小程序端会回落至 400（真字重只有 400 / 600 两档时 500 被就近取整），故「强调选中态」必须用 **`--weight-semibold` = 600** 才生效（与 `首页菜品浏览.md` 的同源口径一致）。

**chip 圆角 = `--radius-pill`（全圆胶囊）**：弹层内 chip 是**可点词条** ⇒ 归 pill 档（标签圆角两档口径见 [设计变量.md](./设计变量.md) §2.1）；**禁**在本页裸写 `28rpx`。

**「一律进弹层」把触达口径归拢成一条**：属性维度成为字段行后，与名称 / 售价 / 楼层等字段**共用同一条 88rpx 基线**，弹层内候选 chip 同为 88rpx ⇒ 本页**无「密集小控件的例外登记」**，跨页评审无须再复述前提：每个维度**恒占一行**、四维度合计四行，与禁止项 2「防页面过长臃肿」同向。

## 卡片结构（自上而下）

1. 菜品锚定行（纯文本，只读）
2. 基础信息表单区（下划线轻量输入）
3. 属性编辑区（`AttributeGroup` ×N，核心）
4. 图片上传区（选填，≤3 张）
5. 提交说明文案
6. 底部提交按钮

> **无页首提示条**：不渲染任何「已自动填充菜品原有信息…」类顶部横幅；进入卡片即锚定行。

### 1. 菜品锚定行（纯文本 · 只读）

- 形态：**无标题、无底色、无卡片背景** —— 直接作为表单最上方一行纯文本 `<菜品名称>｜<食堂>·<楼层>·<档口>`（示例 `杨枝甘露｜嘉园餐厅·负一层·嘉园奶茶`）；**不渲染**「正在菜品问题反馈」标题与「菜品固定不可切换」小字。
- **预填未就绪时**：该行显示「正在载入菜品信息…」，且此时**只渲染锚定行、不渲染表单**（防误改误提交）。
- **楼层展示口径**：楼层段**原样展示 `floor` 值**（本身就是汉字，如「二层」），与楼层单元格口径一致 —— **全链零映射**。口径见「[楼层控件（固定字典单选）](#楼层控件固定字典单选)」。
- **无任何点击交互、无箭头**；作用：防止用户改错菜品（与功能文档「表单内不允许切换」一致）。

### 2. 基础信息表单区（下划线轻量化输入 · 双列并排）

- **行内样式**（不变）：标签在左，输入控件占剩余宽度；**输入框背景透明，仅保留底部横线**（**禁全包围矩形框**）。
- **布局规则**：**菜品名称**独占整行（名称文字长，拆分后每列宽度不足）；其余 4 个短字段**两两并排**，压掉纵向留白。
- **仅保留字段名**：行内不渲染任何附加说明小字（售价行尾单位「元」除外）；字段之间靠**垂直留白**分隔，不使用分割线。

| 行 | 左列 | 右列 |
|---|---|---|
| 1（**跨整行**） | 菜品名称*　`input` | — |
| 2（双列） | 售价*　`input` + 行尾「元」 | 食堂名称*　`input` |
| 3（双列） | 楼层*　**picker 单元格**（见下） | 档口名称*　`input` |

- **实现口径**：双列用 **flex 两列**（每 `.cell` `flex: 1 1 0` + `min-width: 0`，列间 gap `--spacing-lg`），**不用 CSS grid** —— 本项目 `client/src` **零 grid 先例**（grid 仅 `web/` 使用），避免引入 mp-weixin 基础库差异。
- **标签宽度**：跨整行行 **160rpx**；双列行内 **96rpx**（双列每列 ≈307rpx，扣标签后余 ≈190rpx 供输入）。

| 标签 | 必填 | 呈现 | 预填 / 说明 |
|---|---|---|---|
| 菜品名称 | ✅ | 单行 input（跨整行） | 预填详情 `name`，可改；提交前非空、≤64 字 |
| 售价 | ✅ | 单行 input，digit 键盘，**行尾随单位小字「元」** | 预填详情 `price`（**API 层已完成 `fenToYuan` 分 → 元**，页面不换算金额）；单位「元」是**行尾小字**，不写进输入值、不参与提交；提交前 `yuanToFen` 转分（金额红线） |
| 食堂名称 | ✅ | 单行 input | 预填详情 `canteenName`（自由文本，无 picker / 无字典） |
| 楼层 | ✅ | **底部单选弹层**（见「楼层控件（固定字典单选）」） | 预填详情 `floor`（**归属档口**）；**值即汉字**（`负一层` / `一层` / …），显示与提交同一值、**端上零映射** |
| 档口名称 | ✅ | 单行 input | 预填详情 `stallName`（自由文本） |

> **原价不纳入菜品问题反馈**：原价随促销波动、属运营口径，短期打折不构成稳定事实；本页**只菜品问题反馈现价（`price`）**，不渲染原价行。

- 交互：默认底线 `--border-color` → 聚焦切 `--color-primary`；必填标签的 `*` 与行内错误小字**同走 `--color-error`**（错误色 Token）；提交时校验必填，空值在**对应单元格下方**弹错误色行内小字（`padding-left` **跟随本列标签宽**：跨整行 160rpx / 双列 96rpx，不固定为 160rpx），输入行底线同步切错误色，**错误态优先于聚焦态**。

#### 楼层控件（固定字典单选）

- **控件类型**：**底部弹出单选弹层**，走公共 `components/BaseSheet.vue`（底部弹层骨架唯一真源：遮罩点击关闭 / grabber / 下滑关闭手势 / 安全区 / 焦点回收），**本页不自建弹层、不用原生 `<picker>`** —— 本项目 `client/src` **零 `<picker>` / `<picker-view>` / `showActionSheet` 先例**，`BaseSheet` 是弹层唯一真源（`zToken` 走默认 `--z-sheet`）。
- **单元格形态**：汉字文案 + 右侧 `AppIcon name="arrow-down"`（`size="24"`，**已注册键**）；下划线样式与同行 input 一致，**高 88rpx**（独立可点件触达基线，见触达尺寸口径）。

**值模型：`form.floor` = 所选字典项本身（汉字）；显示与提交同一值。**

这样 diff 比对、必填校验、提交组装**三处逻辑零改动**（值是汉字，**无需查表、无需判断「是否等于原值」**）。**字典项（值即汉字，与 [schema/stall.md](../../schema/stall.md) 一致）：`负一层` / `一层` / `二层` / `三层` / `四层`。**

- **加载预填**：详情返回 `floor`（汉字）→ **原样选中对应字典项**；锚定行同样原样展示 —— **无映射、无查表**。
- **提交**：用户选中某项 → `form.floor` = 该项汉字；未改动则不产生 diff、不提交。
- **无「未命中兜底」**：字典外值**不存在**（变更规则：新增楼层免迁移；**删 / 改名须先把该楼层的档口迁到其它楼层**再改字典 —— 见 [schema/stall.md](../../schema/stall.md)），故端上无需容错分支。

| 详情 `floor` | 单元格展示 | 提交行为 |
|---|---|---|
| 命中字典（`负一层` / `二层` …） | 该字典项**高亮选中** | 未动 ⇒ **无 diff**；改动 ⇒ 提交所选汉字 |
| 空串 | 占位「请选择楼层」 | **必填不放行**，错误小字落该单元格下方 |

- **禁止**：楼层**不得提供自由输入**（只能从字典选）；**不得**在端上维护「机器值 ↔ 汉字」映射表（**值即显示值**）。

### 3. 属性编辑区（核心 · `AttributeGroup` 可复用组件）

> **数据驱动**：`GET /dishes/{id}` 的 `attributes[]`（**数组**；每项 `{dimensionId, name, value}`，`value` 为**中文**：`single` → 字符串、`multi` → 数组）决定**当前值**；`GET /dishes/{id}/attributes`（编辑态**按需**）的 `options` 决定**参考候选**；`valueType` 决定单选 / 多选。**每一个维度单独一行 `AttributeGroup`**（维度由后端下发、**端上不硬编码**）。

- **零维度**（详情 `attributes` 为空）⇒ **整段属性编辑区不渲染**（`v-if="model.attributes.length"`，无占位文案、不留空档）；单个维度无原始值时，仅该行显示灰字占位「请选择<维度名>」。
- **属性区无字段级错误**：属性不存在「必填」概念，故不设行内错误位；属性变更只承担「撤下过期失败提示」的职责。

**形态：字段行 + 底部弹层** —— 弹层是该维度的唯一选择场所**

每一个维度 = **一行**，与「楼层」单元格完全同构 ⇒ 属性四行与上方五个基础字段**同一节奏、同一条 88rpx 基线**。主表单**不**渲染已选 chip、常驻候选、删除叉、自定义输入框 —— 一个维度只有一个入口，该维度的**增 / 删 / 清空 / 自定义全在弹层内完成**（同一维度「两处都能选、但能选的东西不一样」是误导性的；低频但要认真填的菜品问题反馈表单，一致性优先于少一次点按）。

```
饮食属性   素食 单选 ⌄                      ← 单选：摘要 = 当前值原文
食材       珍珠、奶茶、芒果 等5项 多选 ⌄     ← 多选：前 3 项顿号连接 + 「等 N 项」
冷热       请选择冷热 单选 ⌄                ← 空值：灰字占位（与 input placeholder 同档）
```

- **摘要规则（补偿「统一进弹层」多出来的那一次点按 —— 不点开也能核对全貌）**：空值 ⇒ 灰字「请选择<维度名>」；单选 ⇒ 当前值原文；多选 ⇒ **前 3 项**顿号连接、超出折成「**等 N 项**」（`N` = **总数**、不是余数 ⇒ 无歧义）。常量 `SUMMARY_MAX = 3`：超过 3 项仍全列会把右端标注与箭头挤走、或诱导整行换行（行高一跳 ⇒ 表单抖）。摘要 `flex: 1` + `min-width: 0` 单行省略 ⇒ **标注与箭头恒不被挤走**。
- **单 / 多选标注**：行内右端「**单选**」/「**多选**」，`--font-tiny` + `--text-placeholder`（信息性、非强调），`flex: none` 常驻（摘要再长只省略摘要、不挤标注），文案由 `valueType` 驱动、端上零硬编码。维度名即行左标签（与 `.row-label` 同宽 160rpx、同色档），一行装完全部信息。
- **行结构**：左 `.ag-label`（维度名）+ 右 `.ag-field`（摘要 + 标注 + `arrow-down`）；`.ag-field` = picker 单元格（高 **88rpx** + 仅底部横线，与 `.row-field--picker` 同源），**整行可点**、无 `input` ⇒ 无聚焦态，按压用 `hover-class` 底色微变（禁 `transform: scale`）。
- **整行可点、无条件**：候选为空（编辑端点失败 / 该维度无候选）时字段行**照样可点开**，进弹层走手动输入 ⇒ 不因候选缺失而丢入口。
- **无障碍**：`.ag-field` 挂 `role="button"` + `aria-label` = 「<维度名>，当前<全量值>，<单选 / 可多选>，共 N 项参考候选，点按选择」（摘要在 WXML 里被省略号截断 ⇒ 读屏给全量）。

**弹层结构（`AttributePickerSheet` · `BaseSheet` 底座 + `scroll-body` + `keyboard-lift`）自上而下**

| 层 | 内容 | 规则 |
|---|---|---|
| ① 搜索 | 「搜索<维度名>候选」下划线输入 + 行尾清空钮 | 候选**总数** ≥ **12**（`SEARCH_MIN`）才渲染（判据用总数 ⇒ 打字过滤到空时搜索框**不闪没**）；**仅本地子串过滤、禁发请求**；`maxlength=10` |
| ② 无候选提示 | 「该维度暂无参考候选，可直接手动输入」 | 仅 `candidates` 为空时出现（明示只剩手动输入，**不暗改行为**） |
| ③ 「已添加」区 | 已选里**不在候选池**的值（= 自定义值），chip 同款 + 分组小标题 | **不参与搜索过滤**（打字时不该找不到自己刚填的值）；点 = 取消该值；小标题让人一眼分清「这不是候选，是我填的」 |
| ④ 候选全览 | 全部候选（含已选项，选中态带 `check` 对勾）流式排布 | `TagChip` 视觉高恒 **88rpx**；勾选态在 **JS 侧**算好下发 `{ value, checked }`（WXML 只取值、不调函数 ⇒ 跨端一致）；搜索无命中给「没有匹配项，可清空搜索或改手动输入」 |
| ⑤ 手动输入 | 折叠态「**＋ 手动输入<维度名>**」→ 展开态下划线输入 + 「添加」 | **恒在**（自定义入口全页仅此一处，折叠展开符合 iOS / Android 设置页「其他…」惯例）；上限 **10 字**、去空格、自动去重、禁空；多选添加后**保留展开**只清文本（连填是常态），单选添加后替换并关闭 |
| ⑥ 底部条 | 左「**不填该项**」（单选）/「**清空全部**」（多选）+ 右【**确认 · 已选 N**】 | 清空语义是**动作** ⇒ 直接回抛空数组并关闭，不要求二次确认；【确认】**仅多选组**渲染、带已选数（「改了没 / 改了几个」在关层前可见）；`min-width: 240rpx` |

- **单选组（无确认按钮）**：点候选 / 添加自定义 = **回抛并立即关闭**（省一步空操作）；点**当前已选项** = **不产生 diff**（但仍关闭 —— 点这一下的语义是「就它了 / 算了离开」）；**清空在弹层内就能做完**（「不填该项」）—— 主表单已无删除叉，清空入口必须落在弹层里。
- **多选组（草稿态）**：点候选只写本地 `draft`（弹层内实时反馈），【确认】才 `emit('update', next)`；**关闭 / 遮罩 / 下滑 = 丢弃草稿**，主表单不变。**每次打开都重置**草稿为主表单当前值（回显即时、且不残留上次未确认内容）⇒ 弹层内任何改动**都不产生 diff，直到回写那一刻**。
- **两套选中态（由 `selectedStyle` 分流，禁互串）**：单选组 = **实心 `--color-primary` 底 + `--color-on-primary` 白字**（`solid`）；多选组 = `--color-primary-soft` 底 + 2rpx `--color-primary` 描边 + `--color-primary-text` 字（`soft`）。两者共同：`--weight-semibold`(600)、圆角 `--radius-pill`（可点词条归 pill 档）、选中态带**勾选对勾**（弹层内没有删除叉，「已选」不能只靠底色表达 —— 色觉障碍 / 低亮度下不可辨）。候选态 = `--bg-soft` 底 + `--text-body` 字 + **2rpx 透明描边**（等高不跳位）。
- **候选池含已选项、不去重、不另排序**：已选项以**选中态**呈现（一眼看出「这个已经选了」），点它即取消选中；不隐藏、不置灰。
- **键盘避让（`BaseSheet` 的 `keyboard-lift`）**：弹层是 `position: fixed`，**不消费**微信 `adjust-position` 的整页上顶 ⇒ 键盘会盖住搜索框与手动输入。故 `BaseSheet` 开启该开关后监听 `uni.onKeyboardHeightChange`，把抽屉的 **`bottom` 由 `0` 抬到键盘高度**（键盘收起归零；监听仅在「开关开 + `visible`」期间注册，关闭 / 卸载即注销）。**硬约束**：弹层内**两个输入框都必须 `:adjust-position="false"`**，否则「整页上顶」与「抽屉抬升」叠加成**双位移**；另配 `:cursor-spacing="40"` 兜底。楼层弹层无输入框 ⇒ 不开此开关（默认 `false`，既有调用方行为零变化）。
- **挂载**：随 `AttributeGroup` 就近挂载，首次打开后 `v-if` 置真**常驻**（候选池可达数十项，避免每次开合重建子树）；挂载与置真**分两个 tick**（`nextTick`）—— 不能在挂载同 tick 内置真，否则 `BaseSheet` 抓不到 `visible` 的变化、开合动画失效。

### 4. 图片上传区（选填）

- 标题：`补充实拍图片（选填，最多 3 张）`。
- 初始态（**与公共 `ImagePicker` 逐项对齐**）：`--bg-input` 浅底虚线框 + `AppIcon name="image"`（**「添加图片」语义，不是相机图标**）+ 文案「**添加图片**」；上传中该格显示环形 loading +「上传中…」。
- **提交时上传**（口径见 [公共组件与形态基线.md](./公共组件与形态基线.md) §2.12）：**选图时只落本地临时路径**（不写云存储、不调后端）；**提交时**才逐张送机审转 COS，失败文案带「第 N 张图片」。预填的菜品原图**本身已是正式 URL**，提交时直接跳过。
- 上传后：缩略图**3 列网格**（与公共 `ImagePicker` 一致；超限换行）+ 每张**右上角**删除钮；点击缩略图预览大图（微信原生 `previewImage`）；满 3 张时末位显示 `5/5` 计数格；**破图走统一 `ImagePlaceholder`（灰底 + `image-broken`）且不进预览**。
- 实现复用公共 `ImagePicker`（多图形态，`max=3`），与**服务端上限 ≤3 一致**；**本页不另写上传 / 预览 / 删除逻辑，也不自绘删除钮位置**（图标、文案、位置一律随公共组件，避免两套口径漂移）。提交中删除钮与添加格同步弱化（0.5）并禁点。

### 5. 提交说明文案

- 文案：`提交后人工审核，审核通过更新菜品信息`；浅灰小字，无警示色（**不暗示提交即生效**）。

### 6. 底部提交按钮

- 文案「**提交菜品问题反馈**」（提交中「提交中…」）；**随内容滚动**（非固定底栏）。
- 正常可提交：主色 `--color-primary` 底、`--color-on-primary` 白字、圆角 **`--radius-btn`**（24rpx）、高 **88rpx**（= 44pt）、宽 100%（`AppButton` 公共件）；按压 `hover-class="pressed"`。
- **禁用态**：主色实底 ⇒ **灰底 `--bg-input` + 灰字 `--text-tertiary`**（**不降透明** —— 透明档全站只表「在途 busy」）；禁点由全站唯一令牌 `.is-disabled { pointer-events: none }`（**唯一定义在 `App.vue`**）承担 —— 本页**不自设**任何禁用视觉（灰底灰字档在 `AppButton` 内实现，全站单一来源）。
- 禁用触发条件（四选一即置灰）：必填项为空 **或** 表单**无任何改动**（无改动 = 无可提交内容）**或** 预填未就绪（`loading`）**或** 限频退避中。
- 置灰点击由**外层热区**兜底 toast（`AppButton` 禁用态 `pointer-events: none`，点击落到 `.submit-area`），文案指名缺失项 / 无改动 / 限频倒计时；提交中 `loading` 态（`opacity 0.6` + 禁点）防重复提交。

## 交互规则

1. **加载**：进页按 `dishId` 拉 `GET /dishes/{id}` 预填全部字段与原始属性；`GET /dishes/{id}/attributes` **与详情并发取一次**（弹层内的参考候选依赖它；失败静默 ⇒ 该维度弹层内明示「暂无参考候选，可直接手动输入」，**不阻塞表单、字段行照旧可点**）；**楼层为字典项直取，无端上字典、无额外请求**（后端不提供楼层字典端点；字典真源见 [schema/stall.md](../../schema/stall.md)）。
2. **提交策略**：**仅提交改动项**（patch）—— 与初始快照逐字段比对，未改动不传；`attributes` 仅含**改动的维度项**；`price` 以**分**提交。
3. **成功**：Toast「提交成功，等待审核」→ 自动返回上一页（菜品详情）。
4. **失败**：页面底部**错误色文字**（`--color-error`）提示失败原因，**完整保留已填内容**（不清空表单）；用户一旦改动任一文本字段 / 属性 / 图片，即撤下这条过期提示（不改动则不撤，便于回头核对）。
5. **重置**：不单独提供重置按钮；退出页面即丢弃表单。
6. **边界**：某维度无原始属性 → 字段行显示灰字占位「请选择<维度名>」，**照样可点开弹层**新增；属性候选接口异常 / 该维度无候选 → 弹层内明示「可直接手动输入」，字段行不受影响（**不因候选缺失而丢入口**）；**全部维度为空 → 整段属性编辑区不渲染**。
7. **限频退避**：命中 IP 限频（2 条/分钟、10 条/小时）后进入**退避期** —— 提交按钮置灰（`.is-disabled`）**且不发请求**，点击由外层热区 toast「提交过于频繁，请 N 秒后再试」（N = **实时倒计时**）；退避结束自动恢复可提交态；退避期内连点**不叠加请求、不延长封锁**。
8. **属性弹层**：属性维度**只有一个入口 = 字段行**，点开即该维度的弹层（与候选数量无关，**不设「≤4 就地平铺」的分档**）；打开时**回显当前已选**（多选建草稿、单选高亮当前项，且每次打开重置）；多选**确认才回写**、关闭 / 遮罩 / 下滑**丢弃**；单选**点项即回写并关闭**（点当前项 = 不产生 diff）；清空在弹层内完成（「不填该项」/「清空全部」）；手动输入在弹层内展开、经 `keyboard-lift` 避让键盘。弹层内的任何改动**都不产生 diff，直到回写那一刻**。

## 组件拆分

> 组件自身规格（尺寸 / 圆角 / 颜色 / 状态 / 交互）以 [公共组件与形态基线.md](./公共组件与形态基线.md) §二 为唯一真源；**本表只写「本页用法」**。

| # | 组件 | 职责 |
|---|---|---|
| 1 | `CorrectionForm`（页内私有 `pages/correction/`） | 页面根组件：表单数据 + 校验 + patch 组装 + 提交；**承载双列布局** |
| 2 | `AttributeGroup`（页内私有，**核心复用**） | 单维度属性**字段行**（当前值摘要 + 单 / 多选标注 + 弹层入口）；**就地不渲染 chip 与自定义输入框**；入参见下 |
| 3 | `TagChip`（页内私有，**仅服务 `AttributePickerSheet`**；视觉口径见「触达尺寸口径」） | 弹层内标签：选中态（`soft` = 多选档 / `solid` = 单选档，选中带 `check` 对勾）/ 候选态；视觉高恒 **88rpx** |
| 4 | `AttributePickerSheet`（页内私有：`BaseSheet` + 搜索 + 「已添加」区 + 候选全览 + 手动输入 + 底部条） | 属性维度的**唯一选择场所**（增 / 删 / 清空 / 自定义全在此层）；**只做选择与回抛，不碰提交路径** |
| 5 | `FloorPickerSheet`（页内私有：`BaseSheet` + 5 项单选 + 当前值高亮） | 楼层底部单选弹层；**只管把字典项渲染成可选行 + 回抛所选汉字** |
| 6 | `ImagePicker`（公共，多图形态 `max=3`） | 多图上传 / 预览 / 删除（图标 / 文案 / 删除钮位置随公共组件） |
| 7 | `AppHeader` / `AppButton` / `AppIcon` / `ImagePlaceholder`（公共） | 页头 / 提交按钮 / 图标 / 破图占位 |
| 8 | `BaseSheet`（公共，底部弹层骨架唯一真源） | 底部弹层骨架（`FloorPickerSheet` 与 `AttributePickerSheet` 共用底座；后者取 `scroll-body` + **`keyboard-lift`**（键盘弹起时抬升抽屉）分支） |
| 9 | `useCorrection.ts`（页内私有编排） | 预填 + 候选**并发**取 + 变更比对 + 提交与返回（**楼层字典常量**） |

**`FloorPickerSheet` 入参**：

```ts
props: {
  visible: boolean            // 显隐（v-if 懒挂载后由父级控制）
  value: string               // 当前楼层（汉字，与字典项同值）
  options: string[]           // 楼层字典项（汉字：负一层 / 一层 / 二层 / 三层 / 四层）
}
// emits: select(value: string)  —— 回抛所选汉字（即存储值）
```

> **职责边界**：`FloorPickerSheet` 只负责「把字典项渲染成可选行 + 回抛所选汉字 + 高亮当前值」；**端上无映射表、无兜底判定**（字典外值不存在，见 [schema/stall.md](../../schema/stall.md)）。

**`AttributeGroup` 入参**（对外 props / `change` 契约稳定，`CorrectionForm` / `useCorrection` 零改动）：

```ts
props: {
  dimensionId: number           // 维度 ID（提交时 attributes 的键）
  name: string                  // 维度名，如 食材（同时是弹层标题与占位文案的词根）
  valueType: 'single' | 'multi' // 单选 / 多选
  selected: string[]            // 当前已选（预填原始值；single 至多 1 项）
  candidates: string[]          // 参考候选（来自编辑态接口，仅提示、不限制）
  first?: boolean               // 是否首组（父级 v-for 按 index 传入；仅首组去上边距）
}
// emits: change(dimensionId: number, selected: string[])
```

> **职责边界**：字段行 + 弹层是 `AttributeGroup` 的**内部实现细节**（弹层由组件自身唤起、就近挂载、`pickerMounted` 常驻）；表单值真源恒在 `useCorrection`，本组件**不改 props**、只回抛新数组。
> `first` 原因：`.ag` 是子组件根节点，mp-weixin 下每个实例都被包在各自的宿主节点里 ⇒ `:first-child` 会对**每一组**命中、组间距整体归零，故改由父级显式下发。

**`AttributePickerSheet` 入参**：

```ts
props: {
  visible: boolean                    // 显隐（父级 v-if 懒挂载后置真并常驻，开合动画由 visible 驱动）
  name: string                        // 维度名（标题「选择<维度名>」+ 搜索 / 手动输入占位文案）
  valueType: 'single' | 'multi'       // single = 点项即选即关；multi = 草稿勾选 + 确认 / 清空
  selected: string[]                  // 主表单当前已选（每次打开作为草稿初值；单选「点当前项 = 无改动」判据）
  candidates: string[]                // 全部候选（总数 ≥12 时启用本地搜索过滤；为空 ⇒ 明示可手动输入）
  selectedStyle?: 'soft' | 'solid'    // 选中态视觉档，由父级按 valueType 下发（禁互串）
}
// emits: update(next: string[])  —— 多选确认 / 清空 / 单选点项或添加自定义后回抛**新数组**（父级转发 change）
//        close()                 —— BaseSheet 统一上抛（遮罩 / 下滑 / 关闭钮）；回写后本组件也上抛以自关
```

> `TagChip` **不提供** `requestCustom()` 出参（手动输入在弹层内 ⑤ 层完成，无外部消费方）。
> **`TagChip` 入参**：`{ label: string; variant?: 'selected' | 'candidate'; selectedStyle?: 'soft' | 'solid'; checkable?: boolean; ariaLabel?: string }`，`emits: pick()`；**恒 88rpx 单尺寸档**、只服务弹层，无 `closable` / `pickable`。

## 禁止项（UI 约束）

1. 卡片内部**不使用分割横线**，靠间距 / 分组区分模块，避免割裂感。
2. **属性维度只有一个入口 = 字段行**：候选**无论多少**一律经弹层呈现 —— **禁**在主表单就地平铺候选、**禁**按候选数量分档、**禁**在卡片内做滚动 / 内滚面板、**禁**在主表单放自定义输入框。理由：同一维度「两处都能选、但能选的东西不一样」是误导性的；单入口还让属性四行与基础字段共用 88rpx 基线、页长更短（防页面过长臃肿同向）；**禁**再按 `valueType` 给单选组特判。
3. **不增加多余 Tab**；本页独立，不嵌入意见反馈页。
4. 输入框**禁全包围矩形框**，统一**下划线**轻量样式。
5. **不支持切换菜品**，锚定菜品只读，防提交错误菜品。
6. 颜色走 Token**禁裸 hex**；图标统一 `AppIcon` **禁 emoji**；事件统一 **`@tap`**；按压用 `background` / `opacity` 微降，**禁 `transform: scale`**。

15. **属性弹层不得绕开公共 `BaseSheet`、不得换掉 chip 控件**：弹层内候选与「已添加」值仍是 `TagChip`（恒 88rpx + `checkable` 对勾）；**禁**列表行 / 复选框 / 原生 `<picker>` / `uni.showActionSheet` 等**第二套选择形态**；**禁**把自定义输入搬回主表单（手动输入恒在弹层内 ⑤ 层）；搜索框**只做本地过滤、禁发请求**，且仅候选总数 ≥12 时渲染；**禁**关掉 `keyboard-lift` 后又把输入框的 `adjust-position` 留成 `true`（二者必须同时到位，否则键盘要么遮住输入、要么双位移顶穿 `88vh`）。
16. **弹层草稿态不得污染表单**：多选组弹层内勾选只写本地草稿，点【确认】/【清空全部】才回抛；关闭 / 遮罩 / 下滑一律丢弃草稿，且**每次打开必须把草稿重置为主表单当前值**（禁残留上次未确认内容）。单选组点项即回抛并关闭（点当前项 = 不产生 diff）。**清空入口现在归弹层**（单选「不填该项」/ 多选「清空全部」）：主表单已无删除叉 ⇒ **禁**在主表单恢复删除叉，也**禁**同一层出现两个清空入口。

> **字典真源与变更规则**：楼层字典定义在 [schema/stall.md](../../schema/stall.md)（`负一层` / `一层` / `二层` / `三层` / `四层`，**值即汉字**）；管理端 [A2 档口管理](../../func/web/A-主数据维护/A2-档口管理.md) 下拉与端上单选**同用该字典**。**新增**楼层 = 两端各加一项（免迁移）；**删除 / 改名** = **先把该楼层的档口迁到其它楼层**、再改字典（故端上无需兜底）。

> **采纳写回的两条口径（后端按此实现，本页 UI 不改口径，仍按 patch 提交）：**
> ① **必须「按维度合并」，SHALL NOT 整体覆盖** —— 端上按 patch 只发**改动维度**，采纳时未提交 / 未勾选的维度**保留原值**（否则只改「食材」的菜品问题反馈会抹掉 `dietType` / `flavorTags` / `serveTemp`）。口径见 [B4](../../func/web/B-UGC治理/B4-菜品问题反馈管理.md) / [schema/dish_correction.md](../../schema/dish_correction.md) / [api/dishes.md](../../api/client/dishes.md)。
> ② **清空维度 = 删除该键** —— 单选「不填该项」与多选【清空全部】提交的 `[]` ⇒ 服务端**删除该维度键**（该维度置空），**SHALL NOT 落空数组**（保持 `single` = 字符串 / `multi` = 数组 的形态）。
>
> **弹层内候选顺序仍依赖后端排序**：弹层内候选**照后端原序渲染、端上不另排序** ⇒「常用靠前」完全依赖编辑端点按**使用频次 / 维度 `order`** 倒序下发；若排序口径改为无序，端上应在弹层内做「已选优先 + 命中优先」的稳定排序，**不动后端契约**。
>
> **弹层挂载位（真机待验）**：`AttributePickerSheet` 随 `AttributeGroup` 就近挂载，而表单整体位于页面 `scroll-view` 内 —— `ReviewComposer` 注释记有「小程序 `scroll-view` 内 `fixed` 层级会被压扁 / 裁剪」的历史结论。**若真机出现弹层被裁剪**：按 `ReviewComposer` 口径把弹层实例上移到 `pages/correction/index.vue`（`scroll-view` 之外），由 `openDimensionId` 驱动，**组件本身零改动**。
>
> **键盘避让（真机待验）**：`BaseSheet` 的 `keyboard-lift` 把抽屉的 `bottom` 由 `0` 抬到键盘高度（`uni.onKeyboardHeightChange` 驱动）。真机需验四项：① iOS / Android 键盘高度回调时序（回调是否先于键盘动画到位，会不会看到抽屉两段位移）；② 抬起后**抽屉底边是否贴住键盘顶**（`bottom` = 键盘高理论上无缝，若中间露出页面背景 ⇒ 需补 `bottom` 与键盘高的换算差 / 或改 `transition`）；③ 键盘收起后 `bottom` 是否干净归零（不留残余悬空）；④ `scroll-body` 内容高度上限（`88vh`）与抬升叠加时，⑤ 手动输入行是否始终可见。**若抬升方案在真机不稳**：退路是关掉 `keyboard-lift`、把两个输入框的 `adjust-position` 改回 `true` 并加 `:cursor-spacing`（此时改的是页面整体位移，需真机确认 `fixed` 抽屉是否随之移动），**或**把「手动输入」退回主表单。
>
> 其余口径（锚定只读、仅提交改动项、动态 `attributes`、不暗示生效、失败保留表单）均与功能文档一致。

```

{ type: "gone", note?, images? }      ← note / images 均可不传
```

| 场景 | 请求体 | 服务端 |
|---|---|---|

|---|---|
| 提交中 | 按钮 `loading`、**禁用重复点击** |
| 成功 | **Toast**「已收到，感谢反馈」→ 自动返回上一页 |
| 失败 | 页面底部**错误色文字**（同 `field` 型），**保留表单**（补充内容不丢） |

> 返回后详情页应已不再显示该菜（若管理员已处理）—— 但因**系统不自动下架**，用户可能仍看到该菜；**这符合设计**（人工判断需要时间），**不得端上乐观隐藏**。
